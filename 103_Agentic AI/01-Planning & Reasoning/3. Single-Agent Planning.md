# 📌 PATTERN 1: Planner–Executor Pattern
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 1️⃣ What Is This?

**Simple English:**
The agent has **two separate modes**:

1. **Planner Mode** → Thinks big picture. Creates the full plan.
2. **Executor Mode** → Focuses only on executing each step.

They are **separated on purpose** — the planner never executes, the executor never plans.

```
WITHOUT Separation:         WITH Planner-Executor:
━━━━━━━━━━━━━━━━━━━━━       ━━━━━━━━━━━━━━━━━━━━━━━━━
One confused agent:         Two focused modes:
"Should I plan now?         PLANNER: Creates full plan
 Or execute now?            ↓
 Or both at once?"          EXECUTOR: Executes step 1
Gets confused, mixes        EXECUTOR: Executes step 2
planning with doing.        EXECUTOR: Executes step 3
                            Clean. Focused. Better.
```

---

## 2️⃣ Why Do We Need This Separation?

**The Core Problem:**

Mixing planning and execution causes:

```
❌ PROBLEM 1: Local Optimization Trap
   Without plan: Agent solves each step greedily
   Gets to step 4 and realizes step 1 was wrong
   Now it's too late → full restart needed

   With planner: All steps considered TOGETHER
   Avoids dead ends before they happen

❌ PROBLEM 2: Context Window Contamination
   While executing, the agent sees execution details
   These details pollute the planning thought process
   Planner can't think clearly with executor noise

   With separation: Planner gets clean thinking space
   Executor gets focused execution context

❌ PROBLEM 3: Premature Execution
   Agent starts doing before thinking
   Wastes tool calls on wrong actions
   Expensive and slow to correct

   With planner-first: Think once, execute correctly
```

## 5️⃣ Technical Implementation

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from typing import List, Dict, Any
import json

llm = ChatOpenAI(model="gpt-4o", temperature=0)
fast_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# ═══════════════════════════════════════════════════
# THE PLANNER
# ═══════════════════════════════════════════════════
class Planner:
    """
    Creates a detailed execution plan from a high-level goal.
    Runs ONCE at the beginning (or when replanning is needed).
    """
    
    def __init__(self, llm):
        self.llm = llm
        self.prompt = ChatPromptTemplate.from_messages([
            ("system", """You are an expert planner. 
            Your job: Break any goal into clear, executable steps.
            
            Rules for good plans:
            1. Each step must be ONE concrete action
            2. Steps must be in correct dependency order
            3. Each step must have a clear expected output
            4. Keep steps small enough to execute in one action
            5. Include verification steps for critical actions
            
            Output as JSON list of steps."""),
            ("human", """
            Goal: {goal}
            Available tools: {tools}
            Previous results (if replanning): {context}
            
            Create a detailed execution plan.
            Format: [{{"step": 1, "action": "...", 
                       "tool": "...", 
                       "expected_output": "...",
                       "depends_on": []}}]
            """)
        ])
    
    def create_plan(
        self, 
        goal: str, 
        tools: List[str],
        context: str = "None"
    ) -> List[Dict]:
        """Generate execution plan"""
        
        response = self.llm.invoke(
            self.prompt.format_messages(
                goal=goal,
                tools=tools,
                context=context
            )
        )
        
        # Parse JSON plan
        plan = json.loads(response.content)
        print(f"📋 Plan created: {len(plan)} steps")
        return plan


# ═══════════════════════════════════════════════════
# THE EXECUTOR
# ═══════════════════════════════════════════════════
class Executor:
    """
    Executes individual steps from the plan.
    Focused ONLY on current step — no planning!
    """
    
    def __init__(self, llm, tools: Dict):
        self.llm = llm
        self.tools = tools
        self.prompt = ChatPromptTemplate.from_messages([
            ("system", """You are a precise executor.
            Your job: Execute ONE specific step perfectly.
            
            Rules:
            1. Focus ONLY on the given step
            2. Use the specified tool correctly
            3. Return structured output
            4. Report any failures clearly
            5. Do NOT deviate from the step"""),
            ("human", """
            Step to execute: {step}
            Previous results available: {previous_results}
            
            Execute this step and return:
            {{"status": "success/failure",
              "result": "...",
              "error": "... (if failed)"}}
            """)
        ])
    
    def execute_step(
        self, 
        step: Dict, 
        previous_results: Dict
    ) -> Dict:
        """Execute a single plan step"""
        
        print(f"\n⚡ Executing Step {step['step']}: {step['action']}")
        
        # Get the right tool
        tool_name = step.get("tool", "llm")
        
        if tool_name in self.tools:
            # Execute with tool
            tool = self.tools[tool_name]
            raw_result = tool(step["action"])
        else:
            # Execute with LLM reasoning
            response = self.llm.invoke(
                self.prompt.format_messages(
                    step=step,
                    previous_results=str(previous_results)
                )
            )
            raw_result = response.content
        
        result = {
            "step": step["step"],
            "action": step["action"],
            "result": raw_result,
            "status": "success"
        }
        
        print(f"✅ Step {step['step']} complete")
        return result


# ═══════════════════════════════════════════════════
# THE PLANNER-EXECUTOR ORCHESTRATOR
# ═══════════════════════════════════════════════════
class PlannerExecutorAgent:
    """
    Combines Planner + Executor with replanning capability
    """
    
    def __init__(self):
        self.planner = Planner(llm)
        self.executor = Executor(fast_llm, tools={})
        self.memory = {}  # Stores results from each step
    
    def run(self, goal: str, max_replan: int = 2) -> str:
        """
        Full planner-executor loop with replanning
        """
        
        replan_count = 0
        tools = ["search", "calculator", "code_runner", "write_file"]
        
        while replan_count <= max_replan:
            
            # PHASE 1: PLAN
            print(f"\n📋 {'INITIAL PLAN' if replan_count == 0 else 'REPLANNING...'}")
            plan = self.planner.create_plan(
                goal=goal,
                tools=tools,
                context=str(self.memory) if self.memory else "None"
            )
            
            # PHASE 2: EXECUTE
            failed_step = None
            
            for step in plan:
                result = self.executor.execute_step(step, self.memory)
                
                if result["status"] == "failure":
                    print(f"❌ Step {step['step']} failed!")
                    failed_step = step
                    break
                
                # Store result in memory
                self.memory[f"step_{step['step']}"] = result["result"]
            
            # PHASE 3: CHECK IF DONE OR REPLAN
            if failed_step is None:
                print("\n🎉 All steps completed successfully!")
                return self.memory.get(f"step_{len(plan)}", "Done")
            
            replan_count += 1
            if replan_count > max_replan:
                return f"Failed after {max_replan} replanning attempts"
        
        return "Completed with replanning"


# Run it!
agent = PlannerExecutorAgent()
result = agent.run(
    goal="Research the top 3 AI trends in 2025 and write a 300-word blog post"
)
```

## 6️⃣ Failure Modes

```
❌ FAILURE 1: Stale Plan Problem
   What: Plan is created at start, world changes during execution
   Example: Plan says "search news from today"
            But by step 7, new news has come out
   Fix: Add timestamp to plan, replan periodically

❌ FAILURE 2: Over-Granular Planning
   What: Planner creates 50 tiny micro-steps
   Example: "Open browser" → "Type URL" → "Press Enter" → ...
   Result: Massive overhead, loses big picture
   Fix: Set minimum step size in planning prompt

❌ FAILURE 3: Executor Goes Rogue
   What: Executor deviates from plan to "improve" it
   Example: Step 3 says "search X" but executor decides 
            to also do step 4 while it's there
   Result: Unpredictable execution, order violated
   Fix: Strict prompting: "Execute ONLY the given step"

❌ FAILURE 4: Plan-Execution Gap
   What: Plan assumes capabilities that executor doesn't have
   Example: Plan: "Query the production database"
            Executor: No database access tool available
   Fix: Validate plan against available tools before executing

❌ FAILURE 5: Infinite Replanning
   What: Every execution fails → triggers replan → fails again
   Why: Root cause of failure not addressed by replanning
   Fix: Set max_replan limit
        Log WHY each execution failed
        Planner gets failure reason for better replan
```

## 7️⃣ Interview Q&A

**Q: Explain the Planner-Executor pattern and its advantages.**

> ✅ **Strong Answer:**
> "The Planner-Executor pattern separates the cognitive tasks of planning and executing into distinct phases. The planner creates a complete, ordered execution strategy before any actions are taken, while the executor focuses solely on precise implementation of individual steps. This separation provides three key benefits: it prevents local optimization traps where greedy step-by-step decisions lead to dead ends; it keeps context clean so the planner isn't distracted by execution details; and it enables replanning — when execution fails, we can return to the planner with failure context to generate a better plan. In production, this pattern maps well to LangGraph where planner and executor are separate nodes with conditional replanning edges."

Planner-Executor:           Controller-Worker:

> **Key difference from Planner-Executor:**
> Controller doesn't plan everything upfront.
> Controller **dynamically decides** what to delegate based on current state.

## 5️⃣ Technical Implementation

```python
from langchain_openai import ChatOpenAI
from typing import List, Dict
import asyncio

llm = ChatOpenAI(model="gpt-4o", temperature=0)
worker_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# ═══════════════════════════════════════════════════
# WORKER — Executes one specific task
# ═══════════════════════════════════════════════════
class Worker:
    def __init__(self, worker_id: str, llm):
        self.worker_id = worker_id
        self.llm = llm
    
    def execute(self, task: str, context: str = "") -> Dict:
        """Execute a specific task assigned by controller"""
        
        prompt = f"""
        You are Worker {self.worker_id}.
        Execute this specific task only:
        
        Task: {task}
        Context: {context}
        
        Provide a complete, detailed result.
        """
        
        result = self.llm.invoke(prompt).content
        
        return {
            "worker_id": self.worker_id,
            "task": task,
            "result": result,
            "status": "success"
        }


# ═══════════════════════════════════════════════════
# CONTROLLER — Manages workers dynamically
# ═══════════════════════════════════════════════════
class Controller:
    def __init__(self, llm, num_workers: int = 3):
        self.llm = llm
        self.workers = [
            Worker(f"W{i+1}", worker_llm) 
            for i in range(num_workers)
        ]
        self.results = []
    
    def create_worker_assignments(
        self, 
        goal: str, 
        context: str = ""
    ) -> List[Dict]:
        """Dynamically create task assignments for workers"""
        
        import json
        
        prompt = f"""
        Goal: {goal}
        Current context: {context}
        Available workers: {len(self.workers)}
        
        Create {len(self.workers)} parallel task assignments.
        Each worker gets ONE independent task that contributes to the goal.
        Tasks should be executable IN PARALLEL (no dependencies).
        
        Return JSON:
        [
            {{"worker": "W1", "task": "...", "priority": "high"}},
            {{"worker": "W2", "task": "...", "priority": "medium"}},
            {{"worker": "W3", "task": "...", "priority": "medium"}}
        ]
        """
        
        response = self.llm.invoke(prompt).content
        return json.loads(response)
    
    def synthesize_results(
        self, 
        goal: str, 
        worker_results: List[Dict]
    ) -> str:
        """Combine all worker outputs into final answer"""
        
        results_text = "\n\n".join([
            f"Worker {r['worker_id']} result:\n{r['result']}"
            for r in worker_results
        ])
        
        synthesis_prompt = f"""
        Original Goal: {goal}
        
        Worker Results:
        {results_text}
        
        Synthesize all worker outputs into one cohesive, 
        high-quality final answer. Integrate all insights.
        Remove duplicates. Create a unified response.
        """
        
        return self.llm.invoke(synthesis_prompt).content
    
    def monitor_and_reassign(
        self, 
        failed_task: Dict
    ) -> Dict:
        """Handle worker failures dynamically"""
        
        prompt = f"""
        A worker failed this task: {failed_task['task']}
        
        Create a simpler alternative approach to accomplish 
        the same objective with different methods.
        
        Return: {{"alternative_task": "..."}}
        """
        
        import json
        response = self.llm.invoke(prompt).content
        return json.loads(response)
    
    def run(self, goal: str) -> str:
        """Full controller-worker execution"""
        
        print(f"🎯 Goal: {goal}")
        
        # STEP 1: Create assignments
        assignments = self.create_worker_assignments(goal)
        print(f"\n📋 Created {len(assignments)} worker assignments")
        
        # STEP 2: Execute workers in PARALLEL
        worker_results = []
        
        # Map assignments to workers
        for assignment in assignments:
            worker_id = assignment["worker"]
            worker = next(
                (w for w in self.workers if w.worker_id == worker_id),
                self.workers[0]
            )
            
            result = worker.execute(
                task=assignment["task"],
                context=f"This contributes to: {goal}"
            )
            
            # Handle failure
            if result["status"] == "failure":
                print(f"⚠️ Worker {worker_id} failed. Reassigning...")
                alt = self.monitor_and_reassign(assignment)
                result = worker.execute(alt["alternative_task"])
            
            worker_results.append(result)
            print(f"✅ Worker {worker_id} complete")
        
        # STEP 3: Synthesize results
        print("\n🔄 Synthesizing all results...")
        final_output = self.synthesize_results(goal, worker_results)
        
        return final_output


# Run it!
controller = Controller(llm, num_workers=3)
result = controller.run(
    goal="Create a comprehensive overview of renewable energy trends in 2025"
)
print(f"\n🎉 FINAL OUTPUT:\n{result}")
```

## 6️⃣ Failure Modes

```
❌ FAILURE 1: Worker Task Dependency Violation
   What: Controller assigns parallel tasks that actually depend on each other
   Example: Worker 1: "Write summary" (needs Worker 2's research first!)
            Worker 2: "Do research"
            Worker 1 finishes first with no data to summarize
   Fix: Controller must identify dependencies BEFORE assigning
        Use topological sort for dependent tasks

❌ FAILURE 2: Controller Bottleneck
   What: Controller becomes the slowest part of the system
   Example: 5 fast workers waiting for slow controller decisions
   Why: Controller uses large expensive model for every decision
   Fix: Use fast model for simple routing decisions
        Cache similar assignment patterns

❌ FAILURE 3: Worker Result Inconsistency
   What: Workers produce results that contradict each other
   Example: Worker 1: "Inflation is falling"
            Worker 2: "Inflation is rising"
   Result: Synthesizer confused, produces wrong output
   Fix: Add consistency check step before synthesis
        Give workers the same source data

❌ FAILURE 4: Controller Loses Track
   What: With many workers, controller loses context of what's done
   Example: Controller re-assigns already completed tasks
   Fix: Maintain explicit state tracking
        Workers report completion to shared state store
```

## 1️⃣ What Is This?

**Simple English:**
Hierarchical Planning organizes tasks in a **tree structure with multiple levels**.

```
TOP LEVEL:    Abstract, high-level goals
    ↓
MIDDLE LEVEL: Concrete sub-goals
    ↓
BOTTOM LEVEL: Specific executable actions
```

Each level **only talks to the level immediately below it**.
This creates clean, manageable layers.

GENERAL (Level 1 - Strategic):

    Thinks in: Hours
    Commands: Soldiers

    ↓ delegates to

SOLDIER (Level 4 - Execution):
    Goal: "Move to position A"
    Thinks in: Minutes
    Does: Physical actions

KEY INSIGHT:
    General doesn't manage soldiers directly

    Problems at one level don't collapse the whole system

## 4️⃣ Technical Implementation — LangGraph Hierarchical Agent

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict, List, Optional
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o", temperature=0)

# ═══════════════════════════════════════════════════
# STATE — Shared across all levels
# ═══════════════════════════════════════════════════
class HierarchicalState(TypedDict):
    # Top level
    ultimate_goal: str
    
    # Level 2 - phases
    high_level_phases: List[str]
    current_phase: str
    phase_index: int
    
    # Level 3 - tasks  
    current_phase_tasks: List[str]
    current_task: str
    task_index: int
    
    # Results
    task_results: List[str]
    phase_results: List[str]
    final_output: Optional[str]


# ═══════════════════════════════════════════════════
# LEVEL 1: META-PLANNER NODE
# ═══════════════════════════════════════════════════
def meta_planner(state: HierarchicalState) -> HierarchicalState:
    """
    Highest level planning.
    Breaks ultimate goal into major phases.
    """
    
    print(f"\n🗺️ META-PLANNER: Breaking down '{state['ultimate_goal']}'")
    
    prompt = f"""
    Ultimate Goal: {state['ultimate_goal']}
    
    Break this into 3-5 major phases.
    Each phase should be a significant milestone.
    Order them logically.
    
    Return as numbered list. One phase per line.
    """
    
    response = llm.invoke(prompt).content
    phases = [
        line.strip().split(". ", 1)[1] 
        for line in response.strip().split("\n")
        if line.strip() and line[0].isdigit()
    ]
    
    print(f"📋 Phases created: {len(phases)}")
    for i, phase in enumerate(phases):
        print(f"  Phase {i+1}: {phase}")
    
    return {
        **state,
        "high_level_phases": phases,
        "phase_index": 0,
        "current_phase": phases[0]
    }


# ═══════════════════════════════════════════════════
# LEVEL 2: PHASE PLANNER NODE
# ═══════════════════════════════════════════════════
def phase_planner(state: HierarchicalState) -> HierarchicalState:
    """
    Medium level planning.
    Breaks current phase into specific tasks.
    """
    
    current_phase = state["current_phase"]
    print(f"\n📝 PHASE PLANNER: Breaking down '{current_phase}'")
    
    prompt = f"""
    Ultimate Goal: {state['ultimate_goal']}
    Current Phase: {current_phase}
    
    Break this phase into 3-5 specific executable tasks.
    Each task must be completable in one action.
    
    Return as numbered list. One task per line.
    """
    
    response = llm.invoke(prompt).content
    tasks = [
        line.strip().split(". ", 1)[1]
        for line in response.strip().split("\n")
        if line.strip() and line[0].isdigit()
    ]
    
    print(f"📋 Tasks for phase: {len(tasks)}")
    
    return {
        **state,
        "current_phase_tasks": tasks,
        "task_index": 0,
        "current_task": tasks[0],
        "task_results": []
    }


# ═══════════════════════════════════════════════════
# LEVEL 3: TASK EXECUTOR NODE
# ═══════════════════════════════════════════════════
def task_executor(state: HierarchicalState) -> HierarchicalState:
    """
    Lowest level execution.
    Executes one specific task.
    """
    
    task = state["current_task"]
    print(f"\n⚡ EXECUTOR: Running '{task}'")
    
    prompt = f"""
    Context: Working on '{state['ultimate_goal']}'
    Current Phase: {state['current_phase']}
    Task to execute: {task}
    
    Execute this task completely and return the result.
    Be specific and thorough.
    """
    
    result = llm.invoke(prompt).content
    
    # Store result and advance task index
    new_results = state["task_results"] + [
        f"Task: {task}\nResult: {result[:200]}..."
    ]
    new_task_index = state["task_index"] + 1
    
    # Check if more tasks in this phase
    tasks = state["current_phase_tasks"]
    has_more_tasks = new_task_index < len(tasks)
    
    return {
        **state,
        "task_results": new_results,
        "task_index": new_task_index,
        "current_task": tasks[new_task_index] if has_more_tasks else ""
    }


# ═══════════════════════════════════════════════════
# PHASE AGGREGATOR — Collects phase results
# ═══════════════════════════════════════════════════
def phase_aggregator(state: HierarchicalState) -> HierarchicalState:
    """Summarizes all tasks in a phase, moves to next phase"""
    
    print(f"\n📊 PHASE AGGREGATOR: Summarizing '{state['current_phase']}'")
    
    summary_prompt = f"""
    Phase: {state['current_phase']}
    Task results:
    {chr(10).join(state['task_results'])}
    
    Summarize the key outputs of this entire phase
    in 2-3 sentences.
    """
    
    phase_summary = llm.invoke(summary_prompt).content
    
    new_phase_results = state["phase_results"] + [
        f"Phase: {state['current_phase']}\nSummary: {phase_summary}"
    ]
    
    new_phase_index = state["phase_index"] + 1
    phases = state["high_level_phases"]
    has_more_phases = new_phase_index < len(phases)
    
    return {
        **state,
        "phase_results": new_phase_results,
        "phase_index": new_phase_index,
        "current_phase": phases[new_phase_index] if has_more_phases else "",
    }


# ═══════════════════════════════════════════════════
# ROUTING FUNCTIONS
# ═══════════════════════════════════════════════════
def should_continue_tasks(state: HierarchicalState) -> str:
    """More tasks in current phase?"""
    if state["task_index"] < len(state["current_phase_tasks"]):
        return "continue_tasks"
    return "phase_done"

def should_continue_phases(state: HierarchicalState) -> str:
    """More phases to process?"""
    if state["phase_index"] < len(state["high_level_phases"]):
        return "next_phase"
    return "all_done"


# ═══════════════════════════════════════════════════
# BUILD THE GRAPH
# ═══════════════════════════════════════════════════
def final_synthesizer(state: HierarchicalState) -> HierarchicalState:
    """Combine all phase results into final output"""
    
    print("\n🎉 FINAL SYNTHESIS")
    
    synthesis_prompt = f"""
    Goal: {state['ultimate_goal']}
    
    Phase Results:
    {chr(10).join(state['phase_results'])}
    
    Create the final comprehensive output that fulfills the goal.
    """
    
    final = llm.invoke(synthesis_prompt).content
    return {**state, "final_output": final}


# Build LangGraph
graph = StateGraph(HierarchicalState)

# Add nodes
graph.add_node("meta_planner", meta_planner)
graph.add_node("phase_planner", phase_planner)
graph.add_node("task_executor", task_executor)
graph.add_node("phase_aggregator", phase_aggregator)
graph.add_node("final_synthesizer", final_synthesizer)

# Add edges
graph.set_entry_point("meta_planner")
graph.add_edge("meta_planner", "phase_planner")
graph.add_edge("phase_planner", "task_executor")

# Conditional: more tasks or phase done?
graph.add_conditional_edges(
    "task_executor",
    should_continue_tasks,
    {
        "continue_tasks": "task_executor",
        "phase_done": "phase_aggregator"
    }
)

# Conditional: more phases or all done?
graph.add_conditional_edges(
    "phase_aggregator",
    should_continue_phases,
    {
        "next_phase": "phase_planner",
        "all_done": "final_synthesizer"
    }
)

graph.add_edge("final_synthesizer", END)

# Compile and run
app = graph.compile()

result = app.invoke({
    "ultimate_goal": "Create a comprehensive AI safety research report",
    "high_level_phases": [],
    "current_phase": "",
    "phase_index": 0,
    "current_phase_tasks": [],
    "current_task": "",
    "task_index": 0,
    "task_results": [],
    "phase_results": [],
    "final_output": None
})
```

## 5️⃣ Failure Modes

```
❌ FAILURE 1: Abstraction Level Mismatch
   What: Level 2 creates tasks too abstract for Level 3 to execute
   Example: Level 2: "Understand the problem deeply"
            Level 3: "How do I execute 'understand deeply'?!"
   Fix: Define clear output format for each level
        Level 3 tasks must be tool-executable or LLM-answerable

❌ FAILURE 2: Information Loss Between Levels
   What: Context from higher levels not passed to lower levels
   Example: Level 1 goal says "for a 10-year-old audience"
            Level 3 executor never received this constraint
   Fix: Pass full context (including constraints) at every level

❌ FAILURE 3: Phase Dependency Not Respected
   What: Phase 3 starts before Phase 2 is fully done
   Why: Async execution without proper synchronization
   Fix: Explicit phase completion gates
        Use LangGraph's state to enforce ordering

❌ FAILURE 4: Micro-Management
   What: Too many levels make system slow and expensive
   Example: 5 levels for a task that needs 2
   Fix: Maximum 3-4 levels for most real tasks
        Match depth to actual complexity
```

## 1️⃣ What Is This?

**Simple English:**

```
DECOMPOSITION: Break one big problem into N smaller problems
               Solve each small problem independently
               
AGGREGATION:   Combine N solutions into one final answer

It's like:
    One pizza → Cut into 8 slices (decompose)
    Each person eats their slice (solve independently)
    Everyone satisfied = goal achieved (aggregate)
```

## 2️⃣ The Map-Reduce Analogy — From Big Data to AI

```
📊 MAP-REDUCE (Big Data):
    Big Dataset → Split into chunks (MAP)
    Process each chunk in parallel
    Combine all results (REDUCE)

🤖 DECOMPOSE-AGGREGATE (AI Agent):
    Big Question → Split into sub-questions (DECOMPOSE)
    Answer each sub-question (independently)
    Combine all answers (AGGREGATE)

EXAMPLE:
    Big Question: "What is the state of AI in healthcare,
                   finance, education, and transportation?"

    DECOMPOSE into 4 sub-questions:
    Q1: "What is AI doing in healthcare?"
    Q2: "What is AI doing in finance?"
    Q3: "What is AI doing in education?"
    Q4: "What is AI doing in transportation?"

    Answer each INDEPENDENTLY (parallel!)

    AGGREGATE:
    Combine all 4 answers into comprehensive report
```

## 5️⃣ Technical Implementation

```python
from langchain_openai import ChatOpenAI
from typing import List, Dict
import asyncio

llm = ChatOpenAI(model="gpt-4o", temperature=0)


class DecomposeAggregateAgent:
    """
    Implements Map-Reduce style reasoning for complex questions
    """
    
    def __init__(self, llm):
        self.llm = llm
    
    # ─────────────────────────────────────────────
    # STEP 1: DECOMPOSE
    # ─────────────────────────────────────────────
    def decompose(self, question: str) -> List[Dict]:
        """
        Break main question into independent sub-questions
        that can be answered in parallel
        """
        
        prompt = f"""
        Main Question: {question}
        
        Break this into 3-5 INDEPENDENT sub-questions.
        
        Rules:
        1. Sub-questions must be answerable INDEPENDENTLY
           (no sub-question needs another's answer first)
        2. Together they must FULLY cover the main question
        3. Each should be specific and focused
        
        Return JSON:
        [
            {{"id": 1, "sub_question": "...", "focus_area": "..."}},
            {{"id": 2, "sub_question": "...", "focus_area": "..."}},
            ...
        ]
        """
        
        import json
        response = self.llm.invoke(prompt).content
        sub_questions = json.loads(response)
        
        print(f"\n🔪 DECOMPOSED into {len(sub_questions)} sub-questions:")
        for sq in sub_questions:
            print(f"  Q{sq['id']}: {sq['sub_question']}")
        
        return sub_questions
    
    # ─────────────────────────────────────────────
    # STEP 2: SOLVE (Map Phase - can be parallel)
    # ─────────────────────────────────────────────
    def solve_sub_question(
        self, 
        sub_q: Dict, 
        context: str
    ) -> Dict:
        """Answer one sub-question independently"""
        
        prompt = f"""
        Context: {context}
        Sub-question: {sub_q['sub_question']}
        Focus area: {sub_q['focus_area']}
        
        Provide a thorough, specific answer to this sub-question.
        Include key facts, examples, and insights.
        """
        
        answer = self.llm.invoke(prompt).content
        
        return {
            "id": sub_q["id"],
            "sub_question": sub_q["sub_question"],
            "answer": answer
        }
    
    # ─────────────────────────────────────────────
    # STEP 3: AGGREGATE (Reduce Phase)
    # ─────────────────────────────────────────────
    def aggregate(
        self, 
        original_question: str,
        sub_answers: List[Dict],
        strategy: str = "synthesis"  # or "merge", "vote"
    ) -> str:
        """Combine all sub-answers into final answer"""
        
        print(f"\n🔄 AGGREGATING {len(sub_answers)} answers...")
        
        answers_text = "\n\n".join([
            f"Sub-Question {a['id']}: {a['sub_question']}\n"
            f"Answer: {a['answer']}"
            for a in sub_answers
        ])
        
        if strategy == "synthesis":
            prompt = f"""
            Original Question: {original_question}
            
            Individual Research Results:
            {answers_text}
            
            Synthesize all these findings into ONE comprehensive answer.
            Requirements:
            1. Connect insights across all sub-answers
            2. Resolve any contradictions
            3. Create a cohesive narrative
            4. Don't just list answers — INTEGRATE them
            5. Add a conclusion that answers the original question
            """
        
        elif strategy == "merge":
            prompt = f"""
            Original Question: {original_question}
            
            Answers to merge:
            {answers_text}
            
            Merge these into one organized document.
            Use clear sections. Remove duplicates.
            """
        
        return self.llm.invoke(prompt).content
    
    # ─────────────────────────────────────────────
    # MAIN RUN METHOD
    # ─────────────────────────────────────────────
    def run(self, question: str) -> str:
        """Full decompose → solve → aggregate pipeline"""
        
        print(f"🎯 Question: {question}")
        
        # 1. Decompose
        sub_questions = self.decompose(question)
        
        # 2. Solve each (in production, make this async/parallel)
        sub_answers = []
        for sq in sub_questions:
            print(f"\n📖 Solving Q{sq['id']}...")
            answer = self.solve_sub_question(sq, question)
            sub_answers.append(answer)
        
        # 3. Aggregate
        final_answer = self.aggregate(
            question, 
            sub_answers, 
            strategy="synthesis"
        )
        
        return final_answer


# Run it
agent = DecomposeAggregateAgent(llm)
result = agent.run(
    "How is artificial intelligence transforming healthcare, "
    "education, finance, and transportation in 2025?"
)
print(f"\n✅ FINAL ANSWER:\n{result}")
```

## 6️⃣ Failure Modes

```
❌ FAILURE 1: Non-Independent Sub-Questions
   What: Sub-questions actually depend on each other
   Example: Q1: "Who is the CEO?" 
            Q2: "What did the CEO announce?" (needs Q1's answer!)
   Fix: Dependency check in decomposition
        Reorder to sequential if dependencies exist

❌ FAILURE 2: Coverage Gap
   What: Sub-questions don't fully cover main question
   Example: Main Q: "AI in healthcare AND legal"
            Sub-Qs only cover healthcare → Legal missed!
   Fix: Verification step: "Do these sub-Qs fully cover main Q?"

❌ FAILURE 3: Lossy Aggregation
   What: Key insights from sub-answers lost in aggregation
   Example: Sub-answer 3 had crucial data, aggregator ignored it
   Fix: Structured aggregation template
        Explicitly reference each sub-answer by ID

❌ FAILURE 4: Contradiction Without Resolution
   What: Aggregator combines contradictory facts without noting them
   Example: Q1 says "X is effective", Q2 says "X doesn't work"
            Aggregator combines both as facts — confused output
   Fix: Contradiction detection step before aggregation
        Aggregator must explicitly resolve or flag conflicts
```

## 1️⃣ What Is This?

## 2️⃣ Real-Life Analogy — Jazz Band vs Orchestra

    Each listens to others in real-time

    This is collaborative multi-agent AI:

## 5️⃣ Technical Implementation — Debate Pattern

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage
from typing import List, Dict

llm = ChatOpenAI(model="gpt-4o", temperature=0.7)

class DebateAgent:
    """
    An agent that argues a specific position
    """
    
    def __init__(self, name: str, position: str, llm):
        self.name = name
        self.position = position
        self.llm = llm
    
    def argue(
        self, 
        topic: str, 
        opponent_argument: str = "",
        round_num: int = 1
    ) -> str:
        """Make an argument for this agent's position"""
        
        system = f"""You are {self.name}.
        Your position: {self.position}
        
        Argue strongly for your position.
        Be specific, use evidence and examples.
        Be direct and persuasive.
        Keep response to 150-200 words."""
        
        if round_num == 1:
            human = f"Topic: {topic}\n\nMake your opening argument."
        else:
            human = f"""Topic: {topic}
            
Your opponent argued:
{opponent_argument}

Provide a strong rebuttal. 
Address their points directly.
Reinforce your position with new evidence."""
        
        messages = [
            SystemMessage(content=system),
            HumanMessage(content=human)
        ]
        
        return self.llm.invoke(messages).content


class JudgeAgent:
    """Evaluates debate and delivers verdict"""
    
    def __init__(self, llm):
        self.llm = llm
    
    def evaluate(
        self, 
        topic: str, 
        context: str,
        debate_history: List[Dict]
    ) -> str:
        """Render verdict based on debate quality"""
        
        history_text = "\n\n".join([
            f"{d['agent']} (Round {d['round']}): {d['argument']}"
            for d in debate_history
        ])
        
        prompt = f"""You are an impartial judge.
        
Topic: {topic}
Context: {context}

Full Debate:
{history_text}

Render your verdict:
1. Who made stronger arguments? Why?
2. What evidence was most compelling?
3. What is the BEST answer for THIS specific context?
4. What nuances should be considered?

Provide: Clear verdict + reasoning + recommendations."""
        
        return self.llm.invoke(prompt).content


class MultiAgentDebate:
    """Orchestrates a full debate between multiple agents"""
    
    def __init__(self, num_rounds: int = 3):
        self.num_rounds = num_rounds
    
    def run(
        self, 
        topic: str,
        context: str,
        position_a: str,
        position_b: str
    ) -> Dict:
        
        # Create agents
        agent_a = DebateAgent("Agent A", position_a, llm)
        agent_b = DebateAgent("Agent B", position_b, llm)
        judge = JudgeAgent(llm)
        
        debate_history = []
        last_a = ""
        last_b = ""
        
        print(f"\n⚖️ DEBATE: {topic}")
        print(f"Position A: {position_a}")
        print(f"Position B: {position_b}")
        
        # Run debate rounds
        for round_num in range(1, self.num_rounds + 1):
            print(f"\n--- Round {round_num} ---")
            
            # Agent A argues
            arg_a = agent_a.argue(topic, last_b, round_num)
            debate_history.append({
                "agent": "Agent A", 
                "argument": arg_a, 
                "round": round_num
            })
            print(f"Agent A: {arg_a[:100]}...")
            
            # Agent B argues
            arg_b = agent_b.argue(topic, arg_a, round_num)
            debate_history.append({
                "agent": "Agent B", 
                "argument": arg_b, 
                "round": round_num
            })
            print(f"Agent B: {arg_b[:100]}...")
            
            last_a = arg_a
            last_b = arg_b
        
        # Judge renders verdict
        print("\n⚖️ JUDGE RENDERING VERDICT...")
        verdict = judge.evaluate(topic, context, debate_history)
        
        return {
            "topic": topic,
            "debate_history": debate_history,
            "verdict": verdict
        }


# Run debate
debate = MultiAgentDebate(num_rounds=2)
result = debate.run(
    topic="Should we use microservices or monolithic architecture?",
    context="5-person startup, 6 months old, B2B SaaS product",
    position_a="Microservices: Better for scale and team autonomy",
    position_b="Monolith: Better for early-stage startups"
)

print(f"\n✅ VERDICT:\n{result['verdict']}")
```

## 6️⃣ Failure Modes

```
❌ FAILURE 1: Role Boundary Violations
   What: Agent acts outside their defined role
   Example: Writer starts conducting its own research
            (ignoring the researcher's findings)
   Why: LLM doesn't rigidly follow role constraints
   Fix: Explicit constraints in system prompt
        "You MUST ONLY use the research provided to you"

❌ FAILURE 2: Role Gap
   What: A necessary function has no assigned agent
   Example: No verification agent → errors reach final output
   Fix: Map all required functions before designing roles
        Gap analysis: "Who handles [X]?"

❌ FAILURE 3: Role Overlap Conflict  
   What: Two agents both try to do the same thing
   Example: Both Writer and Editor try to add new facts
            Contradictory additions in final output
   Fix: Explicit responsibility boundaries in all role cards
        Orchestrator resolves conflicts

❌ FAILURE 4: Specialization Overkill
   What: Too many specialized agents for simple task
   Example: 8 specialist agents to write a 2-sentence caption
   Why: Over-engineering the solution
   Fix: Match number of agents to actual task complexity
        Use single agent for simple tasks
```

│     If no → go back to step 1                               │
└─────────────────────────────────────────────────────────────┘
```

## 5️⃣ Technical Implementation — LangGraph Orchestrator

```python
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI
from typing import TypedDict, List, Optional, Dict
import json

# Different model for orchestrator vs subagents
orchestrator_llm = ChatOpenAI(model="gpt-4o", temperature=0)
subagent_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)


# ═══════════════════════════════════════════════════
# SHARED STATE
# ═══════════════════════════════════════════════════
class OrchestratorState(TypedDict):
    # Input
    user_goal: str
    
    # Orchestrator decisions
    next_subagent: str          # Which subagent to call
    task_for_subagent: str      # What to ask subagent
    context_for_subagent: str   # Context to give subagent
    
    # Results accumulation
    completed_tasks: List[Dict]
    all_results: Dict[str, str]
    
    # Control flow
    is_complete: bool
    final_answer: Optional[str]
    iteration: int
    max_iterations: int


# ═══════════════════════════════════════════════════
# SUBAGENTS (specialized tools)
# ═══════════════════════════════════════════════════
def web_search_subagent(task: str, context: str) -> str:
    """Subagent: Web search specialist"""
    prompt = f"""
    You are a web search specialist.
    Task: {task}
    Context: {context}
    
    Provide detailed, accurate search results 
    with key facts and sources.
    """
    return subagent_llm.invoke(prompt).content

def code_writer_subagent(task: str, context: str) -> str:
    """Subagent: Code writing specialist"""
    prompt = f"""
    You are an expert Python developer.
    Task: {task}
    Context: {context}
    
    Write clean, well-commented, working code.
    Include example usage.
    """
    return subagent_llm.invoke(prompt).content

def analysis_subagent(task: str, context: str) -> str:
    """Subagent: Data analysis specialist"""
    prompt = f"""
    You are a senior data analyst.
    Task: {task}
    Context: {context}
    
    Provide structured analysis with key insights,
    trends, and recommendations.
    """
    return subagent_llm.invoke(prompt).content

def writing_subagent(task: str, context: str) -> str:
    """Subagent: Professional writer"""
    prompt = f"""
    You are a senior content writer.
    Task: {task}
    Context: {context}
    
    Write engaging, clear, professional content.
    """
    return subagent_llm.invoke(prompt).content

# Registry of available subagents
SUBAGENT_REGISTRY = {
    "web_search": web_search_subagent,
    "code_writer": code_writer_subagent,
    "analysis": analysis_subagent,
    "writing": writing_subagent
}


# ═══════════════════════════════════════════════════
# ORCHESTRATOR NODE
# ═══════════════════════════════════════════════════
def orchestrator_node(state: OrchestratorState) -> OrchestratorState:
    """
    The master orchestrator — decides what to do next
    """
    
    print(f"\n🎯 ORCHESTRATOR (Iteration {state['iteration']})")
    
    completed_summary = json.dumps(
        state["completed_tasks"], 
        indent=2
    ) if state["completed_tasks"] else "None yet"
    
    decision_prompt = f"""
    You are a master orchestrator coordinating subagents.
    
    Ultimate Goal: {state['user_goal']}
    
    Iteration: {state['iteration']} of {state['max_iterations']}
    
    Completed tasks so far:
    {completed_summary}
    
    Available subagents:
    - web_search: Find information from the internet
    - code_writer: Write Python code
    - analysis: Analyze data and provide insights
    - writing: Write professional content
    
    Decide next action. Return JSON:
    {{
        "is_complete": false,
        "reasoning": "Why this decision?",
        "next_subagent": "web_search|code_writer|analysis|writing",
        "task": "Exact task for the subagent",
        "context": "Relevant context for subagent",
        "final_answer": null
    }}
    
    If goal is fully achieved, return:
    {{
        "is_complete": true,
        "reasoning": "Goal is complete because...",
        "next_subagent": null,
        "task": null,
        "context": null,
        "final_answer": "Complete final answer here"
    }}
    """
    
    response = orchestrator_llm.invoke(decision_prompt).content
    
    # Clean JSON response
    if "```json" in response:
        response = response.split("```json")[1].split("```")[0]
    elif "```" in response:
        response = response.split("```")[1].split("```")[0]
    
    decision = json.loads(response.strip())
    
    print(f"  Reasoning: {decision['reasoning'][:100]}...")
    print(f"  Next: {decision.get('next_subagent', 'COMPLETE')}")
    
    return {
        **state,
        "next_subagent": decision.get("next_subagent", ""),
        "task_for_subagent": decision.get("task", ""),
        "context_for_subagent": decision.get("context", ""),
        "is_complete": decision["is_complete"],
        "final_answer": decision.get("final_answer"),
        "iteration": state["iteration"] + 1
    }


# ═══════════════════════════════════════════════════
# SUBAGENT EXECUTION NODE
# ═══════════════════════════════════════════════════
def subagent_execution_node(
    state: OrchestratorState
) -> OrchestratorState:
    """Routes to correct subagent and executes"""
    
    subagent_name = state["next_subagent"]
    task = state["task_for_subagent"]
    context = state["context_for_subagent"]
    
    print(f"\n⚡ SUBAGENT: {subagent_name}")
    print(f"  Task: {task[:80]}...")
    
    # Execute the correct subagent
    if subagent_name in SUBAGENT_REGISTRY:
        result = SUBAGENT_REGISTRY[subagent_name](task, context)
    else:
        result = f"Error: Unknown subagent '{subagent_name}'"
    
    # Store result
    completed_task = {
        "subagent": subagent_name,
        "task": task,
        "result": result[:500]  # Truncate for state
    }
    
    new_completed = state["completed_tasks"] + [completed_task]
    new_results = {
        **state["all_results"],
        f"{subagent_name}_{state['iteration']}": result
    }
    
    print(f"  ✅ Subagent complete")
    
    return {
        **state,
        "completed_tasks": new_completed,
        "all_results": new_results
    }


# ═══════════════════════════════════════════════════
# ROUTING LOGIC
# ═══════════════════════════════════════════════════
def should_complete(state: OrchestratorState) -> str:
    if state["is_complete"]:
        return "complete"
    if state["iteration"] >= state["max_iterations"]:
        return "complete"  # Force stop
    return "execute_subagent"


# ═══════════════════════════════════════════════════
# BUILD THE GRAPH
# ═══════════════════════════════════════════════════
def build_orchestrator_graph():
    graph = StateGraph(OrchestratorState)
    
    # Add nodes
    graph.add_node("orchestrator", orchestrator_node)
    graph.add_node("subagent_execution", subagent_execution_node)
    
    # Entry point
    graph.set_entry_point("orchestrator")
    
    # After orchestrator: complete OR execute subagent
    graph.add_conditional_edges(
        "orchestrator",
        should_complete,
        {
            "execute_subagent": "subagent_execution",
            "complete": END
        }
    )
    
    # After subagent: always back to orchestrator
    graph.add_edge("subagent_execution", "orchestrator")
    
    return graph.compile()


# Run it!
app = build_orchestrator_graph()

result = app.invoke({
    "user_goal": "Research the top 3 Python frameworks for building "
                 "AI agents, compare them, and write a recommendation",
    "next_subagent": "",
    "task_for_subagent": "",
    "context_for_subagent": "",
    "completed_tasks": [],
    "all_results": {},
    "is_complete": False,
    "final_answer": None,
    "iteration": 0,
    "max_iterations": 8
})

print(f"\n🎉 FINAL ANSWER:\n{result['final_answer']}")

## 6️⃣ Failure Modes

```
❌ FAILURE 1: Orchestrator Becomes Bottleneck
   What: Everything waits for orchestrator to decide
   Example: 5 fast subagents idle while orchestrator thinks
   Fix: Use async subagent execution
        Pre-compute likely next steps during execution

❌ FAILURE 2: Orchestrator Loses State
   What: Orchestrator forgets earlier decisions
   Example: Calls same subagent twice with same task
   Why: Context window fills up with many iterations
   Fix: Summarize completed tasks periodically
        Use external state store (Redis, database)

❌ FAILURE 3: Subagent Task Mismatch
   What: Orchestrator gives wrong subagent the wrong task
   Example: Asks code_writer to do web research
   Why: Poor capability description in available agents list
   Fix: Rich, specific capability descriptions
        Include examples of what each subagent handles

❌ FAILURE 4: Circular Orchestration
   What: Orchestrator loops same sequence forever
   Example: Always: search → analyze → search → analyze
            Never reaches writing phase
   Fix: Iteration counter + force-completion at max
        Progress tracking: "Has this combination been tried?"
```

## 5️⃣ Technical Implementation — P2P Message Bus

```python
from langchain_openai import ChatOpenAI
from typing import Dict, List, Optional, Callable
from dataclasses import dataclass, field
from datetime import datetime
import asyncio
import uuid

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)


# ═══════════════════════════════════════════════════
# MESSAGE SYSTEM
# ═══════════════════════════════════════════════════
@dataclass
class Message:
    """Standard message format for P2P agent communication"""
    from_agent: str
    to_agent: str          # "broadcast" for all agents
    content: str
    message_type: str      # TASK, RESULT, QUERY, STATUS, BROADCAST
    priority: int = 1      # 1=normal, 2=high, 3=urgent
    message_id: str = field(default_factory=lambda: str(uuid.uuid4())[:8])
    timestamp: str = field(
        default_factory=lambda: datetime.now().isoformat()
    )
    reply_to: Optional[str] = None
    metadata: Dict = field(default_factory=dict)


class MessageBus:
    """
    Shared communication bus for P2P agent communication.
    Think of this as the 'internet' the agents communicate through.
    """
    
    def __init__(self):
        self.inboxes: Dict[str, List[Message]] = {}
        self.message_log: List[Message] = []
        self.subscribers: Dict[str, List[str]] = {}
    
    def register_agent(self, agent_id: str):
        """Register an agent to have an inbox"""
        self.inboxes[agent_id] = []
        print(f"  📬 Agent '{agent_id}' registered on message bus")
    
    def send(self, message: Message):
        """Send message to specific agent or broadcast"""
        
        if message.to_agent == "broadcast":
            # Send to all registered agents except sender
            for agent_id in self.inboxes:
                if agent_id != message.from_agent:
                    self.inboxes[agent_id].append(message)
        else:
            # Send to specific agent
            if message.to_agent in self.inboxes:
                self.inboxes[message.to_agent].append(message)
        
        self.message_log.append(message)
        print(f"  📨 {message.from_agent} → {message.to_agent}: "
              f"{message.content[:60]}...")
    
    def receive(self, agent_id: str) -> List[Message]:
        """Get all messages for an agent"""
        messages = self.inboxes.get(agent_id, []).copy()
        self.inboxes[agent_id] = []  # Clear inbox after reading
        return messages
    
    def peek(self, agent_id: str) -> int:
        """Check how many messages are waiting"""
        return len(self.inboxes.get(agent_id, []))


# ═══════════════════════════════════════════════════
# PEER-TO-PEER AGENT
# ═══════════════════════════════════════════════════
class P2PAgent:
    """
    An agent that can communicate directly with other agents
    via the message bus. No central orchestrator needed.
    """
    
    def __init__(
        self, 
        agent_id: str,
        role: str,
        capabilities: List[str],
        message_bus: MessageBus,
        llm
    ):
        self.agent_id = agent_id
        self.role = role
        self.capabilities = capabilities
        self.bus = message_bus
        self.llm = llm
        self.known_agents: Dict[str, List[str]] = {}  # agent_id → capabilities
        
        # Register on message bus
        self.bus.register_agent(agent_id)
    
    def discover_agents(self, other_agents: List['P2PAgent']):
        """Learn about other agents and their capabilities"""
        for agent in other_agents:
            if agent.agent_id != self.agent_id:
                self.known_agents[agent.agent_id] = agent.capabilities
    
    def decide_next_action(
        self, 
        goal: str, 
        messages: List[Message],
        completed: List[str]
    ) -> Dict:
        """
        Core decision making — what should I do next?
        Can be: execute task, request help from peer, broadcast info
        """
        
        messages_text = "\n".join([
            f"From {m.from_agent}: {m.content}"
            for m in messages
        ]) if messages else "No messages"
        
        known_agents_text = "\n".join([
            f"- {aid}: {caps}"
            for aid, caps in self.known_agents.items()
        ])
        
        prompt = f"""
        You are agent '{self.agent_id}'.
        Your role: {self.role}
        Your capabilities: {self.capabilities}
        
        Overall goal: {goal}
        
        Received messages:
        {messages_text}
        
        Completed work so far:
        {completed}
        
        Other available agents:
        {known_agents_text}
        
        Decide your next action. Return JSON:
        {{
            "action_type": "execute|request_peer|broadcast|complete",
            "reasoning": "Why this action?",
            "task_to_execute": "Task to do yourself (if execute)",
            "peer_to_contact": "Agent ID (if request_peer)",
            "message_to_peer": "What to ask peer (if request_peer)",
            "broadcast_message": "Info to share with all (if broadcast)",
            "result": "Your result (if completing a task)",
            "is_done": false
        }}
        """
        
        import json
        response = self.llm.invoke(prompt).content
        if "```json" in response:
            response = response.split("```json")[1].split("```")[0]
        return json.loads(response.strip())
    
    def execute_task(self, task: str, context: str) -> str:
        """Execute a task within this agent's capabilities"""
        
        prompt = f"""
        You are '{self.agent_id}' with role: {self.role}
        Your capabilities: {self.capabilities}
        
        Task: {task}
        Context: {context}
        
        Execute this task using your specialized capabilities.
        Provide detailed, high-quality output.
        """
        
        return self.llm.invoke(prompt).content
    
    def run_step(
        self, 
        goal: str, 
        completed: List[str]
    ) -> Optional[str]:
        """One step of P2P agent execution"""
        
        # Check inbox for messages from peers
        messages = self.bus.receive(self.agent_id)
        
        if messages:
            print(f"\n  {self.agent_id}: Received {len(messages)} messages")
        
        # Decide what to do
        decision = self.decide_next_action(goal, messages, completed)
        
        print(f"\n  {self.agent_id}: {decision['reasoning'][:80]}...")
        
        if decision["action_type"] == "execute":
            # Execute task myself
            result = self.execute_task(
                decision["task_to_execute"],
                f"Goal: {goal}"
            )
            print(f"  {self.agent_id}: ✅ Executed task")
            return result
        
        elif decision["action_type"] == "request_peer":
            # Send message to specific peer
            self.bus.send(Message(
                from_agent=self.agent_id,
                to_agent=decision["peer_to_contact"],
                content=decision["message_to_peer"],
                message_type="TASK"
            ))
            return None
        
        elif decision["action_type"] == "broadcast":
            # Share info with all agents
            self.bus.send(Message(
                from_agent=self.agent_id,
                to_agent="broadcast",
                content=decision["broadcast_message"],
                message_type="STATUS"
            ))
            return None
        
        elif decision["action_type"] == "complete":
            return decision.get("result", "Task complete")
        
        return None


# ═══════════════════════════════════════════════════
# P2P MULTI-AGENT SYSTEM
# ═══════════════════════════════════════════════════
def run_p2p_system(goal: str, max_steps: int = 10):
    """Run a P2P multi-agent system"""
    
    # Create shared message bus
    bus = MessageBus()
    
    # Create specialized agents
    agents = [
        P2PAgent(
            "researcher", "Senior Research Analyst",
            ["web_search", "information_synthesis", "fact_finding"],
            bus, llm
        ),
        P2PAgent(
            "analyst", "Data Analyst",
            ["data_analysis", "pattern_recognition", "statistics"],
            bus, llm
        ),
        P2PAgent(
            "writer", "Content Writer",
            ["writing", "summarization", "formatting"],
            bus, llm
        )
    ]
    
    # Each agent learns about others (peer discovery)
    for agent in agents:
        agent.discover_agents(agents)
    
    print(f"\n🌐 P2P SYSTEM STARTED")
    print(f"Goal: {goal}")
    print(f"Agents: {[a.agent_id for a in agents]}")
    
    completed = []
    results = []
    
    for step in range(max_steps):
        print(f"\n--- Step {step + 1} ---")
        
        step_results = []
        for agent in agents:
            result = agent.run_step(goal, completed)
            if result:
                step_results.append(f"{agent.agent_id}: {result[:200]}")
                results.append(result)
        
        completed.extend(step_results)
        
        # Check if any agent has completed the goal
        if len(results) >= 3:  # Simple completion check
            print("\n✅ Sufficient results gathered")
            break
    
    # Final synthesis (could be done by a writer agent)
    final_prompt = f"""
    Goal: {goal}
    
    Collected agent outputs:
    {chr(10).join(results[:5])}
    
    Synthesize into final comprehensive answer.
    """
    
    final = llm.invoke(final_prompt).content
    return final


# Run it!
result = run_p2p_system(
    goal="Analyze the current state of quantum computing and its impact on cryptography"
)
print(f"\n🎉 FINAL RESULT:\n{result}")
```

## 6️⃣ Failure Modes

```
❌ FAILURE 1: Message Storm
   What: Agents flood the bus with too many messages
   Example: All agents broadcast their results simultaneously
            Bus overwhelmed, agents miss important messages
   Fix: Rate limiting per agent
        Priority queuing on message bus
        Message TTL (time to live)

❌ FAILURE 2: Coordination Deadlock
   What: Agent A waits for Agent B, Agent B waits for Agent A
   Example: A: "Waiting for B to search before I write"
            B: "Waiting for A to outline before I search"
   Fix: Timeout mechanisms — if no response in X seconds, proceed
        Deadlock detection in message bus

❌ FAILURE 3: Information Asymmetry
   What: Different agents have very different information
   Example: Agent A has crucial fact, never shared it
            Agent B makes decision without that fact
   Fix: Mandatory status broadcasts after key discoveries
        Shared blackboard that all agents can read

❌ FAILURE 4: No Clear Completion Signal
   What: System doesn't know when to stop
   Example: Agents keep collaborating endlessly
            No agent declares the goal achieved
   Fix: Explicit goal completion check after each round
        Designated "goal checker" agent
        Max iteration hard stop

❌ FAILURE 5: Message Ordering Issues
   What: Messages arrive out of order
   Example: "Here is the result" arrives before "Please do this task"
   Fix: Message sequence numbers
        Causal consistency tracking
        Reply_to field to track conversation threads
```

## 7️⃣ Interview Questions & Answers (All Patterns)

**Q1: When would you use orchestrator-subagent vs peer-to-peer multi-agent architecture?**

> ✅ **Strong Answer:**
> "Orchestrator-subagent works best when tasks have clear dependencies and you need predictable, auditable behavior. The orchestrator's global view means it can coordinate complex workflows efficiently. However, it has a single point of failure and bottleneck risk. Peer-to-peer is better when tasks are truly independent, when you need fault tolerance without single points of failure, or when the coordination logic itself is complex enough to warrant distributed decision-making. In practice, most production systems use orchestration for its predictability, with P2P elements for specific parallel workloads."

**Q2: What is the difference between collaborative agents and specialized role-based agents?**

> ✅ **Strong Answer:**
> "Both involve multiple agents, but they differ in structure and interaction. Collaborative agents work jointly on the same problem — they share context, build on each other's thoughts, and may take on flexible roles. Specialized role-based agents are strictly defined: each has a specific domain, fixed inputs/outputs, and clear constraints. Role-based agents produce more consistent, predictable results but are less adaptive. Collaborative agents produce more creative, emergent results but are harder to debug and control. Production systems typically use role-based specialization as the foundation, with collaborative interactions enabled within specific phases."

**Q3: Design a multi-agent system for an AI-powered code review tool.**

> ✅ **Strong Answer:**
> "I'd use a specialized role-based architecture with an orchestrator. The orchestrator receives code and coordinates four specialized subagents: a Security Analyst agent that scans for vulnerabilities using static analysis patterns; a Performance Agent that identifies inefficient algorithms, N+1 queries, and memory issues; a Style Agent that checks coding standards, naming conventions, and documentation; and a Logic Agent that reviews business logic correctness and edge case handling. Each agent has strictly defined outputs in a structured format. The orchestrator synthesizes all four reviews into a prioritized, actionable report. I'd add a Conflict Resolution step where the orchestrator resolves when agents give contradictory feedback about the same code section."

# 🛠️ Practice Exercises

## 🟢 Beginner Level
1. **Identify the Pattern:** Look at these descriptions — which pattern is each?
   - *"Agent creates plan, then follows it step by step"*
   - *"Three agents debate whether to use REST or GraphQL"*
   - *"Master agent assigns tasks to 4 worker agents"*

2. **Role Design:** Design role cards for a 3-agent team that writes technical blog posts. Define: name, expertise, responsibilities, constraints, output format.

3. **Architecture Choice:** Which pattern would you choose for each? Why?
   - Build a chatbot that answers customer questions
   - Analyze 1000 customer reviews and find themes
   - Generate, review, and publish a social media campaign

## 🟡 Intermediate Level
4. **Planner-Executor Build:** Implement a Planner-Executor agent that:
   - Takes a user's goal
   - Creates a 5-step plan using GPT-4o-mini
   - Executes each step with a different tool
   - Stores results and handles one failure

5. **Debate System:** Implement the debate pattern with:
   - 2 agents debating a tech decision
   - 3 rounds of arguments
   - A judge agent rendering a verdict with reasoning

6. **Orchestrator Design:** Design (in pseudocode) an orchestrator that manages:
   - Research Agent
   - Writing Agent
   - Fact-Check Agent
   - What state does it maintain?
   - How does it handle failures?

## 🔴 Advanced Level
7. **Production System Design:** Design a complete multi-agent system for an AI-powered competitive intelligence tool that:
   - Monitors competitor websites daily
   - Analyzes pricing, features, and messaging changes
   - Generates weekly executive summary reports
   - Alerts on major competitive threats
   
   Specify: agents, roles, communication patterns, orchestration, failure handling

8. **Failure Recovery:** Your orchestrator-subagent system has a problem: the research subagent takes 45 seconds per call, making the whole system slow. Design a solution using:
   - Parallel execution
   - Result caching
   - Task batching
   - Timeout handling

9. **Evaluation Framework:** How would you test and evaluate a multi-agent system? Design metrics for:
   - Individual agent performance
   - Inter-agent communication quality
   - End-to-end task success rate
   - Cost per successful task

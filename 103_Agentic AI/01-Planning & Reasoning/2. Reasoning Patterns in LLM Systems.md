# 📌 PATTERN 1: Chain-of-Thought Reasoning
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 1️⃣ What Is This?

**Simple English:**
Chain-of-Thought (CoT) is a technique where you tell the LLM:
> *"Don't just give me the answer. Show me your thinking process step by step."*

Instead of:
```
Question → Answer
```

You get:
```
Question → Step 1 → Step 2 → Step 3 → ... → Answer
```

Each step is a **link in a chain of reasoning**.
The chain leads to the final answer.

> **The key insight:**
> When an LLM writes out its thinking,
> it can USE that thinking as context for the next step.
> This makes it dramatically smarter.

---

## 2️⃣ Why Was This Needed?

**The Problem — LLMs Fail at Multi-Step Problems:**

```
❌ WITHOUT Chain-of-Thought:

Question: "If a train travels 60 mph for 2.5 hours,
           then 80 mph for 1.5 hours, what is total distance?"

LLM Answer (Direct): "210 miles"  ← WRONG

Why did it fail?
The LLM tried to pattern-match to a similar problem
instead of actually calculating step by step.
```

```
✅ WITH Chain-of-Thought:

Same Question + "Think step by step"

LLM Answer:
Step 1: First segment: 60 mph × 2.5 hours = 150 miles
Step 2: Second segment: 80 mph × 1.5 hours = 120 miles
Step 3: Total = 150 + 120 = 270 miles

Answer: 270 miles ← CORRECT ✅

Why did it work?
Each step built on the previous.
The written-out intermediate steps
became context for the next calculation.
```

---

## 3️⃣ First Principles Breakdown

```
CORE TRUTH 1:
    LLMs predict the next token based on context.
    More correct context = more correct next prediction.
    Writing steps creates MORE correct context.
    Therefore: Writing steps = better answers.

CORE TRUTH 2:
    Human experts solve hard problems by writing out steps.
    CoT training data contains expert step-by-step solutions.
    LLMs learn to imitate this expert behavior.

CORE TRUTH 3:
    Complex problems can't be solved in one cognitive step.
    Breaking into small steps makes each step easy.
    Easy steps = high accuracy per step.
    Chain of easy steps = accurate complex solution.
```

## 6️⃣ Technical Implementation

```python
# ─────────────────────────────────────
# TYPE 1: Zero-Shot CoT
# ─────────────────────────────────────
prompt = """
Question: Roger has 5 tennis balls. He buys 2 more cans 
of tennis balls. Each can has 3 balls. How many does he have?

Let's think step by step.
"""
# Output: Step 1: Roger starts with 5. 
#         Step 2: He buys 2 cans × 3 balls = 6 balls.
#         Step 3: Total = 5 + 6 = 11 balls. Answer: 11 ✅


# ─────────────────────────────────────
# TYPE 2: Few-Shot CoT
# ─────────────────────────────────────
prompt = """
EXAMPLE 1:
Q: There are 15 trees. Workers plant trees today.
   Now there are 21 trees. How many did workers plant?
A: We started with 15 trees.
   We ended with 21 trees.
   So workers planted 21 - 15 = 6 trees. Answer: 6.

EXAMPLE 2:
Q: Shawn has 5 toys. For Christmas he got 2 more from
   mom and 2 from dad. How many toys does he have?
A: Shawn started with 5 toys.
   Got 2 from mom: 5 + 2 = 7.
   Got 2 from dad: 7 + 2 = 9. Answer: 9.

NOW ANSWER THIS:
Q: Roger has 5 tennis balls. He buys 2 more cans.
   Each can has 3 balls. How many does he have?
A: [LLM follows the demonstrated pattern] 
"""


# ─────────────────────────────────────
# REAL PRODUCTION CODE (LangChain)
# ─────────────────────────────────────
from langchain.prompts import PromptTemplate
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o")

cot_template = PromptTemplate(
    input_variables=["question"],
    template="""
    Question: {question}
    
    Let's solve this step by step:
    
    Step 1: Identify what we know
    Step 2: Identify what we need to find
    Step 3: Plan our approach
    Step 4: Execute step by step
    Step 5: Verify the answer makes sense
    
    Final Answer:
    """
)

chain = cot_template | llm
result = chain.invoke({"question": "Your complex question here"})
```

## 7️⃣ Math Intuition — Why CoT Works

Think of it this way:

```
WITHOUT CoT:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
P(correct answer) = P(one hard leap)
                  = Very Low Probability
                  ≈ 0.3 (30% chance)


WITH CoT:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
P(correct answer) = P(step1) × P(step2) × P(step3)
                  
But each step is EASY, so:
P(each step correct) ≈ 0.95

P(all 3 steps correct) = 0.95 × 0.95 × 0.95
                       = 0.857 (85.7% chance)

RESULT:
30% accuracy → 85% accuracy
Just by thinking step by step! 🤯
```

> The key insight: **Many easy steps beat one hard leap.**

## 8️⃣ Failure Modes — When CoT Breaks

```
❌ FAILURE 1: Verbose But Wrong
   Problem: LLM writes long reasoning chains
            that look correct but contain wrong steps
   Example: Step 3 has a math error that looks reasonable
   Why: LLM is GENERATING text, not COMPUTING math
        It generates plausible-looking steps, not verified ones
   Fix: Use code execution for math — don't trust LLM arithmetic

❌ FAILURE 2: Hallucinated Reasoning Steps
   Problem: LLM invents steps that sound logical but are false
   Example: "Step 3: According to Newton's 4th law..." 
            (Newton has only 3 laws)
   Why: LLM generates plausible text, not truth-verified facts
   Fix: Add fact-checking tools or retrieval augmentation

❌ FAILURE 3: Chain Too Long → Context Drift
   Problem: Very long chains lose focus on original question
   Example: By step 15, LLM has drifted to a different problem
   Why: Attention weakens on very early tokens
   Fix: Summarize intermediate results periodically

❌ FAILURE 4: Wrong Starting Assumption
   Problem: First step is wrong → all steps are wrong
   Example: Step 1: "Assume the price is $100" (but it's $50)
            All later calculations are wrong
   Why: CoT can't catch its own initial errors
   Fix: Combine with Reflection (Pattern 4)

❌ FAILURE 5: Wasted on Simple Questions
   Problem: CoT applied to every question including simple ones
   Example: "What is 2+2?" → 5-step CoT reasoning chain
   Why: Unnecessary compute cost
   Fix: Use deliberation (Pattern 5) to decide WHEN to use CoT
```

## 9️⃣ Interview Questions & Answers

**Q1: What is Chain-of-Thought prompting and why does it improve LLM performance?**

> ✅ **Strong Answer:**
> "Chain-of-Thought prompting is a technique that encourages LLMs to produce intermediate reasoning steps before giving a final answer. It works because LLMs generate text by predicting the next token based on context. When correct intermediate steps are written out, they become part of the context, making subsequent predictions more accurate. Research shows CoT improves accuracy on complex reasoning tasks by 20-50% depending on the task type. The key insight is that many small, easy steps are more reliable than one large cognitive leap."

**Q2: What is the difference between zero-shot and few-shot Chain-of-Thought?**

> ✅ **Strong Answer:**
> "Zero-shot CoT simply appends 'Let's think step by step' to the prompt with no examples — surprisingly effective because modern LLMs have seen step-by-step reasoning in training data. Few-shot CoT provides 2-8 worked examples of step-by-step reasoning before the actual question, which helps the LLM pattern-match to the desired reasoning style. Few-shot is generally more accurate but requires careful example selection — bad examples can actually hurt performance by establishing wrong reasoning patterns."

# 📌 PATTERN 2: Tree-of-Thoughts (ToT)
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 1️⃣ What Is This?

**Simple English:**
Tree-of-Thoughts is like Chain-of-Thought, but instead of following **one path** of thinking, the AI **explores multiple paths at once** — like a tree with many branches.

```
Chain-of-Thought:
    Start → Step1 → Step2 → Step3 → Answer
    (ONE path. Linear. No exploration.)

Tree-of-Thoughts:
    Start → Branch A → A1 → A2 → Dead end ❌
          → Branch B → B1 → B2 → B3 → Answer ✅
          → Branch C → C1 → Dead end ❌
    (MANY paths. Explores. Picks best.)
```

> **The key idea:**
> Sometimes the first approach is wrong.
> Smart thinking means exploring alternatives before committing.

```
♟️ BEGINNER PLAYER (Chain-of-Thought):
    "I'll move my knight here."
    → Follows first idea.
    → Doesn't consider alternatives.
    → Gets into bad positions.

♟️ GRANDMASTER (Tree-of-Thoughts):
    "Option 1: Move knight → opponent responds → I'm in danger ❌"

    → Evaluates all 3 options
    → Picks Option 2 → Wins

The grandmaster's mind is a TREE.
Multiple branches. Evaluate each. Pick the best.
```

## 6️⃣ Technical Implementation

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o", temperature=0.7)

# ─────────────────────────────────────────────
# STEP 1: THOUGHT GENERATION
# Generate multiple candidate thoughts
# ─────────────────────────────────────────────
def generate_thoughts(problem, current_state, num_thoughts=3):
    prompt = f"""
    Problem: {problem}
    Current progress: {current_state}
    
    Generate {num_thoughts} different possible next steps.
    Each should be a distinct approach.
    Number them clearly.
    """
    return llm.invoke(prompt).content

# ─────────────────────────────────────────────
# STEP 2: THOUGHT EVALUATION  
# Score each thought
# ─────────────────────────────────────────────
def evaluate_thought(problem, thought):
    prompt = f"""
    Problem: {problem}
    Proposed approach: {thought}
    
    Evaluate this approach:
    1. How likely is it to solve the problem? (1-10)
    2. What are its strengths?
    3. What are its weaknesses?
    4. Overall score: X/10
    
    Be honest and critical.
    """
    return llm.invoke(prompt).content

# ─────────────────────────────────────────────
# STEP 3: SEARCH (Beam Search - keep top K)
# ─────────────────────────────────────────────
def tree_of_thoughts_search(problem, max_depth=3, beam_width=2):
    """
    Beam Search ToT:
    - At each level, generate thoughts
    - Score all thoughts  
    - Keep only top beam_width thoughts
    - Expand those in next level
    """
    
    # Start with empty state
    current_states = [{"state": "", "score": 0, "path": []}]
    
    for depth in range(max_depth):
        all_candidates = []
        
        for state_info in current_states:
            # Generate thoughts from this state
            thoughts = generate_thoughts(
                problem, 
                state_info["state"],
                num_thoughts=3
            )
            
            # Evaluate each thought
            for thought in thoughts:
                score = evaluate_thought(problem, thought)
                all_candidates.append({
                    "state": thought,
                    "score": score,
                    "path": state_info["path"] + [thought]
                })
        
        # Keep only top beam_width candidates
        current_states = sorted(
            all_candidates, 
            key=lambda x: x["score"], 
            reverse=True
        )[:beam_width]
    
    # Return best final state
    return current_states[0]

result = tree_of_thoughts_search(
    problem="Plan a 3-day trip to Tokyo with $500 budget"
)
```

## 8️⃣ Failure Modes — When ToT Breaks

```
❌ FAILURE 1: Exponential Cost
   Problem: Tree grows exponentially with depth and branches
   Example: 3 branches × 3 levels = 3³ = 27 LLM calls
            4 branches × 4 levels = 4⁴ = 256 LLM calls!
   Why: Each level multiplies calls
   Fix: Use beam search (keep top-K only)
        Set max depth limits
        Use cheaper model for evaluation

❌ FAILURE 2: Bad Evaluation (The Judge Problem)
   Problem: LLM evaluation of thoughts is itself unreliable
   Example: LLM scores a wrong approach as 9/10
            Agent follows wrong path confidently
   Why: The same LLM that generates thoughts also evaluates them
        It can't reliably judge its own outputs
   Fix: Use separate evaluation model
        Use structured scoring rubrics
        Add external validators

❌ FAILURE 3: All Branches Converge
   Problem: All generated thoughts end up being the same idea
   Example: All 3 branches = "Search Google, summarize results"
   Why: LLM has limited diversity without high temperature
   Fix: Increase temperature for generation step
        Use diverse system prompts per branch
        Explicitly ask for "fundamentally different" approaches

❌ FAILURE 4: Depth vs. Breadth Tradeoff
   Problem: Choosing wrong search strategy
   Example: DFS wastes time going deep on a bad branch
            BFS wastes time on too many shallow branches
   Why: No perfect search strategy exists for all problems
   Fix: Use Beam Search as default
        Adjust beam width based on problem complexity
```

## 9️⃣ Interview Questions & Answers

**Q1: What is Tree-of-Thoughts and when should you use it over Chain-of-Thought?**

> ✅ **Strong Answer:**
> "Tree-of-Thoughts extends Chain-of-Thought by exploring multiple reasoning paths simultaneously rather than following one linear chain. It generates several candidate thoughts at each step, evaluates them, and keeps the most promising ones — like a tree search. I'd use ToT when the problem has multiple valid approaches, requires backtracking, or is creative/open-ended where the first approach might not be optimal. CoT is better when the path is clear, speed matters, or cost is a concern, since ToT can require exponentially more LLM calls."

**Q2: What is the main engineering challenge of implementing Tree-of-Thoughts in production?**

> ✅ **Strong Answer:**
> "The main challenges are cost and evaluation quality. ToT can require O(branches^depth) LLM calls, which becomes expensive fast. We mitigate this with beam search — only expanding the top-K candidates at each level. The second challenge is evaluation: the LLM evaluating its own thoughts is unreliable. The same model that generates bad thoughts might score them highly. We address this by using separate evaluation prompts, rubrics, or even different models for generation versus evaluation."

# 📌 PATTERN 3: ReAct (Reason + Act)
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 1️⃣ What Is This?

**Simple English:**
ReAct is a framework where the LLM **alternates between two things**:
1. **Reasoning** → Thinking about what to do
2. **Acting** → Actually doing something (using a tool)

And after each action, it **observes the result** and reasons again.

```
WITHOUT ReAct:
    LLM only reasons → Limited to training data
    Can't look up real info, run code, or take actions

WITH ReAct:
    Reason → Act → Observe → Reason → Act → Observe → ...
    Can use real tools: Google, Calculator, API, Code runner
```

> **The power of ReAct:**
> Reasoning + Real-World Actions = Agent that can DO things

## 3️⃣ The Exact ReAct Format — What The LLM Outputs

```
The LLM outputs text in this exact format:

Thought: [Reasoning about what to do]
Action: [tool_name(parameters)]
Observation: [Result from tool - added by system]
Thought: [Reasoning based on observation]
Action: [Next tool call OR Final Answer]
...
Final Answer: [The complete answer]

Example:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Question: Is the CEO of Microsoft the same person
          who founded it?

Thought: I need to find who is the current CEO of 
         Microsoft and who founded it. Let me search.
         
Action: search("current CEO of Microsoft")

Observation: Satya Nadella is the CEO of Microsoft.
             He became CEO in 2014.

Thought: Now I know the CEO is Satya Nadella. 
         Microsoft was founded by Bill Gates and 
         Paul Allen. Let me confirm this.

Action: search("Microsoft founders")

Observation: Microsoft was founded by Bill Gates 
             and Paul Allen in 1975.

Thought: Satya Nadella is CEO. 
         Bill Gates and Paul Allen are founders.
         They are different people.
         
Final Answer: No. Microsoft was founded by Bill Gates 
              and Paul Allen in 1975. The current CEO 
              is Satya Nadella, who took the role in 2014.
```

## 6️⃣ Technical Implementation — LangChain ReAct

```python
from langchain.agents import create_react_agent, AgentExecutor
from langchain_openai import ChatOpenAI
from langchain.tools import tool
from langchain import hub

# ─────────────────────────────────────────────
# STEP 1: Define Tools
# ─────────────────────────────────────────────
@tool
def search(query: str) -> str:
    """Search the internet for current information."""
    # In real code: call DuckDuckGo, Tavily, or Google API
    return f"Search results for: {query}"

@tool
def calculator(expression: str) -> str:
    """Calculate mathematical expressions accurately."""
    try:
        result = eval(expression)  # Use safer eval in production
        return f"Result: {result}"
    except Exception as e:
        return f"Error: {e}"

@tool  
def get_current_date(query: str) -> str:
    """Get the current date and time."""
    from datetime import datetime
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

# ─────────────────────────────────────────────
# STEP 2: Define the LLM and Agent
# ─────────────────────────────────────────────
llm = ChatOpenAI(model="gpt-4o", temperature=0)
tools = [search, calculator, get_current_date]

# ReAct prompt template (from LangChain hub)
# This teaches the LLM the Thought/Action/Observation format
prompt = hub.pull("hwchase17/react")

# Create the ReAct agent
agent = create_react_agent(llm, tools, prompt)

# ─────────────────────────────────────────────
# STEP 3: Run the Agent Executor
# ─────────────────────────────────────────────
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,        # Shows Thought/Action/Observation
    max_iterations=10,   # Safety limit
    handle_parsing_errors=True
)

# ─────────────────────────────────────────────
# STEP 4: Run!
# ─────────────────────────────────────────────
result = agent_executor.invoke({
    "input": "What is the square root of the current year?"
})

# Real Output Would Look Like:
# Thought: I need the current year first
# Action: get_current_date("")
# Observation: 2025-01-15 10:30:00
# Thought: The year is 2025. Now calculate √2025
# Action: calculator("2025 ** 0.5")
# Observation: Result: 45.0
# Thought: √2025 = 45. That's a perfect square!
# Final Answer: The square root of 2025 (the current year) is 45.
```

## 7️⃣ Failure Modes — When ReAct Breaks

```
❌ FAILURE 1: Action Loop (Most Common!)
   Problem: Agent keeps calling the same tool repeatedly
   Example: 
   Thought: "I need to search for X"
   Action: search("X")
   Observation: "Not found"
   Thought: "Let me search again"
   Action: search("X")  ← Same search!
   ...repeats forever
   Why: Agent doesn't recognize it already tried this
   Fix: Add max_iterations limit
        Track actions already taken
        Force different search query

❌ FAILURE 2: Hallucinated Action
   Problem: LLM invents a tool that doesn't exist
   Example: 
   Action: magic_database_lookup("CEO of XYZ corp")
   (magic_database_lookup is not a real tool)
   Why: LLM generates plausible-looking tool names
   Fix: Strict tool name validation
        Clear tool descriptions in system prompt

❌ FAILURE 3: Wrong Tool Selection
   Problem: Agent uses the wrong tool for the job
   Example: Using search() to do arithmetic
            Answer is then wrong (search returns text)
   Why: Agent doesn't understand tool capabilities
   Fix: Write very clear tool descriptions
        Add examples of WHEN to use each tool

❌ FAILURE 4: Observation Ignored
   Problem: Agent ignores the observation and hallucinates
   Example: 
   Action: search("population of Mars")
   Observation: "No data found — Mars has no population"
   Thought: "The population of Mars is 2 million" ← HALLUCINATED!
   Why: LLM sometimes overrides tool results with prior beliefs
   Fix: Emphasize observation importance in prompt
        Temperature = 0 for action selection

❌ FAILURE 5: Too Many Tool Calls (Cost Explosion)
   Problem: Agent calls tools excessively for simple questions
   Example: 10 web searches to answer "What is 2+2?"
   Why: No cost-awareness in base ReAct
   Fix: Add deliberation step (Pattern 5)
        Set max_iterations wisely
        Use direct answer for simple queries
```

## 8️⃣ Interview Questions & Answers

**Q1: What is the ReAct framework and how does it differ from standard Chain-of-Thought?**

> ✅ **Strong Answer:**
> "ReAct interleaves reasoning and acting in a structured loop: Thought → Action → Observation → Thought → Action. Unlike Chain-of-Thought which is purely internal reasoning, ReAct connects the LLM to external tools — search engines, calculators, APIs, databases. This overcomes two major LLM limitations: knowledge cutoff (tools provide real-time info) and arithmetic errors (calculators give exact answers). The core insight is that real intelligence requires both internal reasoning AND external interaction with the world."

**Q2: How do you handle the action loop problem in ReAct agents?**

> ✅ **Strong Answer:**
> "Action loops happen when the agent repeatedly calls the same tool. I handle this with three mechanisms: first, a max_iterations limit as a hard stop. Second, tracking previously taken actions and adding them to context so the agent knows what it already tried. Third, prompt engineering — instructing the agent to try a different approach if an action has already been attempted. In LangGraph specifically, I can add explicit loop detection as a conditional edge in the graph."

# 📌 PATTERN 4: Reflection & Self-Critique
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 1️⃣ What Is This?

**Simple English:**
Reflection is when the AI **looks at its own output and asks**:
> *"Is this good? Is this correct? How can I improve this?"*

Then it **rewrites** or **corrects** its answer based on that self-critique.

```
Without Reflection:
    Generate Answer → Done
    (First draft is final draft)

With Reflection:
    Generate Answer → Critique Answer → Improve Answer → 
    Critique Again → Improve Again → Final Answer
    (Multiple improvement cycles)
```

> **The analogy:**
> A good writer doesn't submit their first draft.
> They re-read it, find problems, and revise.
> Reflection teaches AI to do the same.

---

## 2️⃣ Why Was This Needed?

**The Core Problem:**

```
LLMs are trained to generate text that SOUNDS correct.
They are NOT trained to always BE correct.

First-draft LLM output typically has:
    → Factual errors they don't notice
    → Logical inconsistencies
    → Missing important points
    → Weak arguments
    → Formatting issues

Without reflection: errors stay in final output
With reflection: agent catches and fixes its own errors
```

## 6️⃣ Technical Implementation — Reflection Pattern

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

llm = ChatOpenAI(model="gpt-4o", temperature=0.7)

# ─────────────────────────────────────────────
# REFLECTION PATTERN IMPLEMENTATION
# ─────────────────────────────────────────────

def reflect_and_improve(task: str, max_rounds: int = 3) -> str:
    
    # STEP 1: Generate initial answer
    generation_prompt = f"""
    Task: {task}
    Generate your best answer to this task.
    """
    
    current_answer = llm.invoke(generation_prompt).content
    print(f"Initial Answer:\n{current_answer}\n")
    
    # STEP 2: Reflection loop
    for round_num in range(max_rounds):
        
        # Generate critique
        critique_prompt = f"""
        Task: {task}
        
        Current Answer:
        {current_answer}
        
        Critically evaluate this answer:
        1. What is WRONG or inaccurate?
        2. What is MISSING?
        3. What could be IMPROVED?
        4. Is the answer complete? (Yes/No)
        
        Be specific and harsh. List concrete problems.
        If the answer is already excellent, say "NO_IMPROVEMENT_NEEDED"
        """
        
        critique = llm.invoke(critique_prompt).content
        print(f"Round {round_num + 1} Critique:\n{critique}\n")
        
        # Check if improvement is needed
        if "NO_IMPROVEMENT_NEEDED" in critique:
            print("✅ Answer is satisfactory. Stopping reflection.")
            break
        
        # Improve based on critique
        improvement_prompt = f"""
        Task: {task}
        
        Previous Answer:
        {current_answer}
        
        Critique received:
        {critique}
        
        Now write an IMPROVED answer that fixes all the issues
        mentioned in the critique. Be concrete about what you changed.
        """
        
        current_answer = llm.invoke(improvement_prompt).content
        print(f"Round {round_num + 1} Improved Answer:\n{current_answer}\n")
    
    return current_answer

# Run it
final_answer = reflect_and_improve(
    task="Write a Python function to check if a string is a palindrome",
    max_rounds=3
)
```

## 7️⃣ Advanced — Reflexion Framework

The **Reflexion** paper (2023) formalized this into a powerful pattern:

```
┌──────────────────────────────────────────────────────────────┐
│                  REFLEXION FRAMEWORK                         │
│                                                              │
│  ┌─────────────┐                                            │
│  │    ACTOR    │ ← Tries the task                          │
│  │   (LLM)     │                                            │
│  └──────┬──────┘                                            │
│         │ Generates action/output                           │
│         ▼                                                    │
│  ┌─────────────┐                                            │
│  │  EVALUATOR  │ ← Judges if output is correct             │
│  │   (LLM)     │   Returns: success/failure + score        │
│  └──────┬──────┘                                            │
│         │ If failed:                                        │
│         ▼                                                    │
│  ┌─────────────┐                                            │
│  │  REFLECTOR  │ ← Analyzes WHY it failed                  │
│  │   (LLM)     │   Generates verbal reflection             │
│  └──────┬──────┘                                            │
│         │ Reflection stored in:                             │
│         ▼                                                    │
│  ┌─────────────┐                                            │
│  │   MEMORY    │ ← Persistent storage of reflections       │
│  │   (Store)   │   Next attempt reads this                 │
│  └──────┬──────┘                                            │
│         │ Loop back to Actor with richer context            │
│         ▼                                                    │
│  Actor tries AGAIN with reflection in context               │
│  → Until success ✅ or max_attempts reached                  │
└──────────────────────────────────────────────────────────────┘

KEY INNOVATION:
Reflexion stores reflections in MEMORY
So lessons from failure PERSIST across attempts
Agent gets smarter with each failure!
```

## 8️⃣ Failure Modes — When Reflection Breaks

```
❌ FAILURE 1: Sycophantic Self-Critique
   Problem: LLM critiques its own work too gently
   Example: Critique = "This is mostly great, maybe add one word"
            (When answer is actually very wrong)
   Why: LLM is trained to be agreeable, not harsh
   Fix: Use a SEPARATE critic model
        Use explicit rubric: "List at least 3 concrete problems"
        Adversarial prompting: "Be brutally honest"

❌ FAILURE 2: Oscillation
   Problem: Reflection loop makes answer WORSE not better
   Example: 
   Round 1: Good answer ✅
   Critique: "Make it longer"
   Round 2: Too long ❌ quality drops
   Critique: "Make it shorter"
   Round 3: Back to similar as Round 1
   Why: Critic doesn't preserve what was good
   Fix: Keep all previous versions
        Critic must explicitly say what to KEEP

❌ FAILURE 3: Reflection on Wrong Criteria
   Problem: Critique focuses on wrong things
   Example: Task = "Be accurate"
            Critic = "Make it sound more confident"
   Result: Agent optimizes for confidence, not accuracy
   Why: Critic's evaluation criteria doesn't match task goal
   Fix: Define explicit success criteria in critique prompt

❌ FAILURE 4: Infinite Loops
   Problem: Reflection never converges
   Example: Agent alternates between 2 different answers
   Why: No convergence criterion
   Fix: Max rounds limit
        Track reflection history
        Stop when critique score exceeds threshold
```

**Q1: What is Reflection in LLM agents and why is it powerful?**

> ✅ **Strong Answer:**
> "Reflection is a technique where an LLM evaluates its own output, identifies problems, and generates an improved version. It's powerful because LLMs generate plausible-sounding text that often contains errors they don't catch in a single pass. By adding a critique loop, we force the model to examine its work from a different perspective. The Reflexion framework extends this by storing reflections in memory — so lessons from failure persist and the agent improves over multiple attempts."

**Q2: What is the risk of self-reflection and how do you mitigate it?**

> ✅ **Strong Answer:**
> "The key risk is sycophantic self-critique — where the same LLM that generated a bad answer also evaluates it too generously. This is because LLMs are trained to be agreeable and tend to see their own outputs as good. I mitigate this with three strategies: using a separate critic model with a different system prompt, providing explicit evaluation rubrics that force the critic to identify specific problems, and occasionally using adversarial critique prompts that assume the answer has flaws."

# 📌 PATTERN 5: Deliberation vs. Direct Answering

## 1️⃣ What Is This?

**Simple English:**
This is the meta-skill of **knowing WHEN to think deeply vs. when to answer immediately**.

```
Direct Answering:
    "What is 2 + 2?" → "4"  (No thinking needed)
    Fast, cheap, correct for simple questions

Deliberation:
    "Should I invest my life savings in crypto?" →
    [Long, careful, multi-step reasoning needed]
    Slow, expensive, necessary for complex questions
```

> **The real-world parallel:**
> You don't pause and think for 5 minutes before saying
> *"my name is John."*
> But you DO think for 5 minutes before deciding
> *"should I quit my job?"*

This is the **intelligence of knowing which mode to use**.

## 2️⃣ Why This Matters in AI Engineering

**The Problem:**

```
❌ ALWAYS Direct: Fast but fails on complex questions
❌ ALWAYS Deliberate: Slow and expensive even for simple queries
✅ ADAPTIVE: Match reasoning depth to question complexity

Cost Example:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Real Cost Difference:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1,000 questions per day:

If 80% of questions are simple:
```

This is directly inspired by **Daniel Kahneman's** (Nobel Prize winner) work:

```
🧠 HUMAN BRAIN (Thinking Fast and Slow):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

    → Automatic, unconscious
    → Quick pattern matching
    → Used for: driving on familiar road,
                reading simple text,
                recognizing faces
    → Effort: Almost zero
    → Accuracy: High for routine things

SYSTEM 2 (Slow / Deliberate):
    → Conscious, effortful
    → Step-by-step reasoning
    → Used for: solving complex math,
                making major life decisions,
                learning new skills
    → Effort: High
    → Accuracy: High for complex things

🤖 AI EQUIVALENT:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SYSTEM 1 (Direct Answer):
    → Single LLM call
    → No reasoning chain
    → Fast and cheap
    → For: factual questions, simple tasks

    → CoT / ToT / ReAct / Reflection
    → Multi-step reasoning
    → Slow and expensive
```

## 6️⃣ Technical Implementation — Adaptive Reasoning Router

```python
from langchain_openai import ChatOpenAI
from enum import Enum

class ReasoningMode(Enum):
    DIRECT = "direct"
    COT = "chain_of_thought"
    REACT = "react_with_tools"
    FULL = "reflection_plus_cot"

def classify_question_complexity(question: str) -> ReasoningMode:
    """
    Use a fast, cheap LLM to classify question complexity.
    Then route to appropriate reasoning pattern.
    """
    
    classification_llm = ChatOpenAI(
        model="gpt-4o-mini",  # Fast + cheap for routing
        temperature=0
    )
    
    routing_prompt = f"""
    Classify this question's complexity for an AI agent:
    
    Question: {question}
    
    Answer with ONLY one of these words:
    
    DIRECT    - Simple fact, greeting, basic definition
               No reasoning needed. Fast answer fine.
    
    COT       - Multi-step reasoning needed
               No external data needed. 
               Math, logic, explanation required.
    
    REACT     - Needs real-time data or tool use
               Needs internet search, calculation, API
    
    FULL      - Complex, high stakes, needs verification
               Research + reasoning + self-checking needed
    
    Output ONLY one word.
    """
    
    mode = classification_llm.invoke(routing_prompt).content.strip()
    return ReasoningMode(mode.lower())


def adaptive_reasoning_agent(question: str) -> str:
    """
    Route question to appropriate reasoning pattern
    """
    
    # Classify the question
    mode = classify_question_complexity(question)
    print(f"Routing to: {mode.value}")
    
    if mode == ReasoningMode.DIRECT:
        # Fast, single call
        llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
        return llm.invoke(question).content
    
    elif mode == ReasoningMode.COT:
        # Chain-of-Thought
        return chain_of_thought_agent(question)
    
    elif mode == ReasoningMode.REACT:
        # ReAct with tools
        return react_agent(question)
    
    elif mode == ReasoningMode.FULL:
        # Full deliberation: CoT + Reflection + possibly ReAct
        return full_deliberation_agent(question)


# Test it
questions = [
    "What is the capital of Japan?",             # → DIRECT
    "Calculate compound interest on $1000",      # → COT
    "What are today's top AI news stories?",     # → REACT
    "Write a detailed market analysis for Tesla" # → FULL
]

for q in questions:
    mode = classify_question_complexity(q)
    print(f"Q: {q[:50]}... → {mode.value}")
```

## 7️⃣ Failure Modes — When Deliberation Decisions Break

```
❌ FAILURE 1: Misclassification
   Problem: Routing question to wrong reasoning mode
   Example: Complex medical question → classified as DIRECT
   Result: Wrong, potentially dangerous answer
   Why: Classification LLM makes mistakes too
   Fix: Err on the side of more deliberation for high-stakes
        Have human-in-the-loop for certain domains

❌ FAILURE 2: Over-Deliberation on Everything
   Problem: Agent uses full reasoning on every question
   Example: "Hello, how are you?" → 10 steps of analysis
   Result: Slow, expensive, annoying user experience
   Why: No classification step, defaults to maximum reasoning
   Fix: Implement the routing classifier

❌ FAILURE 3: Under-Deliberation on Novel Questions
   Problem: Agent treats new complex question as familiar simple one
   Example: Unusual medical symptom combination → treats as basic
   Why: Classifier doesn't recognize novelty
   Fix: Add novelty detection
        Classify "if in doubt, deliberate"

❌ FAILURE 4: Context Ignored in Classification
   Problem: Same question classified differently based on context
   Example: "What should I do?" 
            In coding context → DIRECT (give coding advice)
            In medical context → FULL (high stakes)
   Why: Classifier doesn't use conversation context
   Fix: Include full conversation context in routing prompt
```

## 8️⃣ Interview Questions & Answers

**Q1: What is deliberation in AI agents and why is it important for production systems?**

> ✅ **Strong Answer:**
> "Deliberation is the meta-skill of choosing the right reasoning depth for each question. Direct answering is fast and cheap but fails on complex problems. Deliberative reasoning — CoT, ToT, ReAct — is accurate but expensive. In production, not every question needs the same reasoning intensity. By implementing a routing layer that classifies question complexity and routes to the appropriate reasoning pattern, we can reduce costs dramatically while maintaining quality. This mirrors human System 1 / System 2 thinking from cognitive psychology."

**Q2: How would you design an adaptive reasoning system in production?**

> ✅ **Strong Answer:**
> "I'd build a three-layer system: First, a fast, cheap routing model (like GPT-4o-mini) that classifies question complexity into tiers — direct, CoT, ReAct, or full deliberation. Second, specialized agents for each tier — a simple LLM call for direct, a CoT chain, a ReAct agent with tools, and a full reflection loop. Third, a safety override that escalates any question involving health, finance, legal, or safety topics to full deliberation regardless of classification. I'd also log all routing decisions and audit them weekly to improve the classifier over time."

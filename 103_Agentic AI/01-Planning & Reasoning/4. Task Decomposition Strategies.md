## 1️⃣ What Is This?

**Simple English:**
Subtask Generation is the process of looking at a big, complex goal and **systematically breaking it into smaller, executable pieces** that an agent can actually complete.

```
BEFORE SUBTASK GENERATION:
━━━━━━━━━━━━━━━━━━━━━━━━━━━
Goal: "Launch a new AI product"
Agent: 🤯 Too vague. Too big. Don't know where to start.

AFTER SUBTASK GENERATION:
━━━━━━━━━━━━━━━━━━━━━━━━━━━
Goal broken into:
  T1: Define target market and user persona
  T2: Research competitor products
  T3: Design core feature list
  T4: Build MVP (minimum viable product)
  T5: Set up infrastructure
  T6: Create pricing strategy
  T7: Build marketing landing page
  T8: Set up analytics tracking
  T9: Soft launch to beta users
  T10: Collect feedback and iterate

Agent: ✅ Clear, manageable, actionable steps
```

## 2️⃣ Why Is This Hard?

**Most people think decomposition is easy. It is NOT.**

The real challenge is the **Goldilocks Problem**:

```
TOO COARSE (Too big):           TOO FINE (Too small):
━━━━━━━━━━━━━━━━━━━━━━━━         ━━━━━━━━━━━━━━━━━━━━━━━━━━━
T1: "Build the product"          T1: "Open your laptop"
T2: "Market the product"         T2: "Press the power button"
T3: "Launch the product"         T3: "Wait for it to boot"
                                 T4: "Open your code editor"
Too abstract. Agent still        T5: "Click 'New File'"
doesn't know what to do.         ...
                                 Way too many steps.
                                 Loses big picture.

JUST RIGHT (Goldilocks):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Each subtask:
  → Completable in ONE agent action or LLM call
  → Has a clear, verifiable output
  → Not so small it's meaningless
  → Not so big it still needs major planning
```

## 3️⃣ First Principles — What Makes a Good Subtask?

```
A GOOD SUBTASK MUST HAVE:

✅ ATOMICITY
   One clear action. Not two or three combined.
   BAD: "Research AND write AND review the report"
   GOOD: "Research the report topic" (one action)

✅ CLEAR OUTPUT
   You know exactly when it's done.
   BAD: "Think about the problem"
   GOOD: "List 5 key requirements for the system"

✅ CORRECT GRANULARITY
   Small enough to execute in one step.
   Large enough to make real progress.
   BAD: "Write the entire application" (too big)
   BAD: "Press the Enter key" (too small)
   GOOD: "Write the user authentication module"

✅ VERIFIABILITY
   You can check if the subtask was done correctly.
   BAD: "Make it better"
   GOOD: "Reduce response time below 200ms"

✅ INDEPENDENCE (ideally)
   Doesn't need 5 other things done first.
   (Or dependencies are explicitly stated)
```

## 7️⃣ Technical Implementation — LLM-Powered Subtask Generator

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from pydantic import BaseModel, Field
from typing import List, Optional
import json

llm = ChatOpenAI(model="gpt-4o", temperature=0)

# ═══════════════════════════════════════════════════
# SUBTASK DATA MODEL
# ═══════════════════════════════════════════════════
class Subtask(BaseModel):
    """
    Structured representation of a single subtask
    """
    id: str                          # Unique identifier: "T1", "T2"
    title: str                       # Short descriptive title
    description: str                 # What exactly needs to be done
    expected_output: str             # What does "done" look like?
    estimated_complexity: str        # "low" | "medium" | "high"
    requires_tool: Optional[str]     # Which tool needed? None = LLM only
    success_criteria: str            # How do we verify it's done?
    tags: List[str]                  # Categories: "research", "code", etc.


class DecompositionResult(BaseModel):
    """
    Full decomposition output
    """
    original_goal: str
    decomposition_method: str
    subtasks: List[Subtask]
    estimated_total_steps: int
    critical_path: List[str]         # IDs of most important subtasks
    risks: List[str]                 # Potential problems


# ═══════════════════════════════════════════════════
# SUBTASK GENERATOR
# ═══════════════════════════════════════════════════
class SubtaskGenerator:
    
    def __init__(self, llm):
        self.llm = llm
    
    def generate(
        self,
        goal: str,
        context: str = "",
        constraints: List[str] = None,
        method: str = "auto"
    ) -> DecompositionResult:
        """
        Generate subtasks from a high-level goal.
        
        Args:
            goal: The main objective to decompose
            context: Additional background information
            constraints: Rules/limits (time, tools, resources)
            method: Decomposition method to use
        """
        
        constraints_text = "\n".join(
            f"- {c}" for c in (constraints or [])
        )
        
        prompt = f"""
        You are an expert task planner specializing in 
        decomposing complex goals for AI agent execution.
        
        GOAL TO DECOMPOSE:
        {goal}
        
        CONTEXT:
        {context or "No additional context"}
        
        CONSTRAINTS:
        {constraints_text or "No specific constraints"}
        
        DECOMPOSITION METHOD: {method}
        
        YOUR TASK:
        Break this goal into well-designed subtasks following 
        these quality criteria:
        
        QUALITY CRITERIA FOR EACH SUBTASK:
        1. ATOMIC: One clear action, not multiple combined
        2. SPECIFIC: Clear enough to execute without ambiguity
        3. VERIFIABLE: Clear success criteria
        4. RIGHT-SIZED: Not too big (needs sub-planning) or 
                        too small (trivial)
        5. COMPLETE: All subtasks together must fully achieve goal
        
        Return a JSON object with this exact structure:
        {{
            "original_goal": "{goal}",
            "decomposition_method": "functional|temporal|component|dataflow|outcome",
            "subtasks": [
                {{
                    "id": "T1",
                    "title": "Short title",
                    "description": "Detailed description of what to do",
                    "expected_output": "What 'done' looks like",
                    "estimated_complexity": "low|medium|high",
                    "requires_tool": "search|code_runner|calculator|null",
                    "success_criteria": "How to verify completion",
                    "tags": ["research", "analysis", "writing", "code"]
                }}
            ],
            "estimated_total_steps": 8,
            "critical_path": ["T1", "T3", "T5"],
            "risks": ["Risk 1", "Risk 2"]
        }}
        
        Generate 5-12 subtasks. More for complex goals, 
        fewer for simple ones.
        """
        
        response = self.llm.invoke(prompt).content
        
        # Clean response
        if "```json" in response:
            response = response.split("```json")[1].split("```")[0]
        elif "```" in response:
            response = response.split("```")[1].split("```")[0]
        
        data = json.loads(response.strip())
        
        # Parse into Pydantic model
        subtasks = [Subtask(**st) for st in data["subtasks"]]
        
        result = DecompositionResult(
            original_goal=data["original_goal"],
            decomposition_method=data["decomposition_method"],
            subtasks=subtasks,
            estimated_total_steps=data["estimated_total_steps"],
            critical_path=data["critical_path"],
            risks=data["risks"]
        )
        
        return result
    
    def validate_decomposition(
        self, 
        result: DecompositionResult
    ) -> List[str]:
        """
        Quality check: does the decomposition pass all criteria?
        Returns list of issues found (empty = good decomposition)
        """
        
        issues = []
        subtask_ids = [st.id for st in result.subtasks]
        
        # Check 1: Coverage — do subtasks achieve the goal?
        validation_prompt = f"""
        Original goal: {result.original_goal}
        
        Subtasks:
        {json.dumps([st.model_dump() for st in result.subtasks], indent=2)}
        
        Critically evaluate:
        1. Do these subtasks FULLY achieve the goal? (Yes/No + reason)
        2. Are any important subtasks MISSING? (list them)
        3. Are any subtasks TOO LARGE and need breaking down?
        4. Are any subtasks REDUNDANT with each other?
        5. Is the ORDERING logical?
        
        Return JSON:
        {{
            "fully_achieves_goal": true/false,
            "missing_subtasks": ["..."],
            "too_large": ["T_id: reason"],
            "redundant": ["T_id1 and T_id2 overlap because..."],
            "ordering_issues": ["..."],
            "overall_quality": "excellent|good|needs_improvement|poor"
        }}
        """
        
        response = self.llm.invoke(validation_prompt).content
        if "```json" in response:
            response = response.split("```json")[1].split("```")[0]
        
        validation = json.loads(response.strip())
        
        if not validation["fully_achieves_goal"]:
            issues.append("⚠️ Decomposition doesn't fully achieve goal")
        
        for missing in validation.get("missing_subtasks", []):
            issues.append(f"⚠️ Missing subtask: {missing}")
        
        for large in validation.get("too_large", []):
            issues.append(f"⚠️ Too large: {large}")
        
        for redundant in validation.get("redundant", []):
            issues.append(f"⚠️ Redundant: {redundant}")
        
        return issues
    
    def display_decomposition(self, result: DecompositionResult):
        """Pretty print the decomposition"""
        
        print(f"\n{'='*60}")
        print(f"📋 TASK DECOMPOSITION RESULT")
        print(f"{'='*60}")
        print(f"Goal: {result.original_goal}")
        print(f"Method: {result.decomposition_method}")
        print(f"Total Steps: {result.estimated_total_steps}")
        print(f"Critical Path: {' → '.join(result.critical_path)}")
        print(f"\nRisks:")
        for risk in result.risks:
            print(f"  ⚠️ {risk}")
        
        print(f"\nSubtasks:")
        print(f"{'─'*60}")
        
        complexity_icons = {
            "low": "🟢",
            "medium": "🟡", 
            "high": "🔴"
        }
        
        for st in result.subtasks:
            icon = complexity_icons.get(st.estimated_complexity, "⚪")
            print(f"\n{icon} [{st.id}] {st.title}")
            print(f"   📝 {st.description[:80]}...")
            print(f"   ✅ Output: {st.expected_output}")
            print(f"   🔧 Tool: {st.requires_tool or 'LLM only'}")
            print(f"   🏷️  Tags: {', '.join(st.tags)}")


# ═══════════════════════════════════════════════════
# RUN IT
# ═══════════════════════════════════════════════════
generator = SubtaskGenerator(llm)

result = generator.generate(
    goal="Build a RAG (Retrieval-Augmented Generation) chatbot "
         "for a company's internal knowledge base",
    context="The company has 500 PDF documents. "
            "They want employees to ask questions and get answers.",
    constraints=[
        "Must be production-ready",
        "Use OpenAI GPT-4o for generation",
        "Use ChromaDB for vector storage",
        "Budget: 2 weeks of development time"
    ]
)

generator.display_decomposition(result)

# Validate quality
issues = generator.validate_decomposition(result)
if issues:
    print(f"\n⚠️ VALIDATION ISSUES:")
    for issue in issues:
        print(f"  {issue}")
else:
    print(f"\n✅ VALIDATION PASSED — Good decomposition!")
```

## 8️⃣ Failure Modes — When Subtask Generation Breaks

```
❌ FAILURE 1: The "Waterfall Trap"
   Problem: Decomposing into phases that are each still HUGE
   Example: "Phase 1: Research" (still needs 10 subtasks)
            "Phase 2: Development" (still needs 20 subtasks)
   Why: LLM stops at high level, doesn't go deep enough
   Fix: Specify minimum granularity in prompt
        Ask: "Each step must be doable in ONE tool call"

❌ FAILURE 2: Scope Creep in Subtasks
   Problem: Individual subtasks balloon beyond their scope
   Example: T3: "Research, then write, then also review"
            One subtask doing 3 things
   Why: LLM bundles related activities
   Fix: Explicit rule: "Each subtask = ONE verb + ONE object"
        BAD: "Research AND write the report"
        GOOD: "Research the topic" (T3) + "Write the report" (T4)

❌ FAILURE 3: Coverage Gap (Missing Subtasks)
   Problem: Important subtasks simply not generated
   Example: Building a web app, nobody generates "deploy" task
            Agent builds perfectly but never deploys!
   Why: LLM focuses on obvious steps, misses implicit ones
   Fix: Validation step — check goal coverage explicitly
        Use checklist: "What's needed to TRULY be done?"

❌ FAILURE 4: Wrong Decomposition Method
   Problem: Using temporal decomposition when functional is needed
   Example: Data pipeline task decomposed by time phases
            But should be decomposed by data transformation steps
   Result: Unclear which step does what processing
   Fix: Auto-select method based on task type
        Test multiple methods, pick clearest one

❌ FAILURE 5: Context-Free Decomposition
   Problem: Generic subtasks that ignore specific context
   Example: Goal: "Build AI chatbot for medical clinic"
            T1: "Collect data" (ignores HIPAA compliance need)
            T2: "Train model" (ignores regulatory requirements)
   Fix: Always include domain context in decomposition prompt
        Add: "What domain-specific requirements must be respected?"
```

## 9️⃣ Interview Q&A

**Q: How do you ensure good granularity in task decomposition for AI agents?**

> ✅ **Strong Answer:**
> "Good granularity solves the Goldilocks problem — subtasks shouldn't be so large that they still require major planning, or so small they create unnecessary overhead. I use three tests: the 'one tool call rule' — each subtask should be completable with a single tool invocation or LLM call; the 'clear output test' — I should be able to describe exactly what a completed subtask looks like; and the 'verifiability test' — I should be able to automatically check if the subtask succeeded. I also run a validation pass after generation where a second LLM call checks for coverage gaps, redundancy, and tasks that are still too large."

## 1️⃣ What Is This?

**Simple English:**
Dependency Mapping is the process of figuring out **which subtasks must be completed BEFORE other subtasks can start**.

```
DEPENDENCY = "Task B CANNOT start until Task A is DONE"

WITHOUT DEPENDENCY MAPPING:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Agent tries to write a report (T4)
before doing research (T1) → 
Agent has nothing to write about → 
FAILURE ❌

WITH DEPENDENCY MAPPING:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
T1 (Research) must come before T4 (Write)
This is known BEFORE execution starts →
Agent never tries T4 before T1 →
SUCCESS ✅
```

## 2️⃣ Real-Life Analogy — Building a House

## 3️⃣ Types of Dependencies

```
┌─────────────────────────────────────────────────────────────────┐
│                    DEPENDENCY TYPES                             │
├─────────────────────────┬───────────────────────────────────────┤
│ TYPE                    │ MEANING                               │
├─────────────────────────┼───────────────────────────────────────┤
│ FINISH-TO-START (FS)    │ T_A must FINISH before T_B can START  │
│ (Most common)           │ Example: Research → Write report      │
│                         │ T_B uses T_A's output                 │
├─────────────────────────┼───────────────────────────────────────┤
│ START-TO-START (SS)     │ T_A must START before T_B can START   │
│                         │ Example: Monitor system → Log results │
│                         │ Both start together, B needs A active │
├─────────────────────────┼───────────────────────────────────────┤
│ FINISH-TO-FINISH (FF)   │ T_A must FINISH when T_B FINISHES     │
│                         │ Example: Proofreading finishes with   │
│                         │ writing — they end together           │
├─────────────────────────┼───────────────────────────────────────┤
│ RESOURCE DEPENDENCY     │ T_B can't run because it needs the    │
│                         │ same resource as T_A (API rate limit) │
│                         │ Not logically dependent but           │
│                         │ practically constrained               │
├─────────────────────────┼───────────────────────────────────────┤
│ DATA DEPENDENCY         │ T_B needs specific DATA produced      │
│                         │ by T_A — even if not formally ordered │
│                         │ Example: B needs the CSV that A makes │
└─────────────────────────┴───────────────────────────────────────┘
```

## 4️⃣ The Dependency Graph — The Core Data Structure

**Dependency mapping produces a DAG (Directed Acyclic Graph):**

```
DAG = Directed Acyclic Graph

DIRECTED: Arrows go ONE way (A → B means A before B)
ACYCLIC: No circular dependencies 
         (A → B → C → A would be impossible to execute!)

Example DAG for "Build and launch an AI product":

     T1 (Market Research)
     /                 \
    ▼                   ▼

    \                   /
     ▼                 ▼

          ▼         ▼
          T7 (Beta Launch)
               │
               ▼
          T8 (Analyze Results)
               │
               ▼
          T9 (Full Launch)

## 5️⃣ Topological Sort — The Algorithm That Respects Dependencies

> **Simple Explanation:**
> Topological sort takes a dependency graph and produces a LINEAR ORDER of tasks where **dependencies always come before the tasks that need them**.

```
TOPOLOGICAL SORT ALGORITHM:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 1: Find all tasks with NO dependencies (sources)
        These can start immediately
        
STEP 2: Add them to execution order
        Remove them from the graph
        
STEP 3: Reveal new tasks with no remaining dependencies
        (Tasks whose prerequisites are all done)
        
STEP 4: Add those to execution order
        Remove them from graph
        
STEP 5: Repeat until all tasks are ordered

EXAMPLE:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Tasks: T1, T2, T3, T4, T5
Dependencies: T2→T1, T3→T1, T4→T2, T5→T3, T5→T4

ROUND 1: No dependencies → [T1] → Add T1, remove T1
          Now T2 and T3 have no remaining dependencies

ROUND 2: No dependencies → [T2, T3] → Add both, remove both
          Now T4 has no remaining dependencies (T2 done)
          T5 still needs T3 and T4

ROUND 3: No dependencies → [T4] → Add T4, remove T4
          Now T5 has no remaining dependencies (T3 and T4 done)

ROUND 4: No dependencies → [T5] → Add T5, done!

RESULT: [T1] → [T2, T3] → [T4] → [T5]
         T2 and T3 can be parallel! (both after T1)
```

```python
from langchain_openai import ChatOpenAI
from typing import List, Dict, Set, Tuple, Optional
from collections import defaultdict, deque
from pydantic import BaseModel
import json


# ═══════════════════════════════════════════════════
# DATA MODELS
# ═══════════════════════════════════════════════════
class DependencyMap(BaseModel):
    """Represents dependencies between all subtasks"""
    
    task_ids: List[str]
    dependencies: Dict[str, List[str]]  
    # Key: task_id, Value: list of task_ids that MUST come before
    # Example: {"T4": ["T1", "T2"]} means T1 and T2 before T4
    
    dependency_reasons: Dict[str, str]  
    # Why does this dependency exist?
    # Example: {"T4→T1": "T4 needs T1's research data"}
    
    has_circular: bool                  # Safety check
    critical_path: List[str]            # Longest sequence
    parallelism_opportunities: List[List[str]]  # Tasks that CAN run together


# ═══════════════════════════════════════════════════
# DEPENDENCY ANALYZER
# ═══════════════════════════════════════════════════
class DependencyMapper:
    
    def __init__(self, llm):
        self.llm = llm
    
    # ──────────────────────────────────────────────
    # STEP 1: LLM identifies dependencies
    # ──────────────────────────────────────────────
    def identify_dependencies(
        self,
        subtasks: List[Dict],
        goal: str
    ) -> Dict:
        """Use LLM to identify which tasks depend on which"""
        
        subtasks_text = json.dumps(subtasks, indent=2)
        
        prompt = f"""
        You are an expert project manager analyzing task dependencies.
        
        Goal: {goal}
        
        Subtasks:
        {subtasks_text}
        
        For each task, identify which other tasks MUST be completed 
        BEFORE it can start.
        
        Only include REAL dependencies where:
        - Task B actually NEEDS output/data from Task A, OR
        - Task B logically cannot start before Task A completes
        
        Do NOT add artificial dependencies just to create order.
        If tasks are truly independent, leave dependencies empty.
        
        Return JSON:
        {{
            "dependencies": {{
                "T1": [],
                "T2": ["T1"],
                "T3": ["T1"],
                "T4": ["T2", "T3"]
            }},
            "dependency_reasons": {{
                "T2→T1": "T2 needs the dataset that T1 collects",
                "T3→T1": "T3 analyzes the data T1 gathers"
            }},
            "independence_notes": [
                "T2 and T3 are independent of each other",
                "T5, T6, T7 can all run in parallel after T4"
            ]
        }}
        """
        
        response = self.llm.invoke(prompt).content
        if "```json" in response:
            response = response.split("```json")[1].split("```")[0]
        
        return json.loads(response.strip())
    
    # ──────────────────────────────────────────────
    # STEP 2: Detect circular dependencies (CRITICAL)
    # ──────────────────────────────────────────────
    def detect_circular_dependencies(
        self, 
        dependencies: Dict[str, List[str]]
    ) -> Tuple[bool, Optional[List[str]]]:
        """
        Detect if any circular dependency exists.
        A circular dependency makes execution IMPOSSIBLE.
        
        Example cycle: T1 → T2 → T3 → T1 (impossible!)
        
        Uses DFS (Depth-First Search) cycle detection.
        Returns: (has_cycle, cycle_path_if_found)
        """
        
        # States: 0=unvisited, 1=in-progress, 2=completed
        state = {task: 0 for task in dependencies}
        
        def dfs(task: str, path: List[str]) -> Optional[List[str]]:
            """Returns cycle path if cycle found, None otherwise"""
            
            state[task] = 1  # Mark as in-progress
            path.append(task)
            
            for dep in dependencies.get(task, []):
                if state.get(dep, 0) == 1:
                    # Found a cycle! Return the cycle path
                    cycle_start = path.index(dep)
                    return path[cycle_start:] + [dep]
                elif state.get(dep, 0) == 0:
                    cycle = dfs(dep, path.copy())
                    if cycle:
                        return cycle
            
            state[task] = 2  # Mark as completed
            return None
        
        for task in dependencies:
            if state[task] == 0:
                cycle = dfs(task, [])
                if cycle:
                    return True, cycle
        
        return False, None
    
    # ──────────────────────────────────────────────
    # STEP 3: Topological Sort
    # ──────────────────────────────────────────────
    def topological_sort(
        self,
        task_ids: List[str],
        dependencies: Dict[str, List[str]]
    ) -> List[List[str]]:
        """
        Sort tasks respecting dependencies.
        Returns list of LEVELS where each level is
        a GROUP of tasks that can run in PARALLEL.
        
        This is called "Level-based topological sort"
        or "BFS topological sort"
        """
        
        # Count how many dependencies each task has
        in_degree = {task: 0 for task in task_ids}
        
        # Build reverse map: 
        # "who needs me?" instead of "who do I need?"
        dependents = defaultdict(list)
        
        for task, deps in dependencies.items():
            in_degree[task] = len(deps)
            for dep in deps:
                dependents[dep].append(task)
        
        # Start with tasks that have zero dependencies
        current_level = [
            task for task in task_ids 
            if in_degree[task] == 0
        ]
        
        levels = []  # Each element is a list of parallel tasks
        
        while current_level:
            levels.append(current_level[:])  # Save current level
            
            next_level = []
            
            for completed_task in current_level:
                # For each task that needed this completed task
                for dependent in dependents[completed_task]:
                    in_degree[dependent] -= 1
                    
                    # If all its dependencies are done, 
                    # it can run next!
                    if in_degree[dependent] == 0:
                        next_level.append(dependent)
            
            current_level = next_level
        
        return levels
    
    # ──────────────────────────────────────────────
    # STEP 4: Find Critical Path
    # ──────────────────────────────────────────────
    def find_critical_path(
        self,
        task_ids: List[str],
        dependencies: Dict[str, List[str]],
        task_complexities: Dict[str, str]
    ) -> List[str]:
        """
        Find the LONGEST chain of dependent tasks.
        This is the minimum time the whole project takes.
        Can't speed up the project beyond the critical path!
        
        Complexity weights: low=1, medium=2, high=3
        """
        
        complexity_weights = {"low": 1, "medium": 2, "high": 3}
        
        # Earliest start time for each task
        earliest_start = {task: 0 for task in task_ids}
        predecessors = {}
        
        # Process in topological order
        levels = self.topological_sort(task_ids, dependencies)
        
        for level in levels:
            for task in level:
                deps = dependencies.get(task, [])
                if deps:
                    # This task starts after all its deps finish
                    max_pred_end = max(
                        earliest_start[dep] + 
                        complexity_weights.get(
                            task_complexities.get(dep, "medium"), 2
                        )
                        for dep in deps
                    )
                    
                    # Track which predecessor caused this start time
                    best_pred = max(
                        deps,
                        key=lambda d: earliest_start[d] + 
                        complexity_weights.get(
                            task_complexities.get(d, "medium"), 2
                        )
                    )
                    
                    earliest_start[task] = max_pred_end
                    predecessors[task] = best_pred
        
        # Find task with latest finish time (end of critical path)
        end_task = max(
            task_ids,
            key=lambda t: earliest_start[t] + 
            complexity_weights.get(
                task_complexities.get(t, "medium"), 2
            )
        )
        
        # Trace back the critical path
        critical_path = []
        current = end_task
        while current:
            critical_path.insert(0, current)
            current = predecessors.get(current)
        
        return critical_path
    
    # ──────────────────────────────────────────────
    # MAIN: Full dependency analysis
    # ──────────────────────────────────────────────
    def analyze(
        self,
        subtasks: List[Dict],
        goal: str
    ) -> DependencyMap:
        """Full dependency analysis pipeline"""
        
        print(f"\n🔍 ANALYZING DEPENDENCIES...")
        task_ids = [st["id"] for st in subtasks]
        task_complexities = {
            st["id"]: st.get("estimated_complexity", "medium")
            for st in subtasks
        }
        
        # Step 1: Identify dependencies with LLM
        dep_data = self.identify_dependencies(subtasks, goal)
        dependencies = dep_data["dependencies"]
        
        # Ensure all task IDs are in dependencies dict
        for tid in task_ids:
            if tid not in dependencies:
                dependencies[tid] = []
        
        # Step 2: Check for circular dependencies
        has_circular, cycle = self.detect_circular_dependencies(
            dependencies
        )
        
        if has_circular:
            print(f"❌ CIRCULAR DEPENDENCY DETECTED: {cycle}")
            print("   This plan CANNOT be executed as-is!")
        else:
            print("✅ No circular dependencies found")
        
        # Step 3: Topological sort → parallel groups
        levels = self.topological_sort(task_ids, dependencies)
        parallel_groups = [g for g in levels if len(g) > 1]
        
        # Step 4: Find critical path
        critical_path = self.find_critical_path(
            task_ids, dependencies, task_complexities
        )
        
        print(f"\n📊 DEPENDENCY ANALYSIS RESULTS:")
        print(f"  Parallel execution opportunities: {len(parallel_groups)}")
        print(f"  Critical path: {' → '.join(critical_path)}")
        print(f"  Execution levels: {len(levels)}")
        
        for i, level in enumerate(levels):
            parallelism = "⚡ PARALLEL" if len(level) > 1 else "→ Sequential"
            print(f"  Level {i+1} ({parallelism}): {level}")
        
        return DependencyMap(
            task_ids=task_ids,
            dependencies=dependencies,
            dependency_reasons=dep_data.get("dependency_reasons", {}),
            has_circular=has_circular,
            critical_path=critical_path,
            parallelism_opportunities=parallel_groups
        )


# ═══════════════════════════════════════════════════
# VISUALIZATION — Show the dependency graph as text

## 7️⃣ Failure Modes — When Dependency Mapping Breaks

```
❌ FAILURE 1: Missing Implicit Dependencies
   Problem: Dependencies that are "obvious" to humans missed by LLM
   Example: T5 (deploy model) needs T4 (test model)
            But LLM only maps T5 → T3 (train model)
            Testing step skipped!
   Why: LLM doesn't know your specific process
   Fix: Provide domain-specific dependency templates
        Add: "What would break if T_B ran without T_A being done?"

❌ FAILURE 2: Over-Constraining (False Dependencies)
   Problem: Adding dependencies that don't actually exist
   Example: T3 → T1, T3 → T2 (T3 needs both)
            But actually T3 only needs T1's output!
   Result: Unnecessary sequential execution
           You wait for T2 to finish even though T3 doesn't need it
   Fix: Question each dependency: "Does B TRULY need A's output?"

❌ FAILURE 3: Circular Dependency (The Deadlock Killer)
   Problem: T1 needs T2, T2 needs T3, T3 needs T1 → impossible!
   Example: 
   "Generate test cases" (T1) needs "define requirements" (T3)
   "Define requirements" (T3) needs "understand constraints" (T2)
   "Understand constraints" (T2) needs "generate test cases" (T1)
   → Circular! Nothing can start.
   Why: Over-complex dependency mapping
   Fix: Always run circular dependency detection before execution
        Break cycle by making one task use PARTIAL output

❌ FAILURE 4: Dependency Staleness
   Problem: Execution changes things — dependencies shift
   Example: T5 was independent, but after T3 ran,
            T5 now needs T3's updated data
   Why: Static dependency map created before execution
   Fix: Dynamic dependency checking before each task starts
        Re-validate dependencies after each completed task
```

# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 1️⃣ What Is This?

**Simple English:**

```
ORDERED (Sequential) Execution:
    Task 1 → DONE → Task 2 → DONE → Task 3 → DONE
    One at a time. Must wait for previous to finish.

PARALLEL Execution:
    Task 1 → ─────────────────────────→ DONE
    Task 2 → ─────────────────────────→ DONE    All at same time!
    Task 3 → ─────────────────────────→ DONE

HYBRID (The real world):
    Level 1: [T1] (only one, must be first)
    Level 2: [T2, T3, T4] (all parallel after T1 done)
    Level 3: [T5] (only after T2, T3, T4 all done)
```

## 2️⃣ Why This Matters So Much — The Time Math

```
SEQUENTIAL EXAMPLE:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6 tasks, each takes 10 seconds
Total time = 6 × 10 = 60 seconds

[T1]──[T2]──[T3]──[T4]──[T5]──[T6]
  10   10   10   10   10   10 = 60s

PARALLEL EXAMPLE:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Same 6 tasks, 3 can run in parallel
Total time = 10 + 10 + 10 = 30 seconds (HALF the time!)

Level 1: [T1]──────────────── 10s
         ↓
Level 2: [T2]──[T3]──[T4]──── 10s (all parallel!)
         ↓
Level 3: [T5]──[T6]──────────── 10s (parallel!)
         
TOTAL: 30 seconds instead of 60!

REAL WORLD IMPACT:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
10 tasks × 5 seconds each = 50 seconds sequential
With smart parallelization → 15-20 seconds
That's a 3× speed improvement!
In production: difference between good and great UX
```

## 3️⃣ The Decision Framework — When to Order vs Parallelize

```
┌────────────────────────────────────────────────────────────────┐
│            ORDERED vs PARALLEL DECISION TREE                   │
│                                                                │
│  For any two tasks T_A and T_B, ask:                           │
│                                                                │
│  Q1: Does T_B need any data/output from T_A?                   │
│      YES → T_A must come BEFORE T_B (Ordered)                 │
│      NO  → Continue to Q2                                      │
│                                                                │
│  Q2: Do T_A and T_B use the same limited resource?            │
│      (Same API with rate limit, same DB connection, etc.)      │
│      YES → Run sequentially (Resource constraint)              │
│      NO  → Continue to Q3                                      │
│                                                                │
│  Q3: Does T_B's result change based on T_A's result?          │
│      YES → Ordered (emergent dependency)                        │
│      NO  → Continue to Q4                                      │
│                                                                │
│  Q4: Can T_B be started and stopped cleanly?                   │
│      NO  → Risky to parallelize, go sequential                 │
│      YES → ✅ PARALLELIZE!                                      │
└────────────────────────────────────────────────────────────────┘
```

Tasks:

# Handles both ordered and parallel execution
# ═══════════════════════════════════════════════════
@dataclass

    task_id: str
    title: str
    status: str          # "success" | "failure" | "skipped"
    output: str
    execution_time: float
    error: Optional[str] = None


class HybridExecutionEngine:
    """
    Executes tasks respecting dependencies:
    - Sequential when tasks depend on each other
    - Parallel when tasks are independent
    """
    
    def __init__(self, llm, max_parallel_workers: int = 4):
        self.llm = llm
        self.max_workers = max_parallel_workers
        self.results: Dict[str, TaskResult] = {}
        self.shared_context: Dict[str, str] = {}
    
    # ──────────────────────────────────────────────
    # Execute ONE task (used by both sequential and parallel)
    # ──────────────────────────────────────────────
    def _execute_single_task(
        self,
        task: Dict,
        available_results: Dict[str, str]
    ) -> TaskResult:
        """Execute a single task with all context"""
        
        start_time = time.time()
        task_id = task["id"]
        
        print(f"  ⚡ Starting {task_id}: {task['title']}")
        
        # Build context from dependency results
        dep_context = ""
        if task.get("dependencies"):
            dep_results = []
            for dep_id in task["dependencies"]:
                if dep_id in available_results:
                    dep_results.append(
                        f"{dep_id} result: {available_results[dep_id][:300]}"
                    )
            dep_context = "\n".join(dep_results)
        
        # Execute with LLM
        prompt = f"""
        You are executing task {task_id} as part of a larger workflow.
        
        Task: {task['title']}
        Description: {task.get('description', task['title'])}
        Expected Output: {task.get('expected_output', 'Complete the task')}
        
        Previous task results available to you:
        {dep_context or "This is one of the first tasks - no previous results"}
        
        Execute this task completely.
        Return your result in a clear, structured format.
        """
        
        try:
            result = self.llm.invoke(prompt).content
            elapsed = time.time() - start_time
            
            print(f"  ✅ {task_id} done in {elapsed:.1f}s")
            
            return TaskResult(
                task_id=task_id,
                title=task["title"],
                status="success",
                output=result,
                execution_time=elapsed
            )
        
        except Exception as e:
            elapsed = time.time() - start_time
            print(f"  ❌ {task_id} FAILED: {str(e)[:50]}")
            
            return TaskResult(
                task_id=task_id,
                title=task["title"],
                status="failure",
                output="",
                execution_time=elapsed,
                error=str(e)
            )
    
    # ──────────────────────────────────────────────
    # Execute a LEVEL of parallel tasks
    # ──────────────────────────────────────────────
    def _execute_parallel_level(
        self,
        tasks: List[Dict],
        available_results: Dict[str, str]
    ) -> List[TaskResult]:
        """
        Execute multiple tasks at the same time using threads.
        All tasks in this level are independent of each other.
        """
        
        if len(tasks) == 1:
            # Only one task — no need for parallelism overhead
            result = self._execute_single_task(tasks[0], available_results)
            return [result]
        
        print(f"\n  ⚡⚡ PARALLEL EXECUTION: {len(tasks)} tasks simultaneously")
        
        results = []
        
        # Use ThreadPoolExecutor for parallel execution
        with ThreadPoolExecutor(
            max_workers=min(len(tasks), self.max_workers)
        ) as executor:
            
            # Submit all tasks to thread pool
            future_to_task = {
                executor.submit(
                    self._execute_single_task, 
                    task, 
                    available_results
                ): task
                for task in tasks
            }
            
            # Collect results as they complete
            for future in as_completed(future_to_task):
                result = future.result()
                results.append(result)
        
        return results
    
    # ──────────────────────────────────────────────
    # MAIN EXECUTION: Level by level
    # ──────────────────────────────────────────────
    def execute_with_dependencies(
        self,
        execution_levels: List[List[str]],  # From topological sort
        tasks_by_id: Dict[str, Dict],
        dependencies: Dict[str, List[str]]
    ) -> Dict[str, TaskResult]:
        """
        Execute all tasks level by level.
        Within each level: PARALLEL.
        Between levels: SEQUENTIAL (wait for level to finish).
        """
        
        total_start = time.time()
        
        print(f"\n{'='*60}")
        print(f"🚀 HYBRID EXECUTION ENGINE STARTING")
        print(f"   Sequential levels: {len(execution_levels)}")
        total_tasks = sum(len(level) for level in execution_levels)
        print(f"   Total tasks: {total_tasks}")
        
        # Estimate speedup
        sequential_estimate = total_tasks * 5  # 5s per task estimate
        parallel_estimate = len(execution_levels) * 5
        speedup = sequential_estimate / max(parallel_estimate, 1)
        print(f"   Estimated speedup: {speedup:.1f}× vs sequential")
        print(f"{'='*60}")
        
        # Track all results for dependency context
        all_results: Dict[str, str] = {}
        failed_tasks = []
        
        for level_num, level_task_ids in enumerate(execution_levels):
            
            print(f"\n📋 LEVEL {level_num + 1}/{len(execution_levels)}")
            
            # Get task objects for this level
            level_tasks = []
            skipped = []
            
            for task_id in level_task_ids:
                
                # Check if any dependency failed
                deps = dependencies.get(task_id, [])
                failed_deps = [
                    dep for dep in deps if dep in failed_tasks
                ]
                
                if failed_deps:
                    print(f"  ⏭️ SKIPPING {task_id}: "
                          f"dependency failed: {failed_deps}")
                    
                    self.results[task_id] = TaskResult(
                        task_id=task_id,
                        title=tasks_by_id[task_id]["title"],
                        status="skipped",
                        output="",
                        execution_time=0,
                        error=f"Dependency failed: {failed_deps}"
                    )
                    skipped.append(task_id)
                else:
                    task = tasks_by_id[task_id].copy()
                    task["dependencies"] = deps
                    level_tasks.append(task)
            
            if not level_tasks:
                print(f"  ⚠️ All tasks in level {level_num + 1} were skipped")
                continue
            
            # Execute tasks in this level IN PARALLEL
            level_results = self._execute_parallel_level(
                level_tasks, 
                all_results  # Provide all completed results as context
            )
            
            # Store results
            for result in level_results:
                self.results[result.task_id] = result
                
                if result.status == "success":
                    all_results[result.task_id] = result.output
                else:
                    failed_tasks.append(result.task_id)
        
        # Summary
        total_time = time.time() - total_start
        success_count = sum(
            1 for r in self.results.values() if r.status == "success"
        )
        fail_count = sum(
            1 for r in self.results.values() if r.status == "failure"
        )
        skip_count = sum(
            1 for r in self.results.values() if r.status == "skipped"
        )
        
        print(f"\n{'='*60}")
        print(f"📊 EXECUTION SUMMARY")
        print(f"   Total time: {total_time:.1f}s")
        print(f"   ✅ Succeeded: {success_count}/{total_tasks}")
        print(f"   ❌ Failed: {fail_count}")
        print(f"   ⏭️  Skipped: {skip_count}")
        
        # Show task timing breakdown
        print(f"\n⏱️  TASK TIMING:")
        for task_id, result in sorted(self.results.items()):
            status_icon = {
                "success": "✅", "failure": "❌", "skipped": "⏭️"
            }.get(result.status, "?")
            print(f"   {status_icon} {task_id}: {result.execution_time:.1f}s")
        
        print(f"{'='*60}")
        
        return self.results

## 6️⃣ Failure Modes — Ordered vs Parallel Execution

```
❌ FAILURE 1: Race Conditions
   Problem: Two parallel tasks write to same location simultaneously
   Example: T2 and T3 both write to "results.json" file
            T2 overwrites T3's work halfway through
   Why: No synchronization on shared resources
   Fix: Unique output namespaces per task
        Use task_id in all output file/variable names

❌ FAILURE 2: Context Propagation Failure
   Problem: Later tasks don't get results from parallel predecessors
   Example: T5 needs output from BOTH T2 and T3 (which ran parallel)
            But only T2's result was passed to T5
   Why: Result collection didn't wait for all parallel tasks
   Fix: Wait for ALL tasks in a level before moving to next
        Aggregate all parallel results before passing forward

❌ FAILURE 3: Unnecessary Sequential Ordering
   Problem: Running things sequentially when they could be parallel
   Example: Searching 3 different websites sequentially
            Each takes 5 seconds → 15 seconds total
            Could be parallel → 5 seconds total
   Why: Conservative default = sequential
        Engineer didn't analyze parallelism potential
   Fix: Always check: "Do these tasks share any dependencies?"
        If NO → parallelize them

❌ FAILURE 4: Parallel Execution Cost Explosion
   Problem: Running everything in parallel creates huge API costs
   Example: 10 tasks all running simultaneously = 10× API cost spike
   Why: No rate limiting on parallel execution
   Fix: Set max_parallel_workers limit
        Respect API rate limits in thread pool
        Prioritize tasks — run most critical ones first

❌ FAILURE 5: Partial Completion Handling
   Problem: 3 of 5 parallel tasks succeed, 2 fail
            System doesn't know how to proceed
   Why: No partial failure strategy defined
   Fix: Define policy for each task:
        "Required" → subsequent tasks skipped if this fails
        "Optional" → subsequent tasks continue with partial data
```

# 📌 STRATEGY 4: Recursive Decomposition
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 1️⃣ What Is This?

**Simple English:**
Recursive Decomposition means **applying decomposition to decomposition itself**.

When a subtask is still too complex to execute directly, you break THAT subtask into sub-subtasks. And if those are still too complex, you break them down again.

```
RECURSIVE = applying the same process to its own output

BIG TASK
    ↓ decompose
SUBTASK A (simple enough → execute directly ✅)
SUBTASK B (still too complex → decompose again!)
    ↓ decompose
    SUB-SUBTASK B1 (simple ✅)
    SUB-SUBTASK B2 (still complex → decompose again!)
        ↓ decompose
        MICRO-TASK B2a (simple ✅)
        MICRO-TASK B2b (simple ✅)

Keep going until EVERY leaf task is executable!
```

---

## 2️⃣ Real-Life Analogy — Russian Nesting Dolls + Fractal

```
🪆 RUSSIAN NESTING DOLLS:
    Open big doll → medium doll inside
    Open medium doll → small doll inside
    Open small doll → tiny doll inside
    Tiny doll = can't open anymore (base case!)

🔄 FRACTAL PATTERN:
    Each part looks like the whole
    Zoom in → same structure at smaller scale
    Zoom in again → still same structure

RECURSIVE DECOMPOSITION IS A FRACTAL OF PLANNING:
    Big task → structure of subtasks
    Each subtask → same structure at smaller scale
    Until we hit "atomic" tasks that can't be broken further
    THOSE are the base cases where execution happens
```

---

## 3️⃣ The Critical Concept — Base Case vs Recursive Case

```
EVERY RECURSIVE SYSTEM NEEDS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

BASE CASE (Stop Decomposing When):
  ✅ Task fits in a single LLM call
  ✅ Task can be done with ONE tool call
  ✅ Task takes < 30 seconds of real time
  ✅ Task has a clear binary done/not-done state
  ✅ Task description is specific enough to execute

RECURSIVE CASE (Keep Decomposing When):
  ❌ Task still requires planning before executing
  ❌ Task has multiple distinct phases
  ❌ Task needs different tools for different parts
  ❌ Task would exceed context window in one shot
  ❌ Task outcome depends on intermediate decisions

THE DANGER WITHOUT BASE CASE:
    Task → Subtask → Sub-subtask → Sub-sub-subtask → ∞
    Infinite recursion! Stack overflow!
    Always define: "This task is small enough to execute directly"
```

## 5️⃣ Technical Implementation — Recursive Task Decomposer

```python
from langchain_openai import ChatOpenAI
from typing import Optional
from dataclasses import dataclass, field
import json

llm = ChatOpenAI(model="gpt-4o", temperature=0)
fast_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)


# ═══════════════════════════════════════════════════
# TASK TREE NODE
# ═══════════════════════════════════════════════════
@dataclass
class TaskNode:
    """A node in the recursive task tree"""
    id: str
    title: str
    description: str
    depth: int                            # How many levels deep?
    is_leaf: bool = False                 # Base case reached?
    children: list = field(default_factory=list)  # Sub-decomposition
    result: Optional[str] = None          # Execution result (leaf only)
    status: str = "pending"               # pending|executing|done|failed


# ═══════════════════════════════════════════════════
# RECURSIVE DECOMPOSER
# ═══════════════════════════════════════════════════
class RecursiveDecomposer:
    
    def __init__(
        self,
        llm,
        max_depth: int = 4,          # Maximum recursion depth
        complexity_threshold: str = "medium"  # When to stop decomposing
    ):
        self.llm = llm
        self.max_depth = max_depth
        self.complexity_threshold = complexity_threshold
        self.node_counter = 0
    
    def _new_id(self, parent_id: str = "", index: int = 0) -> str:
        """Generate hierarchical ID like T1.2.3"""
        if not parent_id:
            return f"T{self.node_counter}"
        return f"{parent_id}.{index + 1}"
    
    # ──────────────────────────────────────────────
    # KEY METHOD: Determine if task needs decomposition
    # ──────────────────────────────────────────────
    def _should_decompose(self, task_title: str, task_desc: str) -> bool:
        """
        Ask LLM: Is this task simple enough to execute directly?
        Returns True if we should decompose further.
        """
        
        prompt = f"""
        Evaluate if this task needs further breakdown for an AI agent:
        
        Task: {task_title}
        Description: {task_desc}
        
        An AI agent can execute tasks directly if they:
        1. Require only ONE tool call (search, code, write, calculate)
        2. Can be described completely in 1-2 sentences
        3. Produce ONE clear, specific output
        4. Don't require intermediate decisions during execution
        
        Should this task be decomposed further, or can it be 
        executed directly?
        
        Return JSON: 
        {{
            "should_decompose": true/false,
            "reasoning": "Why?",
            "complexity": "atomic|simple|medium|complex"
        }}
        """
        
        response = fast_llm.invoke(prompt).content
        if "```json" in response:
            response = response.split("```json")[1].split("```")[0]
        
        result = json.loads(response.strip())
        return result["should_decompose"]
    
    # ──────────────────────────────────────────────
    # DECOMPOSE: Break task into subtasks
    # ──────────────────────────────────────────────
    def _decompose_task(
        self, 
        task_title: str,
        task_desc: str,
        context: str = "",
        depth: int = 0
    ) -> list:
        """Generate subtasks for a task"""
        
        indent = "  " * depth
        max_subtasks = max(2, 5 - depth)  # Fewer subtasks at deeper levels
        
        prompt = f"""
        Break this task into {max_subtasks}-{max_subtasks+2} 
        concrete subtasks for an AI agent.
        
        Task: {task_title}
        Description: {task_desc}
        Context: {context or "Part of a larger project"}
        
        Depth level: {depth} (target atomic tasks at level 3+)
        
        IMPORTANT: At deeper levels, make subtasks MORE specific 
        and executable directly.
        
        Return JSON list:
        [
            {{
                "title": "Specific subtask title",
                "description": "Exact description of what to do"
            }}
        ]
        """
        
        response = self.llm.invoke(prompt).content
        if "```json" in response:
            response = response.split("```json")[1].split("```")[0]
        
        return json.loads(response.strip())
    
    # ──────────────────────────────────────────────
    # CORE: Recursive build function
    # ──────────────────────────────────────────────
    def build_task_tree(
        self,
        title: str,
        description: str,
        parent_id: str = "",
        depth: int = 0,
        context: str = ""
    ) -> TaskNode:
        """
        Recursively build the task tree.
        
        BASE CASE: Task is simple enough → leaf node
        RECURSIVE CASE: Task is complex → decompose and recurse
        """
        
        self.node_counter += 1
        task_id = self._new_id(parent_id, depth)
        indent = "  " * depth
        
        print(f"{indent}📦 [{task_id}] {title}")
        
        # BASE CASE 1: Reached maximum depth
        if depth >= self.max_depth:
            print(f"{indent}   ↳ MAX DEPTH → execute directly")
            return TaskNode(
                id=task_id,
                title=title,
                description=description,
                depth=depth,
                is_leaf=True  # Must execute — no more decomposition
            )
        
        # BASE CASE 2: Task is simple enough to execute directly
        if not self._should_decompose(title, description):
            print(f"{indent}   ↳ ATOMIC → execute directly ✅")
            return TaskNode(
                id=task_id,
                title=title,
                description=description,
                depth=depth,
                is_leaf=True
            )
        
        # RECURSIVE CASE: Decompose further
        print(f"{indent}   ↳ COMPLEX → decomposing into subtasks...")
        
        subtask_data = self._decompose_task(
            title, description, context, depth
        )
        
        # Create node for this level (not a leaf)
        node = TaskNode(
            id=task_id,
            title=title,
            description=description,
            depth=depth,
            is_leaf=False
        )
        
        # RECURSE: Build subtree for each subtask
        for i, st_data in enumerate(subtask_data):
            child_node = self.build_task_tree(
                title=st_data["title"],
                description=st_data["description"],
                parent_id=task_id,
                depth=depth + 1,
                context=f"Parent task: {title}"
            )
            node.children.append(child_node)
        
        return node
    
    # ──────────────────────────────────────────────
    # EXECUTE: Run all leaf nodes in order
    # ──────────────────────────────────────────────
    def execute_tree(
        self,
        node: TaskNode,
        accumulated_context: str = ""
    ) -> str:
        """
        Execute the task tree.
        Only LEAF nodes are executed.
        Internal nodes just coordinate.
        """
        
        indent = "  " * node.depth
        
        if node.is_leaf:
            # BASE CASE: Execute this task directly
            print(f"{indent}⚡ EXECUTING: {node.title}")
            
            prompt = f"""
            Execute this specific task:
            Task: {node.title}
            Description: {node.description}
            
            Context from previous tasks:
            {accumulated_context[-2000:] if accumulated_context else "None"}
            
            Provide a complete, detailed result.
            """
            
            result = self.llm.invoke(prompt).content
            node.result = result
            node.status = "done"
            
            print(f"{indent}✅ Done: {node.title}")
            return result
        
        else:
            # RECURSIVE CASE: Execute all children, collect results
            print(f"{indent}📋 COORDINATING: {node.title}")
            
            child_results = []
            running_context = accumulated_context
            
            for child in node.children:
                child_result = self.execute_tree(child, running_context)
                child_results.append(
                    f"[{child.id}] {child.title}:\n{child_result[:500]}"
                )
                # Add result to running context for next sibling
                running_context += f"\n\n{child_results[-1]}"
            
            node.status = "done"
            return "\n\n".join(child_results)
    
    # ──────────────────────────────────────────────
    # DISPLAY: Show the full tree structure
    # ──────────────────────────────────────────────
    def display_tree(self, node: TaskNode, prefix: str = ""):
        """Pretty print the task tree"""
        
        connector = "└── " if not node.children else "├── "
        leaf_icon = "🔧" if node.is_leaf else "📁"
        status_icon = {
            "done": "✅", "failed": "❌", "executing": "⚡", "pending": "⏳"
        }.get(node.status, "⏳")
        
        print(f"{prefix}{leaf_icon} [{node.id}] {node.title} {status_icon}")
        
        for i, child in enumerate(node.children):
            is_last = i == len(node.children) - 1
            new_prefix = prefix + ("    " if is_last else "│   ")
            self.display_tree(child, new_prefix)
    
    # ──────────────────────────────────────────────
    # STATS: Analyze the tree
    # ──────────────────────────────────────────────
    def analyze_tree(self, node: TaskNode) -> Dict:
        """Get statistics about the decomposition tree"""
        
        def _traverse(n: TaskNode, stats: Dict):
            stats["total_nodes"] += 1
            stats["max_depth"] = max(stats["max_depth"], n.depth)
            
            if n.is_leaf:
                stats["leaf_nodes"] += 1
                stats["execution_tasks"] += 1
            else:
                stats["internal_nodes"] += 1
            
            for child in n.children:
                _traverse(child, stats)
        
        stats = {
            "total_nodes": 0,
            "leaf_nodes": 0,
            "internal_nodes": 0,
            "execution_tasks": 0,
            "max_depth": 0
        }
        _traverse(node, stats)
        return stats

decomposer = RecursiveDecomposer(

## 6️⃣ Failure Modes — When Recursive Decomposition Breaks

```
❌ FAILURE 1: Infinite Recursion (Deadly!)
   Problem: No base case → decomposes forever
   Example: "Write summary" → "Draft summary" → 
            "Create draft" → "Write content" →
            "Write summary" → [CYCLE!]
   Why: No check for "is this small enough to execute?"
   Fix: ALWAYS have max_depth limit
        ALWAYS have complexity checker before recursing

❌ FAILURE 2: Context Loss Across Depth
   Problem: Deep subtasks forget what the top-level goal is
   Example: Level 3 task: "Write test cases"
            Forgets it's testing a MEDICAL AI — not just any code
            Writes generic test cases instead of safety-critical ones
   Why: Context doesn't propagate through recursive calls
   Fix: Pass full context chain to every recursive call
        Include: original_goal + parent_task + grandparent_task

❌ FAILURE 3: Unnecessary Depth
   Problem: Decomposing atomic tasks that were already executable
   Example: "Search Google for X" (already atomic!)
            → Decomposed into "Open browser", "Type query", "Press enter"
            → Absurd for an AI agent with a search tool
   Why: Complexity checker is too conservative
   Fix: Tune complexity checker for the specific tool set available
        "If task maps to ONE tool call → base case!"

❌ FAILURE 4: Inconsistent Granularity Across Branches
   Problem: Different branches decomposed to different depths
   Example: Branch A: 4 levels deep, 20 leaf tasks
            Branch B: 1 level deep, 2 leaf tasks (same complexity!)
   Result: Branch B likely under-decomposed, will fail
   Fix: Normalize granularity check across all branches
        Complexity checker must be consistent

❌ FAILURE 5: Exponential Task Count
   Problem: Each level creates 5 subtasks → 5^4 = 625 tasks at depth 4!
   Example: Depth 4 with 5 branches each = 5×5×5×5 = 625 leaf tasks
   Result: Absurd cost, impossible execution time
   Fix: Reduce branching factor at deeper levels (max 3-4 children)
        Increase min complexity threshold at deeper levels
        Set hard limit on total leaf nodes (e.g., max 50)
```

## 1️⃣ What Is This?

**Simple English:**
Dynamic Replanning is the ability to **change the plan WHILE executing it** based on what actually happens — instead of blindly following an outdated plan.

```
STATIC PLANNING (Fragile):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Make plan → Execute plan → Done (or CRASH!)

Problem: Real world NEVER perfectly matches the plan.
If step 3 fails or gives unexpected results,
the entire remaining plan may be wrong.

DYNAMIC REPLANNING (Resilient):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Make plan → 
Execute step → 
Observe result →
CHECK: "Does the plan still make sense?" →
  YES → Continue executing next step
  NO  → REPLAN based on what we learned → 
         Continue with NEW plan

This is planning AS LEARNING.
The plan improves as you execute it.
```

## 4️⃣ The Replanning Decision Spectrum

```
NOT ALL FAILURES NEED FULL REPLANNING!

SPECTRUM OF RESPONSES TO UNEXPECTED EVENTS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MINIMAL:    RETRY            → Try the same step again
            ↕ (less severe)    No plan change needed
            ↕                  Just a transient failure
            
SMALL:      LOCAL FIX        → Modify just this step
            ↕                  Use different tool/approach
            ↕                  Rest of plan unchanged
            
MEDIUM:     PARTIAL REPLAN   → Replan from current step forward
            ↕                  Keep completed work
            ↕                  Regenerate remaining plan
            
LARGE:      FULL REPLAN      → Start planning from scratch
            ↕                  Keep factual information gathered
            ↕ (more severe)    Discard all planned-but-unstarted tasks
            
MAXIMUM:    GOAL REVISION    → The goal itself needs updating
                               User input required
                               Complete restart
                               
DECISION RULE:
  Impact = number of remaining tasks affected by the failure
  
  Impact < 2 tasks   → Retry or Local Fix
  Impact = 3-5 tasks → Partial Replan
  Impact > 5 tasks   → Full Replan
  Goal is wrong      → Goal Revision (needs human)
```

from langchain_openai import ChatOpenAI
from typing import List, Dict, Any, Optional, Tuple
from dataclasses import dataclass, field

import json
import time

fast_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)


# ═══════════════════════════════════════════════════
# DATA MODELS
# ═══════════════════════════════════════════════════
class TaskStatus(Enum):
    PENDING = "pending"
    RUNNING = "running"
    SUCCESS = "success"
    FAILED = "failed"
    SKIPPED = "skipped"
    REPLANNED = "replanned"


class ReplanTrigger(Enum):
    TASK_FAILURE = "task_failure"
    UNEXPECTED_RESULT = "unexpected_result"
    GOAL_SHIFT = "goal_shift"
    NEW_INFORMATION = "new_information"
    RESOURCE_CONSTRAINT = "resource_constraint"


class ReplanScope(Enum):
    RETRY = "retry"
    LOCAL_FIX = "local_fix"
    PARTIAL_REPLAN = "partial_replan"
    FULL_REPLAN = "full_replan"
    GOAL_REVISION = "goal_revision"


@dataclass
class PlanTask:
    id: str
    title: str
    description: str
    expected_output: str
    dependencies: List[str] = field(default_factory=list)
    status: TaskStatus = TaskStatus.PENDING
    result: Optional[str] = None
    error: Optional[str] = None
    retry_count: int = 0
    max_retries: int = 2


@dataclass
class ReplanEvent:
    """Records when and why replanning happened"""
    trigger: ReplanTrigger
    scope: ReplanScope
    failed_task_id: str
    reason: str
    tasks_before_replan: int
    tasks_after_replan: int
    timestamp: float = field(default_factory=time.time)


# ═══════════════════════════════════════════════════
# PLAN MONITOR — Watches execution and detects issues
# ═══════════════════════════════════════════════════
class PlanMonitor:
    """
    Monitors task execution and determines if replanning is needed.
    This is the "nervous system" of the dynamic replanning system.
    """
    
    def __init__(self, llm):
        self.llm = llm
    
    def evaluate_task_result(
        self,
        task: PlanTask,
        result: str,
        original_goal: str,
        remaining_plan: List[PlanTask]
    ) -> Tuple[bool, Optional[str]]:
        """
        Evaluate if a task's result is acceptable.
        Returns: (is_acceptable, issue_description_if_not)
        """
        
        prompt = f"""
        You are monitoring an AI agent's execution.
        
        Original Goal: {original_goal}
        
        Task that just completed:
        Title: {task.title}
        Expected Output: {task.expected_output}
        
        Actual Result (first 500 chars):
        {result[:500]}
        
        Remaining plan tasks:
        {[t.title for t in remaining_plan[:5]]}
        
        Evaluate:
        1. Is the result ACCEPTABLE for what was expected?
        2. Does this result create any PROBLEMS for remaining tasks?
        3. Did this reveal any NEW INFORMATION that changes the plan?
        
        Return JSON:
        {{
            "is_acceptable": true/false,
            "issue": "Description if not acceptable, else null",
            "reveals_new_info": true/false,
            "new_info": "What new info (if any)",
            "impacts_remaining_plan": true/false,
            "impact_description": "How it impacts remaining tasks"
        }}
        """
        
        response = fast_llm.invoke(prompt).content
        if "```json" in response:
            response = response.split("```json")[1].split("```")[0]
        
        evaluation = json.loads(response.strip())
        
        if not evaluation["is_acceptable"]:
            return False, evaluation["issue"]
        
        if evaluation["impacts_remaining_plan"]:
            return False, evaluation["impact_description"]
        
        return True, None
    
    def determine_replan_scope(
        self,
        trigger: ReplanTrigger,
        failed_task: PlanTask,
        remaining_tasks: List[PlanTask],
        completed_count: int,
        total_count: int
    ) -> ReplanScope:
        """
        Decide HOW MUCH of the plan needs to change.
        """
        
        # Check if simple retry is enough
        if (trigger == ReplanTrigger.TASK_FAILURE and 
                failed_task.retry_count < failed_task.max_retries):
            return ReplanScope.RETRY
        
        # Count how many tasks are affected
        affected_count = len(remaining_tasks)
        total_remaining = total_count - completed_count
        affected_ratio = affected_count / max(total_remaining, 1)
        
        # How late in execution are we?
        progress = completed_count / max(total_count, 1)
        
        prompt = f"""
        An AI agent needs to replan. Help decide the scope.
        
        Trigger: {trigger.value}
        Failed task: {failed_task.title}
        Progress: {completed_count}/{total_count} tasks completed
        Tasks affected: {affected_count} of {total_remaining} remaining
        
        Scope options:
        - RETRY: Just try the same task again
        - LOCAL_FIX: Modify only the failed task, keep everything else
        - PARTIAL_REPLAN: Replan from current point forward
        - FULL_REPLAN: Completely rebuild the plan from scratch
        
        Return JSON:
        {{
            "scope": "retry|local_fix|partial_replan|full_replan",
            "reasoning": "Why this scope?"
        }}
        """
        
        response = fast_llm.invoke(prompt).content
        if "```json" in response:
            response = response.split("```json")[1].split("```")[0]
        
        result = json.loads(response.strip())
        scope_map = {
            "retry": ReplanScope.RETRY,
            "local_fix": ReplanScope.LOCAL_FIX,
            "partial_replan": ReplanScope.PARTIAL_REPLAN,
            "full_replan": ReplanScope.FULL_REPLAN
        }
        
        return scope_map.get(result["scope"], ReplanScope.PARTIAL_REPLAN)


# ═══════════════════════════════════════════════════
# REPLANNER — Generates new plan when needed
# ═══════════════════════════════════════════════════
class Replanner:
    """
    Generates updated plans when the current plan breaks.
    Key principle: PRESERVE all completed work, only replan what's left.
    """
    
    def __init__(self, llm):
        self.llm = llm
    
    def generate_replan(
        self,
        scope: ReplanScope,
        original_goal: str,
        failed_task: PlanTask,
        completed_tasks: List[PlanTask],
        remaining_tasks: List[PlanTask],
        failure_reason: str,
        replan_history: List[ReplanEvent]
    ) -> List[PlanTask]:
        """Generate updated plan based on scope"""
        
        completed_summary = "\n".join([
            f"✅ [{t.id}] {t.title}: {t.result[:200] if t.result else 'Done'}..."
            for t in completed_tasks if t.status == TaskStatus.SUCCESS
        ])
        
        failed_summary = "\n".join([
            f"❌ Replan #{i+1}: {e.reason}" 
            for i, e in enumerate(replan_history[-3:])  # Last 3 replans
        ])
        
        remaining_summary = "\n".join([
            f"⏳ {t.id}: {t.title}"
            for t in remaining_tasks
        ])
        
        if scope == ReplanScope.LOCAL_FIX:
            
            prompt = f"""
            Fix ONLY this one failing task with a different approach.
            Keep all other tasks the same.
            
            Original Goal: {original_goal}
            
            Failed Task:
            ID: {failed_task.id}
            Title: {failed_task.title}
            Error: {failure_reason}
            Retry count: {failed_task.retry_count}
            
            Previous replan attempts:
            {failed_summary or "None"}
            
            Generate a LOCAL FIX: 
            Replace this task with 1-3 simpler steps that achieve 
            the same outcome using a different approach.
            
            Return JSON list of replacement tasks:
            [
                {{
                    "id": "{failed_task.id}_v2",
                    "title": "Alternative approach",
                    "description": "...",
                    "expected_output": "...",
                    "dependencies": []
                }}
            ]
            """
        
        elif scope == ReplanScope.PARTIAL_REPLAN:
            
            prompt = f"""
            Replan the REMAINING tasks only. Keep completed work.
            
            Original Goal: {original_goal}
            
            COMPLETED (DO NOT CHANGE):
            {completed_summary}
            
            FAILED TASK:
            {failed_task.title} - Error: {failure_reason}
            
            CURRENTLY PLANNED BUT NOT STARTED:
            {remaining_summary}
            
            Previous replan attempts that failed:
            {failed_summary or "None - this is first replan"}
            
            Generate a NEW plan for the remaining work.
            Start fresh from the failed task.
            Avoid the same approach that caused the failure.
            
            Return JSON list of NEW tasks:
            [
                {{
                    "id": "NEW_T1",
                    "title": "...",
                    "description": "...",
                    "expected_output": "...",
                    "dependencies": ["NEW_T0_if_needed"]
                }}
            ]
            """
        
        else:  # FULL_REPLAN
            
            prompt = f"""
            Generate a COMPLETELY NEW plan from scratch.
            
            Original Goal: {original_goal}
            
            What we KNOW from completed work:
            {completed_summary}
            
            Why the old plan failed:
            {failure_reason}
            
            Previous replan attempts:
            {failed_summary}
            
            Generate a new, better plan that:
            1. Achieves the original goal
            2. Avoids the problems that caused failure
            3. Builds on what we learned from completed tasks
            4. Uses a DIFFERENT overall approach
            
            Return JSON list of tasks.
            """
        
        response = self.llm.invoke(prompt).content
        if "```json" in response:
            response = response.split("```json")[1].split("```")[0]
        
        new_task_data = json.loads(response.strip())
        
        # Convert to PlanTask objects
        new_tasks = [
            PlanTask(
                id=t["id"],
                title=t["title"],
                description=t["description"],
                expected_output=t.get("expected_output", t["title"]),
                dependencies=t.get("dependencies", [])
            )
            for t in new_task_data
        ]
        
        return new_tasks


# ═══════════════════════════════════════════════════
# DYNAMIC EXECUTION ENGINE — Main orchestrator
# ═══════════════════════════════════════════════════
class DynamicPlanningAgent:
    """
    The complete dynamic planning and execution system.
    Plans, executes, monitors, and replans as needed.
    """
    
    def __init__(self, llm, max_replans: int = 3):
        self.llm = llm
        self.max_replans = max_replans
        self.monitor = PlanMonitor(llm)
        self.replanner = Replanner(llm)
        self.replan_history: List[ReplanEvent] = []
    
    def _initial_plan(self, goal: str) -> List[PlanTask]:
        """Generate the initial plan"""
        
        prompt = f"""
        Create a detailed execution plan for an AI agent.
        
        Goal: {goal}
        
        Generate 5-8 concrete, executable tasks.
        
        Return JSON:
        [
            {{
                "id": "T1",
                "title": "Task title",
                "description": "Detailed description",
                "expected_output": "What done looks like",
                "dependencies": []
            }}
        ]
        """
        
        response = self.llm.invoke(prompt).content
        if "```json" in response:
            response = response.split("```json")[1].split("```")[0]
        
        task_data = json.loads(response.strip())
        
        return [
            PlanTask(
                id=t["id"],
                title=t["title"],
                description=t["description"],
                expected_output=t.get("expected_output", t["title"]),
                dependencies=t.get("dependencies", [])
            )
            for t in task_data
        ]
    
    def _execute_task(self, task: PlanTask, context: str) -> str:
        """Execute a single task"""
        
        prompt = f"""
        Execute this task:
        Task: {task.title}
        Description: {task.description}
        Expected: {task.expected_output}
        
        Context from previous work:
        {context[-3000:] if context else "This is the first task"}
        
        Provide complete result.
        """
        
        return self.llm.invoke(prompt).content
    
    def run(self, goal: str) -> Dict:
        """
        Full dynamic planning and execution pipeline.
        """
        
        print(f"\n🎯 GOAL: {goal}")
        print("="*60)
        
        # Initial plan
        print("\n📋 Creating initial plan...")
        current_plan = self._initial_plan(goal)
        print(f"   {len(current_plan)} tasks planned")
        
        completed_tasks: List[PlanTask] = []
        accumulated_context = ""
        replan_count = 0
        task_index = 0
        
        # MAIN EXECUTION LOOP
        while task_index < len(current_plan):
            
            if replan_count >= self.max_replans:
                print(f"\n⚠️ Max replans ({self.max_replans}) reached. Stopping.")
                break
            
            task = current_plan[task_index]
            
            print(f"\n⚡ Task {task_index + 1}/{len(current_plan)}: {task.title}")
            
            # EXECUTE
            task.status = TaskStatus.RUNNING
            
            try:
                result = self._execute_task(task, accumulated_context)
                
                # MONITOR: Is this result acceptable?
                remaining = current_plan[task_index + 1:]
                is_ok, issue = self.monitor.evaluate_task_result(
                    task, result, goal, remaining
                )
                
                if is_ok:
                    # ✅ SUCCESS — continue normally
                    task.result = result
                    task.status = TaskStatus.SUCCESS
                    completed_tasks.append(task)
                    accumulated_context += f"\n\n[{task.id}] {task.title}:\n{result[:500]}"
                    print(f"   ✅ Success")
                    task_index += 1
                    
                else:
                    # ⚠️ RESULT NOT ACCEPTABLE — trigger replan
                    print(f"   ⚠️ Unexpected result: {issue}")
                    trigger = ReplanTrigger.UNEXPECTED_RESULT
                    task.error = issue
                    task.status = TaskStatus.FAILED
                    
                    # Determine replan scope
                    scope = self.monitor.determine_replan_scope(
                        trigger, task, remaining, 
                        len(completed_tasks), len(current_plan)
                    )
                    
                    print(f"   🔄 REPLANNING ({scope.value})...")
                    
                    # Handle retry
                    if scope == ReplanScope.RETRY:
                        task.retry_count += 1
                        task.status = TaskStatus.PENDING
                        print(f"   Retrying task (attempt {task.retry_count})")
                        continue  # Don't advance task_index
                    
                    # Generate new plan
                    new_tasks = self.replanner.generate_replan(
                        scope, goal, task, completed_tasks, 
                        remaining, issue, self.replan_history
                    )
                    
                    # Record replan event
                    event = ReplanEvent(
                        trigger=trigger,
                        scope=scope,
                        failed_task_id=task.id,
                        reason=issue,
                        tasks_before_replan=len(current_plan),
                        tasks_after_replan=len(completed_tasks) + len(new_tasks)
                    )
                    self.replan_history.append(event)
                    replan_count += 1
                    
                    # Update plan: completed + new tasks
                    current_plan = completed_tasks + new_tasks
                    task_index = len(completed_tasks)  # Resume from new tasks
                    
                    print(f"   New plan: {len(new_tasks)} new tasks added")
            
            except Exception as e:
                # ❌ TASK FAILED — trigger replan
                error_msg = str(e)
                print(f"   ❌ Failed: {error_msg[:80]}")
                
                task.error = error_msg
                task.status = TaskStatus.FAILED
                
                if task.retry_count < task.max_retries:
                    task.retry_count += 1
                    task.status = TaskStatus.PENDING
                    print(f"   Retrying ({task.retry_count}/{task.max_retries})")
                    time.sleep(1)  # Brief pause before retry
                    continue
                
                # Exceeded retries — replan
                scope = self.monitor.determine_replan_scope(
                    ReplanTrigger.TASK_FAILURE,
                    task,
                    current_plan[task_index + 1:],
                    len(completed_tasks),
                    len(current_plan)
                )
                
                print(f"   🔄 REPLANNING ({scope.value})...")
                
                new_tasks = self.replanner.generate_replan(
                    scope, goal, task, completed_tasks,
                    current_plan[task_index + 1:],
                    error_msg, self.replan_history
                )
                
                self.replan_history.append(ReplanEvent(
                    trigger=ReplanTrigger.TASK_FAILURE,
                    scope=scope,
                    failed_task_id=task.id,
                    reason=error_msg,
                    tasks_before_replan=len(current_plan),
                    tasks_after_replan=len(completed_tasks) + len(new_tasks)
                ))
                replan_count += 1
                
                current_plan = completed_tasks + new_tasks
                task_index = len(completed_tasks)
        
        # FINAL SYNTHESIS
        print("\n\n🔄 Synthesizing final output...")
        
        successful_results = "\n\n".join([
            f"[{t.id}] {t.title}:\n{t.result[:500]}"
            for t in completed_tasks if t.status == TaskStatus.SUCCESS
        ])
        
        synthesis_prompt = f"""
        Goal: {goal}
        
        Work completed by AI agent:
        {successful_results}
        
        Create the final comprehensive output that achieves the goal.
        Use all the work completed above.
        """
        
        final_output = self.llm.invoke(synthesis_prompt).content
        
        # Summary statistics
        success_count = sum(
            1 for t in completed_tasks if t.status == TaskStatus.SUCCESS
        )
        
        print(f"\n{'='*60}")
        print(f"📊 EXECUTION SUMMARY")
        print(f"   Tasks completed: {success_count}")
        print(f"   Replanning events: {replan_count}")
        print(f"   Replan history:")
        for i, event in enumerate(self.replan_history):
            print(f"     {i+1}. {event.trigger.value} → "
                  f"{event.scope.value}: {event.reason[:50]}...")
        print(f"{'='*60}")
        
        return {
            "goal": goal,
            "final_output": final_output,
            "completed_tasks": completed_tasks,
            "replan_count": replan_count,
            "replan_history": self.replan_history
        }


# ═══════════════════════════════════════════════════
# RUN IT
# ═══════════════════════════════════════════════════
agent = DynamicPlanningAgent(llm, max_replans=3)

result = agent.run(
    goal="Research the competitive landscape of vector databases "
         "and produce an executive summary with recommendations"
)

print(f"\n✅ FINAL OUTPUT:\n{result['final_output'][:1000]}...")

## 7️⃣ Failure Modes — When Dynamic Replanning Breaks

```
❌ FAILURE 1: Replan Loop Hell
   Problem: Each replan triggers another failure → triggers replan
   Example: Replan 1 fails → Replan 2 fails → Replan 3 fails → ∞
   Why: Root cause not identified — replanning same approach
   Fix: Replan must use DIFFERENT approach than previous plans
        Track replan_history and ensure each is different
        Hard limit on max_replans (we set 3)

❌ FAILURE 2: Completed Work Discarded
   Problem: Full replan throws away valuable completed work
   Example: 7 of 10 tasks done, full replan throws away all 7!
            Agent starts completely from scratch
   Why: Replanner doesn't distinguish completed from pending
   Fix: ALWAYS separate completed from pending before replanning
        "These tasks are done and their results are real"
        Only replan from the failure point forward

❌ FAILURE 3: Over-Sensitive Monitor
   Problem: Monitor triggers replanning for minor variations
   Example: Task returned 450 words instead of expected 500
            Monitor: "UNACCEPTABLE!" → triggers full replan
   Result: Constant replanning, no forward progress
   Fix: Define acceptable tolerance ranges
        Not every imperfection needs a replan
        "Good enough" is often correct

❌ FAILURE 4: Replan Plan is Worse Than Original
   Problem: Replanned tasks are HARDER than original
   Example: Original: "Use web search API"
            Replan: "Manually browse and extract"
            (More complex, more failure-prone)
   Why: Replanner doesn't have enough context about constraints
   Fix: Pass full tool inventory to replanner
        Specify: "Available tools: X, Y, Z only"

❌ FAILURE 5: No Learning From Failure
   Problem: Replan makes exact same mistake as original plan
   Example: T3 fails because API is rate-limited
            Replan generates T3_v2: same API call
            Fails again for same reason
   Why: Failure reason not incorporated into replan prompt
   Fix: Include detailed failure reason + error message in replan
        Include: "Do NOT use approach X because of Y"

❌ FAILURE 6: Infinite Retry Without Progress
   Problem: Retry policy allows too many retries
   Example: Task fails 10 times in a row
            Each retry = wasted API calls + time
   Fix: Smart retry policy:
        Only retry on transient failures (network timeouts)
        Don't retry on logical failures (wrong tool for task)
        Max 2-3 retries then escalate to replan
```

## 8️⃣ Interview Q&A — All 5 Strategies

**Q1: What are the key strategies for task decomposition in production AI agents?**

> ✅ **Strong Answer:**
> "Effective task decomposition requires five key strategies working together: First, subtask generation — breaking the goal into atomic, verifiable units using the right method for the task type. Second, dependency mapping — identifying which tasks need other tasks' outputs, ideally using a DAG structure with topological sort. Third, execution strategy — using the dependency graph to identify opportunities for parallel execution, which can dramatically reduce total runtime. Fourth, recursive decomposition — applying decomposition recursively to subtasks that are still too complex, stopping only when tasks are truly executable. Fifth, dynamic replanning — monitoring execution and adjusting the plan when reality doesn't match the plan, which is crucial for production robustness."

**Q2: How do you decide when to trigger replanning and what scope of replan to do?**

> ✅ **Strong Answer:**
> "Replanning should trigger on four key events: task failure exceeding retry limits, task results that are structurally incompatible with remaining tasks, new information discovered that invalidates plan assumptions, and resource constraints that make the current approach impossible. For scope, I use a graduated response: retry for transient failures, local fix when only one task needs replacement, partial replan when several downstream tasks are affected, and full replan only when the fundamental approach is wrong. The key engineering principle is to always preserve completed work — replanning should only affect unstarted tasks. I also maintain a replan history and require each new plan to use a demonstrably different approach from previous failed ones."

**Q3: What is topological sort and why is it essential for AI agent task planning?**

> ✅ **Strong Answer:**
> "Topological sort is an algorithm that takes a directed acyclic graph of task dependencies and produces a linear ordering where every task appears before any task that depends on it. For AI agents, it's essential because it solves two problems simultaneously: it ensures correct ordering — no task executes before its dependencies complete — and it identifies parallelism opportunities — any tasks in the same 'level' of the topological sort are independent and can execute simultaneously. This means instead of running 10 tasks sequentially for 50 seconds, we might run them as three parallel levels in 20 seconds. The cycle detection component is equally critical — if your dependency map has a circular dependency, topological sort catches it before execution starts, preventing the deadlock that would otherwise occur."

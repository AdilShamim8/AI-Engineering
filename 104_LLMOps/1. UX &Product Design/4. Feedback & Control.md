# 🏗️ PART 1: The Control Problem in AI — First Principles

---

## 🔷 Why Feedback & Control Exists — Start From Zero

### The Core Problem:

> Imagine you hire a **brilliant contractor** to renovate your house.
> They are talented, fast, and confident.
> But they make every decision themselves.
> You have no say. No corrections. No revisions.
>
> Even if they are 90% right — the 10% they get wrong is YOUR house.
>
> **That is exactly what AI without feedback & control feels like.**

```
AI WITHOUT FEEDBACK & CONTROL:
────────────────────────────────────────────────────────
User: "Write a product description for my coffee mug"
AI:   [Writes something generic and wrong]
User: "This is completely off-brand"
AI:   "Here's another attempt..." [Still wrong]
User: gives up → leaves → never comes back

Result: Lost user. No learning. No improvement.

────────────────────────────────────────────────────────

AI WITH FEEDBACK & CONTROL:
────────────────────────────────────────────────────────
User: "Write a product description for my coffee mug"
AI:   [Writes first draft]
User: [Clicks "Make it more casual"] → AI refines
User: [Edits one sentence directly] → AI learns tone
User: [Clicks "Regenerate intro"] → specific part redone
User: [Approves final version] → data logged for training

Result: User gets perfect output. AI learns preferences.
```

> **Feedback & Control turns AI from a vending machine into a collaboration.**

# 🔄 PART 2: Regenerate / Refine

---

## 🔷 What Is Regeneration?

### Simple Definition:
> **Regeneration** means generating a completely new response to the same input — **discarding the current output** and asking the AI to try again, typically with different randomness (temperature).

### Real-World Analogy:
> You ask a designer for a logo.
> They show you version 1.
> You say: **"Not what I had in mind. Try again."**
> They start fresh with new ideas.
>
> Same brief. Different attempt. Completely new creative direction.

---

## 🔷 What Is Refinement?

### Simple Definition:
> **Refinement** means **keeping the existing output as a base** and asking the AI to modify it in a specific way — shorter, longer, more formal, simpler, fix a specific section.

### Real-World Analogy:
> Same designer shows you logo version 1.
> You say: **"I love the concept — but make the font bigger and change blue to green."**
> They modify the existing work, not start over.
>
> Same base. Specific changes. Evolutionary improvement.

---

## 🔷 Regenerate vs Refine — The Decision:

```
┌──────────────────────────────────────────────────────────┐
│          WHEN TO REGENERATE vs REFINE                    │
├────────────────────────┬─────────────────────────────────┤
│  REGENERATE            │  REFINE                         │
├────────────────────────┼─────────────────────────────────┤
│ Output is fundamentally│ Output is close but needs       │
│ wrong or off-target    │ specific adjustments            │
│                        │                                 │
│ "This missed the mark  │ "Good direction, but make       │
│  completely."          │  it shorter / more formal."    │
│                        │                                 │
│ User has no specific   │ User has specific feedback      │
│ direction to give      │ about what to change            │
│                        │                                 │
│ Examples:              │ Examples:                       │
│ "Regenerate"           │ "Make shorter"                  │
│ "Try again"            │ "More formal"                   │
│ "Different approach"   │ "Fix this section"              │
│ "New variation"        │ "Simpler language"              │
└────────────────────────┴─────────────────────────────────┘
```

## 🔷 Implementing Regeneration — Backend

```python
from openai import AsyncOpenAI
import hashlib

client = AsyncOpenAI()

class RegenerationEngine:
    """
    Handles regeneration with variation
    and history tracking
    """
    
    def __init__(self):
        # Store all generations per request
        # Key: request_hash, Value: list of generations
        self.generation_history = {}
    
    def _hash_request(self, question: str, context: str) -> str:
        """Create unique ID for this question+context combo"""
        content = f"{question}:{context}"
        return hashlib.md5(content.encode()).hexdigest()
    
    async def generate(
        self, 
        question: str, 
        context: str = "",
        tone: str = "neutral",
        length: str = "medium",
        attempt: int = 1
    ) -> dict:
        """
        Generate response with variation on each call
        Higher attempt number = slightly different result
        """
        
        request_id = self._hash_request(question, context)
        
        # Temperature increases slightly with each attempt
        # More variation = more creative regenerations
        base_temperature = 0.7
        temperature = min(
            base_temperature + (attempt - 1) * 0.1, 
            1.2  # Cap at 1.2 max
        )
        
        # Build tone instruction
        tone_instructions = {
            "casual": "Use conversational, friendly language.",
            "formal": "Use professional, formal language.",
            "bold": "Use confident, punchy, impactful language.",
            "creative": "Use creative, imaginative, unique language."
        }
        
        length_instructions = {
            "short": "Keep the response under 50 words.",
            "medium": "Aim for 100-150 words.",
            "long": "Be comprehensive, around 300 words."
        }
        
        system_prompt = f"""
        You are a helpful assistant.
        Tone: {tone_instructions.get(tone, "Be helpful and clear.")}
        Length: {length_instructions.get(length, "")}
        This is attempt #{attempt} — 
        offer a fresh perspective if you can.
        """
        
        response = await client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": question}
            ],
            temperature=temperature
        )
        
        result = {
            "request_id": request_id,
            "attempt": attempt,
            "tone": tone,
            "length": length,
            "temperature_used": temperature,
            "content": response.choices[0].message.content,
            "tokens_used": response.usage.total_tokens
        }
        
        # Store in history
        if request_id not in self.generation_history:
            self.generation_history[request_id] = []
        
        self.generation_history[request_id].append(result)
        
        return result
    
    def get_history(self, request_id: str) -> list:
        """Get all previous generations for a request"""
        return self.generation_history.get(request_id, [])
```

## 🔷 Implementing Refinement — The Right Way

```python
async def refine_response(
    original_response: str,
    original_question: str,
    refinement_instruction: str,
    conversation_history: list = None
) -> dict:
    """
    Refine an existing AI response based on user instruction
    
    The key insight: pass the ORIGINAL response as context
    so the AI modifies it, not replaces it
    """
    
    refinement_prompt = f"""
    You previously wrote this response:
    
    ─────────────────────────────────────
    {original_response}
    ─────────────────────────────────────
    
    The user's original question was: "{original_question}"
    
    The user wants you to refine it:
    "{refinement_instruction}"
    
    RULES:
    1. Keep the parts the user did not ask to change
    2. Apply ONLY the requested modification
    3. Do not lose important information
    4. Do not add things the user didn't ask for
    
    Provide the refined version:
    """
    
    response = await client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "user", 
                "content": refinement_prompt
            }
        ],
        temperature=0.3  # Lower temp = more faithful refinement
    )
    
    refined_content = response.choices[0].message.content
    
    # Log the refinement for analysis
    refinement_log = {
        "original": original_response,
        "instruction": refinement_instruction,
        "refined": refined_content,
        "timestamp": datetime.utcnow().isoformat()
    }
    
    return {
        "content": refined_content,
        "log": refinement_log
    }
```

# ✏️ PART 3: Editable Outputs

---

## 🔷 What Are Editable Outputs?

### Simple Definition:
> **Editable outputs** means allowing the user to **directly modify the AI's generated text** — treating the AI output as a starting draft that the human can improve, correct, or complete.

### The Philosophy Behind This:

> **AI generates. Humans judge and refine.**
>
> The AI is your first draft writer.
> The human is the editor.
>
> An editable output design acknowledges this reality
> and makes it effortless.

---

## 🔷 Why Editable Outputs Are Powerful

```
DESIGN WITHOUT EDITABLE OUTPUT:
────────────────────────────────────────────────────────────
User: "Write an email to my team about the meeting."
AI: [Generates email]
User: "Almost right — but the tone is wrong and 
       the time is incorrect."
User: Must re-prompt carefully to fix small issues.
User: Frustration builds. Time wasted.
────────────────────────────────────────────────────────────

DESIGN WITH EDITABLE OUTPUT:
────────────────────────────────────────────────────────────
User: "Write an email to my team about the meeting."
AI: [Generates email in editable text box]
User: [Directly clicks on "10 AM" → changes to "2 PM"]
User: [Directly changes "Hi team" → "Hello everyone"]
User: Done in 10 seconds. Perfect output.
────────────────────────────────────────────────────────────
```

> **The edit itself is the most valuable feedback signal.**
> What the user changed tells you exactly where the AI was wrong.

---

## 🔷 Capturing Edits As Feedback Data

> This is the engineering insight that most beginners miss:

```python
from dataclasses import dataclass
from difflib import SequenceMatcher
from datetime import datetime
import json

@dataclass
class EditFeedback:
    """
    Represents what a user changed in an AI output
    This is GOLD for improving your AI system
    """
    session_id: str
    original_ai_output: str
    user_edited_output: str
    edit_similarity: float     # How much was changed (0-1)
    edit_ratio: float          # What % was kept (0-1)
    timestamp: str
    
def capture_edit_feedback(
    session_id: str,
    original: str,
    edited: str
) -> EditFeedback:
    """
    When user edits AI output:
    1. Calculate how much they changed
    2. Store original vs edited pair
    3. This becomes training data
    """
    
    # Calculate similarity between original and edited
    matcher = SequenceMatcher(None, original, edited)
    similarity = matcher.ratio()
    
    feedback = EditFeedback(
        session_id=session_id,
        original_ai_output=original,
        user_edited_output=edited,
        edit_similarity=similarity,
        edit_ratio=len(edited) / max(len(original), 1),
        timestamp=datetime.utcnow().isoformat()
    )
    
    # What this data tells you:
    # similarity = 1.0 → user kept it all → AI was perfect
    # similarity = 0.9 → small fix → AI was mostly right
    # similarity = 0.5 → major rewrite → AI was off target
    # similarity = 0.1 → almost full rewrite → AI was wrong
    
    # Log insight
    if similarity < 0.5:
        severity = "MAJOR_EDIT"  # AI needs improvement here
    elif similarity < 0.85:
        severity = "MINOR_EDIT"  # Small fix needed
    else:
        severity = "MICRO_EDIT"  # Almost perfect
    
    log_entry = {
        "type": "edit_feedback",
        "severity": severity,
        "session_id": session_id,
        "original": original,
        "edited": edited,
        "similarity": similarity,
        "timestamp": feedback.timestamp
    }
    
    # Write to feedback log
    with open("feedback_log.jsonl", "a") as f:
        f.write(json.dumps(log_entry) + "\n")
    
    print(f"Edit logged: {severity} | Similarity: {similarity:.1%}")
    
    return feedback

# These original→edited pairs become fine-tuning data:
# Input:  original AI output
# Target: user's corrected version
# The model learns: "When input is X, correct output is Y"
```

## 🔷 Undo/Redo — Essential for Editable Outputs

```python
class EditHistory:
    """
    Manages undo/redo for editable AI outputs
    Think of it like Ctrl+Z for AI content
    """
    
    def __init__(self):
        self.history = []       # Past states
        self.future = []        # Undone states (for redo)
        self.current = None
    
    def save_state(self, content: str, action: str = ""):
        """Save current state before making change"""
        if self.current is not None:
            self.history.append({
                "content": self.current,
                "action": action,
                "timestamp": datetime.utcnow().isoformat()
            })
        
        self.current = content
        self.future = []  # Clear redo stack on new action
    
    def undo(self) -> str | None:
        """Go back one step"""
        if not self.history:
            return None  # Nothing to undo
        
        # Move current to future (for redo)
        self.future.append({"content": self.current})
        
        # Restore previous state
        previous = self.history.pop()
        self.current = previous["content"]
        
        return self.current
    
    def redo(self) -> str | None:
        """Go forward one step (after undo)"""
        if not self.future:
            return None  # Nothing to redo
        
        # Move current to history
        self.history.append({"content": self.current})
        
        # Restore future state
        next_state = self.future.pop()
        self.current = next_state["content"]
        
        return self.current
    
    def can_undo(self) -> bool:
        return len(self.history) > 0
    
    def can_redo(self) -> bool:
        return len(self.future) > 0
    
    def get_history_summary(self) -> list:
        """Show user a list of all past actions"""
        return [
            f"Step {i+1}: {item.get('action', 'Edit')}"
            for i, item in enumerate(self.history)
        ]

# Usage in Streamlit
```

```python
async def handle_correction(
```

```python
class SessionPreferences:
    """
    Learns user preferences within a conversation session
    Applies them automatically to all future responses
    """
    
    def __init__(self, session_id: str):
        self.session_id = session_id
        self.preferences = {
            "tone": None,           # "formal" / "casual"
            "length": None,         # "short" / "long"
            "format": None,         # "bullets" / "paragraphs"
            "avoid": [],            # phrases to avoid
            "include": [],          # things to always include
            "context": {}           # domain context corrections
        }
        self.correction_count = 0
    
    def update_from_correction(
        self, 
        correction_type: str, 
        correction_value: str
    ):
        """Update preferences based on user correction"""
        
        if correction_type == "tone":
            self.preferences["tone"] = correction_value
            
        elif correction_type == "length":
            self.preferences["length"] = correction_value
            
        elif correction_type == "format":
            self.preferences["format"] = correction_value
            
        elif correction_type == "avoid":
            self.preferences["avoid"].append(correction_value)
            
        self.correction_count += 1
        
        print(
            f"Preference updated: {correction_type} = "
            f"{correction_value}"
        )
    
    def build_preference_system_prompt(self) -> str:
        """
        Build system prompt that encodes learned preferences
        Injected into every subsequent LLM call this session
        """
        
        parts = ["User preferences for this session:"]
        
        if self.preferences["tone"]:
            parts.append(
                f"- Tone: Always use {self.preferences['tone']} "
                f"language"
            )
        
        if self.preferences["length"]:
            parts.append(
                f"- Length: Keep responses "
                f"{self.preferences['length']}"
            )
        
        if self.preferences["format"]:
            parts.append(
                f"- Format: Use "
                f"{self.preferences['format']} format"
            )
        
        if self.preferences["avoid"]:
            avoid_list = ", ".join(self.preferences["avoid"])
            parts.append(
                f"- Avoid: Never use these: {avoid_list}"
            )
        
        if len(parts) == 1:
            return ""  # No preferences learned yet
        
        return "\n".join(parts)
    
    def apply_to_request(
        self, 
        messages: list
    ) -> list:
        """
        Inject learned preferences into message list
        as a system message
        """
        pref_prompt = self.build_preference_system_prompt()
        
        if not pref_prompt:
            return messages
        
        # Add preference as system context
        return [
            {"role": "system", "content": pref_prompt}
        ] + messages
```

```python
import json
import uuid
from datetime import datetime
from dataclasses import dataclass, asdict
from enum import Enum
from pathlib import Path
import sqlite3

class FeedbackType(Enum):
    THUMBS_UP = "thumbs_up"
    THUMBS_DOWN = "thumbs_down"
    STAR_RATING = "star_rating"
    EDIT = "edit"
    CORRECTION = "correction"

    CUSTOM_REFINE = "custom_refine"
    COPY = "copy"         # User copied output (implicit positive)
    ABANDON = "abandon"   # User left without engaging (negative)

@dataclass
class FeedbackEvent:
    """Single feedback event - atomic unit of feedback data"""
    
    # Identity
    feedback_id: str
    session_id: str
    user_id: str
    timestamp: str
    
    # What happened
    feedback_type: str
    
    # Content context
    question: str
    ai_response: str

    edited_response: str = None     # For edits

    # Computed signals
    edit_similarity: float = None   # For edits (0-1)
    
    # UI context
    attempt_number: int = 1  # Which regeneration attempt

class FeedbackLogger:
    """
    Production-ready feedback logging system
    with SQLite storage and JSONL export
    """
    
    def __init__(self, db_path: str = "feedback.db"):
        self.db_path = db_path
        self._init_database()
    
    def _init_database(self):
        """Create feedback table if it doesn't exist"""
        conn = sqlite3.connect(self.db_path)
        conn.execute("""
            CREATE TABLE IF NOT EXISTS feedback (
                feedback_id TEXT PRIMARY KEY,
                session_id TEXT NOT NULL,
                user_id TEXT,
                timestamp TEXT NOT NULL,
                feedback_type TEXT NOT NULL,
                question TEXT,
                ai_response TEXT,
                rating REAL,
                edited_response TEXT,
                correction_text TEXT,
                refine_instruction TEXT,
                response_latency_ms REAL,
                model_used TEXT,
                edit_similarity REAL,
                attempt_number INTEGER,
                raw_json TEXT NOT NULL
            )
        """)
        conn.commit()
        conn.close()
    
    def log(self, event: FeedbackEvent) -> str:
        """Log a feedback event to database"""
        
        conn = sqlite3.connect(self.db_path)
        raw_json = json.dumps(asdict(event))
        
        conn.execute("""
            INSERT OR REPLACE INTO feedback VALUES 
            (?,?,?,?,?,?,?,?,?,?,?,?,?,?,?,?)
        """, (
            event.feedback_id,
            event.session_id,
            event.user_id,
            event.timestamp,
            event.feedback_type,
            event.question[:500] if event.question else None,
            event.ai_response[:1000] if event.ai_response else None,
            event.rating,
            event.edited_response,
            event.correction_text,
            event.refine_instruction,
            event.response_latency_ms,
            event.model_used,
            event.edit_similarity,
            event.attempt_number,
            raw_json
        ))
        
        conn.commit()
        conn.close()
        
        return event.feedback_id
    
    def log_thumbs(
        self, 
        session_id: str,
        question: str,
        ai_response: str,
        is_positive: bool,
        user_id: str = "anonymous"
    ) -> str:
        """Quick thumbs up/down logging"""
        
        event = FeedbackEvent(
            feedback_id=str(uuid.uuid4()),
            session_id=session_id,
            user_id=user_id,
            timestamp=datetime.utcnow().isoformat(),
            feedback_type=(
                FeedbackType.THUMBS_UP.value if is_positive 
                else FeedbackType.THUMBS_DOWN.value
            ),
            question=question,
            ai_response=ai_response
        )
        
        return self.log(event)
    
    def log_edit(
        self,
        session_id: str,
        question: str,
        original_response: str,
        edited_response: str,
        user_id: str = "anonymous"
    ) -> str:
        """Log user edit with diff calculation"""
        
        from difflib import SequenceMatcher
        similarity = SequenceMatcher(
            None, 
            original_response, 
            edited_response
        ).ratio()
        
        event = FeedbackEvent(
            feedback_id=str(uuid.uuid4()),
            session_id=session_id,
            user_id=user_id,
            timestamp=datetime.utcnow().isoformat(),
            feedback_type=FeedbackType.EDIT.value,
            question=question,
            ai_response=original_response,
            edited_response=edited_response,
            edit_similarity=similarity
        )
        
        return self.log(event)
    
    def get_quality_metrics(self) -> dict:
        """
        Compute quality metrics from feedback data
        For your monitoring dashboard
        """
        
        conn = sqlite3.connect(self.db_path)
        
        # Overall thumbs ratio
        thumbs = conn.execute("""
            SELECT 
                feedback_type,
                COUNT(*) as count
            FROM feedback
            WHERE feedback_type IN ('thumbs_up', 'thumbs_down')
            GROUP BY feedback_type
        """).fetchall()
        
        thumbs_dict = {row[0]: row[1] for row in thumbs}
        total_thumbs = sum(thumbs_dict.values())
        
        positive_rate = (
            thumbs_dict.get("thumbs_up", 0) / total_thumbs
            if total_thumbs > 0 else 0
        )
        
        # Average edit similarity (how much users change outputs)
        avg_edit_sim = conn.execute("""
            SELECT AVG(edit_similarity)
            FROM feedback
            WHERE feedback_type = 'edit'
        """).fetchone()[0] or 0
        
        # Regeneration rate
        regen_count = conn.execute("""
            SELECT COUNT(*) FROM feedback
            WHERE feedback_type = 'regeneration'
        """).fetchone()[0]
        
        total_interactions = conn.execute("""
            SELECT COUNT(*) FROM feedback
        """).fetchone()[0]
        
        conn.close()
        
        return {
            "positive_rate": round(positive_rate, 3),
            "avg_edit_similarity": round(avg_edit_sim, 3),
            "regeneration_count": regen_count,
            "total_feedback_events": total_interactions,
            "quality_score": round(
                (positive_rate * 0.4) + 
                (avg_edit_sim * 0.4) + 
                (max(0, 1 - regen_count/max(total_interactions, 1)) * 0.2),
                3
            )
        }
```

```python
        PostHog uses this to measure variant performance
        """

            event="$feature_flag_called",
            properties={
                "$feature_flag": flag_name,
                "$feature_flag_response": variant
            }

    # ─────────────────────────────────────────────────

        self,
        user_id: str,
        session_id: str,
        quality_signals: dict
    ):
        """
        Composite quality tracking event
        All quality signals in one event for easy analysis
        """
        self.ph.capture(
            distinct_id=user_id,
            event="AI Response Quality",
            properties={
                "session_id": session_id,
                
                # Output signals
                "thumbs_up": quality_signals.get("thumbs_up"),
                "star_rating": quality_signals.get("star_rating"),
                "was_edited": quality_signals.get("was_edited"),
                "edit_similarity": quality_signals.get(
                    "edit_similarity"
                ),
                "needed_regeneration": quality_signals.get(
                    "needed_regeneration"
                ),
                
                # Context signals
                "retrieval_score": quality_signals.get(
                    "retrieval_score"
                ),
                "latency_ms": quality_signals.get("latency_ms"),
                "model": quality_signals.get("model"),
                
                # Computed quality score (0-1)
                "quality_score": self._compute_quality(
                    quality_signals
                )
            }
        )
    
    def _compute_quality(self, signals: dict) -> float:
        """
        Composite quality score from multiple signals
        Each signal weighted by how reliable it is
        """
        score = 0.5  # Start neutral
        
        if signals.get("thumbs_up") is True:
            score += 0.3
        elif signals.get("thumbs_up") is False:
            score -= 0.3
        
        if signals.get("was_edited"):
            # Edited = user had to fix something
            similarity = signals.get("edit_similarity", 0.7)
            # High similarity = small edit = less penalty
            score -= (1 - similarity) * 0.2
        
        if signals.get("needed_regeneration"):
            score -= 0.15
        
        if signals.get("star_rating"):
            # Normalize star rating (1-5) to (-0.2, +0.2)
            normalized = (signals["star_rating"] - 3) / 10
            score += normalized
        
        return round(max(0, min(1, score)), 3)
```

## Tool 4: 🧪 A/B Testing Frameworks

---

### What Is A/B Testing?

### Simple Definition:
> **A/B testing** (also called split testing) means showing **two different versions** of something to different groups of users — and measuring which version performs better based on real behavior data.

### Real-World Analogy:
> You run an email newsletter.
> Half your subscribers get Subject A: "5 AI tips"
> Half get Subject B: "The 5 AI tricks experts use"
>
> After sending, you measure which had a higher open rate.
> Winner becomes the standard.
>
> **Same principle applies to every AI product decision.**

---

```python
import hashlib
import json
from datetime import datetime
from typing import Any

class ABTestingFramework:
    """
    Lightweight A/B testing framework for AI products
    Works with any analytics backend (Mixpanel, PostHog, etc.)
    """
    
    def __init__(self):
        # Define your experiments here
        self.experiments = {
            
            "system_prompt_length": {
                "description": "Test shorter vs longer system prompt",
                "status": "running",
                "traffic_split": 0.5,  # 50/50 split
                "variants": {
                    "control": {
                        "name": "Original prompt",
                        "system_prompt": (
                            "You are a helpful AI assistant. "
                            "Answer questions clearly and accurately."
                        )
                    },
                    "treatment": {
                        "name": "Detailed prompt",
                        "system_prompt": (
                            "You are an expert AI assistant. "
                            "Answer with precision and cite sources. "
                            "Use clear, structured formatting. "
                            "If uncertain, acknowledge it explicitly."
                        )
                    }
                },
                "primary_metric": "thumbs_up_rate",
                "secondary_metrics": [
                    "edit_similarity", 
                    "regeneration_rate"
                ]
            },
            
            "model_selection": {
                "description": "GPT-4o vs GPT-4o-mini quality tradeoff",
                "status": "running",
                "traffic_split": 0.3,  # 30% see treatment
                "variants": {
                    "control": {
                        "name": "GPT-4o-mini (fast, cheap)",
                        "model": "gpt-4o-mini",
                        "temperature": 0.7
                    },
                    "treatment": {
                        "name": "GPT-4o (smart, slower)",
                        "model": "gpt-4o",
                        "temperature": 0.7
                    }
                },
                "primary_metric": "quality_score",
                "secondary_metrics": ["latency_ms", "cost_per_query"]
            },
            
            "citation_display": {
                "description": "Inline vs card citations",
                "status": "running",
                "traffic_split": 0.5,
                "variants": {
                    "control": "inline_citations",
                    "treatment": "expandable_cards"
                },
                "primary_metric": "trust_rating",
                "secondary_metrics": ["session_length"]
            }
        }
        
        # Results storage
        self.results = {}
    
    def get_variant(
        self, 
        user_id: str, 
        experiment_name: str
    ) -> str:
        """
        Deterministically assign user to variant
        
        KEY PRINCIPLE:
        Same user_id ALWAYS gets same variant.
        This ensures consistent experience across sessions.
        """
        
        experiment = self.experiments.get(experiment_name)
        
        if not experiment or experiment["status"] != "running":
            return "control"  # Default to control if not running
        
        # Hash user_id + experiment_name for deterministic split
        # This ensures user always sees same variant
        hash_input = f"{user_id}:{experiment_name}"
        hash_value = int(
            hashlib.md5(hash_input.encode()).hexdigest(), 
            16
        )
        
        # Normalize to 0-1 range
        normalized = (hash_value % 10000) / 10000
        
        traffic_split = experiment["traffic_split"]
        
        if normalized < traffic_split:
            return "treatment"
        else:
            return "control"
    
    def get_variant_config(
        self, 
        user_id: str, 
        experiment_name: str
    ) -> dict:
        """Get the actual configuration for user's variant"""
        
        variant = self.get_variant(user_id, experiment_name)
        experiment = self.experiments.get(experiment_name, {})
        variants = experiment.get("variants", {})
        
        config = variants.get(variant, {})
        
        # If config is a string (like "inline_citations"), 
        # wrap it in dict
        if isinstance(config, str):
            config = {"type": config}
        
        return {
            "experiment": experiment_name,
            "variant": variant,
            "config": config,
            "user_id": user_id
        }
    
    def record_outcome(
        self, 
        user_id: str, 
        experiment_name: str, 
        metric_name: str,
        metric_value: float
    ):
        """Record an outcome for statistical analysis"""
        
        variant = self.get_variant(user_id, experiment_name)
        
        key = f"{experiment_name}:{variant}"
        
        if key not in self.results:
            self.results[key] = {
                "experiment": experiment_name,
                "variant": variant,
                "metrics": {}
            }
        
        if metric_name not in self.results[key]["metrics"]:
            self.results[key]["metrics"][metric_name] = []
        
        self.results[key]["metrics"][metric_name].append({
            "value": metric_value,
            "user_id": user_id,
            "timestamp": datetime.utcnow().isoformat()
        })
    
    def get_experiment_results(
        self, 
        experiment_name: str
    ) -> dict:
        """
        Compute statistical summary for an experiment
        Compare control vs treatment performance
        """
        import statistics
        
        results = {}
        
        for variant in ["control", "treatment"]:
            key = f"{experiment_name}:{variant}"
            
            if key not in self.results:
                continue
            
            metrics_summary = {}
            
            for metric, values in (
                self.results[key]["metrics"].items()
            ):
                numeric_values = [v["value"] for v in values]
                
                if len(numeric_values) >= 2:
                    metrics_summary[metric] = {
                        "count": len(numeric_values),
                        "mean": statistics.mean(numeric_values),
                        "stdev": statistics.stdev(numeric_values),
                        "median": statistics.median(numeric_values)
                    }
                elif len(numeric_values) == 1:
                    metrics_summary[metric] = {
                        "count": 1,
                        "mean": numeric_values[0],
                        "stdev": 0,
                        "median": numeric_values[0]
                    }
            
            results[variant] = {
                "total_users": len(set([
                    v["user_id"]
                    for metric_values in (
                        self.results[key]["metrics"].values()
                    )
                    for v in metric_values
                ])),
                "metrics": metrics_summary
            }
        
        # Determine winner if both variants have data
        if "control" in results and "treatment" in results:
            experiment = self.experiments.get(experiment_name, {})
            primary = experiment.get(
                "primary_metric", 
                "quality_score"
            )
            
            control_mean = (
                results["control"]
                .get("metrics", {})
                .get(primary, {})
                .get("mean", 0)
            )
            
            treatment_mean = (
                results["treatment"]
                .get("metrics", {})
                .get(primary, {})
                .get("mean", 0)
            )
            
            if treatment_mean > control_mean * 1.05:
                winner = "treatment"
                lift = round(
                    (treatment_mean - control_mean) 
                    / control_mean * 100, 
                    1
                )
            elif control_mean > treatment_mean * 1.05:
                winner = "control"
                lift = round(
                    (control_mean - treatment_mean) 
                    / treatment_mean * 100, 
                    1
                )
            else:
                winner = "inconclusive"
                lift = 0
            
            results["summary"] = {
                "winner": winner,
                "primary_metric": primary,
                "lift_percent": lift,
                "recommendation": (
                    f"Ship {winner} variant" 
                    if winner != "inconclusive"
                    else "Need more data (run longer)"
                )
            }
        
        return results
```

```python
def get_user_experience(user_id: str) -> dict:

    )
    
    return {
        "citation_style": citation_style or "inline",
        "model_variant": model_variant or "control"
    }
```

### Complete Feedback Loop — End-to-End Example:

```python
async def full_feedback_loop_endpoint(
    request: ChatRequest,
    response_text: str,
    user_feedback: dict
):
    """
    Complete flow: Generate → Track → Feedback → Log → A/B
    """
    
    user_id = request.user_id or "anonymous"
    session_id = request.session_id
    
    # Step 1: Determine A/B test variant
    experiment_config = ab_tests.get_variant_config(
        user_id,
        "system_prompt_length"
    )
    
    # Step 2: Track interaction
    analytics.track_question_asked(
        user_id=user_id,
        session_id=session_id,
        question=request.messages[-1].content,
        input_type="free_text",
        feature="main_chat"
    )
    
    # Step 3: After user gives feedback, log it
    if user_feedback.get("thumbs_up") is not None:
        
        is_positive = user_feedback["thumbs_up"]
        
        # Log to feedback database
        feedback_logger.log_thumbs(
            session_id=session_id,
            question=request.messages[-1].content,
            ai_response=response_text,
            is_positive=is_positive
        )
        
        # Track in Mixpanel
        analytics.track_thumbs_feedback(
            user_id=user_id,
            session_id=session_id,
            is_positive=is_positive,
            question_category="general"
        )
        
        # Record outcome for A/B test
        ab_tests.record_outcome(
            user_id=user_id,
            experiment_name="system_prompt_length",
            metric_name="thumbs_up_rate",
            metric_value=1.0 if is_positive else 0.0
        )
    
    # Step 4: If user edited output, capture the diff
    if user_feedback.get("edited_output"):
        
        feedback_logger.log_edit(
            session_id=session_id,
            question=request.messages[-1].content,
            original_response=response_text,
            edited_response=user_feedback["edited_output"],
            user_id=user_id
        )
        
        from difflib import SequenceMatcher
        similarity = SequenceMatcher(
            None, 
            response_text,
            user_feedback["edited_output"]
        ).ratio()
        
        # Record edit quality for A/B test
        ab_tests.record_outcome(
            user_id=user_id,
            experiment_name="system_prompt_length",
            metric_name="edit_similarity",
            metric_value=similarity
        )
        
        analytics.track_output_edit(
            user_id=user_id,
            session_id=session_id,
            edit_similarity=similarity
        )
```

# 🎤 PART 7: Interview Questions & Strong Answers

---

### ❓ Question 1:
> *"How would you design a feedback system for an AI product?"*

### ✅ Strong Answer:
> "I design feedback systems in three layers. First, explicit signals: thumbs up/down, star ratings, and correction flags — these are high quality but low volume since users have to actively engage. Second, implicit signals: did the user copy the output, regenerate, edit, or leave — these are high volume and happen automatically. Third, and most valuable, edit diffs: when users edit AI output, the original-to-edited pair is ground truth training data. I store all three layers to a feedback database with session context, question, model used, and retrieval scores. This data feeds three downstream uses: prompt engineering improvement, RAG pipeline tuning, and eventually fine-tuning. The key design principle is minimum friction for the user — one click thumbs as the baseline, with optional deeper feedback."

---

### ❓ Question 2:
> *"What is the difference between regeneration and refinement? When is each appropriate?"*

### ✅ Strong Answer:
> "Regeneration discards the current output and generates a completely new response to the same input — I slightly increase temperature to ensure variation. This is appropriate when the output fundamentally missed the mark and the user has no specific direction to give. Refinement keeps the current output as a base and modifies it according to specific instructions — make it shorter, more formal, add bullet points. This is appropriate when the output is directionally correct but needs targeted changes. In my implementation, refinement uses a lower temperature to stay faithful to the original, and the prompt explicitly instructs the model to preserve everything that wasn't mentioned in the instruction. Tracking which type users use more tells me if my AI is hitting a floor it can't escape from — high regeneration rates mean fundamental alignment issues."

---

### ❓ Question 3:
> *"How do you design and run an A/B test for an AI feature?"*

### ✅ Strong Answer:
> "I follow five steps. First, form a specific hypothesis: 'A detailed system prompt will increase thumbs-up rate by 10%.' Second, define the primary metric and secondary metrics before running — never mine for significance after the fact. Third, assign users deterministically by hashing user_id + experiment_name — the same user always sees the same variant for consistency. Fourth, run the test until I reach statistical significance with at least 100 users per variant, and run for at least two weeks to account for novelty effects where users prefer new things initially. Fifth, analyze not just the primary metric but also the secondary ones — sometimes a variant improves quality but increases latency unacceptably. I use PostHog feature flags for this in production because they handle assignment, exposure tracking, and results analysis in one platform."

---

### ❓ Question 4:
> *"How do you use user edits as training data?"*

### ✅ Strong Answer:
> "User edits are the highest quality feedback signal in AI products because they give you explicit wrong-to-right pairs. Every time a user edits AI output, I capture three things: the original AI output, the user's final version, and the cosine similarity between them — which tells me how much was changed. I store these as instruction-response pairs: the instruction is the original question, the wrong response is what the AI said, and the correct response is what the user wrote. Over time, this dataset is used for two purposes. First, immediate analysis: questions that consistently lead to low-similarity edits signal a systematic failure in my prompts or retrieval that I should fix. Second, fine-tuning: once I have enough high-quality pairs, I can fine-tune the model on this dataset — teaching it to produce outputs closer to what users actually want without them having to correct it."

# ❌ PART 8: Common Beginner Mistakes

---

```
Mistake 1: Only implementing thumbs up/down
────────────────────────────────────────────────
Problem: Thumbs give a signal but no insight
Fix: Also track implicit signals (regeneration, copy,
     edit rate) — these tell you more than thumbs

Mistake 2: Not logging edit diffs
──────────────────────────────────
Problem: You know the user edited but not what
Fix: Always compare original vs final on save
     Store the (original, edited) pair — it's gold

Mistake 3: Regeneration produces same output
──────────────────────────────────────────────
Problem: Same temperature = same tokens = same result
         User clicks Regenerate 3 times and gets 
         the same answer each time
Fix: Increase temperature by 0.1 each regeneration
     Or use different random seeds

Mistake 4: Making feedback too effortful
──────────────────────────────────────────
Problem: 5 fields to fill = user skips entirely
Fix: One-click thumbs by default
     Everything else optional and collapsed

Mistake 5: Running A/B test too short
───────────────────────────────────────
Problem: First week = novelty effect (new = better)
         You ship the wrong winner
Fix: Run minimum 2 weeks. Need 100+ per variant.
     Wait for week-over-week stabilization.

Mistake 6: Not tracking which variant user saw
────────────────────────────────────────────────
Problem: Can't correlate feedback to experiment
Fix: Always attach variant name to every event
     "prompt_variant: treatment" on every log entry

Mistake 7: Assigning variants randomly per request
────────────────────────────────────────────────────
Problem: Same user sees variant A sometimes, B others
         Inconsistent experience + corrupted data
Fix: Hash user_id deterministically
     Same user ALWAYS gets same variant

Mistake 8: Not using edit data for improvement
────────────────────────────────────────────────
Problem: Collecting edits but never analyzing them
Fix: Run weekly review of high-edit-rate questions
     Fix prompts/RAG for these systematically
```

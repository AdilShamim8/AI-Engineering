# 🏗️ PILLAR 1: Role-Based Access Control (RBAC)

## What Is RBAC?

**Simple English:**
RBAC = **A system where you assign ROLES to people, and ROLES define what actions are allowed.**

Instead of giving individual permissions to each person, you:
1. Create **roles** (Admin, Developer, Analyst...)
2. Assign **permissions** to roles
3. Assign **roles** to users

```
WITHOUT RBAC (BAD):
  User A → permission1, permission2, permission5, permission9
  User B → permission1, permission3, permission5, permission7
  (Chaotic. Hard to manage. Impossible to audit.)

WITH RBAC (GOOD):
  Role: Admin    → [all permissions]
  Role: Developer→ [read_data, write_code, deploy_staging]
  Role: Analyst  → [read_reports, read_anonymized_data]

  User A → Role: Developer
  User B → Role: Analyst
  (Clean. Manageable. Auditable.)
```

## 🔬 RBAC — First Principles Breakdown

```
RBAC has 3 core components:

SUBJECTS → WHO (Users, Services, Applications)
ROLES    → LABELS (Admin, Developer, Viewer...)
OBJECTS  → WHAT (Database, API, Model, Logs)

PERMISSION = Subject + Role + Object + Action

Example:
  Subject: Data Scientist
  Role: ML_Engineer
  Object: Training Dataset S3 Bucket
  Action: READ only (not write, not delete)
```

def require_permission(permission: Permission):
    """
    Decorator that checks if the current user
    has the required permission.
    """
    def decorator(func):
        @wraps(func)
        async def wrapper(
            *args,
            credentials: HTTPAuthorizationCredentials = Depends(security),
            **kwargs
        ):
            # Decode JWT token
            token = credentials.credentials
            try:
                payload = jwt.decode(
                    token,
                    SECRET_KEY,
                    algorithms=["HS256"]
                )
            except jwt.ExpiredSignatureError:
                raise HTTPException(
                    status_code=401,
                    detail="Token expired. Please login again."
                )
            except jwt.InvalidTokenError:
                raise HTTPException(
                    status_code=401,
                    detail="Invalid token."
                )
            
            # Get user's role
            user_role = Role(payload.get("role"))
            user_id = payload.get("user_id")
            
            # Check permission
            allowed_permissions = ROLE_PERMISSIONS.get(user_role, set())
            if permission not in allowed_permissions:
                raise HTTPException(
                    status_code=403,
                    detail=f"Access denied. Role '{user_role.value}' "
                           f"cannot perform '{permission.value}'"
                )
            
            # Log access attempt (audit trail!)
            await log_access(
                user_id=user_id,
                role=user_role,
                action=permission,
                endpoint=func.__name__
            )
            
            return await func(*args, **kwargs)
        return wrapper
    return decorator

### ⚠️ RBAC Failure Modes

```
FAILURE 1: ROLE EXPLOSION
  Too many roles created → "Developer_v1", "Developer_v2"
  → Nobody knows which role gives what permission
  Fix: Review and consolidate roles quarterly

FAILURE 2: OVER-PRIVILEGED ROLES
  "Give them admin access, we'll restrict later"
  → "Later" never comes
  Fix: Start with minimal permissions. Add only when needed.

FAILURE 3: ROLE INHERITANCE GAPS
  Junior Dev inherits all Senior Dev permissions
  → More access than needed
  Fix: Audit permissions after every role assignment

FAILURE 4: MISSING OFFBOARDING
  Employee leaves → account and role remain active
  → Ex-employee can still access system
  Fix: Automated deactivation tied to HR system

FAILURE 5: RBAC WITHOUT AUDIT TRAIL
  RBAC blocks attacks but doesn't LOG them
  → You have no idea who tried what
  Fix: Log every permission check (pass AND fail)
```

# 🏗️ PILLAR 2: API Key Management

## What Is an API Key?

**Simple English:**
An API key = **A long, unique password for a service (not a human) to authenticate with your LLM system.**

```
HUMANS use:   username + password + MFA
SERVICES use: API keys or tokens

Example API Key:
sk-prod-a7f3d9c2b1e4f8a2d7c3b9e1f4a8d2c7b3e9f1a4d2

It's just a string.
But it proves: "This request comes from an 
               authorized service."
```

## 📋 API Key Best Practices — The Golden Rules

```
RULE 1: NEVER COMMIT KEYS TO CODE

❌ BAD (in your Python file):
   OPENAI_API_KEY = "sk-abc123..."
   
✅ GOOD (environment variable):
   OPENAI_API_KEY = os.getenv("OPENAI_API_KEY")
   
✅ BETTER (secret manager):
   OPENAI_API_KEY = aws_secrets.get("openai/api_key")

─────────────────────────────────────────

RULE 2: ONE KEY PER USE CASE
   
❌ BAD: One key for everything
   
✅ GOOD:
   key_production_webapp    → Production app only
   key_staging_tests        → Test environment only
   key_data_pipeline        → ETL pipeline only
   key_monitoring_service   → Monitoring tool only

─────────────────────────────────────────

RULE 3: MINIMUM SCOPE PER KEY

❌ BAD: Key can do everything (read, write, delete, admin)
✅ GOOD: Key can only do what it needs:
   production_key → read + write responses only
                    cannot deploy or delete

─────────────────────────────────────────

RULE 4: ALWAYS SET EXPIRY
   
❌ BAD: Keys never expire
✅ GOOD: 
   Short-lived: 24 hours (for one-time tasks)
   Medium-lived: 90 days (for services)
   Long-lived: 1 year (with mandatory rotation)

─────────────────────────────────────────

RULE 5: ROTATE PROACTIVELY

Don't wait for a leak. Rotate on schedule.
Old key + new key active simultaneously
  → Switch app to new key
  → Deactivate old key
  → Zero downtime
```

# PRODUCTION API KEY MANAGEMENT SYSTEM
# ============================================

import secrets
import hashlib
import hmac
from datetime import datetime, timedelta
from typing import Optional
import redis
import psycopg2

class APIKeyManager:
    """
    Complete API Key Management System
    Handles: Generate, Store, Validate, Rotate, Revoke
    """
    
    PREFIX_MAP = {
        "production": "sk-prod",
        "staging":    "sk-stg",
        "testing":    "sk-test",
        "readonly":   "sk-ro",
    }
    
    def __init__(self):
        self.db = psycopg2.connect(DATABASE_URL)
        self.cache = redis.Redis(host='localhost', port=6379)
    
    # ─────────────────────────────────────────
    # GENERATE A NEW API KEY
    # ─────────────────────────────────────────
    def generate_key(
        self,
        user_id: str,
        environment: str = "production",
        permissions: list = None,
        expires_in_days: int = 90,
        rate_limit_per_minute: int = 60,
        allowed_ips: list = None,
        name: str = "default"
    ) -> dict:
        """
        Generate a new API key with full configuration
        """
        # Step 1: Generate cryptographically secure random key
        # secrets module is safer than random module!
        raw_key = secrets.token_urlsafe(32)  # 32 bytes = 256 bits
        
        # Step 2: Add environment prefix (helps identify key type)
        prefix = self.PREFIX_MAP.get(environment, "sk")
        full_key = f"{prefix}-{raw_key}"
        # Example: "sk-prod-a7f3d9c2b1e4f8a2..."
        
        # Step 3: Hash the key for storage
        # NEVER store the raw key!
        # Only store the hash (like passwords)
        key_hash = hashlib.sha256(full_key.encode()).hexdigest()
        
        # Step 4: Store key metadata in database
        expiry_date = datetime.utcnow() + timedelta(days=expires_in_days)
        
        cursor = self.db.cursor()
        cursor.execute("""
            INSERT INTO api_keys (
                key_hash,
                key_prefix,     -- Store first 8 chars for identification
                user_id,
                name,
                environment,
                permissions,
                expires_at,
                rate_limit_per_minute,
                allowed_ips,
                created_at,
                is_active
            ) VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s)
            RETURNING id
        """, (
            key_hash,
            full_key[:12],      # "sk-prod-a7f3" (for display only)
            user_id,
            name,
            environment,
            permissions or ["call_api"],  # Default: minimal permission
            expiry_date,
            rate_limit_per_minute,
            allowed_ips or [],
            datetime.utcnow(),
            True
        ))
        
        key_id = cursor.fetchone()[0]
        self.db.commit()
        
        # Step 5: Return the FULL key ONCE
        # After this, we cannot show it again!
        return {
            "key_id": key_id,
            "api_key": full_key,  # Show ONCE to user, then never again
            "prefix": full_key[:12],
            "expires_at": expiry_date.isoformat(),
            "permissions": permissions,
            "rate_limit": f"{rate_limit_per_minute}/minute",
            "warning": "⚠️ Save this key now. It will never be shown again."
        }
    
    # ─────────────────────────────────────────
    # VALIDATE AN API KEY ON EACH REQUEST
    # ─────────────────────────────────────────
    def validate_key(
        self,
        provided_key: str,
        required_permission: str,
        client_ip: str
    ) -> dict:
        """
        Validate API key on every single request
        This runs thousands of times per second in production!
        """
        
        # Step 1: Hash the provided key
        key_hash = hashlib.sha256(provided_key.encode()).hexdigest()
        
        # Step 2: Check Redis cache first (FAST!)
        # Avoid database hit on every request
        cached = self.cache.get(f"apikey:{key_hash}")
        if cached:
            key_data = json.loads(cached)
        else:
            # Step 3: Fetch from database (slower, but only on cache miss)
            cursor = self.db.cursor()
            cursor.execute("""
                SELECT 
                    id, user_id, permissions, expires_at,
                    rate_limit_per_minute, allowed_ips,
                    is_active, environment
                FROM api_keys 
                WHERE key_hash = %s
            """, (key_hash,))
            
            row = cursor.fetchone()
            
            if not row:
                self._log_failed_attempt(provided_key[:12], "KEY_NOT_FOUND")
                raise HTTPException(401, "Invalid API key")
            
            key_data = {
                "id": row[0],
                "user_id": row[1],
                "permissions": row[2],
                "expires_at": row[3].isoformat(),
                "rate_limit": row[4],
                "allowed_ips": row[5],
                "is_active": row[6],
                "environment": row[7]
            }
            
            # Cache for 5 minutes (balance: speed vs freshness)
            self.cache.setex(
                f"apikey:{key_hash}",
                300,  # 5 minutes TTL
                json.dumps(key_data)
            )
        
        # Step 4: Check if key is active
        if not key_data["is_active"]:
            self._log_failed_attempt(key_data["id"], "KEY_REVOKED")
            raise HTTPException(401, "API key has been revoked")
        
        # Step 5: Check expiry
        expires_at = datetime.fromisoformat(key_data["expires_at"])
        if datetime.utcnow() > expires_at:
            self._log_failed_attempt(key_data["id"], "KEY_EXPIRED")
            raise HTTPException(401, "API key has expired. Please rotate your key.")
        
        # Step 6: Check IP whitelist (if configured)
        allowed_ips = key_data.get("allowed_ips", [])
        if allowed_ips and client_ip not in allowed_ips:
            self._log_failed_attempt(key_data["id"], "IP_NOT_ALLOWED")
            raise HTTPException(403, f"IP {client_ip} not authorized for this key")
        
        # Step 7: Check permission
        if required_permission not in key_data["permissions"]:
            self._log_failed_attempt(key_data["id"], "PERMISSION_DENIED")
            raise HTTPException(
                403,
                f"Key does not have permission: {required_permission}"
            )
        
        # Step 8: Rate limiting check
        rate_key = f"ratelimit:{key_data['id']}:{datetime.utcnow().minute}"
        current_count = self.cache.incr(rate_key)
        self.cache.expire(rate_key, 60)  # Reset every minute
        
        if current_count > key_data["rate_limit"]:
            raise HTTPException(
                429,
                f"Rate limit exceeded. Limit: {key_data['rate_limit']}/minute"
            )
        
        # ✅ ALL CHECKS PASSED
        return {
            "user_id": key_data["user_id"],
            "permissions": key_data["permissions"],
            "environment": key_data["environment"]
        }
    
    # ─────────────────────────────────────────
    # ROTATE AN API KEY (Zero Downtime)
    # ─────────────────────────────────────────
    def rotate_key(self, old_key_id: str, user_id: str) -> dict:
        """
        Rotate API key with zero-downtime strategy:
        1. Create new key
        2. Old key still works for 24 hours (grace period)
        3. Client switches to new key
        4. Old key auto-expires
        """
        
        # Fetch old key's config
        cursor = self.db.cursor()
        cursor.execute("""
            SELECT permissions, environment, rate_limit_per_minute, 
                   allowed_ips, name
            FROM api_keys WHERE id = %s AND user_id = %s
        """, (old_key_id, user_id))
        
        old_config = cursor.fetchone()
        if not old_config:
            raise HTTPException(404, "API key not found")
        
        # Generate new key with same config
        new_key_data = self.generate_key(
            user_id=user_id,
            permissions=old_config[0],
            environment=old_config[1],
            rate_limit_per_minute=old_config[2],
            allowed_ips=old_config[3],
            name=f"{old_config[4]}_rotated"
        )
        
        # Set old key to expire in 24 hours (grace period)
        grace_period = datetime.utcnow() + timedelta(hours=24)
        cursor.execute("""
            UPDATE api_keys 
            SET expires_at = %s,
                rotation_note = 'Rotated. Expires after grace period.'
            WHERE id = %s
        """, (grace_period, old_key_id))
        
        self.db.commit()
        
        return {
            "new_key": new_key_data,
            "old_key_expires": grace_period.isoformat(),
            "message": "Switch to new key within 24 hours"
        }
    
    # ─────────────────────────────────────────
    # REVOKE A KEY IMMEDIATELY
    # ─────────────────────────────────────────
    def revoke_key(self, key_id: str, reason: str):
        """
        Immediately deactivate a compromised or unused key
        """
        cursor = self.db.cursor()
        cursor.execute("""
            UPDATE api_keys 
            SET is_active = FALSE,
                revoked_at = %s,
                revoke_reason = %s
            WHERE id = %s
        """, (datetime.utcnow(), reason, key_id))
        
        self.db.commit()
        
        # Immediately clear from cache
        # So next request fails right away
        key_hash = self._get_hash_for_id(key_id)
        self.cache.delete(f"apikey:{key_hash}")
        
        # Alert the team
        self._send_revocation_alert(key_id, reason)
        
        return {"status": "revoked", "effective": "immediately"}

## 🔧 TOOL DEEP DIVE: JWT (JSON Web Tokens)

### What Is JWT?

**Simple English:**
JWT = **A self-contained digital ticket that proves who you are and what you're allowed to do — without checking the database on every single request.**

---

### 🔬 JWT Structure — First Principles

A JWT has exactly **3 parts**, separated by dots:

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.
eyJ1c2VyX2lkIjoiMTIzIiwicm9sZSI6Im1sX2VuZ2luZWVyIn0
.
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

  PART 1: HEADER       PART 2: PAYLOAD      PART 3: SIGNATURE
  (Algorithm info)     (Your data/claims)   (Tamper-proof seal)
```

---

### 🔬 Each Part — Deep Explanation

```
PART 1: HEADER
{
  "alg": "HS256",    ← Signing algorithm (HMAC-SHA256)
  "typ": "JWT"       ← Type of token
}

PART 2: PAYLOAD (The Claims)
{
  "user_id": "usr_abc123",         ← Who you are
  "email": "john@company.com",     ← Your email
  "role": "ml_engineer",           ← Your role
  "permissions": [                 ← What you can do
    "call_api",
    "deploy_staging",
    "train_model"
  ],
  "tenant_id": "company_xyz",      ← Which tenant (multi-tenant)
  "iat": 1690000000,               ← Issued At (Unix timestamp)
  "exp": 1690086400,               ← Expires At (24 hours later)
  "iss": "auth.mycompany.com",     ← Issuer (who created this token)
  "jti": "unique-token-id-xyz"     ← JWT ID (for revocation)
}

PART 3: SIGNATURE
HMAC-SHA256(
  base64(header) + "." + base64(payload),
  SECRET_KEY
)
→ If ANYONE modifies the payload, signature breaks!
→ Server immediately knows it was tampered.
```

---

### 🌍 JWT Analogy — Movie Ticket

```
MOVIE TICKET = JWT

Printed on ticket (PAYLOAD):
  → "John Doe"      (user_id)
  → "Seat 14C"      (permissions)
  → "7:30 PM Show"  (expiry)
  → "Inception"     (what app/resource)

Hologram sticker (SIGNATURE):
  → Proves ticket is genuine
  → Cannot be faked without the stamp machine (SECRET_KEY)

At the door (SERVER VALIDATION):
  → Check hologram valid? → Signature check
  → Check date/time? → Expiry check
  → Check seat exists? → Permission check
  → No need to call the ticket office for every customer!
    → That's the magic of JWT (stateless validation)
```

### ⚠️ JWT Failure Modes

```
FAILURE 1: ALGORITHM CONFUSION ATTACK
  JWT header says "alg: none"
  → No signature check → Anyone can forge tokens!
  Fix: ALWAYS explicitly specify allowed algorithms:
       jwt.decode(token, key, algorithms=["HS256"])
       # Never algorithms=["none"] or algorithms=[]

FAILURE 2: WEAK SECRET KEY
  SECRET_KEY = "password123"
  → Brute-forced in seconds
  Fix: Use cryptographically random 256-bit key:
       secrets.token_urlsafe(32)

FAILURE 3: STORING TOKENS IN LOCALSTORAGE
  Frontend stores JWT in localStorage
  → XSS attack steals token
  Fix: Store access token in memory
       Store refresh token in HttpOnly cookie

FAILURE 4: LONG-LIVED ACCESS TOKENS
  Access token expires in 30 days
  → Compromised token works for 30 days
  Fix: Access tokens: 15-60 minutes max
       Use refresh tokens for longer sessions

FAILURE 5: NO REVOCATION MECHANISM
  User logs out → token still valid until expiry
  → Logged-out user's token still works
  Fix: Maintain a JWT denylist (Redis set of jti values)
       Check denylist on every validation
```

  ↓

  → User is now logged in!

# ============================================

import jwt
from fastapi import FastAPI, Depends, HTTPException
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
import requests
from functools import lru_cache

app = FastAPI()
security = HTTPBearer()

# Auth0 Configuration (from .env file)
AUTH0_DOMAIN = os.getenv("AUTH0_DOMAIN")       # "your-app.auth0.com"
AUTH0_API_AUDIENCE = os.getenv("AUTH0_AUDIENCE") # "https://api.myapp.com"
ALGORITHMS = ["RS256"]  # Auth0 uses RS256 (asymmetric - more secure!)

# ─────────────────────────────────────────
# Fetch Auth0's Public Keys (JWKS)
# Used to verify JWT signatures
# ─────────────────────────────────────────
@lru_cache(maxsize=1)  # Cache JWKS (doesn't change often)
def get_auth0_public_keys():
    """
    Auth0 signs tokens with private key.
    We verify with their PUBLIC key.
    No need to share secrets!
    This is RS256 (asymmetric) - more secure than HS256.
    """
    jwks_url = f"https://{AUTH0_DOMAIN}/.well-known/jwks.json"
    response = requests.get(jwks_url)
    return response.json()


# ─────────────────────────────────────────
# Validate Auth0 JWT
# ─────────────────────────────────────────
def validate_auth0_token(token: str) -> dict:
    """
    Validate JWT issued by Auth0.
    Auth0 uses RS256 (RSA asymmetric signing).
    We verify using Auth0's public keys.
    """
    try:
        # Get the key ID from token header
        header = jwt.get_unverified_header(token)
        kid = header.get("kid")  # Key ID
        
        # Find matching public key from Auth0
        jwks = get_auth0_public_keys()
        public_key = None
        
        for key in jwks["keys"]:
            if key["kid"] == kid:
                public_key = jwt.algorithms.RSAAlgorithm.from_jwk(key)
                break
        
        if not public_key:
            raise HTTPException(401, "Unable to find matching signing key")
        
        # Verify and decode the token
        payload = jwt.decode(
            token,
            public_key,
            algorithms=ALGORITHMS,
            audience=AUTH0_API_AUDIENCE,  # Must match your API
            issuer=f"https://{AUTH0_DOMAIN}/"
        )
        
        return payload
    
    except jwt.ExpiredSignatureError:
        raise HTTPException(401, "Auth0 token has expired")
    except jwt.InvalidTokenError as e:
        raise HTTPException(401, f"Auth0 token invalid: {str(e)}")

    return {
        "user_id": payload.get("sub"),          # Auth0 user ID

        ),
        "permissions": payload.get(             # Custom claim

# 🏗️ PILLAR 4: Environment Separation

## What Is Environment Separation?

**Simple English:**
Environment Separation = **Having completely separate, isolated versions of your system for development, testing, and production — so that mistakes in testing NEVER touch real users or real data.**

---

## 🌍 Analogy — Aircraft Testing

```
✈️ BUILDING A NEW AIRPLANE:

DESIGN ENVIRONMENT (Dev):
  → Engineers design on computers
  → No real parts, just blueprints
  → Mistakes are cheap → just update the file

WIND TUNNEL (Staging):
  → Physical model tested in controlled conditions
  → Simulates real flight conditions
  → Mistakes are identified → fixed before real plane

REAL FLIGHT TEST (Production):
  → Real plane, real pilots
  → Rigorously tested before passengers
  → Mistakes now = catastrophic

SAME FOR SOFTWARE:
Dev → Staging → Production
Each stage more serious than the last.
NEVER skip stages.
```

# ============================================
# ENVIRONMENT CONFIGURATION MANAGEMENT
# ============================================

import os
from pydantic import BaseSettings
from enum import Enum

class Environment(str, Enum):
    DEV     = "development"
    STAGING = "staging"
    PROD    = "production"

class Settings(BaseSettings):
    """
    All config comes from environment variables.
    Different .env files for each environment.
    NEVER hardcode any values.
    """
    
    # Environment
    ENVIRONMENT: Environment = Environment.DEV
    
    # LLM Configuration
    # Dev: cheap small model
    # Prod: best model
    LLM_MODEL: str = "gpt-3.5-turbo"
    LLM_MAX_TOKENS: int = 1000
    LLM_TEMPERATURE: float = 0.7
    
    # Database
    DATABASE_URL: str
    
    # Redis
    REDIS_URL: str
    
    # Auth
    JWT_SECRET_KEY: str
    AUTH0_DOMAIN: str
    
    # AWS
    AWS_REGION: str = "us-east-1"
    S3_BUCKET: str
    KMS_KEY_ID: str
    
    # Monitoring
    LANGFUSE_PUBLIC_KEY: str
    LANGFUSE_SECRET_KEY: str
    
    # Rate Limiting
    RATE_LIMIT_PER_MINUTE: int = 60
    
    class Config:
        env_file = f".env.{os.getenv('APP_ENV', 'development')}"
        # Loads:
        # .env.development  → for dev
        # .env.staging      → for staging
        # .env.production   → for production

# Initialize
settings = Settings()

# Environment-specific logic
def get_llm_model() -> str:
    """
    Use different LLM models per environment.
    Save cost in dev. Use best model in prod.
    """
    model_map = {
        Environment.DEV:     "gpt-3.5-turbo",       # Cheap, fast
        Environment.STAGING: "gpt-4-turbo",           # Same as prod
        Environment.PROD:    "gpt-4o",                # Best model
    }
    return model_map[settings.ENVIRONMENT]


def is_production() -> bool:
    return settings.ENVIRONMENT == Environment.PROD


def require_production_confirmation(action: str):
    """
    Require extra confirmation for dangerous 
    actions in production.
    """
    if is_production():
        confirmation = input(
            f"⚠️ PRODUCTION ACTION: {action}\n"
            f"Type 'CONFIRM' to proceed: "
        )
        if confirmation != "CONFIRM":
            raise Exception("Production action cancelled.")

### What Is an API Gateway?

**Simple English:**
API Gateway = **The front door to your entire LLM system. Every single request goes through it. It handles authentication, rate limiting, routing, logging, and more — BEFORE requests reach your actual LLM service.**

```
WITHOUT API GATEWAY:
  User → [Your LLM Service directly]
  → Your service handles auth + rate limit + logging
  → Every microservice must do this separately
  → Chaotic, inconsistent, hard to manage

WITH API GATEWAY:
  User → [API GATEWAY] → [Your LLM Service]
  → Gateway handles: auth, rate limit, logging, routing
  → Your service only does ONE thing: answer queries
  → Clean, centralized, consistent
```

# 💬 Strong Interview Answers

### Q: "What is the difference between Authentication and Authorization?"

✅ **Strong Answer:**
> "Authentication answers 'WHO are you?' — it verifies identity through credentials like passwords, tokens, or certificates. Authorization answers 'WHAT are you allowed to do?' — it checks permissions after identity is confirmed. For example, in an LLM system: a data scientist authenticates with their JWT token (proving who they are), but then authorization checks if their role has permission to deploy to production (what they can do). Authentication always happens first — you cannot authorize someone whose identity you haven't verified."

---

### Q: "How do you design RBAC for an LLM platform?"

✅ **Strong Answer:**
> "I start by identifying all resources — datasets, models, prompts, APIs, logs, and admin functions. Then I define roles based on job functions: Super Admin, ML Engineer, Prompt Engineer, Developer, Analyst, Auditor, and End User. For each role, I apply the principle of least privilege — giving only the minimum permissions needed for that job. I map roles to permissions in a matrix, implement this in code as a decorator or middleware that runs on every API request, and log every permission check — both pass and fail — for audit purposes. I also build automated offboarding so when someone leaves, their role is revoked immediately."

---

### Q: "Explain the OAuth 2.0 Authorization Code Flow"

✅ **Strong Answer:**
> "In the Authorization Code flow: First, the user clicks 'Login with Google' and my app redirects them to Google's auth server with a client_id, redirect_uri, and requested scopes. Google shows a consent screen listing exactly what access is requested. After the user approves, Google redirects back to my app with a short-lived authorization code. My server — never the browser — exchanges this code plus my client_secret for an access token and refresh token. This flow is secure because the client_secret never leaves the server, the authorization code is single-use and short-lived, and the PKCE extension prevents code interception attacks. The access token is then used for subsequent API calls."

# ⚠️ Common Beginner Mistakes

| Mistake | Why It's Wrong | Correct Approach |
|---------|---------------|-----------------|
| Storing JWT in localStorage | Vulnerable to XSS attacks | HttpOnly cookie for refresh token |
| Using symmetric signing for Auth0 | HS256 requires shared secret | Use RS256 (asymmetric) with Auth0 |
| One API key for all services | Leaked key = full access | One key per service/environment |
| No token refresh strategy | Users get logged out suddenly | Implement silent refresh |
| Skipping MFA in production | Single factor = single point of failure | MFA mandatory for prod access |
| Trusting client-sent role | Client can modify their request | Read role from validated JWT only |
| Generic error messages | "Invalid token" leaks information to attackers | Same: "Unauthorized" for all failures |

# 🏗️ PILLAR 1: Model Versioning

## What Is Model Versioning?

**Simple English:**
Model Versioning = **Tracking every version of your AI model — what it contains, when it was created, what data trained it, what metrics it achieved, and where it's deployed.**

---

## 🌍 Analogy — iPhone Software Updates

```
📱 IPHONE SOFTWARE = Your LLM Model

iOS 16.0   → First release, basic features
iOS 16.1   → Bug fixes + small improvements
iOS 16.2   → New features added
iOS 17.0   → Major upgrade, new architecture

Each version:
  ✅ Has a clear version number
  ✅ Has release notes (what changed)
  ✅ Can be rolled back if problems found
  ✅ Is tested before release
  ✅ Has a clear lineage (built on previous version)

YOUR LLM MODELS SHOULD WORK THE SAME WAY!
```

## 🔬 What Do You Version in a Model?

A model is NOT just the weights file. It is a **complete package**:

```
┌─────────────────────────────────────────────────────┐
│              WHAT MAKES A MODEL VERSION?            │
├─────────────────────────────────────────────────────┤
│                                                     │
│ 1. MODEL WEIGHTS      → The trained parameters      │
│    (model.pkl / model.safetensors)                  │

│ 2. TRAINING DATA      → What data was used?         │
│    (dataset version + data lineage)                 │
│                                                     │
│ 3. HYPERPARAMETERS    → Learning rate, batch size   │
│    (all training config values)                     │
│                                                     │
│ 4. EVALUATION METRICS → How well does it perform?  │
│    (accuracy, BLEU, hallucination rate)             │
│                                                     │
│ 5. BASE MODEL         → Which foundation model?    │

│    (Git commit hash of training script)            │
│                                                     │
│ 7. ENVIRONMENT        → Which Python packages?     │
│    (requirements.txt / conda environment)           │

│    (author, date, purpose, tags)                   │
│                                                     │
└─────────────────────────────────────────────────────┘

Version 1 of your model =
  All 8 things above, locked together, forever.
```

## 📋 Model Version Naming — Semantic Versioning

Use a clear, consistent naming convention:

```
MODEL VERSION: customer-support-llm-v2.3.1

BREAKDOWN:
  customer-support-llm  → Project name
  v2                    → MAJOR version 
                          (new architecture / base model)
  .3                    → MINOR version
                          (new fine-tuning data, significant improvement)
  .1                    → PATCH version
                          (small fix, minor prompt change)

WHEN TO INCREMENT:

MAJOR (v1 → v2):
  → Changed base model (GPT-3.5 → GPT-4)
  → Complete retraining from scratch
  → Architecture change (RAG → fine-tuned)
  → Breaking change in behavior

MINOR (v2.2 → v2.3):
  → Added new training data
  → Significant performance improvement
  → New capability added
  → Fine-tuning on new domain

PATCH (v2.3.0 → v2.3.1):
  → Small prompt adjustment
  → Hyperparameter tweak
  → Bug fix in post-processing
  → Minor evaluation improvement
```

## 📊 Model States — Lifecycle

```
Every model version goes through these states:

┌──────────┐    ┌──────────┐    ┌───────────┐    ┌──────────┐
│ STAGING  │ →  │ CANDIDATE│ →  │PRODUCTION │ →  │ ARCHIVED │
└──────────┘    └──────────┘    └───────────┘    └──────────┘
     ↑                ↑               ↑                ↑
 Just trained    Passed all      Live for         Retired but
 Not tested      eval tests      real users       preserved

STAGING:
  → Model just trained or fine-tuned
  → Internal testing only
  → Cannot serve real users

CANDIDATE (CHALLENGER):
  → Passed automated evaluation
  → Awaiting human approval
  → Can be A/B tested vs production

PRODUCTION:
  → Approved by reviewer
  → Serving real users
  → Monitored continuously
  → Only ONE model in production at a time

ARCHIVED:
  → Replaced by newer version
  → Kept for compliance/rollback
  → Read-only, not deletable
```

### What Is MLflow?

**Simple English:**
MLflow = **An open-source platform that tracks everything about your ML experiments and models — what you tried, what worked, what you deployed, and what you need to go back to.**

MLflow is an open-source platform to manage the complete machine learning lifecycle, including experimentation, reproducibility, deployment, and a central model registry.

```python
import mlflow
import mlflow.transformers
from mlflow import MlflowClient
from datetime import datetime
import os
import json

# SETUP: Point to your MLflow server
# ─────────────────────────────────────────
mlflow.set_tracking_uri(os.getenv("MLFLOW_TRACKING_URI"))
# Options:

# "https://mlflow.mycompany.com" → Remote server
# "databricks"                  → Databricks hosted

# Set the experiment (project grouping)
mlflow.set_experiment("customer-support-llm")

# ─────────────────────────────────────────
# STEP 1: LOG YOUR FINE-TUNING EXPERIMENT
# ─────────────────────────────────────────
def train_and_log_model(
    base_model_name: str,
    training_config: dict,
    training_data_path: str
):
    """
    Fine-tune an LLM and log EVERYTHING to MLflow.
    Full reproducibility: anyone can recreate this exact model.
    """
    
    # Start MLflow run
    with mlflow.start_run(
        run_name=f"finetune_{base_model_name}_{datetime.now().strftime('%Y%m%d_%H%M')}",
        tags={
            "author": os.getenv("USER", "unknown"),
            "project": "customer-support-llm",
            "base_model": base_model_name,
            "git_commit": get_git_commit_hash(),
            "environment": "staging",
            "training_purpose": "Added new product FAQ data",
        }
    ) as run:
        
        print(f"📊 MLflow Run ID: {run.info.run_id}")
        
        # ─────────────────────────────
        # LOG ALL PARAMETERS
        # (Everything that affects the model)
        # ─────────────────────────────
        mlflow.log_params({
            # Model config
            "base_model": base_model_name,
            "model_type": "causal_lm",
            
            # Training config
            "learning_rate": training_config["lr"],
            "batch_size": training_config["batch_size"],
            "num_epochs": training_config["epochs"],
            "max_seq_length": training_config["max_length"],
            "gradient_accumulation_steps": training_config["grad_accum"],
            
            # LoRA / PEFT config
            "lora_rank": training_config.get("lora_r", 16),
            "lora_alpha": training_config.get("lora_alpha", 32),
            "lora_dropout": training_config.get("lora_dropout", 0.05),
            "lora_target_modules": str(training_config.get(
                "target_modules", ["q_proj", "v_proj"]
            )),
            
            # Data config
            "training_data_version": "customer_support_v3.2",
            "training_samples": 15420,
            "val_samples": 1800,
            "data_source": training_data_path,
        })
        
        # ─────────────────────────────
        # TRAIN THE MODEL
        # ─────────────────────────────
        model, tokenizer, training_history = run_fine_tuning(
            base_model=base_model_name,
            config=training_config,
            data_path=training_data_path
        )
        
        # ─────────────────────────────
        # LOG METRICS AT EACH STEP
        # ─────────────────────────────
        for step, metrics in enumerate(training_history):
            mlflow.log_metrics({
                "train_loss": metrics["train_loss"],
                "eval_loss": metrics["eval_loss"],
                "learning_rate": metrics["lr"],
            }, step=step)
        
        # ─────────────────────────────
        # RUN FINAL EVALUATION
        # ─────────────────────────────
        eval_results = evaluate_model(model, tokenizer)
        
        # Log final evaluation metrics
        mlflow.log_metrics({
            # Quality metrics
            "bleu_score": eval_results["bleu"],
            "rouge_l": eval_results["rouge_l"],
            "hallucination_rate": eval_results["hallucination_rate"],
            "answer_relevance_score": eval_results["relevance"],
            "factual_accuracy": eval_results["accuracy"],
            
            # Performance metrics
            "avg_latency_ms": eval_results["avg_latency"],
            "p99_latency_ms": eval_results["p99_latency"],
            "tokens_per_second": eval_results["throughput"],
            
            # Cost metrics
            "cost_per_1k_tokens_usd": eval_results["cost"],
        })
        
        # ─────────────────────────────
        # LOG ARTIFACTS (Files)
        # ─────────────────────────────
        
        # Save evaluation report
        with open("eval_report.json", "w") as f:
            json.dump(eval_results, f, indent=2)
        mlflow.log_artifact("eval_report.json")
        
        # Save training configuration
        with open("training_config.yaml", "w") as f:
            yaml.dump(training_config, f)
        mlflow.log_artifact("training_config.yaml")
        
        # Log the confusion matrix image
        mlflow.log_artifact("evaluation_charts/confusion_matrix.png")

                "model": model,
                "tokenizer": tokenizer

            artifact_path="model",
            registered_model_name="customer-support-llm",

# STEP 2: MANAGE MODEL IN REGISTRY
# (Version Control + Staging)
# ─────────────────────────────────────────
class ModelRegistryManager:
    
    def __init__(self):
        self.client = MlflowClient()
        self.model_name = "customer-support-llm"
    
    def list_all_versions(self):
        """
        See all versions of a model — like git log for models
        """
        versions = self.client.search_model_versions(
            filter_string=f"name='{self.model_name}'"
        )
        
        print(f"\n📊 ALL VERSIONS OF: {self.model_name}")
        print("=" * 70)
        
        for v in versions:
            print(f"""
Version:    {v.version}
Stage:      {v.current_stage}   ← Staging/Candidate/Production/Archived
Run ID:     {v.run_id}
Created:    {v.creation_timestamp}
Author:     {v.tags.get('author', 'unknown')}
Description:{v.description}
            """)
    
    def promote_to_candidate(
        self, 
        version: str, 
        evaluation_summary: str,
        approved_by: str
    ):
        """
        Move model from Staging → Candidate
        (Ready for human review and approval)
        """
        # Add approval metadata
        self.client.set_model_version_tag(
            name=self.model_name,
            version=version,
            key="evaluation_summary",
            value=evaluation_summary
        )
        
        self.client.set_model_version_tag(
            name=self.model_name,
            version=version,
            key="candidate_approved_by",
            value=approved_by
        )
        
        self.client.set_model_version_tag(
            name=self.model_name,
            version=version,
            key="candidate_timestamp",
            value=datetime.utcnow().isoformat()
        )
        
        # Transition stage
        self.client.transition_model_version_stage(
            name=self.model_name,
            version=version,
            stage="Staging",        # → moves to Staging
            archive_existing_versions=False
        )
        
        print(f"✅ v{version} promoted to CANDIDATE stage")
        print(f"   Now awaiting production approval from senior reviewer")
    
    def deploy_to_production(
        self,
        version: str,
        approved_by: str,
        approval_ticket: str,        # e.g., JIRA ticket
        rollback_plan: str
    ):
        """
        Deploy model to production.
        Requires explicit approval documentation.
        Previous production version auto-archived.
        """
        
        # SAFETY CHECK: Verify eval metrics meet threshold
        run_id = self.client.get_model_version(
            self.model_name, version
        ).run_id
        
        run = self.client.get_run(run_id)
        hallucination_rate = run.data.metrics.get("hallucination_rate", 1.0)
        bleu_score = run.data.metrics.get("bleu_score", 0.0)
        
        if hallucination_rate > 0.05:   # Block if > 5% hallucination
            raise ValueError(
                f"❌ DEPLOYMENT BLOCKED: Hallucination rate {hallucination_rate:.2%} "
                f"exceeds threshold 5%"
            )
        
        if bleu_score < 0.70:           # Block if BLEU < 0.70
            raise ValueError(
                f"❌ DEPLOYMENT BLOCKED: BLEU score {bleu_score:.2f} "
                f"below minimum threshold 0.70"
            )
        
        # Add approval documentation
        self.client.set_model_version_tag(
            name=self.model_name, version=version,
            key="deployed_by", value=approved_by
        )
        self.client.set_model_version_tag(
            name=self.model_name, version=version,
            key="approval_ticket", value=approval_ticket
        )
        self.client.set_model_version_tag(
            name=self.model_name, version=version,
            key="deployment_timestamp", value=datetime.utcnow().isoformat()
        )
        self.client.set_model_version_tag(
            name=self.model_name, version=version,
            key="rollback_to_version", value=rollback_plan
        )
        
        # PROMOTE to Production
        # Automatically archives current production model!
        self.client.transition_model_version_stage(
            name=self.model_name,
            version=version,
            stage="Production",
            archive_existing_versions=True   # ← Archives old prod version
        )
        
        print(f"🚀 v{version} is now PRODUCTION!")
        print(f"   Deployed by: {approved_by}")
        print(f"   Approval ticket: {approval_ticket}")
        print(f"   Rollback plan: v{rollback_plan}")
    
    def emergency_rollback(
        self,
        reason: str,
        rolled_back_by: str
    ):
        """
        INSTANT ROLLBACK: Reactivate previous version.
        Used in production incidents.
        """
        # Find current production version
        current_prod = self.client.get_latest_versions(
            self.model_name, stages=["Production"]
        )[0]
        
        # Find rollback target from tags
        rollback_version = current_prod.tags.get("rollback_to_version")
        
        if not rollback_version:
            raise ValueError("No rollback version configured!")
        
        # Archive current broken version
        self.client.transition_model_version_stage(
            name=self.model_name,
            version=current_prod.version,
            stage="Archived"
        )
        
        # Restore previous version
        self.client.transition_model_version_stage(
            name=self.model_name,
            version=rollback_version,
            stage="Production"
        )
        
        # Document the incident
        self.client.set_model_version_tag(
            name=self.model_name,
            version=current_prod.version,
            key="rollback_reason", value=reason
        )
        self.client.set_model_version_tag(
            name=self.model_name,
            version=current_prod.version,
            key="rolled_back_by", value=rolled_back_by
        )
        self.client.set_model_version_tag(
            name=self.model_name,
            version=current_prod.version,
            key="rollback_timestamp", value=datetime.utcnow().isoformat()
        )
        
        print(f"⚡ EMERGENCY ROLLBACK COMPLETE!")
        print(f"   Rolled back from: v{current_prod.version}")
        print(f"   Restored: v{rollback_version}")
        print(f"   Reason: {reason}")
        print(f"   By: {rolled_back_by}")
```

```python
    print(f"   {version_b}: {avg_score_b:.3f}")
    print(f"   🏆 Winner: {winner}")
```

```python
# ============================================
# APPROVAL WORKFLOW SYSTEM FOR LLM CHANGES
# ============================================

from enum import Enum
from dataclasses import dataclass
from typing import List, Optional
from datetime import datetime
import uuid

class ChangeType(str, Enum):
    PATCH = "patch"     # Low risk
    MINOR = "minor"     # Medium risk
    MAJOR = "major"     # High risk

class ApprovalStatus(str, Enum):
    PENDING     = "pending"
    IN_REVIEW   = "in_review"
    APPROVED    = "approved"
    REJECTED    = "rejected"
    DEPLOYED    = "deployed"

@dataclass
class ChangeRequest:
    """
    Every change to model or prompt creates a ChangeRequest.
    This is the audit trail.
    """
    id: str
    
    # What changed
    change_type: ChangeType
    component: str      # "system_prompt" / "model_weights" / "hyperparams"
    from_version: str
    to_version: str
    description: str
    
    # Why it changed
    jira_ticket: str
    business_justification: str
    risk_assessment: str
    
    # Who is involved
    requested_by: str
    required_approvers: List[str]
    
    # Testing evidence
    test_results: dict
    eval_metrics: dict
    
    # Status tracking
    status: ApprovalStatus
    created_at: datetime
    approvals_received: List[dict]
    comments: List[dict]


class ApprovalWorkflowEngine:
    """
    Manages the complete approval lifecycle for
    all LLM model and prompt changes.
    """
    
    def __init__(self):
        self.db = get_database_connection()
        self.notification_service = NotificationService()
    
    # ─────────────────────────────────────────
    # CREATE A CHANGE REQUEST
    # ─────────────────────────────────────────
    def create_change_request(
        self,
        component: str,
        from_version: str,
        to_version: str,
        description: str,
        jira_ticket: str,
        business_justification: str,
        test_results: dict,

    ) -> ChangeRequest:
        """
        Start the approval process for a change.
        """
        
        # Automatically determine risk level
        change_type = self._assess_change_risk(
            component, from_version, to_version, test_results
        )
        
        # Get required approvers based on risk
        required_approvers = self._get_required_approvers(change_type)
        
        # Assess risk automatically
        risk_assessment = self._generate_risk_assessment(

        )
        
        # Create the request
        request = ChangeRequest(
            id=str(uuid.uuid4()),
            change_type=change_type,
            component=component,
            from_version=from_version,
            to_version=to_version,
            description=description,
            jira_ticket=jira_ticket,
            business_justification=business_justification,
            risk_assessment=risk_assessment,
            requested_by=requested_by,
            required_approvers=required_approvers,
            test_results=test_results,
            eval_metrics=test_results.get("metrics", {}),
            status=ApprovalStatus.PENDING,
            created_at=datetime.utcnow(),
            approvals_received=[],
            comments=[]
        )
        
        # Save to database
        self._save_request(request)
        
        # Notify approvers
        self._notify_approvers(request)
        
        print(f"✅ Change Request Created: {request.id}")
        print(f"   Component: {component}")
        print(f"   Risk Level: {change_type.value.upper()}")
        print(f"   Required approvers: {required_approvers}")
        
        return request
    
    # ─────────────────────────────────────────
    # AUTOMATED GATE CHECKS
    # Before human review, automated checks run
    # ─────────────────────────────────────────
    def run_automated_gates(self, request_id: str) -> dict:
        """
        Automated quality gates that must pass
        BEFORE human review begins.
        """
        
        request = self._load_request(request_id)
        gate_results = {}
        
        # GATE 1: Regression tests must pass
        gate_results["regression_tests"] = {
            "passed": request.test_results.get("regression_passed", False),
            "details": request.test_results.get("regression_details", {})
        }
        
        # GATE 2: Hallucination rate within threshold
        hallucination_rate = request.eval_metrics.get("hallucination_rate", 1.0)
        gate_results["hallucination_threshold"] = {
            "passed": hallucination_rate <= 0.05,
            "value": hallucination_rate,
            "threshold": 0.05
        }
        
        # GATE 3: Latency within acceptable range
        avg_latency = request.eval_metrics.get("avg_latency_ms", 9999)
        gate_results["latency_threshold"] = {
            "passed": avg_latency <= 2000,  # 2 second max
            "value": avg_latency,
            "threshold": 2000
        }
        
        # GATE 4: No security vulnerabilities detected
        gate_results["security_scan"] = self._run_security_scan(request)
        
        # GATE 5: No PII in prompt (for prompt changes)
        if "prompt" in request.component:
            gate_results["pii_scan"] = self._scan_prompt_for_pii(request)
        
        # GATE 6: Cost impact acceptable
        cost_impact = request.eval_metrics.get("cost_per_1k_tokens", 0)
        gate_results["cost_threshold"] = {
            "passed": cost_impact <= 0.01,  # Max $0.01 per 1k tokens
            "value": cost_impact,
            "threshold": 0.01
        }
        
        # Overall gate result
        all_passed = all(
            gate["passed"] for gate in gate_results.values()
        )
        
        if all_passed:
            self._update_request_status(
                request_id, ApprovalStatus.IN_REVIEW
            )
            self._notify_approvers_review_ready(request_id)
            print(f"✅ All automated gates PASSED. Sent to reviewers.")
        else:
            failed_gates = [
                gate_name for gate_name, result in gate_results.items()
                if not result["passed"]
            ]
            self._update_request_status(
                request_id, ApprovalStatus.REJECTED,
                reason=f"Automated gates failed: {failed_gates}"
            )
            print(f"❌ Automated gates FAILED: {failed_gates}")
            print("   Fix these issues and resubmit.")
        
        return gate_results
    
    # ─────────────────────────────────────────
    # HUMAN APPROVAL
    # ─────────────────────────────────────────
    def submit_approval(
        self,
        request_id: str,
        approver_email: str,
        decision: str,    # "approve" or "reject"
        comments: str,
        conditions: str = None  # Optional: "approve if X is fixed"
    ):
        """
        Record a human approval decision.
        """
        request = self._load_request(request_id)
        
        # Verify this person is a required approver
        if approver_email not in request.required_approvers:
            raise PermissionError(
                f"{approver_email} is not a required approver for {request_id}"
            )
        
        # Record the approval
        approval_record = {
            "approver": approver_email,
            "decision": decision,
            "comments": comments,
            "conditions": conditions,
            "timestamp": datetime.utcnow().isoformat(),
            "ip_address": get_request_ip(),  # Audit trail!
        }
        
        request.approvals_received.append(approval_record)
        self._save_request(request)
        
        if decision == "reject":
            self._update_request_status(
                request_id, ApprovalStatus.REJECTED,
                reason=f"Rejected by {approver_email}: {comments}"
            )
            print(f"❌ Change Request {request_id} REJECTED by {approver_email}")
            return
        
        # Check if ALL required approvers have approved
        approved_by = [
            a["approver"] for a in request.approvals_received 
            if a["decision"] == "approve"
        ]
        
        all_approved = all(
            req_approver in approved_by 
            for req_approver in request.required_approvers
        )
        
        if all_approved:
            self._update_request_status(
                request_id, ApprovalStatus.APPROVED
            )
            print(f"✅ Change Request {request_id} FULLY APPROVED!")
            print(f"   Ready to deploy.")
            
            # For MAJOR changes: auto-trigger canary deployment
            if request.change_type == ChangeType.MAJOR:
                self._trigger_canary_deployment(request_id)
        else:
            remaining = [
                r for r in request.required_approvers 
                if r not in approved_by
            ]
            print(f"⏳ Approval recorded. Still waiting for: {remaining}")
    
    # ─────────────────────────────────────────
    # RISK ASSESSMENT LOGIC
    # ─────────────────────────────────────────
    def _assess_change_risk(
        self, 
        component: str, 
        from_version: str, 
        to_version: str,
        test_results: dict
    ) -> ChangeType:
        """
        Automatically determine risk level of a change.
        """
        # Check if major version change
        from_major = int(from_version.split(".")[0].replace("v", ""))
        to_major = int(to_version.split(".")[0].replace("v", ""))
        
        if to_major > from_major:
            return ChangeType.MAJOR
        
        # Model weight changes are always at least MINOR
        if "model" in component.lower():
            return ChangeType.MINOR
        
        # Prompt changes with significant metric delta
        if "prompt" in component.lower():
            metric_delta = test_results.get("metric_delta", 0)
            if abs(metric_delta) > 0.05:  # >5% quality change
                return ChangeType.MINOR
        
        # Default: PATCH (low risk)
        return ChangeType.PATCH
    
    def _get_required_approvers(
        self, 
        change_type: ChangeType
    ) -> List[str]:
        """
        Return list of required approvers based on risk level.
        """
        approver_matrix = {
            ChangeType.PATCH: [
                "tech.lead@company.com"
            ],

                "tech.lead@company.com",
                "product.owner@company.com"
            ],
            ChangeType.MAJOR: [
                "tech.lead@company.com",
                "product.owner@company.com",
                "compliance@company.com",
                "cto@company.com"
            ]
        }
        return approver_matrix[change_type]
```

## What Is Change Tracking?

**Simple English:**
Change Tracking = **A complete, tamper-proof record of EVERY change made to your LLM system — who did it, what they changed, when, why, and what the result was.**

---

## 🌍 Analogy — Flight Black Box

```
✈️ AIRCRAFT BLACK BOX = Change Tracking System

The black box records:
  → Every pilot action (WHO + WHAT)
  → Exact timestamps (WHEN)
  → System state (CONTEXT)
  → Sensor readings (METRICS)

If the plane crashes:
  → Investigators can replay exactly what happened
  → Identify the root cause
  → Prevent future crashes

YOUR LLM CHANGE TRACKING IS THE SAME:

If your AI system "crashes" (bad outputs):
  → You replay every change made
  → Identify which change caused the problem
  → Rollback to before that change
  → Learn and prevent recurrence
```

```python
        entry_copy.pop("entry_hash")  # Exclude hash field itself

        self,
        component_name: str = None,
        from_date: str = None,
        to_date: str = None,
        changed_by: str = None,
        limit: int = 50
    ) -> list:
        """
        Query change history with filters.
        Essential for incident investigation.
        """
        query = "SELECT * FROM change_logs WHERE 1=1"
        params = []
        
        if component_name:
            query += " AND component_name = %s"
            params.append(component_name)
        
        if from_date:
            query += " AND timestamp >= %s"
            params.append(from_date)
        
        if to_date:
            query += " AND timestamp <= %s"
            params.append(to_date)
        
        if changed_by:
            query += " AND initiated_by = %s"
            params.append(changed_by)
        
        query += f" ORDER BY timestamp DESC LIMIT {limit}"
        
        return self.db.execute(query, params).fetchall()

    ) -> dict:
        """

        Used to identify root cause.

            SELECT 
                change_id,
                timestamp,
                component_type,
                component_name,
                from_version,
                to_version,
                change_diff,
                initiated_by,
                eval_metrics_before,
                eval_metrics_after
            FROM change_logs
            WHERE timestamp >= NOW() - INTERVAL '%s HOURS'
              AND timestamp <= %s
            ORDER BY timestamp DESC
        """, (hours_before, incident_start_time)).fetchall()
        
        # Find changes where metrics got WORSE
        suspicious_changes = []
        
        for change in changes:
            metrics_before = json.loads(change["eval_metrics_before"])
            metrics_after = json.loads(change["eval_metrics_after"])
            
            # Check if any key metric degraded
            for metric_name, before_value in metrics_before.items():
                after_value = metrics_after.get(metric_name, before_value)
                
                # If metric degraded by > 10%, flag it
                if after_value < before_value * 0.90:
                    suspicious_changes.append({
                        "change_id": change["change_id"],
                        "timestamp": change["timestamp"],
                        "component": change["component_name"],
                        "from_version": change["from_version"],
                        "to_version": change["to_version"],
                        "degraded_metric": metric_name,
                        "before": before_value,
                        "after": after_value,
                        "degradation": f"{((before_value - after_value) / before_value * 100):.1f}%"
                    })
        
        print(f"\n🔍 INCIDENT INVESTIGATION REPORT")
        print(f"   Period: {hours_before}h before {incident_start_time}")
        print(f"   Total changes found: {len(changes)}")
        print(f"   Suspicious changes: {len(suspicious_changes)}")
        
        if suspicious_changes:
            print("\n⚠️ SUSPICIOUS CHANGES (metric degradation detected):")
            for sc in suspicious_changes:
                print(f"""
    Change: {sc['change_id']}
    Time: {sc['timestamp']}
    Component: {sc['component']}
    Version: {sc['from_version']} → {sc['to_version']}
    Degraded: {sc['degraded_metric']} 
              ({sc['before']:.3f} → {sc['after']:.3f}, {sc['degradation']} worse)
                """)
        
        return {
            "all_changes": changes,
            "suspicious_changes": suspicious_changes,
            "recommendation": f"Investigate {suspicious_changes[0]['change_id']}" 
                             if suspicious_changes else "No obvious cause found"
        }
```

### Q: "How do you implement model versioning in an LLM system?"

✅ **Strong Answer:**
> "I treat a model version as a complete, immutable package — not just the weights, but also the training data version, hyperparameters, evaluation metrics, base model reference, code commit hash, and all metadata. I use MLflow Model Registry as the central store, with four stages: Staging (just trained), Candidate (passed automated evaluation), Production (serving real users), and Archived (retired but preserved). Promotion between stages requires explicit documented approval. I use semantic versioning: major for base model changes, minor for new training data, patch for small adjustments. Every production deployment logs to our change tracker with before/after metrics, git commit hash, and rollback instructions."

---

### Q: "Why should prompts be version-controlled and how do you do it?"

✅ **Strong Answer:**
> "Prompts are code. A single word change in a system prompt can completely change model behavior in production — and without version control, you cannot trace what changed, when, or why. I treat prompts as YAML files in a Git repository with the same PR-based workflow as code: branch, test, review, approve, merge. Each YAML file contains the prompt content, version number, author, change reason, evaluation results, and deployment history. I use LangSmith Hub as the runtime prompt registry — pulling prompts dynamically means I can update a prompt without redeploying the application. I compare prompt versions using LangSmith's evaluation tools before promoting any change to production."

---

### Q: "How would you design an approval workflow for LLM changes?"

✅ **Strong Answer:**
> "I design a three-tier approval system based on risk level. For patch changes like minor wording, one technical reviewer suffices with automated test gate. For minor changes like new fine-tuning data, I require both a tech lead and product owner, plus staging deployment results. For major changes like a new base model, I require tech lead, product owner, compliance, and senior leadership — plus a canary deployment to 5% traffic first. Before any human review starts, automated gates must pass: regression tests, hallucination rate below 5%, latency under 2 seconds, security scan, and PII check. Every approval is recorded with the approver's identity, timestamp, comments, and conditions — creating a complete audit trail for compliance purposes."

# ⚠️ Common Beginner Mistakes

| Mistake | Why It's Wrong | Correct Approach |
|---------|---------------|-----------------|
| "Prompt is just a text field in code" | No history, no tracking, no review | Prompts in YAML files, Git versioned |
| Deleting old model versions | Can't rollback, breaks compliance | Archive, never delete |
| No before/after metrics logged | Can't measure improvement or regression | Always log eval before and after |
| Manual deployment without approval | One person can break production | PR + required reviewers + CI gates |
| Logging params but not data version | Experiment not reproducible | Log dataset version in every MLflow run |
| Using W&B only for visualization | Losing model registry functionality | Use MLflow for registry, W&B for viz |
| No rollback plan documented | Emergency rollback becomes chaos | Document rollback procedure on every deploy |

# 🧑‍💻 Engineer Mindset — Senior AI Engineer Checklist

```
🧠 Before Every Model/Prompt Change, Ask:

□ "Is this change in version control?"
   → Git branch + PR, not direct edit

□ "Can I reproduce this exact model?"
   → All params, data version, code hash logged in MLflow?

□ "What were the metrics BEFORE and AFTER?"
   → Both logged in the change tracker?

□ "Has this been reviewed and approved?"
   → PR merged? Required approvers checked?

□ "What do I do if this breaks production?"
   → Rollback plan documented BEFORE deploying?

□ "Can I trace any production issue to a change?"
   → Change tracker has complete audit trail?

□ "Are old versions preserved for compliance?"
   → MLflow Archive, never Delete?

□ "Does the whole team know what version is live?"
   → MLflow dashboard shows current production version?

□ "Can a non-engineer see what changed?"
   → CHANGELOG.md up to date?

□ "How long does rollback take?"
   → Should be < 5 minutes for any version
```

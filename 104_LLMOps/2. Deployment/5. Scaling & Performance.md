## 📌 SECTION 2: Horizontal Scaling

### 2.1 — Vertical vs Horizontal (From First Principles)

#### Real-Life Analogy:

> **Imagine a coffee shop getting more customers:**
>
> **Vertical Scaling (Scale Up):**
> Buy a BIGGER, FASTER espresso machine.
> One barista, one machine — but machine is now 10× faster.
> Problem: There's a physical limit. No machine can be infinitely fast.
> Also: If THIS machine breaks → zero coffee. 💀
>
> **Horizontal Scaling (Scale Out):**
> Add MORE baristas with MORE machines.
> 10 baristas, 10 machines → 10× throughput.
> One machine breaks? 9 still work. ✅
> Traffic doubles? Add 2 more. ✅
> Traffic drops? Remove some. ✅
>
> **Horizontal Scaling = Adding more baristas (servers)**

#### The Maths Behind It:

```
VERTICAL SCALING (One Big Server):
────────────────────────────────────
Server capacity:    50 req/s
Traffic demand:     200 req/s
Solution:           Upgrade to 4× bigger server (costs $$$)
Limit:              Physical hardware ceiling
Failure:            1 server fails = 100% outage

HORIZONTAL SCALING (Many Small Servers):
──────────────────────────────────────────
Each server:        50 req/s
Servers needed:     4 servers × 50 = 200 req/s ✅
Cost:               4 × small server < 1 × giant server
Limit:              Theoretically unlimited (add more)
Failure:            1 server fails = 75% capacity remains ✅
```

### 2.2 — Statelessness — The Foundation of Horizontal Scaling

#### Why This Is The Most Important Concept:

```
STATEFUL APP (Cannot Scale Horizontally):
───────────────────────────────────────────

User Ahmed starts conversation:
Request 1 → Server A stores: {ahmed: ["Hello", "My name is Ahmed"]}
Request 2 → Load balancer sends to Server B
Server B: "Who is Ahmed? I have no memory!" 
AI: "Hi! What's your name?" ← BROKEN! 😱

You CANNOT horizontally scale stateful apps.
Every user is "stuck" to one server.

STATELESS APP (Perfect for Horizontal Scaling):
─────────────────────────────────────────────────

State stored in SHARED EXTERNAL REDIS, not server memory.
Request 1 → Server A reads Redis: {ahmed: ["Hello"]}
Request 2 → Server B reads Redis: {ahmed: ["Hello", "My name is Ahmed"]}
Server B: "I know Ahmed! His name is Ahmed."
AI: "Hello Ahmed!" ← WORKS ✅

Now add 10 servers → ALL read same Redis → ALL know all users
Remove 9 servers → 1 server still reads same Redis → Still works

RULE: State lives in Redis. Servers are disposable.
```

```python
        "response": ai_response,
```

### 2.3 — Load Balancing Algorithms

```
HOW DOES TRAFFIC GET DISTRIBUTED ACROSS SERVERS?
──────────────────────────────────────────────────

ALGORITHM 1: Round Robin (Default, Simple)
────────────────────────────────────────────
Request 1  → Server A
Request 2  → Server B
Request 3  → Server C
Request 4  → Server A (back to start)
...

Problem for AI apps:
Request 1 = "Hi" (50ms, done quickly)
Request 2 = "Analyze this 500-page document" (60 seconds)
Server B is OVERLOADED while A and C are idle!


ALGORITHM 2: Least Connections (Better for AI!)
─────────────────────────────────────────────────
Always sends to server with FEWEST active connections.

Server A: 2 active requests
Server B: 8 active requests (slow AI request running)
Server C: 1 active request

New request → Goes to Server C (fewest connections!) ✅

This is the BEST algorithm for AI apps because:
AI requests vary wildly in processing time.
Least connections = naturally balances the load.


ALGORITHM 3: IP Hash (Session Stickiness)
──────────────────────────────────────────
Same user (IP) always goes to same server.

Good for: Legacy stateful apps (before Redis)
Bad for: Uneven distribution if some users are heavy
Avoid for new systems — use stateless + Redis instead


ALGORITHM 4: Weighted Round Robin
──────────────────────────────────
Some servers are stronger → Give them more traffic.

Server A (32GB GPU): weight=3 → Gets 3× more requests
Server B (16GB GPU): weight=1 → Gets 1× requests
Server C (16GB GPU): weight=1 → Gets 1× requests

Good for: Mixed hardware setups
```

### 2.5 — Auto-Scaling Logic

```python
# scaler.py
# Simple auto-scaler based on request queue depth

import asyncio
import redis.asyncio as aioredis
import docker
import time

class AutoScaler:
    """
    Monitors system load and scales API instances.
    
    Scale UP when:  Queue depth > threshold OR avg latency > threshold
    Scale DOWN when: Queue depth = 0 AND CPU usage < threshold
    """
    
    def __init__(self):
        self.docker_client = docker.from_env()
        self.redis = aioredis.from_url("redis://redis:6379")
        
        # Scaling config
        self.MIN_REPLICAS = 2        # Always at least 2
        self.MAX_REPLICAS = 10       # Never more than 10
        self.SCALE_UP_THRESHOLD = 50  # Scale up if queue > 50
        self.SCALE_DOWN_THRESHOLD = 5  # Scale down if queue < 5
        self.SCALE_COOLDOWN = 120     # Wait 2 min between scale events
        
        self.last_scale_time = 0
        self.current_replicas = 2
    
    async def monitor_and_scale(self):
        """Main monitoring loop"""
        
        while True:
            # Check system metrics
            queue_depth = await self.get_queue_depth()
            current_load = await self.get_system_load()
            active_replicas = self.get_active_replicas()
            
            print(f"📊 Queue: {queue_depth} | Load: {current_load:.1f}% | "
                  f"Replicas: {active_replicas}")
            
            # Check cooldown (don't scale too frequently)
            time_since_last_scale = time.time() - self.last_scale_time
            if time_since_last_scale < self.SCALE_COOLDOWN:
                await asyncio.sleep(10)
                continue
            
            # Scale UP decision
            if (queue_depth > self.SCALE_UP_THRESHOLD and
                    active_replicas < self.MAX_REPLICAS):
                
                new_replicas = min(active_replicas + 2, self.MAX_REPLICAS)
                await self.scale_to(new_replicas)
                print(f"⬆️  Scaled UP to {new_replicas} replicas")
            
            # Scale DOWN decision
            elif (queue_depth < self.SCALE_DOWN_THRESHOLD and
                    current_load < 30 and
                    active_replicas > self.MIN_REPLICAS):
                
                new_replicas = max(active_replicas - 1, self.MIN_REPLICAS)
                await self.scale_to(new_replicas)
                print(f"⬇️  Scaled DOWN to {new_replicas} replicas")
            
            await asyncio.sleep(10)  # Check every 10 seconds
    
    async def get_queue_depth(self) -> int:
        """How many requests are waiting in queue?"""
        depth = await self.redis.llen("request_queue")
        return depth
    
    async def get_system_load(self) -> float:
        """Average CPU load across all instances"""
        load_values = await self.redis.lrange("cpu_load_metrics", 0, -1)
        if not load_values:
            return 0.0
        loads = [float(v) for v in load_values]
        return sum(loads) / len(loads)
    
    def get_active_replicas(self) -> int:
        """Count running API containers"""
        containers = self.docker_client.containers.list(
            filters={"name": "api_", "status": "running"}
        )
        return len(containers)
    
    async def scale_to(self, target_replicas: int):
        """Scale to target number of replicas"""
        # In production: use docker service update or kubectl scale
        # This is simplified for illustration
        self.current_replicas = target_replicas
        self.last_scale_time = time.time()
        
        # Alert the team
        await self.redis.set(
            "scaling_event",
            f"Scaled to {target_replicas} at {time.time()}"
        )


# Run the auto-scaler
if __name__ == "__main__":
    scaler = AutoScaler()
    asyncio.run(scaler.monitor_and_scale())
```

```
WITHOUT CACHE:

WITH CACHE (95% hit rate):
Total API calls = 500 unique questions only
Cost = 500 × $0.01 = $5/day = $150/month 💰

LATENCY IMPROVEMENT:
```

### 3.2 — Types of Caching (From Simple to Advanced)

```
LAYER 1: Exact Match Cache (Simplest)
───────────────────────────────────────
"What are your hours?" → Cache key → Cache hit → Return cached answer

Works perfectly for IDENTICAL questions.
Fails for slight variations:
"What are your business hours?" ← Cache miss
"When are you open?" ← Different question → API call
Both have same answer → Wasted money

Good for: High-volume, exact repetition scenarios


LAYER 2: Semantic Cache (Smart, Uses Embeddings)
──────────────────────────────────────────────────
Convert question to embedding vector.
Find similar cached questions using vector similarity.
If similarity > threshold → return cached answer.

"What are your business hours?" → [0.2, 0.8, 0.1, ...]
"When are you open?"            → [0.21, 0.79, 0.11, ...]
Similarity: 0.97 → Same meaning → Return cached answer!

Good for: Variations of same question (most real-world cases)
Cost: Embedding API call (cheap) vs LLM call (expensive)


LAYER 3: Result Cache (For Heavy Processing)
──────────────────────────────────────────────
Cache results of expensive operations:
- PDF analysis
- Code review
- Document summarization

Key = hash(file_content + prompt)
If key exists → Return cached analysis
If not → Run analysis → Cache result

Good for: Processing same documents multiple times
```

### 3.3 — Complete Redis Caching Implementation

```python
# services/cache_service.py
import redis.asyncio as aioredis
import hashlib
import json
import time
import numpy as np
from typing import Optional, List
import os

class CacheService:
    """
    Multi-layer caching for AI responses.
    
    Layer 1: Exact match cache (Redis String)
    Layer 2: Semantic cache (Redis Vector Search)
    Layer 3: Expensive task cache (Redis Hash)
    """
    
    def __init__(self):
        self.redis = aioredis.from_url(
            os.getenv("REDIS_URL", "redis://localhost:6379"),
            decode_responses=True
        )
        
        # Cache configuration
        self.EXACT_CACHE_TTL = 3600          # 1 hour
        self.SEMANTIC_CACHE_TTL = 86400      # 24 hours
        self.HEAVY_TASK_CACHE_TTL = 604800   # 7 days
        self.SEMANTIC_SIMILARITY_THRESHOLD = 0.92  # 92% similar = cache hit
        
        # Statistics tracking
        self.stats_key = "cache:stats"
    
    
    # ═══════════════════════════════════════════════════════
    # LAYER 1: EXACT MATCH CACHE
    # ═══════════════════════════════════════════════════════
    
    def _make_exact_key(self, prompt: str, model: str,
                        temperature: float) -> str:
        """
        Create cache key from prompt + model + temperature.
        
        WHY INCLUDE TEMPERATURE?
        Same prompt at temp=0 (deterministic) vs temp=1 (random)
        gives different results!
        At temp=0: Always cache (deterministic)
        At temp>0: Don't cache (different each time)
        """
        # Only cache deterministic responses (temp=0)
        if temperature > 0.1:
            return None  # Signal: don't cache
        
        content = f"{model}:{prompt.strip().lower()}"
        return f"cache:exact:{hashlib.sha256(content.encode()).hexdigest()}"
    
    async def get_exact_cache(
        self,
        prompt: str,
        model: str,
        temperature: float = 0.0
    ) -> Optional[dict]:
        """Try exact match cache first."""
        
        key = self._make_exact_key(prompt, model, temperature)
        if not key:
            return None  # Temperature too high — don't cache
        
        cached = await self.redis.get(key)
        
        if cached:
            await self._record_hit("exact")
            result = json.loads(cached)
            result["cache_type"] = "exact"
            result["from_cache"] = True
            return result
        
        await self._record_miss()
        return None
    
    async def set_exact_cache(
        self,
        prompt: str,
        model: str,
        temperature: float,
        response: dict,
        ttl: int = None
    ):
        """Store response in exact cache."""
        
        key = self._make_exact_key(prompt, model, temperature)
        if not key:
            return  # Don't cache non-deterministic responses
        
        ttl = ttl or self.EXACT_CACHE_TTL
        
        cache_data = {
            **response,
            "cached_at": time.time(),
            "original_latency_ms": response.get("latency_ms", 0)
        }
        
        await self.redis.setex(key, ttl, json.dumps(cache_data))
    
    
    # ═══════════════════════════════════════════════════════
    # LAYER 2: SEMANTIC CACHE (Vector Similarity)
    # ═══════════════════════════════════════════════════════
    
    async def get_semantic_cache(
        self,
        prompt: str,
        prompt_embedding: List[float],
        threshold: float = None
    ) -> Optional[dict]:
        """
        Find semantically similar cached response.
        
        HOW IT WORKS:
        1. Convert prompt to embedding vector
        2. Scan cached embeddings for similar ones
        3. If similarity > threshold → return cached response
        
        This catches paraphrase duplicates:
        "What are your hours?" ≈ "When are you open?"
        """
        
        threshold = threshold or self.SEMANTIC_SIMILARITY_THRESHOLD
        
        # Get all semantic cache keys
        cache_keys = await self.redis.keys("cache:semantic:*")
        
        if not cache_keys:
            return None
        
        # Convert query embedding to numpy array
        query_vec = np.array(prompt_embedding)
        
        best_match = None
        best_similarity = 0.0
        
        for key in cache_keys:
            # Get cached item
            cached_json = await self.redis.get(key)
            if not cached_json:
                continue
            
            cached_item = json.loads(cached_json)
            cached_embedding = np.array(cached_item["embedding"])
            
            # Calculate cosine similarity
            similarity = self._cosine_similarity(query_vec, cached_embedding)
            
            if similarity > best_similarity:
                best_similarity = similarity
                best_match = cached_item
                best_match["similarity"] = similarity
        
        # Check if best match exceeds threshold
        if best_match and best_similarity >= threshold:
            await self._record_hit("semantic")
            
            return {
                **best_match["response"],
                "cache_type": "semantic",
                "from_cache": True,
                "similarity_score": best_similarity,
                "original_prompt": best_match["prompt"]
            }
        
        return None
    
    async def set_semantic_cache(
        self,
        prompt: str,
        embedding: List[float],
        response: dict,
        ttl: int = None
    ):
        """Store response with embedding for semantic search."""
        
        # Create unique key from embedding hash
        embedding_str = str(embedding[:10])  # First 10 dimensions
        key = f"cache:semantic:{hashlib.md5(embedding_str.encode()).hexdigest()}"
        
        ttl = ttl or self.SEMANTIC_CACHE_TTL
        
        cache_data = {
            "prompt": prompt,
            "embedding": embedding,
            "response": response,
            "cached_at": time.time()
        }
        
        await self.redis.setex(key, ttl, json.dumps(cache_data))
    
    def _cosine_similarity(
        self,
        vec1: np.ndarray,
        vec2: np.ndarray
    ) -> float:
        """
        Cosine similarity between two vectors.
        
        WHAT IS COSINE SIMILARITY?
        ───────────────────────────
        Measures the ANGLE between two vectors.
        Not their magnitude — just direction.
        
        Result range: -1 to 1
        1.0 = Identical direction (same meaning!)
        0.0 = Perpendicular (unrelated)
        -1.0 = Opposite (opposite meaning)
        
        For text: > 0.92 usually means same question
        """
        # Dot product of two vectors
        dot_product = np.dot(vec1, vec2)
        
        # Product of their magnitudes
        magnitude = np.linalg.norm(vec1) * np.linalg.norm(vec2)
        
        if magnitude == 0:
            return 0.0
        
        return float(dot_product / magnitude)
    
    
    # ═══════════════════════════════════════════════════════
    # LAYER 3: HEAVY TASK CACHE
    # ═══════════════════════════════════════════════════════
    
    def _make_task_key(
        self,
        task_type: str,
        content: str,
        prompt: str
    ) -> str:
        """
        Cache key for heavy tasks (PDF analysis, etc.)
        Based on content hash + prompt hash.
        
        Same document + same question = same answer always.
        """
        content_hash = hashlib.sha256(content.encode()).hexdigest()[:16]
        prompt_hash = hashlib.sha256(prompt.encode()).hexdigest()[:16]
        return f"cache:task:{task_type}:{content_hash}:{prompt_hash}"
    
    async def get_task_cache(
        self,
        task_type: str,
        content: str,
        prompt: str
    ) -> Optional[dict]:
        """Try to get cached result for heavy task."""
        
        key = self._make_task_key(task_type, content, prompt)
        cached = await self.redis.get(key)
        
        if cached:
            await self._record_hit("task")
            result = json.loads(cached)
            result["from_cache"] = True
            result["cache_type"] = "task"
            return result
        
        return None
    
    async def set_task_cache(
        self,
        task_type: str,
        content: str,
        prompt: str,
        result: dict,
        ttl: int = None
    ):
        """Store heavy task result in cache."""
        
        key = self._make_task_key(task_type, content, prompt)
        ttl = ttl or self.HEAVY_TASK_CACHE_TTL
        
        await self.redis.setex(key, ttl, json.dumps(result))
    
    
    # ═══════════════════════════════════════════════════════
    # CACHE STATISTICS & MONITORING
    # ═══════════════════════════════════════════════════════
    
    async def _record_hit(self, cache_type: str):
        """Track cache hit statistics"""
        pipe = self.redis.pipeline()
        pipe.hincrby(self.stats_key, "total_hits", 1)
        pipe.hincrby(self.stats_key, f"{cache_type}_hits", 1)
        await pipe.execute()
    
    async def _record_miss(self):
        """Track cache miss statistics"""
        await self.redis.hincrby(self.stats_key, "total_misses", 1)
    
    async def get_cache_stats(self) -> dict:
        """Get cache performance statistics"""
        
        stats = await self.redis.hgetall(self.stats_key)
        
        total_hits = int(stats.get("total_hits", 0))
        total_misses = int(stats.get("total_misses", 0))
        total_requests = total_hits + total_misses
        
        hit_rate = (total_hits / total_requests * 100) if total_requests > 0 else 0
        
        return {
            "total_requests": total_requests,
            "cache_hits": total_hits,
            "cache_misses": total_misses,
            "hit_rate_percent": round(hit_rate, 2),
            "exact_hits": int(stats.get("exact_hits", 0)),
            "semantic_hits": int(stats.get("semantic_hits", 0)),
            "task_hits": int(stats.get("task_hits", 0)),
            # Estimated cost savings
            "estimated_api_calls_saved": total_hits,
            "estimated_cost_saved_usd": round(total_hits * 0.005, 2)
        }
    
    async def clear_expired(self):
        """Clear expired cache entries (Redis does this automatically)"""
        # Redis TTL handles this automatically!
        # This is just for manual cleanup if needed
        pass
```

```python
from fastapi import FastAPI
from services.cache_service import CacheService
from services.llm_service import LLMService
from services.embedding_service import EmbeddingService

app = FastAPI()
cache = CacheService()
llm = LLMService()

@app.post("/chat")
async def chat(request: ChatRequest):
    """
    3-layer cache lookup before hitting expensive LLM.
    
    Cache lookup order (fastest to slowest):
    1. Exact match (< 1ms)
    2. Semantic match (< 10ms)
    3. LLM API (3,000ms)
    """
    
    start_time = time.time()
    prompt = request.message
    
    # ──────────────────────────────────────────
    # LAYER 1: Exact Cache (< 1ms)
    # ──────────────────────────────────────────
    cached = await cache.get_exact_cache(
        prompt=prompt,
        model=request.model,
        temperature=request.temperature
    )
    
    if cached:
        return {
            **cached,
            "latency_ms": int((time.time() - start_time) * 1000),
            "cost_saved": True
        }
    
    # ──────────────────────────────────────────
    # LAYER 2: Semantic Cache (< 10ms)
    # Only for questions (not commands or creative tasks)
    # ──────────────────────────────────────────
    if is_question(prompt):  # Simple heuristic
        
        embedding = await embed.embed(prompt)
        
        cached = await cache.get_semantic_cache(
            prompt=prompt,
            prompt_embedding=embedding
        )
        
        if cached:
            return {
                **cached,
                "latency_ms": int((time.time() - start_time) * 1000),
                "note": f"Answered similar question (similarity: {cached['similarity_score']:.2f})"
            }
    
    # ──────────────────────────────────────────
    # LAYER 3: Call LLM (3,000ms)
    # ──────────────────────────────────────────
    response = await llm.chat(
        message=prompt,
        model=request.model,
        temperature=request.temperature
    )
    
    latency = int((time.time() - start_time) * 1000)
    result = {**response, "latency_ms": latency, "from_cache": False}
    
    # Store in cache for future requests
    await cache.set_exact_cache(
        prompt=prompt,
        model=request.model,
        temperature=request.temperature,
        response=result
    )
    
    if is_question(prompt) and 'embedding' in locals():
        await cache.set_semantic_cache(
            prompt=prompt,
            embedding=embedding,
            response=result
        )
    
    return result


def is_question(text: str) -> bool:
    """Simple heuristic: is this a question worth caching?"""
    question_words = ["what", "how", "when", "where", "why", "who", "is", "are", "can", "do"]
    text_lower = text.lower().strip()
    return (text_lower.endswith("?") or
            any(text_lower.startswith(w) for w in question_words))
```

### 4.1 — Why Queues? The Traffic Spike Problem

#### Real-Life Analogy First:

> **Think of a hospital emergency room:**
>
> **Without a queue system (naive):**
> 10 patients arrive at once.
> Hospital has 3 doctors.
> 7 patients are told: "We can't help you now."
> → They leave (requests dropped! 💀)
>
> **With a queue system (smart):**
> 10 patients arrive at once.
> All 10 register and GET A NUMBER.
> "Your wait time is ~45 minutes."
> 3 doctors work through the queue steadily.
> ALL patients eventually get helped.
> → Nobody turned away. ✅
>
> **Message Queue = Hospital waiting room for your AI requests**

```
WITHOUT QUEUE (Naive):
────────────────────────
Normal traffic:    10 req/s → Server handles fine ✅
Traffic spike:     100 req/s → Server overwhelmed
                              → Requests DROPPED ❌
                              → Users get errors
                              → 9 out of 10 users angry

WITH QUEUE (Smart):
────────────────────
Normal traffic:    10 req/s → Queue → Server (queue stays empty)
Traffic spike:     100 req/s → Queue absorbs 90 extra
                               → Server still processes 10/s
                               → Users get "Your request is queued"
                               → Queue drains over time
                               → ALL users eventually get response ✅
                               → Nobody dropped
```

### 4.3 — Redis Queue Implementation

```python
# ═══════════════════════════════════════════════
# REDIS-BASED TASK QUEUE (Simple & Fast)
# ═══════════════════════════════════════════════

# services/redis_queue.py
import redis.asyncio as aioredis
import json
import time
import uuid
from enum import Enum
from dataclasses import dataclass, asdict
from typing import Optional

class Priority(int, Enum):
    LOW = 1
    NORMAL = 5
    HIGH = 10
    CRITICAL = 20

@dataclass
class AITask:
    """A task in the AI processing queue"""
    task_id: str
    user_id: str
    task_type: str          # "chat", "analyze", "embed", etc.
    payload: dict           # The actual data
    priority: int
    created_at: float
    max_retries: int = 3
    retry_count: int = 0
    timeout_seconds: int = 120

class RedisQueue:
    """
    Priority queue for AI tasks using Redis Sorted Sets.
    
    SORTED SET = Redis data structure
    Members: task_id
    Scores: priority × time (higher = processed first)
    
    This gives us priority queue behavior:
    CRITICAL tasks processed before NORMAL tasks.
    Within same priority: FIFO (first in, first out).
    """
    
    QUEUE_KEY = "ai:task:queue"
    TASK_DATA_PREFIX = "ai:task:data:"
    PROCESSING_KEY = "ai:task:processing"
    RESULT_PREFIX = "ai:task:result:"
    DEAD_LETTER_KEY = "ai:task:failed"
    
    def __init__(self, redis_url: str = "redis://localhost:6379"):
        self.redis = aioredis.from_url(redis_url, decode_responses=True)
    
    async def enqueue(
        self,
        user_id: str,
        task_type: str,
        payload: dict,
        priority: Priority = Priority.NORMAL,
        timeout: int = 120
    ) -> str:
        """
        Add task to queue. Returns task_id for status polling.
        
        SCORE CALCULATION:
        score = priority × 1000 - timestamp
        Higher priority = higher score = processed first.
        Same priority? Earlier timestamp = higher score = FIFO.
        """
        
        task_id = str(uuid.uuid4())
        
        task = AITask(
            task_id=task_id,
            user_id=user_id,
            task_type=task_type,
            payload=payload,
            priority=priority,
            created_at=time.time(),
            timeout_seconds=timeout
        )
        
        # Score: higher = higher priority
        # For same priority: earlier = higher score (FIFO)
        score = priority * 1_000_000 - time.time()
        
        pipe = self.redis.pipeline()
        
        # Store task data
        pipe.setex(
            f"{self.TASK_DATA_PREFIX}{task_id}",
            timeout + 300,  # Keep for timeout + 5 min
            json.dumps(asdict(task))
        )
        
        # Add to priority queue
        pipe.zadd(self.QUEUE_KEY, {task_id: score})
        
        # Set initial status
        pipe.setex(
            f"{self.RESULT_PREFIX}{task_id}",
            86400,  # 24 hour result retention
            json.dumps({
                "status": "queued",
                "position": 0,  # Will be updated
                "task_id": task_id,
                "created_at": task.created_at
            })
        )
        
        await pipe.execute()
        
        # Update queue position estimate
        await self._update_position(task_id)
        
        print(f"✅ Enqueued: {task_id} (priority={priority.name})")
        return task_id
    
    async def dequeue(self) -> Optional[AITask]:
        """
        Get highest priority task for processing.
        Uses atomic pop to prevent race conditions.
        Multiple workers can safely call this simultaneously!
        """
        
        # zpopmax = Get and REMOVE highest score item atomically
        # Atomic = No two workers get the same task!
        result = await self.redis.zpopmax(self.QUEUE_KEY, count=1)
        
        if not result:
            return None  # Queue is empty
        
        task_id, score = result[0]
        
        # Get full task data
        task_json = await self.redis.get(f"{self.TASK_DATA_PREFIX}{task_id}")
        if not task_json:
            return None  # Task data expired
        
        task = AITask(**json.loads(task_json))
        
        # Track as "processing" with timeout
        await self.redis.setex(
            f"{self.PROCESSING_KEY}:{task_id}",
            task.timeout_seconds,
            json.dumps({"started_at": time.time(), "worker": "worker_1"})
        )
        
        # Update status
        await self.update_status(task_id, "processing", {"started_at": time.time()})
        
        return task
    
    async def complete_task(self, task_id: str, result: dict):
        """Mark task as complete and store result."""
        
        pipe = self.redis.pipeline()
        
        # Store result
        pipe.setex(
            f"{self.RESULT_PREFIX}{task_id}",
            86400,  # Keep result for 24 hours
            json.dumps({
                "status": "complete",
                "result": result,
                "completed_at": time.time()
            })
        )
        
        # Remove from processing tracker
        pipe.delete(f"{self.PROCESSING_KEY}:{task_id}")
        
        # Delete task data (no longer needed)
        pipe.delete(f"{self.TASK_DATA_PREFIX}{task_id}")
        
        await pipe.execute()
    
    async def fail_task(self, task_id: str, error: str, task: AITask):
        """Handle task failure with retry logic."""
        
        if task.retry_count < task.max_retries:
            # Retry with delay (exponential backoff)
            task.retry_count += 1
            delay_seconds = 2 ** task.retry_count  # 2, 4, 8 seconds
            
            print(f"⚠️ Task {task_id} failed. Retry {task.retry_count}/{task.max_retries} "
                  f"in {delay_seconds}s")
            
            # Re-queue after delay
            await asyncio.sleep(delay_seconds)
            await self.redis.zadd(
                self.QUEUE_KEY,
                {task_id: Priority.NORMAL * 1_000_000 - time.time()}
            )
            
            # Update task data with incremented retry count
            await self.redis.setex(
                f"{self.TASK_DATA_PREFIX}{task_id}",
                task.timeout_seconds + 300,
                json.dumps(asdict(task))
            )
        
        else:
            # Move to dead letter queue (failed permanently)
            print(f"💀 Task {task_id} moved to dead letter queue after "
                  f"{task.max_retries} retries")
            
            dead_task = {
                "task_id": task_id,
                "task": asdict(task),
                "error": error,
                "failed_at": time.time()
            }
            
            await self.redis.lpush(
                self.DEAD_LETTER_KEY,
                json.dumps(dead_task)
            )
            
            await self.update_status(task_id, "failed", {"error": error})
    
    async def get_status(self, task_id: str) -> Optional[dict]:
        """Get current task status for polling."""
        
        result_json = await self.redis.get(f"{self.RESULT_PREFIX}{task_id}")
        if not result_json:
            return None
        
        status = json.loads(result_json)
        
        # Add queue position if still queued
        if status["status"] == "queued":
            position = await self.redis.zrank(self.QUEUE_KEY, task_id)
            queue_length = await self.redis.zcard(self.QUEUE_KEY)
            
            status["queue_position"] = position + 1 if position is not None else 0
            status["queue_length"] = queue_length
            status["estimated_wait_seconds"] = (
                (position + 1) * 5 if position is not None else 0
            )
        
        return status
    
    async def update_status(
        self,
        task_id: str,
        status: str,
        extra: dict = None
    ):
        """Update task status."""
        current = await self.get_status(task_id) or {}
        updated = {**current, "status": status, **(extra or {})}
        await self.redis.setex(
            f"{self.RESULT_PREFIX}{task_id}",
            86400,
            json.dumps(updated)
        )
    
    async def _update_position(self, task_id: str):
        """Update estimated queue position"""
        rank = await self.redis.zrank(self.QUEUE_KEY, task_id)
        if rank is not None:
            await self.update_status(
                task_id, "queued",
                {"queue_position": rank + 1}
            )
    
    async def get_queue_stats(self) -> dict:
        """Monitor queue health"""
        return {
            "queued": await self.redis.zcard(self.QUEUE_KEY),
            "processing": len(await self.redis.keys(
                f"{self.PROCESSING_KEY}:*"
            )),
            "failed": await self.redis.llen(self.DEAD_LETTER_KEY),
            "stats": {
                "timestamp": time.time()
            }
        }
```

```python
# worker.py
# Background worker that processes AI tasks from queue

import asyncio
from services.redis_queue import RedisQueue
from services.llm_service import LLMService
from services.cache_service import CacheService

class AIWorker:
    """
    Processes AI tasks from Redis queue.
    
    Architecture: Many workers can run in parallel.
    Each worker independently:
    1. Polls queue for tasks
    2. Processes the task (calls AI)
    3. Stores result
    4. Handles errors/retries
    """
    
    def __init__(self, worker_id: str = "worker_1"):
        self.worker_id = worker_id
        self.queue = RedisQueue()
        self.llm = LLMService()
        self.cache = CacheService()
        self.running = True
        self.tasks_processed = 0
    
    async def start(self):
        """Main worker loop"""
        print(f"🚀 Worker {self.worker_id} started")
        
        while self.running:
            try:
                # Try to get a task from the queue
                task = await self.queue.dequeue()
                
                if task is None:
                    # Queue is empty — wait before checking again
                    await asyncio.sleep(0.5)
                    continue
                
                print(f"📋 Worker {self.worker_id} processing: "
                      f"{task.task_id[:8]}... ({task.task_type})")
                
                # Process the task
                await self.process_task(task)
                self.tasks_processed += 1
            
            except Exception as e:
                print(f"❌ Worker error: {e}")
                await asyncio.sleep(1)
    
    async def process_task(self, task):
        """Route task to appropriate handler"""
        
        try:
            # Route based on task type
            if task.task_type == "chat":
                result = await self.handle_chat(task)
            
            elif task.task_type == "analyze_document":
                result = await self.handle_document_analysis(task)
            
            elif task.task_type == "batch_embed":
                result = await self.handle_batch_embed(task)
            
            elif task.task_type == "summarize":
                result = await self.handle_summarize(task)
            
            else:
                raise ValueError(f"Unknown task type: {task.task_type}")
            
            # Mark complete
            await self.queue.complete_task(task.task_id, result)
            
            print(f"✅ Completed: {task.task_id[:8]}...")
        
        except asyncio.TimeoutError:
            await self.queue.fail_task(
                task.task_id,
                "Task timed out",
                task
            )
        
        except Exception as e:
            await self.queue.fail_task(
                task.task_id,
                str(e),
                task
            )
    
    async def handle_chat(self, task) -> dict:
        """Process chat task"""
        
        payload = task.payload
        
        # Check cache first
        cached = await self.cache.get_exact_cache(
            prompt=payload["message"],
            model=payload.get("model", "gpt-4o-mini"),
            temperature=payload.get("temperature", 0.0)
        )
        
        if cached:
            return {**cached, "worker_id": self.worker_id}
        
        # Call LLM with timeout
        response = await asyncio.wait_for(
            self.llm.chat(
                message=payload["message"],
                model=payload.get("model", "gpt-4o-mini"),
                temperature=payload.get("temperature", 0.7)
            ),
            timeout=task.timeout_seconds
        )
        
        return {**response, "worker_id": self.worker_id}
    
    async def handle_document_analysis(self, task) -> dict:
        """Process document analysis task (can be slow)"""
        
        payload = task.payload
        document_text = payload["document"]
        prompt = payload["prompt"]
        
        # Check task cache
        cached = await self.cache.get_task_cache(
            task_type="analyze_document",
            content=document_text,
            prompt=prompt
        )
        
        if cached:
            return cached
        
        # Chunk and analyze
        chunks = self.chunk_document(document_text)
        
        # Analyze each chunk
        analyses = []
        for i, chunk in enumerate(chunks):
            await self.queue.update_status(
                task.task_id,
                "processing",
                {"progress": int((i / len(chunks)) * 100),
                 "current_chunk": i + 1,
                 "total_chunks": len(chunks)}
            )
            
            analysis = await self.llm.chat(
                message=f"{prompt}\n\nDocument section:\n{chunk}",
                model="gpt-4o-mini",
                temperature=0.0
            )
            analyses.append(analysis["text"])
        
        # Combine analyses
        combined = await self.llm.chat(
            message=f"Combine these analyses into one coherent summary:\n\n"
                   f"{chr(10).join(analyses)}",
            model="gpt-4o",
            temperature=0.0
        )
        
        result = {
            "analysis": combined["text"],
            "chunks_processed": len(chunks),
            "worker_id": self.worker_id
        }
        
        # Cache for future identical requests
        await self.cache.set_task_cache(
            task_type="analyze_document",
            content=document_text,
```

```python
# RabbitMQ for guaranteed message delivery
# pip install aio-pika

import aio_pika
import json
import asyncio

class RabbitMQQueue:
    """
    RabbitMQ provides:
    - Guaranteed delivery (messages survive server restart)
    - Complex routing (exchanges, bindings)
    - Dead letter queues (failed messages go here automatically)
    - Message acknowledgment (worker confirms processing before delete)
    
    KEY DIFFERENCE FROM REDIS:
    Redis: "Fire and forget" by default
    RabbitMQ: "I'll keep this message until you ACK it"
    
    If worker crashes BEFORE ack → Message goes back to queue
    → Task retried automatically
    → Guaranteed at-least-once delivery
    """
    
    RABBITMQ_URL = "amqp://user:password@rabbitmq:5672/"
    
    async def connect(self):
        self.connection = await aio_pika.connect_robust(
            self.RABBITMQ_URL,
            reconnect_interval=5
        )
        self.channel = await self.connection.channel()
        
        # Set QoS — worker only takes 1 message at a time
        # This enables fair dispatch: busy workers don't get more
        await self.channel.set_qos(prefetch_count=1)
        
        # Declare queues (creates if doesn't exist)
        self.ai_queue = await self.channel.declare_queue(
            "ai_tasks",
            durable=True,  # Survive RabbitMQ restart!
            arguments={
                "x-dead-letter-exchange": "ai_dead_letter",  # Failed → here
                "x-message-ttl": 3600000,  # Messages expire after 1 hour
                "x-max-priority": 10        # Enable priority queue
            }
        )
        
        # Dead letter queue for failed messages
        self.dead_letter_queue = await self.channel.declare_queue(
            "ai_tasks_failed",
            durable=True
        )
    
    async def publish(
        self,
        task: dict,
        priority: int = 5
    ) -> str:
        """
        Publish task to queue.
        
        KEY CONCEPTS:
        - delivery_mode=2 = Persistent (survives restart)
        - priority = Task priority (0-10)
        - correlation_id = For tracking/tracing
        """
        
        task_id = str(uuid.uuid4())
        task["task_id"] = task_id
        
        await self.channel.default_exchange.publish(
            aio_pika.Message(
                body=json.dumps(task).encode(),
                delivery_mode=aio_pika.DeliveryMode.PERSISTENT,  # Survives restart!
                priority=priority,
                correlation_id=task_id,
                content_type="application/json",
                expiration=str(3600 * 1000)  # 1 hour TTL in ms
            ),
            routing_key="ai_tasks"
        )
        
        return task_id
    
    async def consume(self, callback):
        """
        Start consuming messages.
        
        CRITICAL: We only ack (confirm) AFTER successful processing.
        If processing fails → NACK → Message goes back to queue.
        If worker crashes → Message goes back (no ack received).
        
        This is GUARANTEED DELIVERY.
        """
        
        async def on_message(message: aio_pika.IncomingMessage):
            async with message.process(ignore_processed=True):
                try:
                    task = json.loads(message.body)
                    
                    await callback(task)
                    
                    # Acknowledge: "I processed this successfully"
                    await message.ack()
                    print(f"✅ ACK: {task.get('task_id', 'unknown')}")
                
                except Exception as e:
                    print(f"❌ NACK: {e}")
                    
                    # Negative acknowledge: "I failed, put it back"
                    # requeue=False → goes to dead letter queue after max retries
                    await message.nack(requeue=False)
        
        await self.ai_queue.consume(on_message)
        print("📡 RabbitMQ consumer started, waiting for messages...")
        
        # Wait forever (consumer runs until stopped)
        await asyncio.Future()
```

```python
                    await consumer.commit()
                
                except Exception as e:
                    print(f"Consumer error: {e}")
                    # Don't commit → message will be reprocessed
        
        finally:
            await consumer.stop()
```

```python
# services/token_optimizer.py
import tiktoken
from typing import Optional

class TokenOptimizer:
    """
    Optimize token usage across all LLM calls.
    
    Strategies:
    1. Prompt compression
    2. Dynamic context trimming
    3. Output length control
    4. Model routing (cheap model for simple tasks)
    5. Token budget management
    """
    
    def __init__(self):
        # tiktoken = OpenAI's tokenizer library
        # Use it to COUNT tokens before sending!
        self.encoder_gpt4 = tiktoken.encoding_for_model("gpt-4o")
        self.encoder_gpt4_mini = tiktoken.encoding_for_model("gpt-4o-mini")
        
        # Pricing per 1000 tokens (input, output)
        self.pricing = {
            "gpt-4o":      {"input": 0.005,  "output": 0.015},
            "gpt-4o-mini": {"input": 0.00015, "output": 0.0006},
            "claude-3-5-sonnet": {"input": 0.003, "output": 0.015},
        }
    
    def count_tokens(self, text: str, model: str = "gpt-4o") -> int:
        """Count tokens BEFORE sending to API (avoid surprise bills!)"""
        encoder = self.encoder_gpt4
        return len(encoder.encode(text))
    
    def estimate_cost(
        self,
        input_tokens: int,
        output_tokens: int,
        model: str = "gpt-4o"
    ) -> float:
        """Estimate cost before making API call"""
        pricing = self.pricing.get(model, {"input": 0.005, "output": 0.015})
        return (
            input_tokens / 1000 * pricing["input"] +
            output_tokens / 1000 * pricing["output"]
        )
    
    def trim_conversation_history(
        self,
        messages: list[dict],
        max_tokens: int = 3000,
        preserve_last_n: int = 4
    ) -> list[dict]:
        """
        Trim conversation history to fit token budget.
        
        STRATEGY:
        1. Always keep system prompt (if present)
        2. Always keep last N messages (recent context)
        3. Remove oldest messages until under token limit
        4. Add summary of removed messages if possible
        
        WHY THIS MATTERS:
        Long conversation = many tokens = expensive + slower
        User: "What did we discuss first?"
        AI: "Sorry, I don't remember the beginning."
        
        Better: Summarize old context, keep recent details.
        """
        
        if not messages:
            return messages
        
        # Separate system prompt from conversation
        system_messages = [m for m in messages if m["role"] == "system"]
        conversation = [m for m in messages if m["role"] != "system"]
        
        # Always preserve last N messages
        recent = conversation[-preserve_last_n:] if len(conversation) > preserve_last_n else conversation
        older = conversation[:-preserve_last_n] if len(conversation) > preserve_last_n else []
        
        # Build result starting with system prompt
        result = system_messages.copy()
        
        # Count current tokens
        current_tokens = self.count_tokens(
            " ".join([m["content"] for m in result + recent])
        )
        
        if current_tokens <= max_tokens:
            # Everything fits — add older messages too (newest first)
            for msg in reversed(older):
                additional_tokens = self.count_tokens(msg["content"])
                if current_tokens + additional_tokens <= max_tokens:
                    result.insert(len(system_messages), msg)
                    current_tokens += additional_tokens
                else:
                    break
        
        # Add recent messages
        result.extend(recent)
        
        removed_count = len(older) - (len(result) - len(system_messages) - len(recent))
        if removed_count > 0:
            print(f"✂️ Trimmed {removed_count} old messages "
                  f"({current_tokens} tokens)")
        
        return result
    
    def compress_prompt(self, prompt: str) -> str:
        """
        Remove unnecessary words from prompts.
        
        EXAMPLES:
        Before: "I was just wondering if you could maybe help me 
                 understand what exactly LLMOps is?"
        After:  "What is LLMOps?"
        
        Before: "Can you please write me a Python function that 
                 takes as input a list of numbers and returns the 
                 sum of all the numbers in the list?"
        After:  "Python function: sum of list numbers"
        
        In practice: Use another LLM to compress prompts!
        """
        
        # Simple rule-based compression
        filler_phrases = [
            "I was just wondering if",
            "Could you please",
            "Can you help me",
            "I would like to",
            "I need you to",
            "Please help me",
            "I want to know",
            "Would you be able to",
        ]
        
        compressed = prompt
        for phrase in filler_phrases:
            compressed = compressed.replace(phrase, "")
            compressed = compressed.replace(phrase.lower(), "")
        
        # Clean up extra spaces
        compressed = " ".join(compressed.split())
        
        original_tokens = self.count_tokens(prompt)
        compressed_tokens = self.count_tokens(compressed)
        
        print(f"Compressed: {original_tokens} → {compressed_tokens} tokens "
              f"({int((1 - compressed_tokens/original_tokens)*100)}% reduction)")
        
        return compressed
    
    def route_to_optimal_model(
        self,
        prompt: str,
        task_type: str,
        required_quality: str = "standard"
    ) -> str:
        """
        Choose cheapest model that meets quality requirements.
        
        DECISION LOGIC:
        ─────────────────
        Simple task + standard quality → gpt-4o-mini ($0.00015/1K)
        Complex reasoning + high quality → gpt-4o ($0.005/1K)
        Cost difference: 33×
        
        For 1M input tokens:
        gpt-4o:      $5.00
        gpt-4o-mini: $0.15
        Savings: $4.85 (97% cheaper!)
        """
        
        simple_tasks = ["classify", "extract", "format", "translate",
                       "summarize_short", "yes_no_question"]
        
        complex_tasks = ["complex_reasoning", "code_generation",
                        "creative_writing", "multi_step_analysis"]
        
        prompt_tokens = self.count_tokens(prompt)
        
        # Short, simple tasks → cheap model
        if (task_type in simple_tasks or
                prompt_tokens < 200 or
                required_quality == "standard"):
            return "gpt-4o-mini"
        
        # Complex or long prompts → powerful model
        return "gpt-4o"
    
    def set_optimal_max_tokens(

    ) -> int:
        """

        DEFAULT: 2048 tokens = ~1,500 words

        → AI generates unnecessary padding
```

```python
# services/latency_optimizer.py
import asyncio
import time
from typing import AsyncIterator

class LatencyOptimizer:
    """
    Techniques to reduce perceived and actual latency.
    
    Actual latency: Time until first token arrives
    Perceived latency: How fast it FEELS to the user
    
    Key insight: Users accept slow responses if they SEE progress.
    ChatGPT feels fast because it streams tokens instantly.
    A 10-second response with streaming feels faster than
    a 5-second response that shows nothing until the end!
    """
    
    # ═══════════════════════════════════════════════
    # STRATEGY 1: STREAMING (Reduces Perceived Latency)
    # ═══════════════════════════════════════════════
    
    async def stream_with_progress(
        self,
        llm_client,
        messages: list,
        model: str = "gpt-4o-mini"
    ) -> AsyncIterator[dict]:
        """
        Stream tokens with timing metadata.
        
        STREAMING PSYCHOLOGY:
        ───────────────────────
        User sends message at T=0
        Without streaming: Spinner for 8 seconds → Full response at T=8
        With streaming: First word at T=0.8 → words keep coming
        
        User feels: "It's responding immediately!"
        Actual time: Same 8 seconds total
        Perceived time: Much faster!
        """
        
        start_time = time.time()
        first_token_time = None
        token_count = 0
        full_response = ""
        
        stream = await llm_client.chat.completions.create(
            model=model,
            messages=messages,
            stream=True,
            max_tokens=500
        )
        
        async for chunk in stream:
            token = chunk.choices[0].delta.content
            
            if token is not None:
                if first_token_time is None:
                    first_token_time = time.time()
                    ttft = (first_token_time - start_time) * 1000
                    print(f"⚡ Time to First Token: {ttft:.0f}ms")
                
                full_response += token
                token_count += 1
                
                yield {
                    "token": token,
                    "token_count": token_count,
                    "elapsed_ms": int((time.time() - start_time) * 1000)
                }
        
        total_time = (time.time() - start_time) * 1000
        tokens_per_second = token_count / (total_time / 1000)
        
        # Final metadata
        yield {
            "done": True,
            "total_tokens": token_count,
            "total_time_ms": int(total_time),
            "tokens_per_second": round(tokens_per_second, 1),
            "time_to_first_token_ms": int((first_token_time - start_time) * 1000) if first_token_time else 0
        }
    
    
    # ═══════════════════════════════════════════════
    # STRATEGY 2: SPECULATIVE DECODING
    # ═══════════════════════════════════════════════
    
    async def speculative_generation(
        self,
        fast_client,    # Small fast model (draft)
        quality_client, # Large quality model (verify)
        prompt: str,
        draft_model: str = "gpt-4o-mini",
        quality_model: str = "gpt-4o"
    ) -> str:
        """
        SPECULATIVE DECODING CONCEPT:
        ───────────────────────────────
        
        Problem: Large model is slow but accurate.
        Small model is fast but less accurate.
        
        Solution: "Draft and Verify" pattern
        1. Small model generates draft quickly (5 tokens at once)
        2. Large model VERIFIES all 5 tokens simultaneously
        3. Accept tokens where small model was right
        4. Regenerate from first wrong token
        
        Result: 2-3× speedup when small model is often right.
        
        This is used by EVERY major LLM provider internally!
        """
        
        # Generate draft with fast model
        draft_response = await fast_client.chat.completions.create(
            model=draft_model,
            messages=[{"role": "user", "content": prompt}],
            max_tokens=200,
            temperature=0.0  # Deterministic draft
        )
        
        draft_text = draft_response.choices[0].message.content
        
        # Ask quality model to review and improve if needed
        verify_prompt = f"""
User question: {prompt}

Draft answer: {draft_text}

Is this draft answer accurate and complete?
- If YES: Reply with exactly: "APPROVED: [draft_text]"
- If NO: Reply with: "IMPROVED: [your better answer]"
```

```javascript
          "X-Cache": "HIT",
          "X-Cache-Location": "Edge"
        }
      });
    }
    
    console.log("💸 Edge cache MISS — forwarding to origin");
    
    // Cache miss — call origin server
    const response = await fetch(request);
    const responseData = await response.json();
    
    // Cache successful responses for 1 hour
    if (response.status === 200) {
      const cacheResponse = new Response(

          ...responseData,
          cached_at_edge: new Date().toISOString(),
          served_from: "cloudflare-edge"
        }),
        {
          headers: {
            "Content-Type": "application/json",
            "Cache-Control": "public, max-age=3600",
            "X-Cache": "MISS"
          }
        }
      );
      
      // Store in edge cache
      await cache.put(cacheKey, cacheResponse.clone());
    }
    
    return response;
  }
};

async function createCacheKey(message) {
  // Create deterministic cache key from message
  const encoder = new TextEncoder();
  const data = encoder.encode(message.trim().toLowerCase());
  const hashBuffer = await crypto.subtle.digest("SHA-256", data);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  const hashHex = hashArray.map(b => b.toString(16).padStart(2, "0")).join("");
```

## 📌 SECTION 7: Failure Modes (Critical!)

### ⚠️ Failure 1: Cache Stampede (Thundering Herd)

```
SCENARIO:
──────────
10:00 AM: Popular answer cached (100 RPM hitting it)
11:00 AM: Cache TTL expires (all at same second!)
11:00 AM: 100 requests see "cache miss" SIMULTANEOUSLY
11:00 AM: 100 requests call OpenAI API simultaneously
Cost: 100 × $0.01 = $1.00 (should have been $0.01)
Server: Overwhelmed by sudden 100× load increase

THE THUNDERING HERD:
─────────────────────
Imagine 100 elephants (requests) all thundering
toward the same watering hole (API) at once!

FIX: Cache locking + jittered TTL
```

```python
# Fix: Cache Stampede Prevention

import asyncio
import random

class StampedeProofCache:
    
    def __init__(self, redis_client):
        self.redis = redis_client
        self.LOCK_TIMEOUT = 30  # Lock expires after 30 seconds
    
    async def get_or_compute(
        self,
        key: str,
        compute_fn,
        ttl: int = 3600
    ):
        """
        Thread-safe cache with stampede protection.
        
        PATTERN: Cache-aside with distributed lock
        1. Check cache
        2. On miss: acquire lock
        3. Check cache again (another worker may have filled it!)
        4. If still miss: compute and store
        5. Release lock
        """
        
        # Step 1: Check cache
        cached = await self.redis.get(key)
        if cached:
            return json.loads(cached)
        
        # Step 2: Acquire distributed lock
        lock_key = f"lock:{key}"
        lock_acquired = await self.redis.set(
            lock_key,
            "locked",
            nx=True,       # Only set if NOT exists (atomic!)
            ex=self.LOCK_TIMEOUT
        )
        
        if not lock_acquired:
            # Another worker is computing → Wait and retry
            for attempt in range(10):
                await asyncio.sleep(0.5 * (attempt + 1))  # Exponential backoff
                cached = await self.redis.get(key)
                if cached:
                    return json.loads(cached)
            
            # Timeout waiting for lock → Compute ourselves (fallback)
            return await compute_fn()
        
        try:
            # Step 3: Check cache AGAIN (double-check after lock)
            cached = await self.redis.get(key)
            if cached:
                return json.loads(cached)
            
            # Step 4: Actually compute the value
            result = await compute_fn()
            
            # Step 5: Store with JITTERED TTL
            # Jitter prevents all keys expiring at same time!
            jitter = random.randint(-300, 300)  # ±5 minutes
            actual_ttl = max(ttl + jitter, 60)   # Minimum 1 minute
            
            await self.redis.setex(key, actual_ttl, json.dumps(result))
            
            return result
        
        finally:
            # Always release lock!
            await self.redis.delete(lock_key)
```

### Q1: "How would you design a caching strategy for an AI chatbot with 1M daily users?"

**Strong Answer:**
> *"I'd use a three-layer approach. First, exact match cache in Redis with SHA-256 hash keys for identical queries — temperature=0 only, as random outputs shouldn't be cached. Second, semantic cache using embeddings and cosine similarity — catch paraphrases like 'What are your hours?' and 'When are you open?' with ~92% similarity threshold. Expected hit rate: 70-80%, reducing API costs by same percentage."*

### Q2: "When would you use Kafka vs Redis for a queue system?"

**Strong Answer:**
> *"Redis queues work perfectly for most AI task queues — they're simpler, faster, and sufficient for millions of tasks. I'd use Redis when I need simple FIFO or priority queuing with no replay needs. I'd choose Kafka when I need to log every AI interaction for audit compliance or analytics — Kafka's log retention means I can replay last 7 days of events for debugging or retraining. Also Kafka when multiple independent consumers need the same event stream: analytics service, monitoring service, and training data pipeline all consuming the same AI interactions in parallel. The operational complexity of Kafka is only justified at high scale or when replay/multi-consumer patterns are required."*

---

### Q3: "What is backpressure and why is it critical for AI systems?"

**Strong Answer:**
> *"Backpressure is deliberately rejecting requests when your system reaches capacity, rather than accepting them and degrading for everyone. Without it, a traffic spike fills your queue indefinitely — Redis runs out of memory, workers fall further behind, latency grows to hours, and users get no feedback. With backpressure, once queue depth exceeds threshold, new requests receive an immediate 503 with 'Retry-After' header and estimated wait time. This gives users actionable feedback, protects system health, and ensures queued requests complete in reasonable time. The key insight: it's better to reject 20% of requests clearly than to accept 100% and fail all of them slowly."*

---

### Q4: "How does horizontal scaling differ for AI apps vs regular web apps?"

**Strong Answer:**
> *"Three major differences. First, AI requests are 100-1000× slower than regular requests — 3-10 seconds vs 10-50ms — so horizontal scaling has more impact but requires longer timeouts and async handling everywhere. Second, AI apps have high per-request costs, so you can't just 'scale up' — you must combine horizontal scaling with caching and optimization, or you just pay more for the same waste. Third, the statelessness requirement is more challenging — conversation history, model state, and session data must all live in external Redis from day one, since any server might handle any request. The scaling strategy for AI is always: cache first, queue second, scale third."*

## 📌 SECTION 10: Circuit Breaker Pattern

```python
# circuit_breaker.py
# Essential for resilient AI systems

import time
from enum import Enum

class CircuitState(Enum):
    CLOSED = "closed"       # Normal operation
    OPEN = "open"           # Failing, reject all requests
    HALF_OPEN = "half_open" # Testing if service recovered

class CircuitBreaker:
    """
    Like an electrical circuit breaker:
    - CLOSED: Current flows normally (requests pass through)
    - OPEN: Circuit broken (requests rejected immediately)
    - HALF-OPEN: Testing (let one request through)
    
    WHY THIS MATTERS FOR AI:
    OpenAI/Anthropic have outages.
    Without circuit breaker: All requests timeout (30s each)
    100 users × 30s timeout = server overwhelmed
    
    With circuit breaker:
    After 5 failures → OPEN state
    New requests: Immediate 503 (< 1ms, not 30s timeout!)
    After 60 seconds → HALF-OPEN, test one request
    If success → CLOSED again
    
    SAVES: Server resources during outages
           Users get fast error vs slow timeout
           System recovers cleanly when service comes back
    """
    
    def __init__(
        self,
        failure_threshold: int = 5,
        recovery_timeout: int = 60,
        name: str = "service"
    ):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.name = name
        
        self.failure_count = 0
        self.last_failure_time = None
        self.state = CircuitState.CLOSED
    
    async def call(self, func, *args, **kwargs):
        """Execute function with circuit breaker protection"""
        
        # Check circuit state
        if self.state == CircuitState.OPEN:
            # Check if recovery timeout passed
            if time.time() - self.last_failure_time > self.recovery_timeout:
                self.state = CircuitState.HALF_OPEN
                print(f"🔄 Circuit {self.name}: HALF_OPEN — testing...")
            else:
                remaining = self.recovery_timeout - (time.time() - self.last_failure_time)
                raise Exception(
                    f"Circuit OPEN for {self.name}. "
                    f"Try again in {int(remaining)}s"
                )
        
        try:
            result = await func(*args, **kwargs)
            
            # Success! Reset failures
            if self.state == CircuitState.HALF_OPEN:
                self.state = CircuitState.CLOSED
                self.failure_count = 0
                print(f"✅ Circuit {self.name}: CLOSED — service recovered!")
            
            return result
        
        except Exception as e:
            self.failure_count += 1
            self.last_failure_time = time.time()
            
            if self.failure_count >= self.failure_threshold:
                self.state = CircuitState.OPEN
                print(f"🔴 Circuit {self.name}: OPEN — {self.failure_count} failures!")
            
            raise e

# Usage in LLM service
openai_circuit = CircuitBreaker(
    failure_threshold=5,
    recovery_timeout=60,
    name="OpenAI"
)

async def resilient_llm_call(prompt: str) -> str:
    try:
        return await openai_circuit.call(call_openai, prompt)
    except Exception as e:
        if "Circuit OPEN" in str(e):
            # Fallback to Ollama when OpenAI circuit is open
            return await call_ollama(prompt)
        raise
```

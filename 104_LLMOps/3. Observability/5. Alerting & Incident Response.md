## 📦 SECTION 1: What Is This?

### 🇬🇧 Simple English

| Term | Simple Meaning |
|---|---|
| **Alert** | An automatic notification that something needs attention |
| **Threshold** | A line you draw — if a number crosses it, fire the alert |
| **Incident** | A problem serious enough to disrupt users or business |
| **Incident Response** | The structured process of detecting, investigating, fixing, and learning from incidents |
| **On-call** | The person responsible for responding to alerts at any hour |
| **Escalation** | Automatically notifying more senior people if the first responder doesn't act |
| **Rollback** | Reverting your system to a previously working state |
| **Runbook** | Step-by-step instructions for how to respond to a specific alert |
| **SLO Breach** | When your system breaks the promise you made to users |
| **MTTD** | Mean Time To Detect — how long before you know something is wrong |
| **MTTR** | Mean Time To Recover — how long to fix it after you know |

---

### 🧠 The Alerting Equation

```
Effective Alerting = Right Signal + Right Person + Right Time + Right Context

Right Signal:
→ Alert fires on REAL problems, not noise
→ Does NOT fire when everything is fine
→ Catches problems BEFORE users notice

Right Person:
→ Goes to whoever can actually fix it
→ Not to everyone (alert fatigue)
→ Escalates if first person doesn't respond

Right Time:
→ Fires within MINUTES of the problem starting
→ Not hours later
→ Not days later when the monthly bill arrives

Right Context:
→ Alert contains ENOUGH INFO to start debugging
→ Links to traces, dashboards, runbooks
→ Shows what changed, not just what broke

Miss any ONE of these four:
→ Alert fatigue (too many wrong signals)
→ Alert ignored (wrong person)
→ Damage done (too slow)
→ Debugging starts from zero (no context)
```

### 🧱 Building Block 2: Alert Quality — Signal vs Noise

The #1 enemy of alerting is **alert fatigue:**

```
Alert Fatigue Spiral:
──────────────────────
Too many alerts fire
         ↓
On-call engineer starts ignoring them
         ↓
REAL alert fires
         ↓
Engineer assumes it's noise (again)
         ↓
Real incident goes unaddressed for hours
         ↓
Major outage or cost explosion
         ↓
Company loses money/trust

The target:
Every alert that fires = requires human action.
No alert fires for a false reason.

Alert Quality Metrics:
──────────────────────
Precision = (True alerts) / (Total alerts)
           Target: > 90%
           
Recall = (Caught incidents) / (All incidents)
         Target: > 95%

Alert Noise Ratio = (False alerts) / (Total alerts)
                   Target: < 10%

MTTD = Average time from incident start to alert firing
       Target: < 5 minutes for critical issues
```

### 🧱 Building Block 4: Static vs Dynamic Thresholds

```
Static Threshold (Simple):
─────────────────────────────
Alert if: p99_latency > 5000ms

Problem:
Monday 2am (low traffic):   p99 = 800ms  → No alert (fine)
Monday 9am (peak traffic):  p99 = 800ms  → No alert (fine)
Monday 9am (traffic spike): p99 = 4900ms → No alert (wrong!)

Static thresholds ignore CONTEXT.
"4900ms is fine at 2am but catastrophic at 9am"

Dynamic/Anomaly-Based Threshold:
──────────────────────────────────
Alert if: current_value > (baseline × multiplier)
         OR
Alert if: current_value > (rolling_avg + 2 × standard_deviation)

Monday 2am baseline:       p99 = 700ms
Monday 9am baseline:       p99 = 800ms
Monday 9am current:        p99 = 4900ms
9am baseline × 3:          800 × 3 = 2400ms
4900ms > 2400ms → ALERT ✅

Same logic for costs:
Tuesday baseline spend:    $145/hour
Tuesday current spend:     $890/hour
$890 > ($145 × 3 = $435) → ALERT ✅

Dynamic thresholds adapt to your normal patterns.
They are MUCH more accurate than fixed numbers.
```

## 🏛️ ALERT TYPE 1: Error Threshold Alerts

### What Are Error Threshold Alerts?

Error alerts fire when your LLM system is **returning failures** instead of successful responses.

```
Types of errors in LLM systems:

Category 1: LLM Provider Errors (External)
────────────────────────────────────────────
• HTTP 429 — Rate limit exceeded
• HTTP 500 — OpenAI/Anthropic server error
• HTTP 503 — Service unavailable (they're down)
• Timeout — Request took too long
• Connection refused — Can't reach provider

Category 2: Application Errors (Internal)
──────────────────────────────────────────
• Invalid prompt — Malformed request
• Context overflow — Too many tokens
• Tool execution failed — Database, API errors
• Parsing failed — Can't parse LLM output
• Validation failed — Output doesn't meet requirements

Category 3: Quality Errors (Semantic Failures)
───────────────────────────────────────────────
• Hallucination detected — Below groundedness threshold
• Relevance too low — Answer doesn't match question
• Guardrail block — Safety filter triggered
• Empty response — LLM returned nothing useful
• Refusal — LLM refused to answer

Each category needs different thresholds and responses.
```

---

### Error Rate Calculations

```
Error Rate = (Failed Requests / Total Requests) × 100%

But which errors count?
────────────────────────
Approach 1: Hard errors only
→ Only HTTP errors, timeouts, crashes
→ Misses quality failures (silent errors)

Approach 2: All failure types
→ Hard errors + quality failures + validation failures
→ More comprehensive but noisier

Best practice: Track separately and alert on each:

hard_error_rate = http_errors / total × 100
quality_error_rate = (hallucinations + low_relevance) / evaluated × 100
validation_error_rate = validation_failures / total × 100

Thresholds:
hard_error_rate > 1%      → P1 alert (serious)
quality_error_rate > 10%  → P2 alert (investigate)
validation_error_rate > 5%→ P2 alert (investigate)
```

### Error Alert Implementation

```python
import time
import asyncio
from collections import deque, defaultdict
from dataclasses import dataclass, field
from typing import Optional, Callable
from enum import Enum

class AlertSeverity(Enum):
    P0_CRITICAL = "p0_critical"
    P1_HIGH     = "p1_high"
    P2_MEDIUM   = "p2_medium"
    P3_LOW      = "p3_low"

class AlertState(Enum):
    FIRING       = "firing"
    RESOLVED     = "resolved"
    ACKNOWLEDGED = "acknowledged"
    SILENCED     = "silenced"

@dataclass
class Alert:
    """A fired alert with all context needed for response"""
    
    # Identity
    alert_id: str
    alert_name: str
    severity: AlertSeverity
    
    # State
    state: AlertState
    fired_at: float
    resolved_at: Optional[float] = None
    acknowledged_at: Optional[float] = None
    acknowledged_by: Optional[str] = None
    
    # Context (CRITICAL — this is what engineers use to debug)
    metric_name: str = ""
    current_value: float = 0.0
    threshold_value: float = 0.0
    unit: str = ""
    
    # Links
    trace_link: str = ""       # Link to relevant trace
    dashboard_link: str = ""   # Link to metrics dashboard
    runbook_link: str = ""     # Link to how-to-fix guide
    
    # Message
    summary: str = ""
    details: str = ""
    
    # Impact
    affected_feature: str = ""
    estimated_user_impact: str = ""
    estimated_cost_impact: str = ""

@dataclass
class ErrorRateTracker:
    """
    Track error rates across rolling time windows.
    Fire alerts when thresholds are crossed.
    """
    
    window_seconds: int = 300  # 5-minute rolling window
    requests: deque = field(default_factory=deque)
    errors: deque = field(default_factory=deque)
    error_by_type: dict = field(
        default_factory=lambda: defaultdict(deque)
    )
    
    # Alert thresholds
    thresholds: dict = field(default_factory=lambda: {
        "p0_total_error_rate": 10.0,  # % — everything is failing
        "p1_total_error_rate": 5.0,   # % — serious degradation
        "p2_total_error_rate": 2.0,   # % — investigate needed
        "p1_rate_limit_rate": 3.0,    # % — OpenAI rate limiting us
        "p1_timeout_rate": 2.0,       # % — responses timing out
        "p0_zero_success": 100.0,     # % error = complete outage
    })
    
    def record_request(
        self,
        success: bool,
        error_type: Optional[str] = None,
        trace_id: str = ""
    ):
        """Record one request result"""
        now = time.time()
        
        self.requests.append({
            "timestamp": now,
            "success": success,
            "trace_id": trace_id
        })
        
        if not success and error_type:
            self.errors.append({
                "timestamp": now,
                "error_type": error_type,
                "trace_id": trace_id
            })
            self.error_by_type[error_type].append({
                "timestamp": now,
                "trace_id": trace_id
            })
        
        self._clean_old_data(now)
    
    def _clean_old_data(self, now: float):
        """Remove data outside the rolling window"""
        cutoff = now - self.window_seconds
        
        while self.requests and self.requests[0]["timestamp"] < cutoff:
            self.requests.popleft()
        while self.errors and self.errors[0]["timestamp"] < cutoff:
            self.errors.popleft()
        
        for error_type in list(self.error_by_type.keys()):
            while (self.error_by_type[error_type] and
                   self.error_by_type[error_type][0]["timestamp"] < cutoff):
                self.error_by_type[error_type].popleft()
    
    def get_error_rates(self) -> dict:
        """Calculate current error rates"""
        total = len(self.requests)
        errors = len(self.errors)
        
        if total == 0:
            return {"status": "no_data"}
        
        total_error_rate = (errors / total) * 100
        
        # Per-type error rates
        per_type = {}
        for error_type, type_errors in self.error_by_type.items():
            per_type[error_type] = {
                "count": len(type_errors),
                "rate_pct": (len(type_errors) / total) * 100
            }
        
        return {
            "window_seconds": self.window_seconds,
            "total_requests": total,
            "total_errors": errors,
            "total_error_rate_pct": round(total_error_rate, 3),
            "success_rate_pct": round(100 - total_error_rate, 3),
            "by_error_type": per_type
        }
    
    def check_alert_conditions(self) -> list[Alert]:
        """Check all error thresholds and return any alerts"""
        
        rates = self.get_error_rates()
        if rates.get("status") == "no_data":
            return []
        
        alerts = []
        error_rate = rates["total_error_rate_pct"]
        
        # Check P0: Complete outage
        if error_rate >= 90:
            alerts.append(Alert(
                alert_id=f"err_p0_{int(time.time())}",
                alert_name="COMPLETE_OUTAGE",
                severity=AlertSeverity.P0_CRITICAL,
                state=AlertState.FIRING,
                fired_at=time.time(),
                metric_name="total_error_rate",
                current_value=error_rate,
                threshold_value=90,
                unit="percent",
                summary=(
                    f"🚨 COMPLETE OUTAGE: {error_rate:.1f}% of requests failing"
                ),
                details=(
                    f"Total requests: {rates['total_requests']}\n"
                    f"Total errors: {rates['total_errors']}\n"
                    f"Error breakdown: {rates['by_error_type']}"
                ),
                runbook_link="https://wiki.company.com/runbooks/llm-outage",
                estimated_user_impact="ALL users affected",
                estimated_cost_impact=(
                    "Revenue loss accumulating per minute"
                )
            ))
        
        # Check P1: High error rate
        elif error_rate >= self.thresholds["p1_total_error_rate"]:
            alerts.append(Alert(
                alert_id=f"err_p1_{int(time.time())}",
                alert_name="HIGH_ERROR_RATE",
                severity=AlertSeverity.P1_HIGH,
                state=AlertState.FIRING,
                fired_at=time.time(),
                metric_name="total_error_rate",
                current_value=error_rate,
                threshold_value=self.thresholds["p1_total_error_rate"],
                unit="percent",
                summary=(
                    f"⚠️ HIGH ERROR RATE: {error_rate:.1f}% of requests failing "
                    f"(threshold: {self.thresholds['p1_total_error_rate']}%)"
                ),
                details=(
                    f"Total requests: {rates['total_requests']}\n"
                    f"Errors: {rates['total_errors']}\n"
                    f"Top errors: "
                    f"{sorted(rates['by_error_type'].items(), "
                    f"key=lambda x: x[1]['count'], reverse=True)[:3]}"
                ),
                runbook_link="https://wiki.company.com/runbooks/high-error-rate"
            ))
        
        # Check specific error types (rate limit = we need to optimize)
        rate_limit_rate = rates["by_error_type"].get(
            "RateLimitError", {}
        ).get("rate_pct", 0)
        
        if rate_limit_rate >= self.thresholds["p1_rate_limit_rate"]:
            alerts.append(Alert(
                alert_id=f"ratelimit_p1_{int(time.time())}",
                alert_name="RATE_LIMIT_HIGH",
                severity=AlertSeverity.P1_HIGH,
                state=AlertState.FIRING,
                fired_at=time.time(),
                metric_name="rate_limit_error_rate",
                current_value=rate_limit_rate,
                threshold_value=self.thresholds["p1_rate_limit_rate"],
                unit="percent",
                summary=(
                    f"🔴 RATE LIMIT ALERT: {rate_limit_rate:.1f}% of requests "
                    f"hitting OpenAI rate limits"
                ),
                details=(
                    "Approaching or exceeding OpenAI token-per-minute limits.\n"
                    "Actions:\n"
                    "1. Implement request queuing\n"
                    "2. Reduce token usage per request\n"
                    "3. Consider model downgrade for some requests\n"
                    "4. Check for runaway loops consuming excess tokens"
                ),
                runbook_link=(
                    "https://wiki.company.com/runbooks/rate-limit-exceeded"
                )
            ))
        
        return alerts
```

## 🏛️ ALERT TYPE 2: Cost Spike Alerts

### The Unique Cost Problem in LLM Systems

```
Why LLM cost alerting is fundamentally different:

Traditional API cost model:
→ Cost = fixed monthly fee or usage tiers
→ Predictable, hard to accidentally spend 10x overnight
→ A bug rarely causes 10x cost increase

LLM cost model:
→ Cost = (tokens × price) PER REQUEST
→ Completely variable — can spike instantly
→ A single line of code change (adding to system prompt)
   can 10x your costs in seconds

Real cost spike scenarios:
──────────────────────────
Scenario A: Prompt expansion bug
  Prompt v1: 400 tokens → $0.04/request
  Prompt v2: 4,000 tokens → $0.40/request (10x!)
  10,000 requests/hour × $0.40 = $4,000/hour
  
Scenario B: Infinite loop in agent
  Normal agent: 3 LLM calls per task → $0.15
  Looping agent: 300 LLM calls per task → $15.00 (100x!)
  
Scenario C: Wrong model for feature
  GPT-3.5 Turbo: $0.001/1k tokens
  GPT-4 Turbo: $0.030/1k tokens (30x more expensive)
  Feature accidentally switched to GPT-4: 30x cost spike
  
Scenario D: Traffic spike without circuit breaker
  Normal: 100 requests/minute
  Viral moment: 10,000 requests/minute
  No throttling = 100x normal cost
```

### Cost Spike Detection — Static vs Dynamic

```python
import time
import statistics
from collections import deque
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class CostRecord:
    """One cost measurement point"""
    timestamp: float
    cost_usd: float
    tokens_used: int
    model: str
    feature: str
    trace_id: str

class CostSpikeDetector:
    """
    Detect cost anomalies using both static and dynamic methods.
    Static: crosses absolute limits
    Dynamic: deviates from historical baseline
    """
    
    def __init__(
        self,
        alert_callback: callable,
        
        # Static thresholds (absolute limits)
        per_request_max_usd: float = 0.50,      # $0.50 per single request
        per_minute_max_usd: float = 50.0,        # $50/minute
        per_hour_max_usd: float = 500.0,         # $500/hour
        daily_budget_usd: float = 2000.0,         # $2000/day total
        
        # Dynamic thresholds (anomaly detection)
        baseline_window_hours: int = 24,          # Learn from last 24 hours
        spike_multiplier: float = 3.0,            # Alert if 3x baseline
        anomaly_z_score: float = 3.0,             # Alert if 3 std devs above mean
    ):
        self.alert_callback = alert_callback
        
        # Static limits
        self.per_request_max = per_request_max_usd
        self.per_minute_max = per_minute_max_usd
        self.per_hour_max = per_hour_max_usd
        self.daily_budget = daily_budget_usd
        
        # Dynamic config
        self.baseline_window = baseline_window_hours * 3600
        self.spike_multiplier = spike_multiplier
        self.anomaly_z_score = anomaly_z_score
        
        # Data stores
        self.cost_records: deque = deque()
        self.daily_cost_accumulator: float = 0.0
        self.daily_reset_time: float = time.time()
        
        # Alert deduplication (don't spam the same alert)
        self.active_alerts: dict = {}
        self.alert_cooldown_seconds: int = 300  # 5-minute cooldown
    
    def record_cost(
        self,
        cost_usd: float,
        tokens_used: int,
        model: str,
        feature: str,
        trace_id: str
    ) -> list[Alert]:
        """Record a cost and check all thresholds"""
        
        now = time.time()
        
        # Reset daily accumulator if new day
        if now - self.daily_reset_time > 86400:  # 24 hours
            self.daily_cost_accumulator = 0.0
            self.daily_reset_time = now
        
        record = CostRecord(
            timestamp=now,
            cost_usd=cost_usd,
            tokens_used=tokens_used,
            model=model,
            feature=feature,
            trace_id=trace_id
        )
        
        self.cost_records.append(record)
        self.daily_cost_accumulator += cost_usd
        self._clean_old_records(now)
        
        # Check all alert conditions
        return self._check_all_conditions(record, now)
    
    def _clean_old_records(self, now: float):
        """Keep only records within baseline window"""
        cutoff = now - self.baseline_window
        while self.cost_records and self.cost_records[0].timestamp < cutoff:
            self.cost_records.popleft()
    
    def _get_rolling_cost(self, window_seconds: int, now: float) -> float:
        """Sum costs in a rolling time window"""
        cutoff = now - window_seconds
        return sum(
            r.cost_usd for r in self.cost_records
            if r.timestamp >= cutoff
        )
    
    def _get_baseline_stats(
        self,
        window_seconds: int,
        now: float,
        reference_hours_back: int = 24
    ) -> dict:
        """
        Calculate baseline statistics from historical data.
        Compare current window against same window 24 hours ago.
        """
        
        # Current window
        current_cost = self._get_rolling_cost(window_seconds, now)
        
        # Historical reference: same window size, shifted 24h back
        reference_end = now - (reference_hours_back * 3600)
        reference_start = reference_end - window_seconds
        
        historical_records = [
            r for r in self.cost_records
            if reference_start <= r.timestamp <= reference_end
        ]
        historical_cost = sum(r.cost_usd for r in historical_records)
        
        # Hourly cost samples for std dev calculation
        hourly_costs = []
        check_point = now - self.baseline_window
        while check_point < now - window_seconds:
            window_cost = sum(
                r.cost_usd for r in self.cost_records
                if check_point <= r.timestamp < check_point + window_seconds
            )
            if window_cost > 0:
                hourly_costs.append(window_cost)
            check_point += window_seconds
        
        mean_cost = statistics.mean(hourly_costs) if hourly_costs else 0
        std_cost = statistics.stdev(hourly_costs) if len(hourly_costs) > 1 else 0
        
        return {
            "current": current_cost,
            "historical_same_window": historical_cost,
            "mean_window_cost": mean_cost,
            "std_window_cost": std_cost,
            "multiplier_vs_historical": (
                current_cost / historical_cost
                if historical_cost > 0 else None
            ),
            "z_score": (
                (current_cost - mean_cost) / std_cost
                if std_cost > 0 else None
            )
        }
    
    def _should_fire_alert(self, alert_key: str) -> bool:
        """Deduplication: don't fire same alert within cooldown period"""
        if alert_key not in self.active_alerts:
            self.active_alerts[alert_key] = time.time()
            return True
        
        time_since_last = time.time() - self.active_alerts[alert_key]
        if time_since_last > self.alert_cooldown_seconds:
            self.active_alerts[alert_key] = time.time()
            return True
        
        return False  # Still in cooldown
    
    def _check_all_conditions(
        self,
        latest_record: CostRecord,
        now: float
    ) -> list[Alert]:
        """Check all cost alert conditions"""
        
        alerts = []
        
        # ═══ CHECK 1: Single request too expensive ═══
        if latest_record.cost_usd > self.per_request_max:
            if self._should_fire_alert("per_request_spike"):
                alerts.append(Alert(
                    alert_id=f"cost_req_{int(now)}",
                    alert_name="EXPENSIVE_SINGLE_REQUEST",
                    severity=AlertSeverity.P1_HIGH,
                    state=AlertState.FIRING,
                    fired_at=now,
                    metric_name="request_cost_usd",
                    current_value=latest_record.cost_usd,
                    threshold_value=self.per_request_max,
                    unit="USD",
                    summary=(
                        f"💸 EXPENSIVE REQUEST: Single request cost "
                        f"${latest_record.cost_usd:.4f} "
                        f"(limit: ${self.per_request_max})"
                    ),
                    details=(
                        f"Model: {latest_record.model}\n"
                        f"Feature: {latest_record.feature}\n"
                        f"Tokens: {latest_record.tokens_used:,}\n"
                        f"Trace ID: {latest_record.trace_id}\n\n"

                        f"  1. Very large context/prompt\n"

        # ═══ CHECK 2: Per-minute rate spike ═══

        if minute_cost > self.per_minute_max:
            if self._should_fire_alert("per_minute_spike"):
                alerts.append(Alert(
                    alert_id=f"cost_min_{int(now)}",
                    alert_name="COST_SPIKE_PER_MINUTE",
                    severity=AlertSeverity.P0_CRITICAL,
                    state=AlertState.FIRING,
                    fired_at=now,
                    metric_name="cost_per_minute_usd",
                    current_value=minute_cost,

        return alerts
```

## 🏛️ ALERT TYPE 3: Latency Anomaly Alerts

### The Latency Alerting Challenge

```
Why latency alerting is tricky:

Problem 1: NATURAL VARIATION
─────────────────────────────
2am latency: P99 = 800ms   ← Low traffic, fast
9am latency: P99 = 1800ms  ← Peak traffic, slower
Alerting on absolute P99 > 1500ms = false alerts all morning

Solution: Alert on RELATIVE change from baseline
          "P99 is 3x its normal value for this time of day"

Problem 2: STREAMING vs NON-STREAMING
──────────────────────────────────────
Non-streaming: User waits for FULL response before seeing ANYTHING
               Total latency = what matters
Streaming: User sees FIRST token immediately, then words appear
           TTFT (Time to First Token) = what matters for UX

Alert differently:
  Streaming app: Alert on TTFT > 2s (user starts seeing response slow)
  Non-streaming app: Alert on TOTAL latency > 5s

Problem 3: LATENCY DISTRIBUTION vs AVERAGE
────────────────────────────────────────────
Average latency can be FINE while P99 is TERRIBLE:
  900 requests at 500ms = 450,000ms
  100 requests at 20,000ms = 2,000,000ms
  Average = (450,000 + 2,000,000) / 1000 = 2,450ms
  P99 = 20,000ms (20 seconds!)

ALWAYS alert on percentiles, never averages.
```

### Latency Anomaly Detection System

```python
import time
import statistics
import math
from collections import deque
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class LatencyMeasurement:
    """One latency measurement"""
    timestamp: float
    total_ms: float
    ttft_ms: Optional[float]
    retrieval_ms: Optional[float]
    llm_ms: Optional[float]
    tool_ms: Optional[float]
    feature: str
    model: str
    trace_id: str

class LatencyAnomalyDetector:
    """
    Detect latency anomalies using multiple methods:
    1. Static thresholds (absolute limits)
    2. Percentile-based (P95/P99 monitoring)
    3. Dynamic baseline (compare to historical)
    4. Step-level breakdown (which component is slow)
    """
    
    def __init__(
        self,
        alert_callback: callable,
        
        # Absolute static limits (SLA boundaries)
        p95_target_ms: float = 3000,
        p99_target_ms: float = 5000,
        ttft_target_ms: float = 1000,
        absolute_max_ms: float = 10000,   # Never allow > 10s
        
        # Dynamic anomaly config
        baseline_window_hours: int = 24,
        anomaly_multiplier: float = 3.0,  # Alert if 3x baseline
        min_samples: int = 50,            # Need 50 samples before alerting
    ):
        self.alert_callback = alert_callback
        self.p95_target = p95_target_ms
        self.p99_target = p99_target_ms
        self.ttft_target = ttft_target_ms
        self.absolute_max = absolute_max_ms
        self.baseline_window = baseline_window_hours * 3600
        self.anomaly_multiplier = anomaly_multiplier
        self.min_samples = min_samples
        
        # Rolling measurement window (last 5 minutes)
        self.recent_measurements: deque = deque()
        self.recent_window = 300  # 5 minutes
        
        # Historical baseline (last 24 hours)
        self.historical: deque = deque()
        
        # Alert deduplication
        self.fired_alerts: dict = {}
        self.cooldown_seconds = 300
    
    def record_latency(
        self,
        total_ms: float,
        ttft_ms: Optional[float] = None,
        retrieval_ms: Optional[float] = None,
        llm_ms: Optional[float] = None,
        tool_ms: Optional[float] = None,
        feature: str = "unknown",
        model: str = "unknown",
        trace_id: str = ""
    ) -> list[Alert]:
        """Record one latency measurement and check all conditions"""
        
        now = time.time()
        
        measurement = LatencyMeasurement(
            timestamp=now,
            total_ms=total_ms,
            ttft_ms=ttft_ms,
            retrieval_ms=retrieval_ms,
            llm_ms=llm_ms,
            tool_ms=tool_ms,
            feature=feature,
            model=model,
            trace_id=trace_id
        )
        
        self.recent_measurements.append(measurement)
        self.historical.append(measurement)
        
        self._clean_old_data(now)
        
        return self._check_conditions(measurement, now)
    
    def _clean_old_data(self, now: float):
        """Remove stale measurements"""
        recent_cutoff = now - self.recent_window
        historical_cutoff = now - self.baseline_window
        
        while (self.recent_measurements and
               self.recent_measurements[0].timestamp < recent_cutoff):
            self.recent_measurements.popleft()
        
        while (self.historical and
               self.historical[0].timestamp < historical_cutoff):
            self.historical.popleft()
    
    def _calculate_percentile(
        self,
        measurements: list[LatencyMeasurement],
        percentile: float,
        field: str = "total_ms"
    ) -> float:
        """Calculate a latency percentile from measurements"""
        
        values = sorted([
            getattr(m, field) for m in measurements
            if getattr(m, field) is not None
        ])
        
        if not values:
            return 0.0
        
        index = math.ceil((percentile / 100) * len(values)) - 1
        return values[max(0, index)]
    
    def _get_historical_baseline(
        self,
        now: float,
        window_seconds: int = 300,
        hours_back: int = 24
    ) -> Optional[dict]:
        """Get baseline stats from same time window yesterday"""
        
        reference_end = now - (hours_back * 3600)
        reference_start = reference_end - window_seconds
        
        reference_data = [
            m for m in self.historical
            if reference_start <= m.timestamp <= reference_end
        ]
        
        if len(reference_data) < 10:  # Need enough samples
            return None
        
        values = [m.total_ms for m in reference_data]
        return {
            "mean": statistics.mean(values),
            "std": statistics.stdev(values) if len(values) > 1 else 0,
            "p95": self._calculate_percentile(reference_data, 95),
            "sample_count": len(reference_data)
        }
    
    def _should_fire(self, key: str) -> bool:
        """Deduplication check"""
        if key not in self.fired_alerts:
            self.fired_alerts[key] = time.time()
            return True
        
        if time.time() - self.fired_alerts[key] > self.cooldown_seconds:
            self.fired_alerts[key] = time.time()
            return True
        
        return False
    
    def _check_conditions(
        self,
        latest: LatencyMeasurement,
        now: float
    ) -> list[Alert]:
        """Check all latency alert conditions"""
        
        alerts = []
        recent = list(self.recent_measurements)
        
        if len(recent) < 10:
            return []  # Not enough data yet
        
        # ═══ CHECK 1: Single request absolute maximum ═══
        if latest.total_ms > self.absolute_max:
            if self._should_fire("absolute_max"):
                alerts.append(Alert(
                    alert_id=f"lat_max_{int(now)}",
                    alert_name="ABSOLUTE_LATENCY_MAX",
                    severity=AlertSeverity.P1_HIGH,
                    state=AlertState.FIRING,
                    fired_at=now,
                    metric_name="request_latency_ms",
                    current_value=latest.total_ms,
                    threshold_value=self.absolute_max,
                    unit="milliseconds",
                    summary=(
                        f"🐌 EXTREME LATENCY: {latest.total_ms:.0f}ms response "
                        f"(max: {self.absolute_max:.0f}ms)"
                    ),
                    details=(
                        f"Breakdown:\n"
                        f"  Total:     {latest.total_ms:.0f}ms\n"
                        f"  TTFT:      {latest.ttft_ms or 'N/A'}ms\n"
                        f"  Retrieval: {latest.retrieval_ms or 'N/A'}ms\n"
                        f"  LLM:       {latest.llm_ms or 'N/A'}ms\n"
                        f"  Tools:     {latest.tool_ms or 'N/A'}ms\n"
                        f"  Feature: {latest.feature}\n"
                        f"  Model: {latest.model}"
                    ),
                    trace_link=(
                        f"https://langsmith.com/traces/{latest.trace_id}"
                    ),
                    runbook_link=(
                        "https://wiki.company.com/runbooks/extreme-latency"
                    )
                ))
        
        # ═══ CHECK 2: P95/P99 SLA breach ═══
        current_p95 = self._calculate_percentile(recent, 95)
        current_p99 = self._calculate_percentile(recent, 99)
        
        if current_p99 > self.p99_target:
            if self._should_fire("p99_breach"):
                # Find the bottleneck
                bottleneck = self._find_bottleneck(recent)
                
                alerts.append(Alert(
                    alert_id=f"lat_p99_{int(now)}",
                    alert_name="P99_SLA_BREACH",
                    severity=AlertSeverity.P1_HIGH,
                    state=AlertState.FIRING,
                    fired_at=now,
                    metric_name="p99_latency_ms",
                    current_value=current_p99,
                    threshold_value=self.p99_target,
                    unit="milliseconds",
                    summary=(
                        f"⏱️ P99 SLA BREACH: {current_p99:.0f}ms "
                        f"(target: < {self.p99_target:.0f}ms)\n"
                        f"P95: {current_p95:.0f}ms\n"
                        f"Bottleneck: {bottleneck}"
                    ),
                    details=(
                        f"Current percentiles (5-min window, {len(recent)} samples):\n"
                        f"  P50: {self._calculate_percentile(recent, 50):.0f}ms\n"
                        f"  P90: {self._calculate_percentile(recent, 90):.0f}ms\n"
                        f"  P95: {current_p95:.0f}ms\n"
                        f"  P99: {current_p99:.0f}ms\n"
                        f"  Max: {max(m.total_ms for m in recent):.0f}ms\n\n"
                        f"Bottleneck component: {bottleneck}\n"
                        f"Fix: Check component-level traces for slow operations"
                    ),
                    runbook_link=(
                        "https://wiki.company.com/runbooks/latency-sla-breach"
                    )
                ))
        
        elif current_p95 > self.p95_target:
            if self._should_fire("p95_elevated"):
                alerts.append(Alert(
                    alert_id=f"lat_p95_{int(now)}",
                    alert_name="P95_LATENCY_ELEVATED",
                    severity=AlertSeverity.P2_MEDIUM,
                    state=AlertState.FIRING,
                    fired_at=now,
                    metric_name="p95_latency_ms",
                    current_value=current_p95,
                    threshold_value=self.p95_target,
                    unit="milliseconds",
                    summary=(
                        f"⚠️ P95 ELEVATED: {current_p95:.0f}ms "
                        f"(target: < {self.p95_target:.0f}ms)"
                    )
                ))
        
        # ═══ CHECK 3: TTFT anomaly (streaming UX) ═══
        if latest.ttft_ms and latest.ttft_ms > self.ttft_target:
            if self._should_fire("ttft_spike"):
                alerts.append(Alert(
                    alert_id=f"ttft_{int(now)}",
                    alert_name="TTFT_SLA_BREACH",
                    severity=AlertSeverity.P2_MEDIUM,
                    state=AlertState.FIRING,
                    fired_at=now,
                    metric_name="ttft_ms",
                    current_value=latest.ttft_ms,
                    threshold_value=self.ttft_target,
                    unit="milliseconds",
                    summary=(
                        f"⏳ SLOW FIRST TOKEN: {latest.ttft_ms:.0f}ms "
                        f"(target: < {self.ttft_target:.0f}ms)\n"
                        "Users see a blank screen for too long."
                    ),
                    details=(
                        "TTFT impacts perceived performance most.\n"
                        "Even if total latency is OK, slow TTFT\n"
                        "makes the app feel broken to users.\n\n"
                        "Common causes:\n"
                        "  1. LLM provider processing delay\n"
                        "  2. Large input prompt (takes longer to process)\n"
                        "  3. Network latency to LLM provider\n"
                        "  4. Cold start on serverless deployment"
                    )
                ))
        
        # ═══ CHECK 4: Dynamic anomaly (compare to baseline) ═══
        baseline = self._get_historical_baseline(now)
        
        if baseline and len(recent) >= self.min_samples:
            current_mean = statistics.mean(m.total_ms for m in recent)
            
            if (baseline["mean"] > 0 and
                current_mean > baseline["mean"] * self.anomaly_multiplier):
                
                if self._should_fire("latency_anomaly"):
                    ratio = current_mean / baseline["mean"]
                    alerts.append(Alert(
                        alert_id=f"lat_anomaly_{int(now)}",
                        alert_name="LATENCY_ANOMALY",
                        severity=AlertSeverity.P1_HIGH,
                        state=AlertState.FIRING,
                        fired_at=now,
                        metric_name="latency_anomaly_ratio",
                        current_value=current_mean,
                        threshold_value=baseline["mean"],
                        unit="milliseconds",
                        summary=(
                            f"📈 LATENCY ANOMALY: {ratio:.1f}x normal speed\n"
                            f"Current: {current_mean:.0f}ms avg\n"
                            f"Baseline (same time yesterday): "
                            f"{baseline['mean']:.0f}ms avg"
                        )
                    ))
        
        # Fire all alerts
        for alert in alerts:
            asyncio.create_task(self.alert_callback(alert))
        
        return alerts
    
    def _find_bottleneck(
        self,
        measurements: list[LatencyMeasurement]
    ) -> str:
        """Find which component is causing the most latency"""
        
        components = {
            "retrieval": [
                m.retrieval_ms for m in measurements
                if m.retrieval_ms is not None
            ],
            "llm_generation": [
                m.llm_ms for m in measurements
                if m.llm_ms is not None
            ],
            "tool_calls": [
                m.tool_ms for m in measurements
                if m.tool_ms is not None
            ]
        }
        
        avg_by_component = {
            name: statistics.mean(values)
            for name, values in components.items()
            if values
        }
        
        if not avg_by_component:
            return "unknown"
        
        bottleneck = max(avg_by_component, key=avg_by_component.get)
        bottleneck_avg = avg_by_component[bottleneck]
        
        return (
            f"{bottleneck} ({bottleneck_avg:.0f}ms avg) — "
            f"investigate traces for slow {bottleneck} operations"
        )
```

## 🏛️ ALERT TYPE 4: Automated Rollback Triggers

### What Is Automated Rollback?

```
The Problem:
─────────────
You deploy a new prompt version at 2pm.
By 2:05pm, quality scores drop from 0.89 to 0.51.
By 2:10pm, error rate doubles.

Without automated rollback:
→ On-call engineer gets paged
→ Investigates (10 mins)
→ Decides to rollback (5 mins)
→ Executes rollback (5 mins)
→ Total: 20 minutes of degraded service

With automated rollback:
→ Quality drop detected (2 mins)
→ Rollback criteria met (3 mins)
→ Automated rollback executes (1 min)
→ Health checks pass (1 min)
→ Total: 7 minutes, no human needed

Rollback candidates in LLM systems:
────────────────────────────────────
1. Prompt version rollback
   → New prompt → quality/cost/latency degraded → revert to previous prompt

2. Model version rollback
   → New model (GPT-4o vs GPT-4) → worse performance → revert to previous model

3. RAG configuration rollback
   → Changed chunk size/overlap → worse retrieval → revert to previous config

4. Application code rollback
   → New feature deployment broke something → revert to previous release

5. Configuration rollback
   → Changed temperature/max_tokens → weird behavior → revert settings
```

```python
import asyncio
import time
import json
from dataclasses import dataclass, field
from typing import Optional, Callable
from enum import Enum

class RollbackTrigger(Enum):
    ERROR_RATE_HIGH    = "error_rate_high"
    COST_SPIKE         = "cost_spike"
    QUALITY_DROP       = "quality_drop"
    LATENCY_SPIKE      = "latency_spike"
    HALLUCINATION_HIGH = "hallucination_high"

@dataclass
class SystemVersion:
    """Snapshot of a complete system configuration"""
    version_id: str
    deployed_at: float
    deployed_by: str
    description: str
    
    # The actual configuration
    prompt_template: str
    model_name: str
    model_temperature: float
    model_max_tokens: int
    rag_chunk_size: int
    rag_chunk_overlap: int
    retrieval_top_k: int
    system_prompt: str
    
    # Baseline metrics when this version was healthy
    baseline_error_rate: float = 0.0
    baseline_p99_latency_ms: float = 0.0
    baseline_quality_score: float = 0.0
    baseline_cost_per_request: float = 0.0

@dataclass
class RollbackEvent:
    """Record of one rollback action"""
    rollback_id: str
    timestamp: float
    trigger: RollbackTrigger
    from_version: str
    to_version: str
    trigger_metric: str
    trigger_value: float
    trigger_threshold: float
    was_automatic: bool
    approved_by: Optional[str]
    success: bool
    duration_seconds: float
    post_rollback_health: dict = field(default_factory=dict)

class AutomatedRollbackSystem:
    """
    Detect system degradation and automatically roll back
    to the last known good configuration.
    
    Safety-first design:
    - Rollback only when MULTIPLE signals agree
    - Never rollback during active rollback
    - Always notify humans even for automatic rollbacks
    - Require human approval for rollbacks during business hours
    - Full audit trail of every rollback event
    """
    
    def __init__(
        self,
        alert_callback: Callable,
        rollback_executor: Callable,  # Actual function that does the rollback
        human_approval_required_hours: tuple = (9, 18),  # 9am-6pm
        
        # Rollback trigger thresholds
        error_rate_threshold: float = 5.0,      # % — rollback if > 5% errors
        quality_drop_threshold: float = 0.15,   # Absolute drop in quality score
        latency_spike_threshold: float = 3.0,   # Multiplier vs baseline
        cost_spike_threshold: float = 3.0,       # Multiplier vs baseline
        
        # Safety: need multiple signals to agree
        min_signals_for_auto_rollback: int = 2,  # 2 bad metrics
        monitoring_window_seconds: int = 300,     # 5-minute window
        min_samples_before_rollback: int = 30,    # 30 requests minimum
    ):
        self.alert_callback = alert_callback
        self.rollback_executor = rollback_executor
        self.human_approval_hours = human_approval_required_hours
        
        self.thresholds = {
            "error_rate": error_rate_threshold,
            "quality_drop": quality_drop_threshold,
            "latency_spike": latency_spike_threshold,
            "cost_spike": cost_spike_threshold
        }
        
        self.min_signals = min_signals_for_auto_rollback
        self.monitoring_window = monitoring_window_seconds
        self.min_samples = min_samples_before_rollback
        
        # Version history (ring buffer of last 10 versions)
        self.version_history: list[SystemVersion] = []
        self.current_version: Optional[SystemVersion] = None
        
        # State
        self.rollback_in_progress: bool = False
        self.rollback_history: list[RollbackEvent] = []
        self.pending_approval: Optional[dict] = None
        
        # Current metrics for comparison
        self.current_metrics: dict = {}
        self.deployment_time: float = time.time()
        self.post_deployment_samples: int = 0
    
    def register_version(self, version: SystemVersion):
        """Register a new deployment. Old version becomes rollback candidate."""
        
        if self.current_version:
            self.version_history.append(self.current_version)
            # Keep last 5 versions for rollback
            if len(self.version_history) > 5:
                self.version_history.pop(0)
        
        self.current_version = version
        self.deployment_time = time.time()
        self.post_deployment_samples = 0
        
        print(f"📦 New version registered: {version.version_id}")
        print(f"   Description: {version.description}")
        print(f"   Model: {version.model_name}")
        print(f"   Deployed by: {version.deployed_by}")
    
    def update_metrics(
        self,
        error_rate: float,
        p99_latency_ms: float,
        quality_score: float,
        cost_per_request: float
    ):
        """Update current metrics and check rollback conditions"""
        
        self.post_deployment_samples += 1
        
        self.current_metrics = {
            "error_rate": error_rate,
            "p99_latency_ms": p99_latency_ms,
            "quality_score": quality_score,
            "cost_per_request": cost_per_request,
            "timestamp": time.time()
        }
        
        # Don't check rollback until we have enough samples
        if self.post_deployment_samples < self.min_samples:
            return
        
        # Don't check if already rolling back
        if self.rollback_in_progress:
            return
        
        # Don't check if no previous version to roll back to
        if not self.version_history:
            return
        
        # Check rollback conditions
        asyncio.create_task(self._evaluate_rollback_need())
    
    async def _evaluate_rollback_need(self):
        """
        Evaluate whether conditions warrant a rollback.
        Requires MULTIPLE bad signals to avoid false positives.
        """
        
        if not self.current_version or not self.version_history:
            return
        
        baseline = self.current_version
        current = self.current_metrics
        
        # Collect all triggered signals
        triggered_signals = []
        
        # Signal 1: Error rate too high
        if current["error_rate"] > self.thresholds["error_rate"]:
            triggered_signals.append({
                "signal": RollbackTrigger.ERROR_RATE_HIGH,
                "current": current["error_rate"],
                "threshold": self.thresholds["error_rate"],
                "severity": "high",
                "description": (
                    f"Error rate {current['error_rate']:.1f}% "
                    f"exceeds threshold {self.thresholds['error_rate']}%"
                )
            })
        
        # Signal 2: Quality score dropped significantly
        quality_drop = baseline.baseline_quality_score - current["quality_score"]
        if quality_drop > self.thresholds["quality_drop"]:
            triggered_signals.append({
                "signal": RollbackTrigger.QUALITY_DROP,
                "current": current["quality_score"],
                "threshold": baseline.baseline_quality_score - self.thresholds["quality_drop"],
                "severity": "high",
                "description": (
                    f"Quality score dropped {quality_drop:.2f} points "
                    f"({baseline.baseline_quality_score:.2f} → "
                    f"{current['quality_score']:.2f})"
                )
            })
        
        # Signal 3: Latency spiked
        if (baseline.baseline_p99_latency_ms > 0 and
            current["p99_latency_ms"] > 
            baseline.baseline_p99_latency_ms * self.thresholds["latency_spike"]):
            
            ratio = current["p99_latency_ms"] / baseline.baseline_p99_latency_ms
            triggered_signals.append({
                "signal": RollbackTrigger.LATENCY_SPIKE,
                "current": current["p99_latency_ms"],
                "threshold": (
                    baseline.baseline_p99_latency_ms *
                    self.thresholds["latency_spike"]
                ),
                "severity": "medium",
                "description": (
                    f"P99 latency {ratio:.1f}x baseline "
                    f"({current['p99_latency_ms']:.0f}ms vs "
                    f"{baseline.baseline_p99_latency_ms:.0f}ms baseline)"
                )
            })
        
        # Signal 4: Cost spiked
        if (baseline.baseline_cost_per_request > 0 and
            current["cost_per_request"] > 
            baseline.baseline_cost_per_request * self.thresholds["cost_spike"]):
            
            ratio = current["cost_per_request"] / baseline.baseline_cost_per_request
            triggered_signals.append({
                "signal": RollbackTrigger.COST_SPIKE,
                "current": current["cost_per_request"],
                "threshold": (
                    baseline.baseline_cost_per_request *
                    self.thresholds["cost_spike"]
                ),
                "severity": "high",
                "description": (
                    f"Cost {ratio:.1f}x baseline "
                    f"(${current['cost_per_request']:.4f} vs "
                    f"${baseline.baseline_cost_per_request:.4f} baseline)"
                )
            })
        
        # Decide if rollback is warranted
        if len(triggered_signals) >= self.min_signals:
            await self._initiate_rollback(triggered_signals)
    
    async def _initiate_rollback(self, triggered_signals: list[dict]):
        """Initiate rollback — automatic or request human approval"""
        
        if self.rollback_in_progress:
            return
        
        rollback_target = self.version_history[-1]  # Most recent previous version
        
        # Determine if we need human approval
        current_hour = time.localtime().tm_hour
        during_business_hours = (
            self.human_approval_hours[0] <= 
            current_hour < 
            self.human_approval_hours[1]
        )
        
        signal_summary = "\n".join([
            f"  • {s['description']}"
            for s in triggered_signals
        ])
        
        if during_business_hours:
            # Business hours: request human approval first
            print(f"\n⚠️ ROLLBACK APPROVAL REQUESTED")
            print(f"   From: {self.current_version.version_id}")
            print(f"   To: {rollback_target.version_id}")
            print(f"   Signals:\n{signal_summary}")
            
            await self.alert_callback(Alert(
                alert_id=f"rollback_approval_{int(time.time())}",
                alert_name="ROLLBACK_APPROVAL_REQUIRED",
                severity=AlertSeverity.P1_HIGH,
                state=AlertState.FIRING,
                fired_at=time.time(),
                metric_name="multiple_degradation_signals",
                current_value=len(triggered_signals),
                threshold_value=self.min_signals,
                unit="signals",
                summary=(
                    f"🔄 ROLLBACK APPROVAL NEEDED\n"
                    f"Current version: {self.current_version.version_id}\n"
                    f"Target version: {rollback_target.version_id}\n"
                    f"Triggered {len(triggered_signals)} degradation signals:\n"
                    f"{signal_summary}"
                ),
                details=(
                    "Reply 'APPROVE ROLLBACK' to execute immediately\n"
                    "Reply 'DENY ROLLBACK' to keep current version\n"
                    "Auto-rollback will execute in 10 minutes if no response."
                ),
                runbook_link=(
                    "https://wiki.company.com/runbooks/rollback-procedure"
                )
            ))
            
            self.pending_approval = {
                "signals": triggered_signals,
                "target_version": rollback_target,
                "expires_at": time.time() + 600  # 10 minute approval window
            }
            
            # Schedule auto-execution if no approval
            asyncio.create_task(
                self._auto_approve_after_timeout()
            )
        
        else:
            # Off-hours: execute automatically + notify
            print(f"\n🔄 AUTOMATIC ROLLBACK INITIATING (off-hours)")
            await self._execute_rollback(
                rollback_target,
                triggered_signals,
                automatic=True
            )
    
    async def _auto_approve_after_timeout(self):
        """Auto-execute rollback if no human response within timeout"""
        await asyncio.sleep(600)  # 10 minutes
        
        if self.pending_approval and not self.rollback_in_progress:
            print("⏰ Auto-approval timeout reached. Executing rollback.")
            await self._execute_rollback(
                self.pending_approval["target_version"],
                self.pending_approval["signals"],
                automatic=True
            )
            self.pending_approval = None
    
    async def approve_rollback(self, approved_by: str):
        """Human approves the pending rollback"""
        if not self.pending_approval:
            print("No pending rollback to approve")
            return
        
        print(f"✅ Rollback approved by {approved_by}")
        await self._execute_rollback(
            self.pending_approval["target_version"],
            self.pending_approval["signals"],
            automatic=False,
            approved_by=approved_by
        )
        self.pending_approval = None
    
    async def _execute_rollback(
        self,
        target_version: SystemVersion,
        signals: list[dict],
        automatic: bool,
        approved_by: Optional[str] = None
    ):
        """Execute the actual rollback"""
        
        if self.rollback_in_progress:
            return
        
        self.rollback_in_progress = True
        rollback_start = time.time()
        
        print(f"\n{'='*60}")
        print(f"🔄 EXECUTING ROLLBACK")
        print(f"   From: {self.current_version.version_id}")
        print(f"   To:   {target_version.version_id}")
        print(f"   Automatic: {automatic}")
        print(f"{'='*60}")
        
        try:
            # Execute the actual rollback via provided executor function
            success = await self.rollback_executor(target_version)
            
            if success:
                # Update current version
                previous_version = self.current_version
                self.current_version = target_version
                self.deployment_time = time.time()
                self.post_deployment_samples = 0
                
                duration = time.time() - rollback_start
                
                # Record rollback event
                event = RollbackEvent(
                    rollback_id=f"rollback_{int(rollback_start)}",
                    timestamp=rollback_start,
                    trigger=signals[0]["signal"],
                    from_version=previous_version.version_id,
                    to_version=target_version.version_id,
                    trigger_metric=signals[0]["signal"].value,
                    trigger_value=signals[0]["current"],
                    trigger_threshold=signals[0]["threshold"],
                    was_automatic=automatic,
                    approved_by=approved_by,
                    success=True,
                    duration_seconds=duration
                )
                self.rollback_history.append(event)
                
                # Notify success
                await self.alert_callback(Alert(
                    alert_id=f"rollback_success_{int(time.time())}",
                    alert_name="ROLLBACK_COMPLETED",
                    severity=AlertSeverity.P2_MEDIUM,
                    state=AlertState.RESOLVED,
                    fired_at=rollback_start,
                    resolved_at=time.time(),
                    metric_name="rollback_status",
                    current_value=1,
                    threshold_value=1,
                    unit="boolean",
                    summary=(
                        f"✅ ROLLBACK COMPLETE ({duration:.0f}s)\n"
                        f"Reverted to: {target_version.version_id}\n"
                        f"Automatic: {automatic}\n"
                        f"Approved by: {approved_by or 'Auto'}"
                    ),
                    details=(
                        "Post-rollback health check in progress.\n"
                        "Monitor metrics for the next 10 minutes.\n"
                        f"Rollback ID: {event.rollback_id}\n"
                        "Schedule post-mortem within 24 hours."
                    )
                ))
                
                print(f"✅ Rollback completed in {duration:.1f}s")
                
            else:
                print(f"❌ Rollback FAILED — manual intervention required!")
                await self.alert_callback(Alert(
                    alert_id=f"rollback_failed_{int(time.time())}",
                    alert_name="ROLLBACK_FAILED",
                    severity=AlertSeverity.P0_CRITICAL,
                    state=AlertState.FIRING,
                    fired_at=time.time(),
                    metric_name="rollback_status",
                    current_value=0,
                    threshold_value=1,
                    unit="boolean",
                    summary=(
                        "🚨 ROLLBACK FAILED — MANUAL INTERVENTION REQUIRED\n"
                        "The system could not automatically revert.\n"
                        "Both current and target version may be broken!"
                    )
                ))
        
        finally:
            self.rollback_in_progress = False
```

```python
import aiohttp
import json
import hashlib
import time
from typing import Optional

class PagerDutyIntegration:
    """
    Send alerts to PagerDuty with full incident management.
    Supports: trigger, acknowledge, resolve events.
    """
    
    SEVERITY_TO_PAGERDUTY = {
        AlertSeverity.P0_CRITICAL: "critical",
        AlertSeverity.P1_HIGH: "error",
        AlertSeverity.P2_MEDIUM: "warning",
        AlertSeverity.P3_LOW: "info"
    }
    
    def __init__(
        self,
        routing_key: str,
        service_name: str = "LLM Production System",
        environment: str = "production",
        base_url: str = "https://events.pagerduty.com"
    ):
        self.routing_key = routing_key
        self.service_name = service_name
        self.environment = environment
        self.base_url = base_url
        
        # Track active incidents for resolution
        self.active_incidents: dict[str, str] = {}  # alert_id → dedup_key
    
    async def trigger_incident(self, alert: Alert) -> dict:
        """
        Create a new PagerDuty incident from an alert.
        Uses dedup_key to prevent duplicate incidents for the same issue.
        """
        
        # Dedup key: same alert type + same day = same incident
        # This prevents spam if alert keeps re-firing
        dedup_key = hashlib.md5(
            f"{alert.alert_name}_{int(time.time() // 3600)}".encode()
        ).hexdigest()
        
        # PagerDuty Events v2 payload
        payload = {
            "routing_key": self.routing_key,
            "event_action": "trigger",
            "dedup_key": dedup_key,
            
            "payload": {
                "summary": alert.summary,
                "source": self.service_name,
                "severity": self.SEVERITY_TO_PAGERDUTY[alert.severity],
                "timestamp": time.strftime(
                    "%Y-%m-%dT%H:%M:%SZ",
                    time.gmtime(alert.fired_at)
                ),
                "component": alert.affected_feature or "llm_system",
                "group": "llm_operations",
                "class": alert.alert_name,
                
                # Custom details (visible in PagerDuty alert)
                "custom_details": {
                    "alert_id": alert.alert_id,
                    "metric_name": alert.metric_name,
                    "current_value": f"{alert.current_value:.4f} {alert.unit}",
                    "threshold": f"{alert.threshold_value:.4f} {alert.unit}",
                    "details": alert.details,
                    "feature_affected": alert.affected_feature,
                    "user_impact": alert.estimated_user_impact,
                    "cost_impact": alert.estimated_cost_impact,
                    "environment": self.environment,
                    
                    # Critical: Include links for fast investigation
                    "🔍 Trace Link": alert.trace_link,
                    "📊 Dashboard": alert.dashboard_link,
                    "📚 Runbook": alert.runbook_link,
                }
            },
            
            # Links visible in PagerDuty mobile app
            "links": [
                link for link in [
                    {
                        "href": alert.trace_link,
                        "text": "🔍 View Trace"
                    } if alert.trace_link else None,
                    {
                        "href": alert.dashboard_link,
                        "text": "📊 View Dashboard"
                    } if alert.dashboard_link else None,
                    {
                        "href": alert.runbook_link,
                        "text": "📚 Runbook"
                    } if alert.runbook_link else None,
                ] if link is not None
            ]
        }
        
        async with aiohttp.ClientSession() as session:
            async with session.post(
                f"{self.base_url}/v2/enqueue",
                json=payload,
                headers={"Content-Type": "application/json"}
            ) as response:
                result = await response.json()
                
                if response.status == 202:
                    self.active_incidents[alert.alert_id] = dedup_key
                    print(
                        f"✅ PagerDuty incident created: "
                        f"{result.get('dedup_key')}"
                    )
                else:
                    print(
                        f"❌ PagerDuty failed: "
                        f"{response.status} - {result}"
                    )
                
                return result
    
    async def resolve_incident(self, alert_id: str) -> dict:
        """Resolve a PagerDuty incident when the underlying issue is fixed"""
        
        dedup_key = self.active_incidents.get(alert_id)
        if not dedup_key:
            return {"status": "no_active_incident"}
        
        payload = {
            "routing_key": self.routing_key,
            "event_action": "resolve",
            "dedup_key": dedup_key,
            "payload": {
                "summary": f"Resolved: {alert_id}",
                "source": self.service_name,
                "severity": "info"
            }
        }
        
        async with aiohttp.ClientSession() as session:
            async with session.post(
                f"{self.base_url}/v2/enqueue",
                json=payload,
                headers={"Content-Type": "application/json"}
            ) as response:
                result = await response.json()
                
                if response.status == 202:
                    del self.active_incidents[alert_id]
                    print(f"✅ PagerDuty incident resolved: {dedup_key}")
                
                return result
    
    async def send_status_update(
        self,
        alert_id: str,
        update_message: str
    ) -> dict:
        """Send a note to an existing PagerDuty incident"""
        
        dedup_key = self.active_incidents.get(alert_id)
        if not dedup_key:
            return {"status": "no_active_incident"}
        
        payload = {
            "routing_key": self.routing_key,
            "event_action": "acknowledge",
            "dedup_key": dedup_key,
            "payload": {
                "summary": update_message,
                "source": self.service_name,
                "severity": "info",
                "custom_details": {"status_update": update_message}
            }
        }
        
        async with aiohttp.ClientSession() as session:
            async with session.post(
                f"{self.base_url}/v2/enqueue",
                json=payload
            ) as response:
                return await response.json()
```

```python
class CloudWatchLLMAlerts:

        self.cloudwatch.put_metric_data(
            Namespace=self.namespace,
            MetricData=[
                {
                    "MetricName": metric_name,
                    "Dimensions": dimensions,
                    "Value": value,

                }
            ]

        tokens_input: int,

        feature: str
    ):

        dimensions = [
            {"Name": "Model", "Value": model},
            {"Name": "Feature", "Value": feature},
            {"Name": "Environment", "Value": "production"}
        ]
        
        # Batch put all metrics
        metrics = [

                "MetricName": "RequestLatency",
                "Dimensions": dimensions,
                "Value": latency_ms,
                "Unit": "Milliseconds"
            },
            {
                "MetricName": "InputTokens",

                "Dimensions": dimensions,
                "Value": 0 if success else 1,

        # We use a math expression: errors / total
        self.cloudwatch.put_metric_alarm(
```

## 📐 SECTION 8: Math Intuition — The Key Alert Math

### MTTD, MTTA, MTTR

```
These are the 3 most important incident KPIs:

MTTD (Mean Time to Detect):
─────────────────────────────
Time from when problem STARTED to when alert FIRED.

If bug deployed at 14:00 and alert fired at 14:05:
MTTD = 5 minutes

Target: < 5 minutes for P0, < 15 minutes for P1

How to improve MTTD:
→ Smaller alert evaluation windows (5 min → 1 min)
→ Lower thresholds (catch problems earlier)
→ Better anomaly detection (catches subtle degradations)

MTTA (Mean Time to Acknowledge):
──────────────────────────────────
Time from alert FIRED to engineer ACKNOWLEDGED.

If alert fired at 14:05 and engineer acked at 14:12:
MTTA = 7 minutes

Target: < 5 minutes for P0

How to improve MTTA:
→ Better on-call rotation (clear primary/secondary)
→ PagerDuty phone calls for P0 (louder than Slack)
→ Team members in multiple timezones
→ Clear escalation policy

MTTR (Mean Time to Resolve):
──────────────────────────────
Time from problem STARTED to fully RESOLVED.

If bug at 14:00 and fix deployed at 14:45:
MTTR = 45 minutes

Target: < 30 minutes for P0, < 4 hours for P1

MTTR = MTTD + MTTA + Investigation time + Fix time

How to improve MTTR:
→ Better runbooks (investigation guidance)
→ Automated rollback (cut fix time to 2 minutes)
→ Better trace links in alerts (faster investigation)
→ Pre-written runbooks for common scenarios


Compound formula:
─────────────────
Availability % = (Total time - Downtime) / Total time × 100

If MTTR = 45 minutes and incidents happen once per month:
Monthly downtime = 45 minutes
Monthly availability = (43,200 - 45) / 43,200 × 100 = 99.9%

If MTTR = 5 minutes (with automated rollback):
Monthly availability = (43,200 - 5) / 43,200 × 100 = 99.99%

Automated rollback improved availability from 99.9% to 99.99%!
That's the difference between 8.7 hours/year downtime
and 52 minutes/year downtime.
```

### Alert Threshold Math — Setting the Right Numbers

```
The Threshold Optimization Problem:
─────────────────────────────────────
Too HIGH threshold → Miss real problems (false negatives)
Too LOW threshold  → Alert fatigue (false positives)

Statistical approach:
─────────────────────
Take 30 days of healthy metric data.

Calculate:
mean = average value
std = standard deviation

Conservative threshold: mean + 2σ
→ Catches ~95% of anomalies
→ 5% false positive rate

Aggressive threshold: mean + 3σ
→ Catches ~99.7% of anomalies
→ 0.3% false positive rate

Example for P99 latency:
30-day data: mean=1200ms, std=300ms

2σ threshold: 1200 + 2(300) = 1800ms
3σ threshold: 1200 + 3(300) = 2100ms

Start with 3σ for lower noise.
Investigate everything that fires.
Tune based on real incidents.


Alert Budget Formula:
──────────────────────
How many alerts can your team handle?

Engineering_capacity = engineers × hours × 0.20
(20% of engineering time can go to incident response)

Max_alerts_per_week = Engineering_capacity / avg_alert_handling_time

Example:
5 engineers × 40 hours × 0.20 = 40 hours/week for incidents
Average alert handling time: 30 minutes
Max alerts: 40 hours / 0.5 hours = 80 alerts/week

If you're getting 500 alerts/week → 80% is noise
→ You MUST reduce alert noise
```

## 💥 SECTION 9: Failure Modes — When Alerting Breaks

| # | Failure | Root Cause | Detection | Fix |
|---|---|---|---|---|
| 1 | **Alert fatigue** | Too many alerts, mostly noise | Engineers start ignoring alerts | Reduce to only actionable alerts; track signal-to-noise ratio |
| 2 | **Alert storm** | 100 alerts fire simultaneously | Correlated failures trigger all metrics | Alert suppression/grouping; parent-child alert relationships |
| 3 | **Alert gap** | Problem occurs but no alert fires | Threshold too high or wrong metric | Test alerts with synthetic failures; track MTTD |
| 4 | **Alert delivered wrong channel** | Wrong routing in PagerDuty | Alert goes to off-duty team | Test alert routing quarterly; verify on-call schedules |
| 5 | **No context in alert** | Alert just says "latency high" | Engineer starts debugging blind | Every alert MUST include: trace link, dashboard, runbook |
| 6 | **Rollback loops** | New version is bad, rollback is also bad | Metrics never recover after rollback | Pin to known-good version, not just "previous" |
| 7 | **Alert during maintenance** | Deployment triggers alerts | On-call gets paged for planned work | Maintenance windows that suppress alerts |
| 8 | **Duplicate incidents** | Alert fires multiple times for same issue | No deduplication logic | Use dedup_key in PagerDuty; cooldown periods |
| 9 | **Flapping alerts** | Alert fires and resolves rapidly | Threshold at current operating point | Add evaluation periods (alert must fire for 2+ periods) |
| 10 | **No post-mortem** | Incident resolved, lesson lost | Same incident recurs | Mandatory post-mortems within 24 hours; track recurring alerts |

## 💬 SECTION 11: Strong Interview Answers

### Answer Q1: MTTD vs MTTR

> *"MTTD is Mean Time to Detect — how long from when a problem starts until an alert fires. This measures the quality of your monitoring. A low MTTD means your system catches problems quickly before they damage many users. MTTR is Mean Time to Resolve — how long from problem start to full resolution. This measures the efficiency of your response process. MTTR equals MTTD plus investigation time plus fix time. So even perfect MTTD is wasted without fast investigation and execution. In LLM systems, MTTD matters because cost can multiply exponentially while you're unaware — every minute of late detection costs money. MTTR matters for user experience — the longer the incident, the more trust you lose. Automated rollback is the single biggest lever for reducing MTTR, cutting it from 30-45 minutes to 5-10 minutes."*

---

### Answer Q4: Cost Spike Investigation

> *"My response follows a structured 30-minute playbook. In the first 5 minutes, I acknowledge the PagerDuty alert, open the incident channel, and check the cost dashboard to confirm the spike is real and quantify it — say, 10x normal means $150/hour instead of $15/hour. Minutes 5-15 I investigate the root cause: first check for any deployments in the last 30 minutes, then open LangSmith traces to look for patterns — are all requests expensive, or just from one feature? Are there infinite loops? Is a wrong model being used? Minutes 15-25 I apply mitigation: if it's a deployment, immediate rollback via the automated rollback system; if it's a loop, activate circuit breakers; if it's traffic, enable request throttling. Minutes 25-30 I verify the fix is working — cost rate returning to baseline — and update stakeholders. Afterwards, I schedule a post-mortem to determine which monitoring gap allowed this to happen and prevent recurrence."*

---

### Answer Q9: Flapping Alerts

> *"Alert flapping is when an alert rapidly fires and resolves, fires and resolves — often several times per hour. This happens when a metric oscillates right around the threshold. For example, P99 latency threshold is 3,000ms and the actual P99 bounces between 2,900ms and 3,100ms. This creates noise without any real problem to fix. The solutions are: First, require the metric to SUSTAIN the threshold breach for multiple evaluation periods — in Prometheus, set 'for: 5m' so it must be above threshold for 5 continuous minutes before firing. In Datadog and CloudWatch, set 'evaluation_periods: 2' and 'datapoints_to_alarm: 2'. Second, set a recovery threshold that's LOWER than the alert threshold — alert at 3,000ms but only resolve when it drops to 2,500ms, creating a buffer zone. This prevents rapid oscillation. Third, add a cooldown period between alerts for the same condition — once an alert fires, suppress re-fires for 5 minutes."*

## ⚠️ SECTION 12: Common Mistakes

| Mistake | Impact | Fix |
|---|---|---|
| Alerting on averages instead of percentiles | Miss tail latency SLA breaches | Always alert on P95/P99 |
| No runbook linked in alert | Engineer debugs from scratch at 2am | Every alert must have runbook link |

| No post-mortems | Same incidents repeat forever | Mandatory post-mortem, track recurring alerts |

```python
        if success:  # Only track cost for completed requests
            self.cost_detector.record_cost(
                cost_usd=cost_usd,
                tokens_used=tokens_input + tokens_output,
                model=model,
                feature=feature,
                trace_id=trace_id
            )
        
        # Latency tracking
        self.latency_detector.record_latency(
            total_ms=latency_ms,
            ttft_ms=ttft_ms,
            retrieval_ms=retrieval_ms,
            llm_ms=llm_ms,
            feature=feature,
            model=model,
            trace_id=trace_id
        )
        
        # Check error rate alerts every 30 seconds
        if int(time.time()) % 30 == 0:
            error_alerts = self.error_tracker.check_alert_conditions()
            for alert in error_alerts:
                await self._dispatch_alert(alert)
    
    def get_system_status(self) -> dict:
        """Current health status of all monitoring systems"""
        
        error_rates = self.error_tracker.get_error_rates()
        incident_metrics = self.incident_manager.get_incident_metrics()
        
        return {
            "timestamp": time.time(),
            "active_incidents": len(
                self.incident_manager.active_incidents
            ),
            "error_rate_pct": error_rates.get("total_error_rate_pct", 0),
            "incident_kpis": incident_metrics,
            "system_health": (
                "🔴 CRITICAL" if self.incident_manager.active_incidents
                else "🟢 HEALTHY"
            )
        }
```

## 🧠 SECTION 14: Engineer Mindset

```
How a Senior AI Engineer thinks about Alerting:

On day 1 of any LLM project, I ask:

✅ "What is the WORST thing that could happen in production?"
   Cost explosion → set tight cost alerts first
   Wrong answers → set quality alerts
   Complete outage → set error rate alerts
   → Prioritize by impact, not likelihood.

✅ "What is the FASTEST way to fix each problem?"
   Cost spike → rollback prompt / reduce tokens
   Quality drop → rollback prompt version
   Outage → rollback deployment / use fallback
   → Design rollback BEFORE you need it.

✅ "Who gets woken up at 2am?"
   Define clear on-call rotation before launch
   Never have "everyone" on call = no one is on call
   → PagerDuty rotation set up day 1.

✅ "What context do I need to debug in 5 minutes?"
   Trace link to the problematic request
   Dashboard showing the metric over time
   Runbook for the specific alert type
   → Put all 3 in every single alert.

✅ "How do I know my alerting is working?"
   Run monthly fire drills (simulate incidents)
   Test alert routing with synthetic failures
   Track MTTD, MTTA, MTTR as KPIs
   → Test your safety net before you need it.

✅ "What is my noise budget?"
   Count alerts per week
   Target < 5 actionable P1 alerts/week
   If > 20 alerts/week → alert fatigue incoming
   → Alert noise is a product quality problem.

The maturity model:
Level 1: Manual monitoring (log in and check dashboards)
Level 2: Static alerts (threshold-based)
Level 3: Dynamic alerts (anomaly-based)
Level 4: Automated response (rollback, circuit breakers)
Level 5: Predictive alerting (alert before threshold crossed)

Most teams are at Level 2. 
World-class teams operate at Level 4-5.
```

## 🎓 Final Summary — The 20% That Gives 80% Understanding

| Core Concept | One Sentence |
|---|---|
| **Why alerting matters** | Every minute of undetected problem costs money, users, and trust |
| **Error threshold alerts** | Alert on error RATE not error COUNT; track hard errors + quality errors separately |
| **Cost spike alerts** | Alert on per-minute rate, not monthly bill; use dynamic baselines, not static limits |
| **Latency anomaly alerts** | Always alert on P99 not average; use component-level breakdown to find bottleneck |
| **Automated rollback** | Requires multiple bad signals; auto-execute off-hours, require approval during business hours |
| **MTTD** | How fast you detect problems — minimize with small evaluation windows and sensitive thresholds |
| **MTTR** | How fast you resolve — minimize with runbooks, trace links, and automated rollback |
| **PagerDuty** | On-call management + escalation policies; pages the RIGHT person at the RIGHT time |
| **Slack alerts** | Rich Block Kit messages with links; right channel for right severity |
| **Engineer mindset** | Design your response BEFORE the incident; test your alerts BEFORE you need them |

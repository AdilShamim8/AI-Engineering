## 🏛️ PART 1: TOKEN USAGE TRACKING — From Zero

### 🧱 What is a Token? — Absolute Zero Explanation

Tokens are NOT words. They are NOT characters.
They are the **smallest meaningful chunks** that a language model processes.

```
Tokenization examples (using GPT tokenizer):

"Hello"          → 1 token
"Hello world"    → 2 tokens
"Hello, world!"  → 4 tokens  (comma and ! are separate tokens)
"ChatGPT"        → 1 token   (common word = 1 token)
"antidisestablishmentarianism" → 6 tokens (rare long word = many tokens)
"the"            → 1 token
"The"            → 1 token   (capital T = different token!)
" the"           → 1 token   (space before = different token!)
"2024"           → 1 token
"12345"          → 3 tokens  (1234 + 5)
```

**The golden rule of thumb:**
```
1 token ≈ 4 characters ≈ 0.75 words (in English)
1,000 tokens ≈ 750 words ≈ about 1.5 pages of text
```

## 🏛️ PART 2: COST PER REQUEST — Complete Math

### 🔢 Pricing Models Explained

Most LLM APIs use **pay-per-token pricing:**

```
GPT-4o (as of 2025):
  Input:  $2.50 per 1,000,000 tokens = $0.0000025 per token
  Output: $10.00 per 1,000,000 tokens = $0.00001 per token

GPT-4 Turbo:
  Input:  $10.00 per 1,000,000 tokens = $0.00001 per token
  Output: $30.00 per 1,000,000 tokens = $0.00003 per token

GPT-3.5 Turbo:
  Input:  $0.50 per 1,000,000 tokens  = $0.0000005 per token
  Output: $1.50 per 1,000,000 tokens  = $0.0000015 per token

Claude 3.5 Sonnet:
  Input:  $3.00 per 1,000,000 tokens  = $0.000003 per token
  Output: $15.00 per 1,000,000 tokens = $0.000015 per token
```

---

### 📐 Cost Formula — Step by Step

**The fundamental formula:**

```
cost_per_request = (input_tokens × input_price) 
                 + (output_tokens × output_price)
```

**Let's calculate step by step:**

```
Example Request on GPT-4 Turbo:
─────────────────────────────────────────────────────

Input tokens breakdown:
  System prompt:     420 tokens
  Retrieved docs:  2,840 tokens
  Chat history:      680 tokens
  User message:       42 tokens
  ─────────────────────────────
  Total input:     3,982 tokens

Output tokens:
  Model response:    312 tokens

Step 1: Calculate input cost
input_cost = 3,982 × $0.00001
           = 3,982 × (10/1,000,000)
           = $0.03982

Step 2: Calculate output cost
output_cost = 312 × $0.00003
            = 312 × (30/1,000,000)
            = $0.009360

Step 3: Total per request
total_cost = $0.03982 + $0.009360
           = $0.049180  (≈ 5 cents per conversation turn)
```

```python
import time
from dataclasses import dataclass
from typing import Optional
import tiktoken  # OpenAI's token counter library

@dataclass
class CostTracker:
    """Track and calculate LLM costs in real time"""
    
    # Pricing table (per 1M tokens)
    PRICING = {
        "gpt-4-turbo": {"input": 10.0, "output": 30.0},
        "gpt-4o": {"input": 2.5, "output": 10.0},
        "gpt-3.5-turbo": {"input": 0.5, "output": 1.5},
        "claude-3-5-sonnet": {"input": 3.0, "output": 15.0},
    }
    
    def count_tokens(self, text: str, model: str = "gpt-4") -> int:
        """Count tokens BEFORE sending to API (save money on failed attempts)"""
        try:
            encoding = tiktoken.encoding_for_model(model)
            return len(encoding.encode(text))
        except Exception:
            # Fallback: approximate (1 token ≈ 4 chars)
            return len(text) // 4
    
    def calculate_cost(
        self,
        model: str,
        input_tokens: int,
        output_tokens: int
    ) -> dict:
        """Calculate exact cost for a request"""
        
        if model not in self.PRICING:
            raise ValueError(f"Unknown model: {model}")
        
        pricing = self.PRICING[model]
        
        input_cost = input_tokens * (pricing["input"] / 1_000_000)
        output_cost = output_tokens * (pricing["output"] / 1_000_000)
        total_cost = input_cost + output_cost
        
        return {
            "model": model,
            "input_tokens": input_tokens,
            "output_tokens": output_tokens,
            "total_tokens": input_tokens + output_tokens,
            "input_cost_usd": round(input_cost, 6),
            "output_cost_usd": round(output_cost, 6),
            "total_cost_usd": round(total_cost, 6),
            "cost_breakdown_pct": {
                "input": round(input_cost / total_cost * 100, 1),
                "output": round(output_cost / total_cost * 100, 1)
            }
        }
    
    def estimate_cost_before_call(
        self,
        prompt: str,
        model: str,
        expected_output_tokens: int = 500
    ) -> dict:
        """Estimate cost BEFORE making the API call"""
        
        input_tokens = self.count_tokens(prompt, model)
        estimate = self.calculate_cost(model, input_tokens, expected_output_tokens)
        estimate["note"] = "PRE-CALL ESTIMATE — output tokens are estimated"
        
        # Safety check
        if estimate["total_cost_usd"] > 1.0:
            estimate["WARNING"] = "⚠️ This single call costs more than $1.00!"
        
        return estimate


# Usage example:
tracker = CostTracker()

# Pre-flight check before expensive calls
prompt = "System: You are helpful...\n\nUser: Explain quantum computing..."
estimate = tracker.estimate_cost_before_call(prompt, "gpt-4-turbo")
print(f"Estimated cost: ${estimate['total_cost_usd']}")

# Post-call exact calculation  
actual = tracker.calculate_cost(
    model="gpt-4-turbo",
    input_tokens=890,
    output_tokens=312
)
print(f"Actual cost: ${actual['total_cost_usd']}")
print(f"Breakdown: {actual['cost_breakdown_pct']}")
# Output: Breakdown: {'input': 74.2, 'output': 25.8}
# → 74% of cost was just the input (prompt!) — optimize that first!
```

```python
from collections import defaultdict
from datetime import datetime, timedelta
import threading

class BudgetMonitor:
    """Real-time budget monitoring with alerts"""
    
    def __init__(self, alert_callback):
        self.costs = defaultdict(float)  # {date: total_cost}
        self.user_costs = defaultdict(float)  # {user_id: cost_today}
        self.alert_callback = alert_callback
        
        # Budget limits
        self.limits = {
            "daily_total": 500.0,          # $500/day total
            "hourly_total": 50.0,           # $50/hour
            "per_user_daily": 5.0,          # $5 per user per day
            "per_request": 0.50,            # $0.50 per single request
        }
    
    def record_cost(
        self,
        cost: float,
        user_id: str,
        request_id: str,
        model: str
    ):
        """Record a cost and check all budget limits"""
        
        today = datetime.now().date().isoformat()
        current_hour = datetime.now().strftime("%Y-%m-%d-%H")
        
        # Accumulate costs
        self.costs[today] += cost
        self.costs[current_hour] += cost
        self.user_costs[f"{user_id}_{today}"] += cost
        
        # Check limits and alert
        checks = [
            {
                "name": "per_request",
                "actual": cost,
                "limit": self.limits["per_request"],
                "message": f"🚨 Single request cost ${cost:.4f} "
                           f"(limit: ${self.limits['per_request']})"
            },
            {
                "name": "daily_total",
                "actual": self.costs[today],
                "limit": self.limits["daily_total"],
                "message": f"🚨 Daily cost ${self.costs[today]:.2f} "
                           f"exceeded ${self.limits['daily_total']} limit"
            },
            {
                "name": "per_user_daily",
                "actual": self.user_costs[f"{user_id}_{today}"],
                "limit": self.limits["per_user_daily"],
                "message": f"🚨 User {user_id} spent "
                           f"${self.user_costs[f'{user_id}_{today}']:.2f} today "
                           f"(limit: ${self.limits['per_user_daily']})"
            },
        ]
        
        for check in checks:
            if check["actual"] > check["limit"]:
                self.alert_callback(
                    level="CRITICAL",
                    check_name=check["name"],
                    message=check["message"],
                    context={
                        "request_id": request_id,
                        "user_id": user_id,
                        "model": model,
                        "actual": check["actual"],
                        "limit": check["limit"]
                    }
                )
```

### Time to First Token (TTFT) vs Total Latency

This is crucial for user experience:

```
Scenario A: No Streaming
User types → [waiting 6 seconds] → Full response appears at once
→ Feels VERY slow even if 6s is acceptable

Scenario B: With Streaming
User types → [waiting 600ms] → Words start appearing...
→ "The refund policy is..." (streaming continues)
→ Full response after 6s total
→ Feels MUCH faster because user sees progress

Key metrics:
TTFT (Time to First Token):
→ User starts seeing words
→ Target: < 1 second
→ Most important for perceived speed

TGT (Total Generation Time):
→ Last word appears
→ Total time from request to complete response
→ Affects copy-paste, downstream processing

Tokens Per Second (TPS):
→ How fast words are appearing
→ Target: > 20 tokens/second for comfortable reading
→ Formula: output_tokens / (TGT - TTFT)
```

### Latency Breakdown — Complete Instrumentation

```python
import time
import asyncio
from contextlib import asynccontextmanager
from dataclasses import dataclass, field
from typing import Dict, List, Optional

@dataclass
class LatencyTracker:
    """Track latency for every step in the LLM pipeline"""
    
    trace_id: str
    measurements: Dict[str, float] = field(default_factory=dict)
    step_order: List[str] = field(default_factory=list)
    start_time: float = field(default_factory=time.perf_counter)
    first_token_time: Optional[float] = None
    
    @asynccontextmanager
    async def measure(self, step_name: str):
        """Context manager: auto-measure any step's duration"""
        step_start = time.perf_counter()
        try:
            yield self  # Run the code inside the `with` block
        finally:
            duration_ms = (time.perf_counter() - step_start) * 1000
            self.measurements[step_name] = round(duration_ms, 2)
            self.step_order.append(step_name)
    
    def record_first_token(self):
        """Call this when first token is received (streaming)"""
        self.first_token_time = time.perf_counter()
    
    def get_breakdown(self) -> dict:
        """Generate complete latency breakdown report"""
        total_ms = sum(self.measurements.values())
        
        # TTFT calculation
        ttft_ms = None
        if self.first_token_time:
            ttft_ms = (self.first_token_time - self.start_time) * 1000
        
        # Per-step analysis with percentage
        breakdown = {}
        for step in self.step_order:
            duration = self.measurements[step]
            breakdown[step] = {
                "duration_ms": duration,
                "percentage_of_total": round((duration / total_ms) * 100, 1),
                "is_bottleneck": duration > total_ms * 0.5  # >50% of total = bottleneck
            }
        
        return {
            "trace_id": self.trace_id,
            "total_latency_ms": round(total_ms, 2),
            "ttft_ms": round(ttft_ms, 2) if ttft_ms else None,
            "step_breakdown": breakdown,
            "bottleneck": max(self.measurements, key=self.measurements.get),
            "slowest_step_ms": max(self.measurements.values()),
            "step_sequence": self.step_order
        }

# Using the tracker in your pipeline:
async def handle_request_with_latency_tracking(user_message: str):
    tracker = LatencyTracker(trace_id="req_xyz123")
    
    # Step 1: Build prompt
    async with tracker.measure("prompt_building"):
        prompt = await build_prompt(user_message)
    
    # Step 2: Document retrieval
    async with tracker.measure("document_retrieval"):
        docs = await retrieve_documents(user_message)
    
    # Step 3: Embedding for retrieval
    async with tracker.measure("embedding_creation"):
        embedding = await create_embedding(user_message)
    
    # Step 4: Vector DB search
    async with tracker.measure("vector_db_search"):
        results = await vector_db.search(embedding)
    
    # Step 5: LLM call
    async with tracker.measure("llm_generation"):
        response = await call_openai_streaming(
            prompt,
            on_first_token=tracker.record_first_token  # TTFT tracking
        )
    
    # Step 6: Safety check
    async with tracker.measure("safety_filter"):
        safe_response = await check_safety(response)
    
    # Get the breakdown
    breakdown = tracker.get_breakdown()
    
    # Log it
    print(f"""
    ═══ LATENCY BREAKDOWN ═══
    Total: {breakdown['total_latency_ms']}ms
    TTFT:  {breakdown['ttft_ms']}ms

    ])}

    return safe_response, breakdown
```

### Parallel vs Sequential Latency — Critical Optimization

```
Sequential execution (most beginner implementations):
───────────────────────────────────────────────────────
retrieve_web ──────────────── 2,000ms ──────────────┐
                                                      ↓
retrieve_db  ──────────────── 1,500ms ─────────────┐ ↓ (after web done)
                                                    ↓ ↓
format_prompt ── 100ms ─────────────────────────────→ ↓
                                                      ↓
llm_call ──────────────────── 1,200ms ──────────────→
─────────────────────────────────────────────────────────
Total: 2,000 + 1,500 + 100 + 1,200 = 4,800ms

Parallel execution (optimized):
───────────────────────────────────────────────────────
retrieve_web ──────────────── 2,000ms ──────┐
                                             ↓ (both finish here)
retrieve_db  ──── 1,500ms ──────────────────┘
                                             ↓
format_prompt ── 100ms ──────────────────────→
                                             ↓
llm_call ──────────────────── 1,200ms ──────→
─────────────────────────────────────────────────────────
Total: max(2000, 1500) + 100 + 1200 = 3,300ms

Savings: 1,500ms = 31% faster!
```

```python
import asyncio

# Sequential (slow):
async def get_context_sequential(query):
    web_results = await search_web(query)      # 2000ms
    db_results = await search_database(query)  # 1500ms (waits for web!)
    return web_results + db_results
# Total: 3,500ms

# Parallel (fast):
async def get_context_parallel(query):
    # Both start at the SAME TIME
    web_task = asyncio.create_task(search_web(query))
    db_task = asyncio.create_task(search_database(query))
    
    # Wait for BOTH to finish (total = slowest, not sum)
    web_results, db_results = await asyncio.gather(web_task, db_task)
    return web_results + db_results
# Total: max(2000, 1500) = 2,000ms — 43% faster!
```

## 🏛️ PART 4: SLA MONITORING — Your Promise to Users

### What is an SLA?

**SLA = Service Level Agreement**

It's a **promise** you make about your system's behavior:

```
Common LLM SLA examples:

Availability SLA:
"Our service will be available 99.9% of the time"
→ Allowed downtime: 8.7 hours/year = 43.8 minutes/month

Latency SLA:
"95% of requests will complete within 3 seconds"
→ P95 latency target: < 3,000ms

Quality SLA:
"AI responses will be relevant 90% of the time"
→ Relevance score target: > 0.90

Error Rate SLA:
"Less than 0.1% of requests will return errors"
→ Error rate target: < 0.1%
```

---

### The 4 Key SLA Metrics for LLM Systems

#### SLA Metric 1: Availability

```
Availability = (Total time - Downtime) / Total time × 100%

Common SLA tiers:
99%    → 3.65 days downtime/year   (low-tier product)
99.9%  → 8.77 hours downtime/year  (standard SaaS)
99.99% → 52.6 minutes downtime/year (enterprise)

For LLMs, "downtime" includes:
- API server is down
- LLM provider is down (OpenAI outage)
- Response error rate > threshold
- Latency so high it's effectively unusable
```

#### SLA Metric 2: Latency SLOs (Service Level Objectives)

```
Typical LLM Latency Targets:

Tier 1: Interactive chat (real-time feel)
  P50: < 1,000ms
  P95: < 3,000ms
  P99: < 5,000ms
  TTFT: < 500ms (with streaming)

Tier 2: Background processing
  P50: < 5,000ms
  P95: < 15,000ms
  P99: < 30,000ms

Tier 3: Batch/async tasks
  No strict real-time SLA
  Focus on throughput (requests per minute)

Alert thresholds:
  Yellow alert: P95 > 2,500ms (approaching limit)
  Red alert: P95 > 3,000ms (SLA violated)
  Page on-call: P99 > 8,000ms (severe degradation)
```

#### SLA Metric 3: Error Rate

```
Error Rate = (Failed Requests / Total Requests) × 100%

Types of errors to track:
1. Hard errors: HTTP 500, timeout, API failure
2. Soft errors: Response was empty, too short, refused to answer
3. Quality errors: Hallucination detected, irrelevant response

Example SLA:
  Hard error rate: < 0.1%
  Soft error rate: < 1%
  Quality error rate: < 5%
```

#### SLA Metric 4: Throughput

```
Throughput = Requests per second (RPS) or Requests per minute (RPM)

Why it matters:
  If your system can only handle 100 RPS but you get 150 RPS
  → Some requests get queued or dropped
  → Latency spikes
  → SLA violated

OpenAI Rate Limits (2025 example):
  GPT-4 Turbo: 10,000 tokens per minute (TPM)
  GPT-3.5 Turbo: 90,000 tokens per minute

Your monitoring must track:
  - Current RPS vs limit
  - Token consumption rate vs rate limit
  - Queue depth (how many requests waiting)
```

### SLA Monitoring Implementation

```python
from collections import deque
from datetime import datetime, timedelta
import statistics
import time

class SLAMonitor:
    """
    Real-time SLA monitoring for LLM systems
    Tracks rolling windows of metrics
    """
    
    def __init__(self, window_minutes: int = 5):
        self.window = window_minutes * 60  # Convert to seconds
        
        # Rolling windows of recent data
        # Each entry: (timestamp, value)
        self.latencies = deque()      # All latency measurements
        self.errors = deque()         # All error events
        self.requests = deque()       # All requests
        
        # SLA targets (your promises)
        self.targets = {
            "p50_ms": 1_000,
            "p95_ms": 3_000,
            "p99_ms": 5_000,
            "ttft_ms": 500,
            "error_rate_pct": 0.5,
            "availability_pct": 99.9,
        }
        
        # SLA breach tracking
        self.breach_count = 0
        self.total_checks = 0
    
    def _clean_old_data(self):
        """Remove data older than the rolling window"""
        cutoff = time.time() - self.window
        
        while self.latencies and self.latencies[0][0] < cutoff:
            self.latencies.popleft()
        while self.errors and self.errors[0][0] < cutoff:
            self.errors.popleft()
        while self.requests and self.requests[0][0] < cutoff:
            self.requests.popleft()
    
    def record_request(
        self,
        latency_ms: float,
        ttft_ms: float,
        is_error: bool,
        trace_id: str
    ):
        """Record a completed request"""
        now = time.time()
        
        self.requests.append((now, trace_id))
        self.latencies.append((now, latency_ms, ttft_ms))
        
        if is_error:
            self.errors.append((now, trace_id))
        
        self._clean_old_data()
    
    def get_current_sla_status(self) -> dict:
        """Calculate current SLA compliance"""
        self._clean_old_data()
        
        if len(self.latencies) < 10:
            return {"status": "insufficient_data", "sample_size": len(self.latencies)}
        
        # Extract latency values
        lat_values = [lat for _, lat, _ in self.latencies]
        ttft_values = [ttft for _, _, ttft in self.latencies if ttft is not None]
        
        # Calculate percentiles
        lat_sorted = sorted(lat_values)
        n = len(lat_sorted)
        
        p50 = lat_sorted[int(n * 0.50)]
        p95 = lat_sorted[int(n * 0.95)]
        p99 = lat_sorted[int(n * 0.99)]
        avg_ttft = statistics.mean(ttft_values) if ttft_values else None
        
        # Error rate
        error_rate = (len(self.errors) / max(len(self.requests), 1)) * 100
        
        # Check SLA compliance
        breaches = []
        
        if p50 > self.targets["p50_ms"]:
            breaches.append({
                "metric": "P50 Latency",
                "actual": f"{p50:.0f}ms",
                "target": f"{self.targets['p50_ms']}ms",
                "severity": "WARNING"
            })
        
        if p95 > self.targets["p95_ms"]:
            breaches.append({
                "metric": "P95 Latency",
                "actual": f"{p95:.0f}ms",
                "target": f"{self.targets['p95_ms']}ms",
                "severity": "CRITICAL"
            })
        
        if p99 > self.targets["p99_ms"]:
            breaches.append({
                "metric": "P99 Latency",
                "actual": f"{p99:.0f}ms",
                "target": f"{self.targets['p99_ms']}ms",
                "severity": "CRITICAL"
            })
        
        if error_rate > self.targets["error_rate_pct"]:
            breaches.append({
                "metric": "Error Rate",
                "actual": f"{error_rate:.2f}%",
                "target": f"{self.targets['error_rate_pct']}%",
                "severity": "CRITICAL"
            })
        
        return {
            "window_minutes": self.window // 60,
            "sample_size": len(self.latencies),
            "current_metrics": {
                "p50_ms": round(p50, 2),
                "p95_ms": round(p95, 2),
                "p99_ms": round(p99, 2),
                "avg_ttft_ms": round(avg_ttft, 2) if avg_ttft else None,
                "error_rate_pct": round(error_rate, 3),
                "requests_in_window": len(self.requests),
            },
            "sla_status": "BREACHED" if breaches else "COMPLIANT",
            "breaches": breaches,
            "compliance_score": round(
                (1 - len(breaches) / len(self.targets)) * 100, 1
            )
        }

# Usage:
sla_monitor = SLAMonitor(window_minutes=5)

# Record each request as it completes
sla_monitor.record_request(
    latency_ms=1_240,
    ttft_ms=380,
    is_error=False,
    trace_id="req_001"
)

# Check SLA status (run every minute in production)
status = sla_monitor.get_current_sla_status()
if status["sla_status"] == "BREACHED":
    for breach in status["breaches"]:
        print(f"🚨 SLA BREACH: {breach['metric']} = "
              f"{breach['actual']} (target: {breach['target']})")
```

```python
            raise

            error_type = "unknown"
            raise

            llm_active_requests.dec()
            
            # Always record errors
            if error_type:
                llm_requests_total.labels(
                    model=model,
                    feature=feature,
                    status="error"
                ).inc()
                
                llm_errors_total.labels(
                    model=model,
                    error_type=error_type
                ).inc()
```

## 💥 SECTION 6: Failure Modes — When Monitoring Itself Fails

| # | Failure | Why It Happens | How to Prevent |
|---|---|---|---|
| 1 | **Metric cardinality explosion** | Too many unique label combinations | Limit label values; avoid user IDs as labels |
| 2 | **Clock skew between services** | Different servers have different clocks | Use NTP sync; use monotonic clocks for duration |
| 3 | **P99 looks fine but users suffer** | Wrong percentile window | Also monitor P99.9 and max |
| 4 | **Cost lag** | API providers report costs with delay | Track tokens locally; don't rely on delayed cost APIs |
| 5 | **Missing TTFT metric** | Only measuring total latency | Explicitly measure and log first-token time |
| 6 | **Alert fatigue** | Too many non-actionable alerts | Set meaningful thresholds; use tiered alerting |
| 7 | **Monitoring adds latency** | Synchronous logging slows app | Always use async/non-blocking metrics |
| 8 | **Rate limit not monitored** | Suddenly hit OpenAI rate limits | Track token-per-minute vs API limit continuously |
| 9 | **Budget alert too late** | Alert triggers after spending | Alert at 50%, 80%, 90% of budget |
| 10 | **Wrong percentile bucket boundaries** | Can't tell where P95 falls | Set buckets based on your actual SLA targets |

### The Cardinality Explosion Problem (Deep Dive)

This is a **very common beginner mistake** with Prometheus:

```python
# ❌ WRONG: Using user_id as a label
llm_cost = Counter(
    'llm_cost_total',
    'LLM cost',
    ['model', 'user_id']  # ← DANGER!
)

# If you have 100,000 users:
# 100,000 unique user_id values × 5 models 
# = 500,000 unique time series in Prometheus
# → Prometheus runs out of memory
# → Dashboard crashes
# → Monitoring system goes down!

# ✅ RIGHT: Use user_tier instead of user_id
llm_cost = Counter(
    'llm_cost_total',
    'LLM cost',
    ['model', 'user_tier']  # 'free', 'pro', 'enterprise'
)
# Only 5 models × 3 tiers = 15 time series
# Completely manageable!

# For per-user costs → store in a proper database
# (PostgreSQL, BigQuery), not in Prometheus
```

## 💬 SECTION 8: Strong Interview Answers

### Answer Q2: P99 = 8s but Average = 1.2s

> *"This is a classic tail latency problem. The average is being dragged down by the large number of fast requests, while a small percentage of requests are extremely slow. If P99 is 8 seconds, it means 1 in 100 users is waiting 8 seconds — that's unacceptable for an interactive chat app. I would investigate by: First, looking at the latency breakdown per step — retrieval, LLM, tool calls. Second, I'd check if the slow requests correlate with specific users, specific query types, or specific times of day. Third, I'd look for patterns — are the slow requests ones with long histories? Complex queries? Large retrieved contexts? The fix depends on what the breakdown shows — it's almost always retrieval or context building that causes these tail latency issues."*

---

### Answer Q4: Cost Doubled Overnight

> *"I'd follow a systematic investigation path. First, check if request volume doubled — if traffic doubled, cost doubling is expected and not a bug. Second, check cost per request: did the average cost per individual request increase? Third, break down by model: did someone switch from GPT-3.5 to GPT-4 for a feature? Fourth, check token usage — did average prompt length increase? A new system prompt version or enabling conversation history could do this. Fifth, look for any new features or deployments that went live yesterday. Sixth, check for any loops or retry storms — an agent stuck in a tool-calling loop could generate massive costs. I'd use my cost attribution metrics filtered by feature and model to narrow down in about 10 minutes."*

---

### Answer Q10: Cost Formula

> *"The cost formula is: total_cost = (input_tokens × input_price_per_token) + (output_tokens × output_price_per_token). For GPT-4 Turbo, input is $0.00001 per token and output is $0.00003 per token. So for a request with 1,000 input tokens and 300 output tokens: cost = (1000 × 0.00001) + (300 × 0.00003) = $0.01 + $0.009 = $0.019. Output tokens are priced higher because text generation requires a forward pass through the entire model for each token, while input processing can be done more efficiently. For monitoring, I track this per request and attribute it by user, feature, and model to enable cost optimization decisions."*

## ⚠️ SECTION 9: Common Mistakes

| Mistake | Impact | Fix |
|---|---|---|
| Only monitoring average latency | Miss tail latency SLA breaches | Always monitor P95, P99 |
| No token counting before API call | Can't catch expensive prompts early | Use tiktoken to pre-count tokens |
| No per-feature cost attribution | Can't tell which feature is expensive | Add feature label to all cost metrics |
| Setting alerts only at 100% of budget | Too late to react | Alert at 50%, 75%, 90% |
| Not monitoring TTFT separately | Miss streaming UX issues | Explicitly track TTFT |
| No rate limit monitoring | Sudden rate limit errors | Track TPM vs limit continuously |
| Prometheus cardinality explosion | Monitoring system crashes | Never use user IDs as labels |
| Not testing monitoring in staging | Production monitoring gaps | Test monitoring before going live |
| Manual cost calculation at month end | No real-time visibility | Real-time cost accumulation |
| Not comparing prompt versions by cost | Can't optimize what you don't measure | Tag all metrics by prompt version |

## 🏭 SECTION 10: Complete Production System

```python
"""
Production Token, Cost & Latency Monitoring System
Complete implementation bringing all pieces together
"""

import time
import asyncio
import tiktoken
from dataclasses import dataclass, field
from typing import Optional, Callable
from prometheus_client import Counter, Histogram, Gauge, start_http_server
from langfuse import Langfuse

# ═══ METRICS SETUP ═══
REQUEST_COUNTER = Counter(
    'llm_requests_total', '', ['model', 'feature', 'status']
)
TOKEN_COUNTER = Counter(
    'llm_tokens_total', '', ['model', 'token_type', 'feature']
)
COST_COUNTER = Counter(
    'llm_cost_usd_total', '', ['model', 'feature']
)
LATENCY_HIST = Histogram(
    'llm_request_duration_ms', '',
    ['model', 'feature'],
    buckets=[100, 250, 500, 1000, 2000, 3000, 5000, 10000, float('inf')]
)
TTFT_HIST = Histogram(
    'llm_ttft_ms', '', ['model'],
    buckets=[100, 200, 500, 1000, 2000, float('inf')]
)
RETRIEVAL_HIST = Histogram(
    'llm_retrieval_duration_ms', '', ['retrieval_type'],
    buckets=[10, 50, 100, 250, 500, 1000, 3000, float('inf')]
)
ACTIVE_REQUESTS = Gauge('llm_active_requests', '')
DAILY_COST = Gauge('llm_daily_cost_usd', '')

PRICING = {
    "gpt-4-turbo": {"input": 10.0 / 1e6, "output": 30.0 / 1e6},
    "gpt-4o": {"input": 2.5 / 1e6, "output": 10.0 / 1e6},
    "gpt-3.5-turbo": {"input": 0.5 / 1e6, "output": 1.5 / 1e6},
}

@dataclass
class RequestMetrics:
    trace_id: str
    model: str
    feature: str
    start_time: float = field(default_factory=time.perf_counter)
    
    # Step timings
    retrieval_ms: Optional[float] = None
    embedding_ms: Optional[float] = None
    llm_ms: Optional[float] = None
    tools_ms: Optional[float] = None
    safety_ms: Optional[float] = None
    ttft_ms: Optional[float] = None
    
    # Token & cost
    input_tokens: int = 0
    output_tokens: int = 0
    cost_usd: float = 0.0
    
    # Status
    status: str = "success"
    error_type: Optional[str] = None

class ProductionLLMMonitor:
    
    def __init__(self):
        self.langfuse = Langfuse()
        self._daily_cost_total = 0.0
        start_http_server(8000)
        print("📊 Prometheus metrics server started on :8000")
    
    async def monitored_rag_request(
        self,
        user_message: str,
        model: str = "gpt-4-turbo",
        feature: str = "chat",
        user_id: str = "anonymous"
    ) -> dict:
        
        metrics = RequestMetrics(
            trace_id=f"req_{int(time.time()*1000)}",
            model=model,
            feature=feature
        )
        
        # Langfuse trace for quality monitoring
        lf_trace = self.langfuse.trace(
            name="rag_request",
            metadata={"trace_id": metrics.trace_id, "feature": feature}
        )
        
        ACTIVE_REQUESTS.inc()
        
        try:
            # STEP 1: Retrieval
            ret_start = time.perf_counter()
            async with asyncio.timeout(5.0):  # 5s timeout
                docs = await self._retrieve_documents(user_message)
            metrics.retrieval_ms = (time.perf_counter() - ret_start) * 1000
            
            # STEP 2: Prompt building
            prompt = self._build_prompt(user_message, docs)
            
            # Pre-count tokens (before paying for the call)
            enc = tiktoken.encoding_for_model(model)
            estimated_input_tokens = len(enc.encode(prompt))
            
            # STEP 3: LLM call with TTFT tracking
            llm_start = time.perf_counter()
            first_token_received = False
            
            response_text = ""
            
            async for chunk in self._call_openai_streaming(prompt, model):
                if not first_token_received:
                    metrics.ttft_ms = (time.perf_counter() - llm_start) * 1000
                    first_token_received = True
                response_text += chunk
            
            metrics.llm_ms = (time.perf_counter() - llm_start) * 1000
            
            # Calculate actual tokens and cost
            metrics.input_tokens = estimated_input_tokens
            metrics.output_tokens = len(enc.encode(response_text))
            
            pricing = PRICING.get(model, PRICING["gpt-4-turbo"])
            metrics.cost_usd = (
                metrics.input_tokens * pricing["input"] +
                metrics.output_tokens * pricing["output"]
            )
            
            metrics.status = "success"
            
            return {
                "response": response_text,
                "metrics": metrics,
                "trace_id": metrics.trace_id
            }
            
        except asyncio.TimeoutError:
            metrics.status = "error"
            metrics.error_type = "timeout"
            raise
            
        except Exception as e:
            metrics.status = "error"
            metrics.error_type = "unknown"
            raise
            
        finally:
            # ALWAYS record metrics (success or failure)
            self._record_all_metrics(metrics)
            ACTIVE_REQUESTS.dec()
            lf_trace.update(
                metadata={
                    "total_cost": metrics.cost_usd,
                    "total_tokens": metrics.input_tokens + metrics.output_tokens,
                    "status": metrics.status
                }
            )
    
    def _record_all_metrics(self, m: RequestMetrics):
        """Record every metric to Prometheus"""
        
        total_ms = (time.perf_counter() - m.start_time) * 1000
        
        # Request counter
        REQUEST_COUNTER.labels(
            model=m.model, feature=m.feature, status=m.status
        ).inc()
        
        # Tokens
        TOKEN_COUNTER.labels(
            model=m.model, token_type="input", feature=m.feature
        ).inc(m.input_tokens)
        
        TOKEN_COUNTER.labels(
            model=m.model, token_type="output", feature=m.feature
        ).inc(m.output_tokens)
        
        # Cost
        COST_COUNTER.labels(model=m.model, feature=m.feature).inc(m.cost_usd)
        self._daily_cost_total += m.cost_usd
        DAILY_COST.set(self._daily_cost_total)
        
        # Latency
        LATENCY_HIST.labels(model=m.model, feature=m.feature).observe(total_ms)
        
        if m.ttft_ms is not None:
            TTFT_HIST.labels(model=m.model).observe(m.ttft_ms)
        
        if m.retrieval_ms is not None:
            RETRIEVAL_HIST.labels(retrieval_type="vector_db").observe(m.retrieval_ms)
        
        # Log for debugging (structured)
        print(f"""
        ✅ Request Complete [{m.trace_id}]
        ─────────────────────────────────────
        Model:    {m.model}
        Feature:  {m.feature}
        Status:   {m.status}
        
        Tokens:   {m.input_tokens} in / {m.output_tokens} out
        Cost:     ${m.cost_usd:.6f}
        
        Latency Breakdown:
          Total:     {total_ms:.0f}ms
          TTFT:      {m.ttft_ms:.0f}ms
          Retrieval: {m.retrieval_ms:.0f}ms
          LLM:       {m.llm_ms:.0f}ms
        ─────────────────────────────────────
        """)
```

## 🧠 SECTION 11: Engineer Mindset

```
How a Senior AI Engineer thinks about this:

BEFORE building any LLM feature, I ask:

1. "What is my token budget per request?"
   → Set limits, build prompts within them

2. "What is my cost target per user?"

3. "What is my latency SLA?"

4. "Where is the likely bottleneck?"
   → Usually retrieval in RAG, usually tool calls in agents

   → Budget alerts at 50%, 80%, 100%

6. "How do I debug a slow response?"
   → Latency breakdown in every trace, always

7. "How will I compare model A vs model B?"
   → Same metrics, tag by model, compare in dashboard

The goal is to always know:
  - What it costs (per request, per user, per feature)
  - How fast it is (P50, P95, P99, TTFT)
  - Whether it's meeting SLA (compliance %)
  - Where the bottleneck is (step-by-step breakdown)

Without these, you're flying blind in production.
```

| **TTFT vs total latency** | TTFT controls perceived speed; total latency controls actual speed |
| **Why P99 over average** | Average hides the tail — 1% of users with 10s waits is a real problem |
| **What SLA monitoring is** | Continuously measuring if you're keeping your promises to users |
| **The right tool stack** | Prometheus for collection → Grafana for visualization → Alerts for action |
| **Engineer mindset** | Know your cost per request, P95 latency, and SLA compliance at all times |

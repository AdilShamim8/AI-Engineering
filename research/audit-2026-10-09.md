## Why the guide did not demonstrate expert practice

The curriculum already covers advanced names and concepts. Its weaker point was the evidence behind the explanations:

- **Incompatible denominators:** the skills page combined a 3,100+ headline, a 1,247 methodology total and tables summing to 1,200. Other summaries used different responsibility/use-case totals without corresponding records.
- **Untraceable precision:** regional percentages, salary tables, skill-growth figures and callback multipliers lacked inspectable observations and a reproducible method.
- **Illustrations presented as results:** design exercises and caching/evaluation examples used precise performance figures and claims of production readiness without executed workloads or measurements.
- **Missing execution contracts:** useful explanations did not consistently state dataset/version, split, baseline, labels, uncertainty, failure slices or operational acceptance criteria.
- **Security overclaims:** filtering one vector query was described as guaranteeing zero leakage; a cache appeared before identity/authorization in the architecture.
- **Stale reference risk:** legacy model catalogs and package examples carried blanket verification labels without source-specific review, version pins or runtime evidence.
- **Navigation and example defects:** absent data inventories, section-relative license links, malformed strings/arguments, mixed shell/Python fences and a broken fallback handler undermined reproducibility.

Expertise is demonstrated by reliable measurement, defensible tradeoffs and accountable operation. More terminology, longer lessons or a new date do not establish it.

## Validation and its limits

- **Real-data analysis executed:** all 8,051 raw/structured pairs were read; input provenance and the data fingerprint are stored with the result. The method rejects an unexpected commit, dirty dataset, duplicate YAML keys, duplicate IDs within a scrape and mismatched raw/structured files.
- **Documentation checked:** rendered Python fences were parsed for syntax; relative file targets were checked across the final repository. These checks do not execute training/serving examples, validate anchors, or certify facts.
- **Filtered retrieval exercised:** Qdrant local-mode checks covered permitted records, other tenants, insufficient clearance, inactive records, missing scope and an invalid limit. This fixture establishes selector behavior, not production authentication or complete isolation.
- **Fallback handler exercised:** isolated asynchronous fixtures checked a failed primary with successful fallback, completion access, and a sanitized 503 when both providers fail. No live provider API was used.
- **Primary references inspected:** commits and content checksums are in [sources.json](sources.json). Their benchmark suites were not executed. Source-reported release statements are not new measurements by this guide.

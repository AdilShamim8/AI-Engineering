# 🏛️ FOUNDATION — Why Memory Failures Are Different

## The Invisible Failure Problem

```
NORMAL SOFTWARE FAILURE:
  System crashes → Error log → Alert fires → Engineer fixes
  User sees: "Something went wrong. Please try again."
  Impact: Temporary inconvenience

MEMORY SYSTEM FAILURE:
  System runs normally → No errors → No alerts → No logs
  User sees: "Based on your preferences, I recommend X"
  But X is based on: stale data, wrong user's info,
                     contradictory facts, or random noise
  Impact: User makes WRONG DECISIONS based on AI "guidance"

THE DIFFERENCE:
  Normal failures are LOUD and SHORT
  Memory failures are QUIET and LONG
  
  A memory bug can silently corrupt AI behavior for:
  → Days before anyone notices
  → Thousands of users before it's caught
  → Every interaction for those users during that period
```

Memory failures are a set of failure modes that stack over time and are easy to miss until results drift. The first failure mode is counterintuitive: more context makes agents worse. As prompts grow, models don't just slow down — they also degrade.

# 💥 FAILURE MODE 1: Context Overflow

## 1. What Is It?

> **Context Overflow = The total amount of memory injected into the LLM's context window exceeds safe operating limits, causing degraded response quality, silent accuracy loss, extreme cost inflation, or hard token limit errors.**

---

## 2. First-Principles Breakdown

```
THE ATTENTION MECHANISM TRUTH:
  LLMs process tokens through an attention mechanism.
  Attention = "For each token, how much should I focus
               on every other token?"
  
  With 100 tokens: attention is focused, precise
  With 10,000 tokens: attention is DILUTED
  With 100,000 tokens: attention is spread so thin
                       that early tokens barely matter

MATHEMATICAL REALITY:
  Attention complexity = O(n²) where n = token count
  
  1,000 tokens  → 1,000,000 attention operations
  10,000 tokens → 100,000,000 attention operations
  100,000 tokens → 10,000,000,000 attention operations
  
  More tokens = exponentially more work AND worse focus.
  The model CAN process 128K tokens.
  The model cannot RELIABLY ATTEND to all 128K tokens equally.
```

Around 60-70% in production: if your LLM advertises 200k tokens, expect reliable performance up to 130k tokens max. Models start degrading before hitting advertised limits, losing early instructions and known facts without throwing errors.

---

## 3. The Three Types of Context Overflow

```
TYPE 1: HARD OVERFLOW (The Obvious One)
  Token count > model's maximum limit
  API returns: "Error: max_tokens exceeded"
  Visible, immediate, fixable
  
  Example:
  GPT-4o limit: 128,000 tokens
  Your prompt: 150,000 tokens → ERROR

TYPE 2: SOFT OVERFLOW (The Dangerous One)
  Token count within limit BUT too large for reliable attention
  API returns: 200 OK — LOOKS SUCCESSFUL
  LLM "forgets" facts from early in the context
  No error. No warning. Silent failure.
  
  Example:
  Memory stored at position 500 of 100,000 tokens
  LLM almost certainly ignores it
  Response acts as if that memory doesn't exist

TYPE 3: COST OVERFLOW (The Financial One)
  Too many tokens → extreme API costs
  100 users × 20,000 token prompts = $400/hour
  No technical failure, just financial ruin
  Example:
  Conversation with 200 messages = 40,000 tokens
  At $10/1M tokens (GPT-4o input): $0.40 per call
  100 active users doing this: $40/hour = $35,000/month
```

---

## 4. The "Lost in the Middle" Problem

Transcript replay causes context to grow with turn count, reduces attention selectivity, and allows early errors to persist and reappear, which increases hallucination carryover and drift from established constraints.

```
EXPERIMENT: The "Lost in the Middle" Phenomenon

Prompt Structure:
[IMPORTANT FACT at position 1]
[10,000 tokens of other memories]
[QUESTION at position 10,001]

Result:
LLM cannot reliably recall the fact from position 1.
It was buried under 10,000 tokens.
It answers the question WITHOUT the important fact.

Real Example:
Position 1:  "User's budget is $50,000"
Position 5,000: ... (many other memories)
Question: "What proposal fits this user's budget?"
LLM answer: Proposes something for $5,000 (ignores buried fact!)

THIS IS CONTEXT OVERFLOW — no error, completely wrong answer.
```

```python
# context_overflow_detector.py
import tiktoken
from typing import List, Dict, Tuple, Optional
from dataclasses import dataclass
from enum import Enum


class OverflowRisk(Enum):
    SAFE     = "safe"      # < 40% of limit
    WARNING  = "warning"   # 40-70% of limit
    DANGER   = "danger"    # 70-90% of limit
    CRITICAL = "critical"  # > 90% of limit


@dataclass
class ContextHealthReport:
    """Complete health report for a context window."""
    total_tokens: int
    model_limit: int
    reliable_limit: int          # 70% of advertised limit
    utilization_pct: float
    risk_level: OverflowRisk
    
    # Breakdown by source
    system_prompt_tokens: int
    memory_tokens: int
    conversation_tokens: int
    
    # Warnings
    warnings: List[str]
    recommendations: List[str]
    
    # Cost estimate
    estimated_cost_usd: float

    @property
    def is_safe(self) -> bool:
        return self.risk_level in (OverflowRisk.SAFE, OverflowRisk.WARNING)

    @property
    def needs_compression(self) -> bool:
        return self.risk_level in (OverflowRisk.DANGER, OverflowRisk.CRITICAL)


class ContextOverflowDetector:
    """
    Monitor and detect context overflow before it causes silent failures.
    
    USAGE: Call check() before EVERY LLM API call.
    If risk is DANGER or CRITICAL → compress before calling.
    """

    # Model context limits (tokens)
    MODEL_LIMITS = {
        "gpt-4o":           128_000,
        "gpt-4o-mini":      128_000,
        "gpt-4-turbo":      128_000,
        "claude-3-5-sonnet": 200_000,
        "claude-3-haiku":   200_000,
        "gemini-1.5-pro":   1_000_000,
        "llama-3-70b":       8_000,
    }

    # Cost per 1M INPUT tokens (USD) — approximate 2025 rates
    MODEL_COSTS_PER_1M = {
        "gpt-4o":           2.50,
        "gpt-4o-mini":      0.15,
        "gpt-4-turbo":     10.00,
        "claude-3-5-sonnet": 3.00,
        "claude-3-haiku":   0.25,
    }

    # RELIABLE limit is 70% of advertised (accounts for attention degradation)
    RELIABLE_LIMIT_FACTOR = 0.70

    def __init__(self, model: str = "gpt-4o-mini"):
        self.model = model
        self.model_limit = self.MODEL_LIMITS.get(model, 128_000)
        self.reliable_limit = int(self.model_limit * self.RELIABLE_LIMIT_FACTOR)
        self.cost_per_1m = self.MODEL_COSTS_PER_1M.get(model, 1.0)

        try:
            self.encoder = tiktoken.encoding_for_model(
                model if model in ["gpt-4o", "gpt-4o-mini"] else "gpt-4o"
            )
        except Exception:
            self.encoder = tiktoken.get_encoding("cl100k_base")

    def count_tokens(self, text: str) -> int:
        """Count tokens accurately using tiktoken."""
        return len(self.encoder.encode(text))

    def count_messages_tokens(self, messages: List[Dict]) -> int:
        """Count tokens in a message list including overhead."""
        total = 3  # Base overhead
        for msg in messages:
            total += 4  # Per-message overhead
            total += self.count_tokens(msg.get("content", ""))
        return total

    def check(
        self,
        system_prompt: str = "",
        memories: List[str] = None,
        conversation: List[Dict] = None
    ) -> ContextHealthReport:
        """
        Check context health before an LLM call.
        Call this EVERY TIME before calling the LLM.
        
        Returns: ContextHealthReport with risk level and recommendations.
        """
        memories = memories or []
        conversation = conversation or []

        # Count tokens by source
        system_tokens = self.count_tokens(system_prompt)
        memory_tokens = sum(self.count_tokens(m) for m in memories)
        conv_tokens = self.count_messages_tokens(conversation)
        total_tokens = system_tokens + memory_tokens + conv_tokens

        # Calculate utilization
        util_pct = total_tokens / self.model_limit * 100
        reliable_util_pct = total_tokens / self.reliable_limit * 100

        # Determine risk level (based on RELIABLE limit, not advertised)
        if reliable_util_pct < 40:
            risk = OverflowRisk.SAFE
        elif reliable_util_pct < 70:
            risk = OverflowRisk.WARNING
        elif reliable_util_pct < 90:
            risk = OverflowRisk.DANGER
        else:
            risk = OverflowRisk.CRITICAL

        # Generate warnings
        warnings = []
        recommendations = []

        if total_tokens > self.model_limit:
            warnings.append(
                f"🚨 HARD OVERFLOW: {total_tokens:,} tokens exceeds "
                f"model limit of {self.model_limit:,}. API will ERROR."
            )
            recommendations.append("URGENT: Compress conversation immediately")

        if total_tokens > self.reliable_limit:
            warnings.append(
                f"⚠️ SOFT OVERFLOW: {total_tokens:,} tokens exceeds "
                f"reliable limit of {self.reliable_limit:,}. "
                f"Silent quality degradation is occurring."
            )

        if memory_tokens > system_tokens + conv_tokens:
            warnings.append(
                f"📦 Memory ({memory_tokens:,} tokens) exceeds "
                f"all other content combined. Too many memories injected!"
            )
            recommendations.append(
                "Reduce retrieved memories to top 3-5 most relevant"
            )

        if len(memories) > 10:
            warnings.append(
                f"📚 {len(memories)} memories injected. "
                f"Above 5-7 memories causes context pollution."
            )
            recommendations.append(
                "Filter memories to top 5 by relevance score"
            )

        # Cost estimate (per call)
        cost_usd = (total_tokens / 1_000_000) * self.cost_per_1m

        if cost_usd > 0.05:
            warnings.append(
                f"💰 High cost per call: ${cost_usd:.4f}. "
                f"Projected monthly (1000 calls/day): "
                f"${cost_usd * 1000 * 30:.2f}"
            )

        return ContextHealthReport(
            total_tokens=total_tokens,
            model_limit=self.model_limit,
            reliable_limit=self.reliable_limit,
            utilization_pct=util_pct,
            risk_level=risk,
            system_prompt_tokens=system_tokens,
            memory_tokens=memory_tokens,
            conversation_tokens=conv_tokens,
            warnings=warnings,
            recommendations=recommendations,
            estimated_cost_usd=cost_usd
        )

    def check_and_print(
        self,
        system_prompt: str = "",
        memories: List[str] = None,
        conversation: List[Dict] = None
    ) -> ContextHealthReport:
        """Check and print a detailed health report."""
        report = self.check(system_prompt, memories, conversation)

        risk_icons = {
            OverflowRisk.SAFE:     "🟢",
            OverflowRisk.WARNING:  "🟡",
            OverflowRisk.DANGER:   "🟠",
            OverflowRisk.CRITICAL: "🔴"
        }

        print(f"\n{'='*60}")
        print(f"CONTEXT HEALTH REPORT — {self.model}")
        print(f"{'='*60}")
        print(f"  {risk_icons[report.risk_level]} Risk: "
              f"{report.risk_level.value.upper()}")
        print(f"  Total tokens:     {report.total_tokens:>8,}")
        print(f"  Reliable limit:   {report.reliable_limit:>8,}")
        print(f"  Utilization:      {report.utilization_pct:>7.1f}%")
        print(f"  Est. cost/call:   ${report.estimated_cost_usd:.4f}")
        print(f"\n  Breakdown:")
        print(f"    System prompt:  {report.system_prompt_tokens:>6,} tokens")
        print(f"    Memories:       {report.memory_tokens:>6,} tokens")
        print(f"    Conversation:   {report.conversation_tokens:>6,} tokens")

        if report.warnings:
            print(f"\n  ⚠️  WARNINGS:")
            for w in report.warnings:
                print(f"    → {w}")

        if report.recommendations:
            print(f"\n  💡 RECOMMENDATIONS:")
            for r in report.recommendations:
                print(f"    → {r}")

        print(f"{'='*60}\n")
        return report


class ContextOverflowFixer:
    """
    Automatic fixes for detected context overflow.
    Applied when ContextOverflowDetector reports DANGER or CRITICAL.
    """

    def __init__(self, detector: ContextOverflowDetector):
        self.detector = detector

    def fix_memory_overflow(
        self,
        memories: List[Dict],
        target_token_budget: int = 2000,
        min_similarity: float = 0.7
    ) -> List[Dict]:
        """
        Reduce memories to fit within token budget.
        
        Strategy (in order):
        1. Filter by similarity score (keep most relevant)
        2. Truncate long memory texts
        3. Remove duplicates
        4. Remove lowest importance memories
        """
        if not memories:
            return []

        # Step 1: Sort by relevance/importance
        scored = sorted(
            memories,
            key=lambda m: (
                m.get("similarity", 0) +
                m.get("importance", 0)
            ),
            reverse=True
        )

        # Step 2: Greedily add until budget exhausted
        selected = []
        tokens_used = 0

        for memory in scored:
            mem_text = memory.get("text", memory.get("memory", ""))
            mem_tokens = self.detector.count_tokens(mem_text)

            if tokens_used + mem_tokens <= target_token_budget:
                selected.append(memory)
                tokens_used += mem_tokens
            else:
                # Try truncated version
                words = mem_text.split()
                truncated = " ".join(words[:30]) + "..."
                trunc_tokens = self.detector.count_tokens(truncated)

                if tokens_used + trunc_tokens <= target_token_budget:
                    truncated_memory = {**memory, "text": truncated,
                                       "_truncated": True}
                    selected.append(truncated_memory)
                    tokens_used += trunc_tokens

        print(f"  🗜️  Memory fixed: {len(memories)} → {len(selected)} "
              f"memories ({tokens_used:,} tokens)")
        return selected

    def fix_conversation_overflow(
        self,
        conversation: List[Dict],
        target_messages: int = 10,
        summarizer=None
    ) -> Tuple[List[Dict], Optional[str]]:
        """
        Fix conversation overflow using sliding window + optional summarization.
        
        Returns: (trimmed_conversation, summary_if_generated)
        """
        if len(conversation) <= target_messages:
            return conversation, None

        old_messages = conversation[:-target_messages]
        recent_messages = conversation[-target_messages:]

        summary = None
        if summarizer and old_messages:
            try:
                summary = summarizer.summarize_quick(old_messages)
            except Exception as e:
                print(f"  ⚠️ Summarization failed: {e}. Using truncation.")

        kept_count = len(old_messages)
        print(
            f"  🗜️  Conversation fixed: {len(conversation)} → "
            f"{len(recent_messages)} messages "
            f"({kept_count} {'summarized' if summary else 'truncated'})"
        )
        return recent_messages, summary

    def auto_fix(
        self,
        system_prompt: str,
        memories: List[Dict],
        conversation: List[Dict],
        target_utilization: float = 0.60
    ) -> Tuple[List[Dict], List[Dict], str]:
        """
        Automatically fix any detected overflow.
        
        Returns: (fixed_memories, fixed_conversation, status_message)
        """
        report = self.detector.check(
            system_prompt=system_prompt,
            memories=[m.get("text", "") for m in memories],
            conversation=conversation
        )

        if report.is_safe:
            return memories, conversation, "No overflow detected"

        target_tokens = int(
            self.detector.reliable_limit * target_utilization
        )
        system_tokens = report.system_prompt_tokens
        conv_tokens = report.conversation_tokens
        available_for_memories = (
            target_tokens - system_tokens - conv_tokens
        )

        # Fix memories first (easiest)
        fixed_memories = self.fix_memory_overflow(
            memories,
            target_token_budget=max(available_for_memories, 500)
        )

        # Fix conversation if still over budget
        re_check = self.detector.check(
            system_prompt=system_prompt,
            memories=[m.get("text", "") for m in fixed_memories],
            conversation=conversation
        )

        fixed_conversation = conversation
        if re_check.needs_compression:
            fixed_conversation, _ = self.fix_conversation_overflow(
                conversation, target_messages=8
            )

        return fixed_memories, fixed_conversation, (
            f"Fixed: {report.total_tokens:,} → "
            f"estimated ~{target_tokens:,} tokens"
        )


# ── USAGE EXAMPLE ────────────────────────────────────────────────
if __name__ == "__main__":
    detector = ContextOverflowDetector(model="gpt-4o-mini")
    fixer = ContextOverflowFixer(detector)

    # Simulate a bloated context
    system_prompt = "You are a helpful AI assistant with memory."
    memories = [f"Memory fact {i}: User data point {i}" * 20
                for i in range(30)]  # 30 large memories = overflow!
    conversation = [
        {"role": "user", "content": f"Message {i}"}
        for i in range(50)
    ]

    report = detector.check_and_print(
        system_prompt=system_prompt,
        memories=memories,
        conversation=conversation
    )

    if report.needs_compression:
        fixed_mems, fixed_conv, status = fixer.auto_fix(
            system_prompt, 
            [{"text": m} for m in memories],
            conversation
        )
        print(f"Fix status: {status}")
        print(f"Fixed: {len(fixed_mems)} memories, "
              f"{len(fixed_conv)} messages")
```

# 📅 FAILURE MODE 2: Stale or Outdated Memory

## 1. What Is It?

> **Stale Memory = A memory fact that was true when stored but is no longer true — yet the system continues treating it as current reality, causing the AI to act on outdated information.**

---

## 2. First-Principles Breakdown

```
THE FUNDAMENTAL PROBLEM:
  Memory systems are good at storing facts.
  They are TERRIBLE at knowing when facts expire.

  The world changes constantly:
  → People change jobs, cities, technologies
  → Projects complete, pivot, or die
  → Prices, policies, and preferences evolve
  → Technical versions get upgraded

  But memory systems keep facts forever unless told to delete.
  Result: The AI confidently uses WRONG information.

REAL EXAMPLES OF STALE MEMORY DISASTERS:
  Stored 6 months ago: "User uses Python 3.8"
  Reality today: User upgraded to Python 3.12
  AI: Gives advice for 3.8 features → causes confusion

  Stored 1 year ago: "User works at Google"
  Reality today: User left Google, now at a startup
  AI: "How's everything going at Google?" → embarrassing

  Stored 3 months ago: "User's deadline is December 15th"
  Reality today: Project was cancelled in October
  AI: "Are you on track for your December 15th deadline?" → wrong
```

The biggest enterprise failure mode is not wrong memory. It is memory that should not exist anymore.

---

## 3. Analogy: The Outdated Tour Guide Book

```
📖 Stale Memory = Using a 5-Year-Old Travel Guidebook

Tourist (AI user): "What restaurant should I visit in Paris?"
Guidebook (stale memory): "Le Grand Café on Rue Rivoli — excellent!"
Reality: That restaurant closed 3 years ago.

Tourist follows guidebook to an empty building.
"The guide says it's here!" Yes, it WAS here 5 years ago.
Now it's a pharmacy.

The guidebook had PERFECT information when written.
Time made it WRONG.

The guide didn't become wrong because of an error.
It became wrong because the WORLD CHANGED
but the guide didn't update.

THIS IS STALE MEMORY.
Correct at time of storage → Wrong at time of retrieval.
```

---

## 4. Staleness Taxonomy

```
STALENESS BY TYPE:

FACT STALENESS (User changed):
  "User is a junior developer" → now senior
  "User uses Django" → switched to FastAPI
  "User lives in Dhaka" → moved to London

VERSION STALENESS (Technology changed):
  "User uses GPT-3.5" → GPT-4o is available
  "Recommended library: requests 2.28" → 2.31 is current
  "Use this API endpoint" → endpoint deprecated

RELATIONSHIP STALENESS (Situation changed):
  "User is working on Project X" → project finished
  "User is debugging bug #4521" → bug was fixed yesterday
  "User's colleague is Bob" → Bob left the company

PREFERENCE STALENESS (User evolved):
  "User prefers verbose explanations" → now wants concise
  "User doesn't know Kubernetes" → took a course, now expert
  "User likes Java" → switched to Rust

POLICY STALENESS (Rules changed):
  "Free tier limit is 100 API calls/day" → changed to 50
  "Company uses AWS" → migrated to Azure
```

```python
# stale_memory_detector.py
import math
from datetime import datetime, timedelta
from typing import List, Dict, Optional, Tuple, Set
from dataclasses import dataclass, field
from openai import OpenAI
import json


@dataclass
class StalenessAssessment:
    """Assessment of a memory's staleness risk."""
    memory_id: str
    memory_text: str
    staleness_score: float        # 0 = fresh, 1 = definitely stale
    staleness_risk: str           # low, medium, high, critical
    days_old: int
    days_since_accessed: int
    staleness_signals: List[str]  # Why we think it's stale
    recommended_action: str       # verify, update, archive, keep


class StalenessDetector:
    """
    Detects potentially stale memories using multiple signals.
    
    DETECTION SIGNALS:
    1. Age of memory (old = higher staleness risk)
    2. Category (tech facts expire faster than identity facts)
    3. Temporal language ("current", "now", "this week" = high risk)
    4. Version numbers (v2.3.1 in stored memory = outdated risk)
    5. Contradiction signals from recent messages
    6. User-provided corrections
    """

    # How fast each category goes stale (days to reach 50% staleness)
    CATEGORY_HALF_LIVES = {
        "core_identity":    3650,   # 10 years — names rarely change
        "contact_info":     365,    # 1 year — emails/phones change
        "project_fact":     180,    # 6 months
        "technical":        90,     # 3 months — tech moves fast!
        "version_info":     30,     # 1 month — versions change constantly
        "debugging":        60,     # 2 months
        "preference":       365,    # 1 year
        "task_context":     3,      # 3 days — tasks complete quickly
        "session_context":  1,      # 1 day
        "casual":           30,     # 1 month
        "price_policy":     30,     # 1 month — prices change often
    }

    # High-risk temporal language patterns
    TEMPORAL_PATTERNS = [
        "currently", "right now", "at the moment", "as of today",
        "this week", "this month", "today", "now working on",
        "current version", "latest version", "just released",
        "recently", "just started", "just finished",
        "this quarter", "this year's"
    ]

    # Version number pattern (high staleness risk)
    VERSION_PATTERNS = [
        r"\d+\.\d+\.\d+",    # semantic version: 3.11.2
        r"v\d+\.\d+",         # v prefix: v2.3
        r"version \d+",       # written out: version 3
    ]

    def compute_staleness_score(
        self,
        memory: Dict
    ) -> Tuple[float, List[str]]:
        """
        Compute staleness score (0=fresh → 1=stale) for a memory.
        Returns (score, signals_that_triggered)
        """
        signals = []
        score = 0.0

        # ── Signal 1: Age-based decay ─────────────────────────
        created_str = memory.get("created_at", datetime.now().isoformat())
        if isinstance(created_str, str):
            created = datetime.fromisoformat(created_str)
        else:
            created = created_str

        days_old = (datetime.now() - created).days

        category = memory.get("category", "casual")
        half_life = self.CATEGORY_HALF_LIVES.get(category, 90)

        # Exponential decay: score = 1 - e^(-ln(2) * days / half_life)
        # At half_life days → score = 0.5 (50% stale)
        age_score = 1 - math.exp(-math.log(2) * days_old / half_life)
        score += age_score * 0.40

        if days_old > half_life:
            signals.append(
                f"Age: {days_old} days old (half-life: {half_life} days)"
            )

        # ── Signal 2: Temporal language ───────────────────────
        text = memory.get("text", "").lower()
        temporal_found = [p for p in self.TEMPORAL_PATTERNS if p in text]

        if temporal_found:
            temporal_score = min(len(temporal_found) * 0.2, 0.6)
            score += temporal_score * 0.25
            signals.append(
                f"Temporal language: {temporal_found[:3]}"
            )

        # ── Signal 3: Version numbers ─────────────────────────
        import re
        version_found = any(
            re.search(pattern, memory.get("text", ""))
            for pattern in self.VERSION_PATTERNS
        )

        if version_found:
            score += 0.3 * 0.20
            signals.append("Contains version number (versions change often)")

        # ── Signal 4: Access recency ──────────────────────────
        last_accessed_str = memory.get("last_accessed_at")
        if last_accessed_str:
            if isinstance(last_accessed_str, str):
                last_accessed = datetime.fromisoformat(last_accessed_str)
            else:
                last_accessed = last_accessed_str

            days_not_accessed = (datetime.now() - last_accessed).days

            if days_not_accessed > half_life * 2:
                score += 0.15
                signals.append(
                    f"Not accessed in {days_not_accessed} days"
                )

        # ── Signal 5: Superseded flag ─────────────────────────
        if memory.get("is_superseded", False):
            score = max(score, 0.95)
            signals.append("SUPERSEDED: explicitly marked as outdated")

        # ── Signal 6: Low confidence ──────────────────────────
        confidence = memory.get("confidence", 1.0)
        if confidence < 0.5:
            score += (1 - confidence) * 0.10
            signals.append(
                f"Low confidence score: {confidence:.2f}"
            )

        final_score = min(1.0, score)
        return round(final_score, 4), signals

    def assess_memory(self, memory: Dict) -> StalenessAssessment:
        """Full staleness assessment for a single memory."""
        score, signals = self.compute_staleness_score(memory)

        # Determine risk level
        if score < 0.25:   risk = "low"
        elif score < 0.50: risk = "medium"
        elif score < 0.75: risk = "high"
        else:              risk = "critical"

        # Determine recommended action
        if score < 0.25:
            action = "keep"
        elif score < 0.50:
            action = "verify_on_next_interaction"
        elif score < 0.75:
            action = "mark_for_verification"
        else:
            action = "archive_or_delete"

        # Calculate days
        created_str = memory.get("created_at", datetime.now().isoformat())
        created = (
            datetime.fromisoformat(created_str)
            if isinstance(created_str, str)
            else created_str
        )

        last_acc_str = memory.get("last_accessed_at")
        if last_acc_str:
            last_acc = (
                datetime.fromisoformat(last_acc_str)
                if isinstance(last_acc_str, str) else last_acc_str
            )
            days_since_accessed = (datetime.now() - last_acc).days
        else:
            days_since_accessed = (datetime.now() - created).days

        return StalenessAssessment(
            memory_id=memory.get("id", ""),
            memory_text=memory.get("text", "")[:100],
            staleness_score=score,
            staleness_risk=risk,
            days_old=(datetime.now() - created).days,
            days_since_accessed=days_since_accessed,
            staleness_signals=signals,
            recommended_action=action
        )

    def scan_all_memories(
        self,
        memories: List[Dict],
        user_id: str
    ) -> Dict:
        """
        Scan ALL memories for a user and produce staleness report.
        Run as a weekly background job.
        """
        user_memories = [
            m for m in memories if m.get("user_id") == user_id
        ]

        assessments = [self.assess_memory(m) for m in user_memories]

        critical = [a for a in assessments if a.staleness_risk == "critical"]
        high     = [a for a in assessments if a.staleness_risk == "high"]
        medium   = [a for a in assessments if a.staleness_risk == "medium"]
        low      = [a for a in assessments if a.staleness_risk == "low"]

        print(f"\n{'='*60}")
        print(f"🕐 STALENESS SCAN REPORT — User: {user_id}")
        print(f"{'='*60}")
        print(f"  Total memories scanned: {len(assessments)}")
        print(f"  🔴 Critical (likely stale):  {len(critical)}")
        print(f"  🟠 High (probably stale):    {len(high)}")
        print(f"  🟡 Medium (might be stale):  {len(medium)}")
        print(f"  🟢 Low (likely fresh):       {len(low)}")

        if critical:
            print(f"\n  ⚠️  TOP CRITICAL STALE MEMORIES:")
            for a in sorted(critical,
                            key=lambda x: x.staleness_score,
                            reverse=True)[:5]:
                print(f"    [{a.staleness_score:.2f}] {a.memory_text[:55]}")
                print(f"           → {a.staleness_signals[0]
                                       if a.staleness_signals else 'age'}")

        return {
            "total": len(assessments),
            "critical": len(critical),
            "high": len(high),
            "medium": len(medium),
            "low": len(low),
            "action_required": len(critical) + len(high),
            "critical_memories": [a.memory_id for a in critical]
        }


class StalenessVerifier:

Respond with JSON:

        response = self.client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )

        return json.loads(response.choices[0].message.content)

    def detect_contradiction_in_new_message(

        potential contradictions with what they just said.

        contradictions = []

        for memory in existing_memories[:20]:  # Check top memories
            mem_text = memory.get("text", "")

            prompt = f"""Does this new user statement CONTRADICT or UPDATE this memory?

NEW STATEMENT: "{new_message}"

Respond: {{"contradicts": true/false, "confidence": 0.0-1.0, "reason": "..."}}
Only flag CLEAR contradictions, not just related topics."""

            try:
                response = self.client.chat.completions.create(
                    model="gpt-4o-mini",
                    messages=[{"role": "user", "content": prompt}],
                    temperature=0,
                    response_format={"type": "json_object"}
                )
                result = json.loads(
                    response.choices[0].message.content

                if result.get("contradicts") and result.get("confidence", 0) > 0.8:
                    contradictions.append({
                        "memory": mem_text,
                        "memory_id": memory.get("id"),
                        "contradiction_confidence": result["confidence"],
                        "reason": result["reason"]
                    })
            except Exception:
                continue

        return contradictions
```

# ⚡ FAILURE MODE 3: Contradictory Memory

## 1. What Is It?

> **Contradictory Memory = Two or more stored memories assert OPPOSING facts about the same entity or concept. When the LLM encounters both, it becomes confused, hallucinates a resolution, or randomly picks one — producing unpredictable, unreliable responses.**

---

## 2. First-Principles Breakdown

```
THE CORE PROBLEM:
  Memory systems store facts.
  Facts change.
  Old facts are not always deleted.
  New facts are stored alongside old ones.
  
  Result: Same subject → Two opposite answers.

EXAMPLE:
  Session 1 (Jan): Stored → "User works at Google in London"
  Session 6 (Mar): Stored → "User recently joined a startup in Berlin"
  Session 12 (Jul): Both memories still in the DB!

  User asks: "Where do I work?"
  
  Memory retrieval returns BOTH:
    Memory 1: "Works at Google in London"
    Memory 2: "Recently joined startup in Berlin"
  
  LLM sees two contradictory facts.
  LLM response: ??? (Could say either one. Could hallucinate a blend.)
  "You mentioned working at Google... or was it a startup in Berlin?"
  COMPLETELY UNRELIABLE! 😱
```

Agents may store contradictory memory entries. Without a resolution strategy, systems either contradict themselves or hallucinate. Mitigation: introduce versioning and confidence scoring for memory items.

---

## 3. Analogy: The Conflicting Witness Statements

```
⚖️ Contradictory Memory = Conflicting Witness Statements in Court

Witness A: "The suspect was wearing a red jacket."
Witness B: "The suspect was wearing a blue jacket."

JUDGE OPTIONS:
  Option 1: Trust Witness A (arbitrary)
  Option 2: Trust Witness B (arbitrary)
  Option 3: Fabricate: "The jacket was red-blue" (hallucinate)
  Option 4: "The jacket was indeterminate" (refuse to answer)
  Option 5: Investigate: "Who has more evidence? What's the timeline?"

The court uses Option 5 — proper investigation.
Most AI systems use Options 1-4 (bad!)

PROPER RESOLUTION:
  More recent witness → likely more accurate
  More detailed witness → likely more reliable
  Cross-reference with other evidence
  When uncertain → flag for human review

AI memory contradiction resolution = Legal evidence evaluation.
You need a systematic process, not random selection.
```

---

## 4. Types of Contradictions

```
TYPE 1: DIRECT CONTRADICTION (Same fact, opposite value)
  Memory A: "User is a Python developer"
  Memory B: "User is a Java developer"
  → Clear conflict, one must be wrong or superseded

TYPE 2: TEMPORAL CONTRADICTION (Old vs new)
  Memory A: "User uses Python 3.8" (6 months ago)
  Memory B: "User upgraded to Python 3.12" (1 month ago)
  → Resolution: newer memory wins
  → Action: Mark Memory A as superseded

TYPE 3: PARTIAL CONTRADICTION (Overlap with conflict)
  Memory A: "User's project uses PostgreSQL"
  Memory B: "User migrated from PostgreSQL to MongoDB"
  → Resolution: B supersedes A for the storage fact
  → But both might be partially true (during migration?)

TYPE 4: SCOPE CONTRADICTION (Different contexts, seem to conflict)
  Memory A: "User prefers Python for backend"
  Memory B: "User prefers TypeScript for projects"
  → NOT a contradiction! Different contexts.
  → Resolution: Keep both, add scope labels
```

```python
# contradiction_detector.py
from openai import OpenAI
from typing import List, Dict, Optional, Tuple
from dataclasses import dataclass, field
from datetime import datetime
import json
from enum import Enum


class ResolutionStrategy(Enum):
    NEWER_WINS         = "newer_wins"
    HIGHER_CONFIDENCE  = "higher_confidence"
    MERGE              = "merge"
    KEEP_BOTH          = "keep_both"
    FLAG_FOR_HUMAN     = "flag_for_human"
    LLM_RESOLVE        = "llm_resolve"


@dataclass
class ContradictionPair:
    """A detected pair of contradicting memories."""
    memory_a_id: str
    memory_a_text: str
    memory_a_created: str
    memory_a_confidence: float

    memory_b_id: str
    memory_b_text: str
    memory_b_created: str
    memory_b_confidence: float

    contradiction_type: str
    contradiction_confidence: float
    resolution: Optional[str] = None
    resolution_strategy: Optional[str] = None
    winner_id: Optional[str] = None
    loser_id: Optional[str] = None


class ContradictionDetector:
    """
    Detects and resolves contradictions in AI memory.
    
    TWO APPROACHES:
    1. Fast (heuristic): Subject overlap + opposing patterns
    2. Accurate (LLM): Ask LLM to compare memory pairs
    
    Use Fast approach during read (low latency)
    Use Accurate approach during background maintenance jobs
    """

    def __init__(self):
        self.client = OpenAI()

    # ── HEURISTIC DETECTION (Fast, runs during retrieval) ──────

    # Pairs of words that signal contradiction
    CONTRADICTION_PATTERNS = [
        (["works at", "employed at", "job at"], "employer"),
        (["lives in", "based in", "located in"], "location"),
        (["uses python", "python developer"], "python_usage"),
        (["uses java", "java developer"], "java_usage"),
        (["version", "v", "release"], "version"),
        (["prefers", "likes", "loves", "favors"], "preference"),
        (["doesn't use", "not using", "stopped using",
          "switched away from"], "negation"),
    ]

    def fast_contradiction_check(
        self,
        memories: List[Dict]
    ) -> List[Tuple[int, int, str]]:
        """
        Quick heuristic scan for potential contradictions.
        Returns: List of (index_a, index_b, potential_topic)
        
        Runs in O(n²) — only use for small sets (< 50 memories).
        For larger sets, use the entity-based approach.
        """
        potential_conflicts = []

        for i in range(len(memories)):
            for j in range(i + 1, len(memories)):
                text_a = memories[i].get("text", "").lower()
                text_b = memories[j].get("text", "").lower()

                for keywords, topic in self.CONTRADICTION_PATTERNS:
                    a_matches = any(kw in text_a for kw in keywords)
                    b_matches = any(kw in text_b for kw in keywords)

                    if a_matches and b_matches:
                        # Both mention the same topic → potential conflict
                        potential_conflicts.append((i, j, topic))
                        break

        return potential_conflicts

    # ── LLM DETECTION (Accurate, runs in background) ───────────

    def llm_check_contradiction(
        self,
        memory_a: Dict,
        memory_b: Dict
    ) -> Dict:
        """
        Use LLM to determine if two memories contradict each other.
        
        More accurate than heuristics but costs API calls.
        Use for: periodic background sweeps, post-retrieval checks.
        """
        text_a = memory_a.get("text", "")
        text_b = memory_b.get("text", "")
        date_a = memory_a.get("created_at", "unknown")
        date_b = memory_b.get("created_at", "unknown")

        prompt = f"""Analyze two memory facts about the same person/system.
Determine if they CONTRADICT each other.

Memory A (stored: {date_a}):
"{text_a}"

Memory B (stored: {date_b}):
"{text_b}"

Respond with JSON:
{{
  "contradicts": true/false,
  "contradiction_type": "direct/temporal/partial/scope/none",
  "confidence": 0.0-1.0,
  "topic": "what aspect they conflict on",
  "resolution": "newer_wins/merge/keep_both/llm_resolve",
  "reasoning": "brief explanation",
  "suggested_canonical": "best single fact that should remain"
}}

IMPORTANT: Only flag REAL contradictions, not just related topics.
"User likes Python" and "User likes JavaScript" = NOT a contradiction.
"User works at Google" and "User works at Meta" = CONTRADICTION."""

        response = self.client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )

        return json.loads(response.choices[0].message.content)

    def resolve_contradiction(
        self,
        pair: ContradictionPair,
        strategy: ResolutionStrategy = ResolutionStrategy.NEWER_WINS
    ) -> Dict:
        """
        Apply resolution strategy to a contradiction pair.
        
        Returns: {
            "action": "delete_a" | "delete_b" | "update_a" | "merge",
            "keep_id": str,
            "delete_id": str,
            "new_text": str (if merge),
            "reason": str
        }
        """
        if strategy == ResolutionStrategy.NEWER_WINS:
            # Determine which is newer
            date_a = datetime.fromisoformat(pair.memory_a_created)
            date_b = datetime.fromisoformat(pair.memory_b_created)

            if date_b > date_a:
                # B is newer → keep B, delete A
                return {
                    "action": "delete_loser",
                    "keep_id": pair.memory_b_id,
                    "delete_id": pair.memory_a_id,
                    "reason": f"Memory B is newer ({pair.memory_b_created})"
                }
            else:
                return {
                    "action": "delete_loser",
                    "keep_id": pair.memory_a_id,
                    "delete_id": pair.memory_b_id,
                    "reason": f"Memory A is newer ({pair.memory_a_created})"
                }

        elif strategy == ResolutionStrategy.HIGHER_CONFIDENCE:
            if pair.memory_a_confidence >= pair.memory_b_confidence:
                return {
                    "action": "delete_loser",
                    "keep_id": pair.memory_a_id,
                    "delete_id": pair.memory_b_id,
                    "reason": (
                        f"Memory A has higher confidence "
                        f"({pair.memory_a_confidence:.2f} vs "
                        f"{pair.memory_b_confidence:.2f})"
                    )
                }
            else:
                return {
                    "action": "delete_loser",
                    "keep_id": pair.memory_b_id,
                    "delete_id": pair.memory_a_id,
                    "reason": "Memory B has higher confidence"
                }

        elif strategy == ResolutionStrategy.FLAG_FOR_HUMAN:
            return {
                "action": "flag_for_human",
                "keep_id": None,
                "delete_id": None,
                "reason": "Contradiction requires human review"
            }

        # Default: newer wins
        return self.resolve_contradiction(
            pair, ResolutionStrategy.NEWER_WINS
        )

    def run_contradiction_scan(
        self,
        memories: List[Dict],
        user_id: str,
        use_llm: bool = False
    ) -> List[ContradictionPair]:
        """
        Full contradiction scan for a user's memories.
        
        use_llm=False: Fast heuristic scan (use for real-time)
        use_llm=True: LLM-powered accurate scan (use for maintenance)
        """
        user_memories = [
            m for m in memories if m.get("user_id") == user_id
        ]

        print(f"\n🔍 CONTRADICTION SCAN")
        print(f"   Memories: {len(user_memories)}")
        print(f"   Mode: {'LLM-powered' if use_llm else 'Heuristic (fast)'}")

        contradictions = []

        if use_llm:
            # LLM scan — check all pairs
            for i in range(len(user_memories)):
                for j in range(i + 1, len(user_memories)):
                    result = self.llm_check_contradiction(
                        user_memories[i], user_memories[j]
                    )

                    if result.get("contradicts") and result.get("confidence", 0) > 0.75:
                        pair = ContradictionPair(
                            memory_a_id=user_memories[i].get("id", ""),
                            memory_a_text=user_memories[i].get("text", ""),
                            memory_a_created=user_memories[i].get(
                                "created_at", ""
                            ),
                            memory_a_confidence=user_memories[i].get(
                                "confidence", 1.0
                            ),
                            memory_b_id=user_memories[j].get("id", ""),
                            memory_b_text=user_memories[j].get("text", ""),
                            memory_b_created=user_memories[j].get(
                                "created_at", ""
                            ),
                            memory_b_confidence=user_memories[j].get(
                                "confidence", 1.0
                            ),
                            contradiction_type=result.get(
                                "contradiction_type", "unknown"
                            ),
                            contradiction_confidence=result.get(
                                "confidence", 0.5
                            ),
                        )
                        contradictions.append(pair)
        else:
            # Fast heuristic scan
            conflicts = self.fast_contradiction_check(user_memories)
            for i, j, topic in conflicts:
                pair = ContradictionPair(
                    memory_a_id=user_memories[i].get("id", ""),
                    memory_a_text=user_memories[i].get("text", ""),
                    memory_a_created=user_memories[i].get("created_at", ""),
                    memory_a_confidence=user_memories[i].get("confidence", 1.0),
                    memory_b_id=user_memories[j].get("id", ""),
                    memory_b_text=user_memories[j].get("text", ""),
                    memory_b_created=user_memories[j].get("created_at", ""),
                    memory_b_confidence=user_memories[j].get("confidence", 1.0),
                    contradiction_type="potential_" + topic,
                    contradiction_confidence=0.5,  # Heuristic uncertainty
                )
                contradictions.append(pair)

        print(f"   Found: {len(contradictions)} contradictions")
        return contradictions
```

# 🌊 FAILURE MODE 4: Retrieval Drift

## 1. What Is It?

> **Retrieval Drift = The memory retrieval system returns memories that are semantically RELATED but not actually RELEVANT to the current query. These off-target memories subtly steer the LLM toward wrong conclusions — without any obvious error signal.**

Retrieval-based memory adds selection error: stale, conflicting, or injected artifacts can perturb the current task state and destabilize long-horizon behavior. Retrieval systems optimize for semantic similarity rather than decision relevance, allowing recalled artifacts to perturb goals, constraints, and intermediate assumptions in unstable ways.

---

## 2. First-Principles Breakdown

```
THE SIMILARITY ≠ RELEVANCE PROBLEM:
  Vector search finds memories SIMILAR to the query.
  But similar ≠ relevant to THIS query's actual need.

EXAMPLE:
  User query: "What Python libraries should I use for my project?"
  
  Memory retrieved: "User uses Python for data science projects"
  ↓
  AI thinks: User wants DATA SCIENCE libraries
  AI answers: "For your project, use pandas, numpy, sklearn..."
  
  Reality: User was asking about WEB DEVELOPMENT libraries
  Their project is a Flask API, not a data science project!
  
  The memory was SIMILAR to Python (correct)
  but NOT RELEVANT to the question about THIS project.
  
  Result: AI drifted toward data science answer.
  User is confused: "Why is it recommending data science tools?"
```

```python
# retrieval_drift_detector.py
from openai import OpenAI
from typing import List, Dict, Optional, Tuple
import numpy as np
import json
from dataclasses import dataclass


@dataclass
class DriftReport:
    """Report on retrieval drift for a single retrieval."""
    query: str
    memories_retrieved: int
    drift_detected: bool
    drift_score: float           # 0 = no drift, 1 = severe drift
    problematic_memories: List[Dict]
    clean_memories: List[Dict]
    drift_types: List[str]
    recommendation: str


class RetrievalDriftDetector:
    """
    Detects and prevents retrieval drift.
    
    CORE INSIGHT:
    Cosine similarity measures EMBEDDING distance.
    We need RELEVANCE to the CURRENT TASK — which is different.
    
    A memory can be:
    HIGH similarity + LOW relevance → retrieval drift!
    LOW similarity + HIGH relevance → retrieval miss!
    
    We need to ADD a relevance layer ON TOP of similarity.
    """

    def __init__(self):
        self.client = OpenAI()

    def compute_relevance_reranking(
        self,
        query: str,
        memories: List[Dict],
        current_task_context: str = None
    ) -> List[Dict]:
        """
        Re-rank retrieved memories by TRUE RELEVANCE, not just similarity.
        
        This is a Cross-Encoder approach:
        Instead of comparing embeddings (bi-encoder),
        we feed (query, memory) pair to LLM and ask:
        "How relevant is this memory to answering this query?"
        
        More expensive than vector search, but much more accurate.
        Only run this on top 10-15 candidates from vector search.
        """
        if not memories:
            return []

        memories_text = "\n".join([
            f"[{i}] {m.get('text', m.get('memory', ''))}"
            for i, m in enumerate(memories)
        ])

        context_str = (
            f"\nCurrent task context: {current_task_context}"
            if current_task_context else ""
        )

        prompt = f"""You are a relevance judge for a memory system.

User query: "{query}"{context_str}

Retrieved memories:
{memories_text}

For each memory, rate its TRUE RELEVANCE to answering the user's query.
Consider: Does this memory DIRECTLY help answer the question?
(Not just related topic — actually useful for THIS query)

Return JSON array with scores (0.0-1.0):
[{{"index": 0, "relevance": 0.9, "reason": "..."}}, ...]

Be STRICT. If a memory is only tangentially related, score < 0.5.
If unrelated despite superficial similarity, score < 0.2."""

        try:
            response = self.client.chat.completions.create(
                model="gpt-4o-mini",
                messages=[{"role": "user", "content": prompt}],
                temperature=0,
                response_format={"type": "json_object"}
            )

            # Parse response
            raw = json.loads(response.choices[0].message.content)
            scores = raw if isinstance(raw, list) else raw.get("scores", [])

            # Apply relevance scores to memories
            for score_item in scores:
                idx = score_item.get("index", -1)
                if 0 <= idx < len(memories):
                    memories[idx]["relevance_score"] = score_item.get(
                        "relevance", 0.5
                    )
                    memories[idx]["relevance_reason"] = score_item.get(
                        "reason", ""
                    )

            # Sort by relevance (highest first)
            memories_with_scores = [
                m for m in memories if "relevance_score" in m
            ]
            return sorted(
                memories_with_scores,
                key=lambda m: m["relevance_score"],
                reverse=True
            )

        except Exception as e:
            print(f"  ⚠️ Reranking failed: {e}. Using original order.")
            return memories

    def filter_by_relevance(
        self,
        memories: List[Dict],
        min_relevance: float = 0.6
    ) -> Tuple[List[Dict], List[Dict]]:
        """
        Filter memories by relevance score.
        Returns: (kept_memories, filtered_out_memories)
        """
        kept = []
        filtered = []

        for memory in memories:
            rel_score = memory.get("relevance_score", 0.5)
            if rel_score >= min_relevance:
                kept.append(memory)
            else:
                filtered.append(memory)

        return kept, filtered

    def detect_topic_drift(
        self,
        query: str,
        memories: List[Dict]
    ) -> DriftReport:
        """
        Detect if retrieved memories have drifted from the query topic.
        """
        problematic = []
        clean = []
        drift_types = []

        for memory in memories:
            text = memory.get("text", "").lower()
            similarity = memory.get("similarity", 0.5)
            relevance = memory.get("relevance_score", similarity)

            # Drift signal: HIGH similarity but LOW relevance
            if similarity > 0.7 and relevance < 0.5:
                problematic.append(memory)
                drift_types.append("high_similarity_low_relevance")
            else:
                clean.append(memory)

        drift_score = len(problematic) / max(len(memories), 1)
        drift_detected = drift_score > 0.3

        recommendation = ""
        if drift_detected:
            if drift_score > 0.6:
                recommendation = (
                    "Severe drift: Remove all problematic memories, "
                    "add stronger metadata filters to query"
                )
            else:
                recommendation = (
                    "Moderate drift: Filter out low-relevance memories, "
                    "consider adding task context to retrieval query"
                )
        else:
            recommendation = "No significant drift detected"

        return DriftReport(
            query=query,
            memories_retrieved=len(memories),
            drift_detected=drift_detected,
            drift_score=round(drift_score, 3),
            problematic_memories=problematic,
            clean_memories=clean,
            drift_types=list(set(drift_types)),
            recommendation=recommendation
        )

    def build_anti_drift_query(
        self,
        original_query: str,
        current_task_context: str = None,
        recent_messages: List[Dict] = None,
        excluded_topics: List[str] = None
    ) -> str:
        """
        Build an enriched query that reduces retrieval drift.
        
        THE TECHNIQUE: Instead of searching with just the user's question,
        add context that NARROWS the search to truly relevant memories.
        
        Original: "How do I fix this error?"
        Enhanced: "Flask API debugging error, web development context,
                   NOT data science, NOT general Python"
        
        The enhanced query guides vector search to the RIGHT neighborhood.
        """
        parts = [original_query]

        if current_task_context:
            parts.append(f"[Context: {current_task_context}]")

        if recent_messages:
            # Add recent topics from conversation
            recent_topics = []
            for msg in recent_messages[-3:]:
                content = msg.get("content", "")[:100]
                recent_topics.append(content)
            if recent_topics:
                parts.append(f"[Recent: {', '.join(recent_topics)}]")

        if excluded_topics:
            parts.append(f"[Exclude: {', '.join(excluded_topics)}]")

        return " | ".join(parts)

    def maximal_marginal_relevance(
        self,
        query_embedding: List[float],
        candidate_memories: List[Dict],
        memory_embeddings: List[List[float]],
        lambda_: float = 0.7,
        k: int = 5
    ) -> List[Dict]:
        """
        Maximal Marginal Relevance (MMR) selection.
        
        PURPOSE: Select memories that are:
        1. Relevant to the query (relevance)
        2. Diverse from each other (diversity)
        
        WHY: Without diversity, all 5 retrieved memories
             might be slight variations of the same memory!
             That's redundant AND causes context pollution.
        
        lambda_ controls the tradeoff:
        lambda_ = 1.0 → pure relevance (no diversity)
        lambda_ = 0.0 → pure diversity (no relevance)
        lambda_ = 0.7 → balanced (recommended)
        """
        if not candidate_memories or not memory_embeddings:
            return candidate_memories[:k]

        query_vec = np.array(query_embedding)
        mem_vecs = [np.array(emb) for emb in memory_embeddings]

        def cosine_sim(v1, v2):
            norm = np.linalg.norm(v1) * np.linalg.norm(v2)
            return float(np.dot(v1, v2) / norm) if norm > 0 else 0.0

        # Start with most relevant memory
        relevance_scores = [
            cosine_sim(query_vec, v) for v in mem_vecs
        ]
        selected_indices = [int(np.argmax(relevance_scores))]
        remaining = [i for i in range(len(candidate_memories))
                     if i not in selected_indices]

        # Iteratively add memories that maximize MMR
        while len(selected_indices) < k and remaining:
            mmr_scores = []

            for i in remaining:
                # Relevance to query
                rel_score = cosine_sim(query_vec, mem_vecs[i])

                # Maximum similarity to already-selected
                max_sim_to_selected = max(
                    cosine_sim(mem_vecs[i], mem_vecs[j])
                    for j in selected_indices
                )

                # MMR = λ × relevance - (1-λ) × max_similarity_to_selected
                mmr = lambda_ * rel_score - (1 - lambda_) * max_sim_to_selected
                mmr_scores.append((mmr, i))

            # Select best MMR score
            best_score, best_idx = max(mmr_scores, key=lambda x: x[0])
            selected_indices.append(best_idx)
            remaining.remove(best_idx)

        return [candidate_memories[i] for i in selected_indices]
```

```python
            r"(?i)(api[_-]?key|apikey|secret[_-]?key)\s*[:=]\s*\S{10,}",

        ),
        "bank_account": (
            r"\b\d{8,17}\b",
            "potential_bank_account"
        ),
    }

    def scan(self, text: str) -> List[Dict]:
        """
        Scan text for PII patterns.
        Returns list of detected PII items.
        """
        detected = []

        for pii_type, (pattern, label) in self.PII_PATTERNS.items():
            matches = re.findall(pattern, text)
            if matches:
                detected.append({
                    "type": label,
                    "count": len(matches),
                    "sample_masked": self._mask(matches[0])
                })

        return detected

    def _mask(self, value: str) -> str:
        """Mask PII value for logging."""
        if len(value) <= 4:
            return "****"
        return value[:2] + "*" * (len(value) - 4) + value[-2:]

    def contains_pii(self, text: str) -> bool:
        return len(self.scan(text)) > 0

    def sanitize(self, text: str) -> Tuple[str, List[str]]:
        """
        Replace PII with masked versions.
        Returns: (sanitized_text, list_of_removed_pii_types)
        """
        removed_types = []
        sanitized = text

        for pii_type, (pattern, label) in self.PII_PATTERNS.items():
            matches = re.findall(pattern, sanitized)
            if matches:
                sanitized = re.sub(pattern, f"[REDACTED_{label.upper()}]",
                                   sanitized)
                removed_types.append(label)

        return sanitized, removed_types

            }

                        mandatory_filter,
                        safe_additional
                    ]
                }
```

# 🎯 INTERVIEW QUESTIONS + STRONG ANSWERS

### ❓ Q1: "What are the main failure modes of AI memory systems and why are they dangerous?"

**💬 Strong Answer:**
> "There are five major failure modes, and all of them are dangerous for the same reason: they fail silently. The API returns 200 OK, no exception is thrown, but the AI is wrong. Context overflow happens when too much memory is injected into the context window, causing the attention mechanism to dilute — the LLM can't reliably attend to all tokens, so important facts get buried. Stale memory occurs when facts that were true when stored are no longer true, but the system treats them as current reality. Contradictory memory happens when two stored facts assert opposing things about the same subject. Retrieval drift is when the vector search returns semantically related but pragmatically irrelevant memories, subtly steering the LLM toward wrong conclusions. Privacy leakage is when one user's memories are exposed to another through missing access controls. The common thread: none of these produce an error — they produce confident, smooth, plausible-sounding but wrong answers."

---

### ❓ Q2: "Explain the 'Lost in the Middle' problem and how you handle it."

**💬 Strong Answer:**
> "The Lost in the Middle problem refers to the empirically observed phenomenon where LLMs struggle to reliably use information positioned in the middle of a long context — they attend well to the beginning and end but miss the middle. This means if I inject a critical memory at position 50,000 of a 100,000-token prompt, the LLM may ignore it even though it's well within the advertised context limit. The practical implication is that the true reliable limit of an LLM is around 60 to 70 percent of its advertised limit — if GPT-4o advertises 128K tokens, I treat 90K as my real safe limit. My mitigations are: first, always check token count before each LLM call and compress if above the reliable limit. Second, place the most important memories near the beginning of the context, not the middle. Third, limit retrieved memories to the top 5 to 7 by relevance rather than pulling everything. Fourth, use rolling summarization to prevent conversation histories from growing unbounded."

---

### ❓ Q3: "How do you detect and resolve contradictory memories?"

**💬 Strong Answer:**
> "I use a two-stage approach. For real-time detection during retrieval, I use heuristic pattern matching — if two retrieved memories both mention the same topic like employer name or location, I flag them as potential conflicts and run a quick check. For background maintenance, I use LLM-powered comparison that's more accurate but slower — I feed pairs of semantically similar memories to a small, cheap LLM and ask whether they contradict each other. For resolution, I apply the newer-wins strategy by default for temporal contradictions like job changes — the more recent memory supersedes the older one, and I mark the old one as superseded. For ambiguous cases where I'm not confident, I use confidence scoring — the memory with higher confidence is trusted. For high-stakes contradictions that could cause significant errors, I create a Human-in-the-Loop request asking the user to clarify. The key engineering discipline is that resolution must be deterministic — random selection between contradicting memories is never acceptable."

---

### ❓ Q4: "What is retrieval drift and how do you prevent it?"

**💬 Strong Answer:**
> "Retrieval drift happens when vector similarity search returns memories that are semantically close to the query embedding but not actually relevant to what the user needs right now. The core problem is that cosine similarity measures embedding distance, not usefulness for the current task. For example, a query about Flask web development might retrieve memories about Python data science because both involve Python and coding — the embeddings are similar, but the memories are useless for the web question. I prevent retrieval drift using three techniques. First, relevance reranking — after vector search returns top candidates, I run a cross-encoder step using an LLM to score each memory's true relevance to this specific query. This adds a second filter layer beyond pure similarity. Second, MMR, or Maximal Marginal Relevance, which selects a diverse set of relevant memories rather than five variations of the same memory. Third, enriched queries — I augment the retrieval query with current task context, recent conversation topics, and exclusion hints, which guides the vector search toward the right semantic neighborhood."

---

### ❓ Q5: "How do you prevent privacy and data leakage in multi-user AI memory systems?"

**💬 Strong Answer:**
> "Privacy defense requires multiple independent layers because any single layer can fail. The foundation is mandatory scoping — every memory storage and retrieval operation must include both user_id and tenant_id filters, and these are enforced at the infrastructure level, not application level. This means no application code can accidentally bypass them. Second, I run prompt injection detection on all content before it's stored in memory, looking for patterns that try to override instructions or extract system information. Third, I run PII detection before storage and sanitize or block content containing credit cards, passwords, SSNs, or API keys — not storing what you shouldn't is better than protecting it after the fact. Fourth, I maintain a complete audit log of every memory operation — who stored what, who retrieved what, when. This enables both security monitoring and GDPR compliance. For GDPR specifically, I implement a comprehensive deletion pipeline that removes not just the source text but also the embedding vectors and any derived data when a user exercises their right to erasure."

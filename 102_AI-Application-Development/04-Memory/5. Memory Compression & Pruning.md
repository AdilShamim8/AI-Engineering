# 🏛️ FOUNDATION — Why Compression & Pruning?

## The Core Problem: Memory Entropy

> **Memory Entropy = Over time, without management, memory becomes less useful even as it grows larger.**

Let me make this painfully clear with numbers:

```
DAY 1 of your AI app:
  Stored memories: 10
  Useful memories: 10
  Usefulness ratio: 100%

MONTH 1:
  Stored memories: 500
  Useful memories: 400
  Usefulness ratio: 80%

MONTH 6:
  Stored memories: 5,000
  Useful memories: 1,500
  (Stale, duplicate, contradictory memories: 3,500)
  Usefulness ratio: 30% ← DECLINING FAST!

YEAR 2:
  Stored memories: 50,000
  Useful memories: 3,000
  Usefulness ratio: 6% ← DISASTER!
  
  ALSO:
  → Retrieval is slow (searching 50k items)
  → LLM gets confused by contradictory old facts
  → Storage costs explode
  → Users get wrong personalization
```

## The Memory Lifecycle

```
BIRTH → GROWTH → MATURITY → DECLINE → DEATH

BIRTH:
  Memory is created → High relevance → High freshness
  Action: Store with full detail

GROWTH:
  Memory is accessed frequently → Importance increases
  Action: Promote to higher tier, protect from pruning

MATURITY:
  Memory is stable, accessed occasionally
  Action: Compress if similar memories exist, deduplicate

DECLINE:
  Memory is rarely accessed → May be stale or superseded
  Action: Apply decay, check for contradictions

DEATH:
  Memory is never accessed → Definitely outdated → Contradicted
  Action: Archive or permanently delete

COMPRESSION HAPPENS: At Maturity + Decline stages
PRUNING HAPPENS: At Decline + Death stages
```

---

## The C.A.R.E. Framework for Memory Management

```
Every compression/pruning decision must balance:

C = Completeness  (Don't lose important information)
A = Accuracy      (Remove contradictory/stale facts)
R = Relevance     (Keep only what helps the AI right now)
E = Efficiency    (Minimize storage and retrieval cost)

The art of memory management:
Maximize C + A + R while minimizing storage (E)
These are in tension — your job is to find the balance.
```

# 📝 TECHNIQUE 1: Conversation Summarization

## 1. What Is It?

> **Conversation Summarization = When a conversation becomes too long to fit efficiently in memory, use an LLM to compress it into a dense, information-rich summary that captures all key facts without the verbosity.**

---

## 2. First-Principles Breakdown

```
THE FUNDAMENTAL PROBLEM:
  You have 200 messages of conversation.
  That's ~40,000 tokens.
  Sending all 200 messages to LLM every time = expensive + slow.
  Context window might not even fit 200 messages!

NAIVE SOLUTION 1: Just cut old messages
  → Fast but LOSES INFORMATION
  → "What was my name?" → "I don't know" (was in message 1!)

NAIVE SOLUTION 2: Send all messages every time
  → No information lost but 40,000 tokens = $1.60 per API call
  → 100 users × 100 messages = unsustainable

SMART SOLUTION: Summarization
  200 messages (40,000 tokens)
  ↓ LLM Summarizes
  1 paragraph (500 tokens) + last 10 messages (2,000 tokens)
  = 2,500 tokens instead of 40,000
  = 94% cost reduction!
  = All key facts preserved! ✅
```

```
📋 Conversation Summarization = Meeting Minutes

A 3-hour meeting (full conversation):
  [10:00] Alice: "Let's discuss the budget for Q4"

  [10:05] Alice: "That seems high. Last year was $30k"

---

## 4. Types of Summarization Strategies

```
STRATEGY A: Full Summarization
  ALL messages → One comprehensive summary
  Best for: Complete session archives
  Risk: Might lose subtle context

STRATEGY B: Rolling Summarization
  Summarize oldest N messages → Keep recent M messages
  As chat grows: Keep summarizing older parts
  Best for: Long ongoing conversations
  
  VISUAL:
  [Summary of messages 1-50] + [Messages 51-70] (live)
  ↓ Chat continues to message 90
  [Summary of messages 1-70] + [Messages 71-90] (live)

STRATEGY C: Hierarchical Summarization
  Session summary → Weekly summary → Monthly summary
  Like a pyramid of abstraction
  Best for: Long-term memory compression

STRATEGY D: Entity-Centric Summarization
  Instead of summarizing chronologically,
  summarize by TOPIC or ENTITY
  Output: "What we know about [topic]"
  Best for: Knowledge accumulation
```

# conversation_summarization.py
from openai import OpenAI
from typing import List, Dict, Optional, Tuple
from datetime import datetime
from dataclasses import dataclass, field
import json
import tiktoken


@dataclass
class ConversationSegment:
    """A chunk of conversation to be summarized."""
    messages: List[Dict]
    start_index: int
    end_index: int
    created_at: str = field(
        default_factory=lambda: datetime.now().isoformat()
    )
    summary: Optional[str] = None
    key_facts: List[str] = field(default_factory=list)
    token_count: int = 0


class TokenCounter:
    """
    Count tokens in text to manage context window size.
    Critical for knowing WHEN to trigger summarization.
    """

    def __init__(self, model: str = "gpt-4o-mini"):
        try:
            self.encoder = tiktoken.encoding_for_model(model)
        except Exception:
            self.encoder = tiktoken.get_encoding("cl100k_base")

    def count_tokens(self, text: str) -> int:
        """Count tokens in a text string."""
        return len(self.encoder.encode(text))

    def count_messages_tokens(self, messages: List[Dict]) -> int:
        """Count total tokens in a list of messages."""
        total = 0
        for msg in messages:
            # Each message has overhead + content
            total += 4  # Every message overhead
            total += self.count_tokens(msg.get("content", ""))
            total += self.count_tokens(msg.get("role", ""))
        total += 2  # Conversation overhead
        return total

    def messages_to_text(self, messages: List[Dict]) -> str:
        """Convert message list to readable text."""
        lines = []
        for msg in messages:
            role = msg.get("role", "unknown").upper()
            content = msg.get("content", "")
            lines.append(f"{role}: {content}")
        return "\n".join(lines)


class ConversationSummarizer:
    """
    Intelligent conversation summarization system.

    Handles:
    - Rolling summarization (keep recent + summarize old)
    - Progressive compression (summary of summaries)
    - Fact extraction (pull key facts into long-term memory)
    - Entity tracking (what we know about each topic)
    """

    # Configuration constants
    MAX_TOKENS_BEFORE_SUMMARIZE = 3000   # Trigger when > 3000 tokens
    MESSAGES_TO_KEEP_LIVE = 6            # Always keep last 6 messages
    SUMMARY_TARGET_TOKENS = 500          # Aim for ~500 token summaries

    def __init__(
        self,
        model: str = "gpt-4o-mini",
        summary_model: str = "gpt-4o-mini"
    ):
        self.client = OpenAI()
        self.model = model
        self.summary_model = summary_model
        self.token_counter = TokenCounter(model)

    def should_summarize(self, messages: List[Dict]) -> bool:
        """
        Decide if the conversation needs summarization.
        Triggered when token count exceeds MAX_TOKENS_BEFORE_SUMMARIZE.
        """
        token_count = self.token_counter.count_messages_tokens(messages)
        should = token_count > self.MAX_TOKENS_BEFORE_SUMMARIZE

        if should:
            print(f"  ⚡ Summarization triggered: {token_count} tokens "
                  f"(limit: {self.MAX_TOKENS_BEFORE_SUMMARIZE})")

        return should

    def summarize_messages(
        self,
        messages: List[Dict],
        existing_summary: str = None,
        focus: str = None
    ) -> Dict:
        """
        Core summarization function.
        Converts a list of messages into a rich summary object.

        Returns:
        {
          "summary": "Dense paragraph summary...",
          "key_facts": ["User's name is Rahim", "Flask API project", ...],
          "entities": {"user": {...}, "project": {...}},
          "decisions": ["Chose PostgreSQL", "Using REST not GraphQL"],
          "open_questions": ["Which deployment method?"],
          "token_count": 245
        }
        """
        conversation_text = self.token_counter.messages_to_text(messages)

        # Build context from existing summary
        prior_context = ""
        if existing_summary:
            prior_context = f"""
PRIOR CONVERSATION SUMMARY:
{existing_summary}

NEW MESSAGES TO ADD TO SUMMARY:
"""

        prompt = f"""You are a precise AI conversation analyst.
Analyze the following conversation and extract structured information.

{prior_context}
CONVERSATION:
{conversation_text}

Extract and return a JSON object with this exact structure:
{{
  "summary": "A dense 2-3 sentence paragraph capturing ALL important 
              information from this conversation. Must be self-contained 
              and include every key fact.",
  
  "key_facts": [
    "Short atomic fact 1 about the user or their work",
    "Short atomic fact 2",
    "..."
  ],
  
  "entities": {{
    "user": {{
      "name": "...",
      "role": "...",
      "skills": ["..."]
    }},
    "projects": [{{
      "name": "...",
      "tech_stack": ["..."],
      "status": "..."
    }}]
  }},
  
  "decisions_made": [
    "Decision 1 (e.g., chose PostgreSQL over MongoDB)"
  ],
  
  "problems_solved": [
    "Problem and its solution (e.g., JWT bug fixed by checking SECRET_KEY)"
  ],
  
  "open_items": [
    "Unresolved items or next steps"
  ],
  
  "topics_covered": ["topic1", "topic2"]
}}

Return ONLY valid JSON. Be precise and comprehensive."""

        response = self.client.chat.completions.create(
            model=self.summary_model,
            messages=[{"role": "user", "content": prompt}],
            temperature=0.1,    # Low temperature = more consistent output
            response_format={"type": "json_object"}
        )

        try:
            result = json.loads(response.choices[0].message.content)
        except json.JSONDecodeError:
            # Fallback: basic summary if JSON parsing fails
            result = {
                "summary": response.choices[0].message.content,
                "key_facts": [],
                "entities": {},
                "decisions_made": [],
                "problems_solved": [],
                "open_items": [],
                "topics_covered": []
            }

        # Add token stats
        result["original_token_count"] = (
            self.token_counter.count_messages_tokens(messages)
        )
        result["summary_token_count"] = (
            self.token_counter.count_tokens(result.get("summary", ""))
        )
        result["compression_ratio"] = round(
            result["original_token_count"] /
            max(result["summary_token_count"], 1), 1
        )

        print(f"  ✅ Summarized {result['original_token_count']} tokens "
              f"→ {result['summary_token_count']} tokens "
              f"({result['compression_ratio']}x compression)")

        return result

    def rolling_summarize(
        self,
        messages: List[Dict],
        existing_summary: str = None
    ) -> Tuple[str, List[Dict]]:
        """
        Rolling summarization strategy.

        ALGORITHM:
        1. Keep last MESSAGES_TO_KEEP_LIVE messages as-is
        2. Summarize everything before that
        3. Return: (new_summary, recent_messages_to_keep)

        USAGE:
        Before every LLM call:
          summary, live_messages = rolling_summarize(all_messages)
          context = [system_prompt] + format_summary(summary) + live_messages
          call_llm(context)
        """
        if len(messages) <= self.MESSAGES_TO_KEEP_LIVE:
            # Not enough messages to summarize yet
            return existing_summary or "", messages

        # Split: old messages (to summarize) + recent (keep live)
        messages_to_summarize = messages[:-self.MESSAGES_TO_KEEP_LIVE]
        recent_messages = messages[-self.MESSAGES_TO_KEEP_LIVE:]

        print(f"\n🗜️ Rolling summarization:")
        print(f"   Summarizing: {len(messages_to_summarize)} messages")
        print(f"   Keeping live: {len(recent_messages)} messages")

        # Summarize old messages (incorporating any existing summary)
        summary_result = self.summarize_messages(
            messages=messages_to_summarize,
            existing_summary=existing_summary
        )

        new_summary = summary_result["summary"]

        return new_summary, recent_messages

    def hierarchical_summarize(
        self,
        sessions: List[List[Dict]],
        session_summaries: List[str] = None
    ) -> Dict:
        """
        Multi-level hierarchical summarization.

        LEVEL 1: Each session gets a summary
        LEVEL 2: Last N sessions get a weekly summary
        LEVEL 3: Weeks get a monthly summary

        Like a pyramid:
          Monthly Summary
          ├── Week 1 Summary
          │   ├── Session 1 Summary
          │   ├── Session 2 Summary
          │   └── Session 3 Summary
          └── Week 2 Summary
              ├── Session 4 Summary
              └── Session 5 Summary

        This is how you handle YEARS of conversation history!
        """
        # If session summaries not provided, generate them
        if not session_summaries:
            session_summaries = []
            for i, session in enumerate(sessions):
                print(f"  Summarizing session {i+1}/{len(sessions)}...")
                summary = self.summarize_messages(session)
                session_summaries.append(summary["summary"])

        # Now summarize the summaries (meta-summary!)
        combined_text = "\n\n".join([
            f"Session {i+1}: {s}"
            for i, s in enumerate(session_summaries)
        ])

        meta_prompt = f"""Create a comprehensive user profile from these 
session summaries.

SESSION SUMMARIES:
{combined_text}

Return JSON with:
{{
  "user_profile": "Dense paragraph describing who this user is,
                   what they work on, their expertise level",
  "consistent_patterns": ["Pattern 1", "Pattern 2"],
  "key_knowledge": ["Important fact 1", "Important fact 2"],
  "projects": [{{"name": "...", "description": "...", "status": "..."}}],
  "preferences": {{"communication": "...", "technical": "..."}}
}}"""

        response = self.client.chat.completions.create(
            model=self.summary_model,
            messages=[{"role": "user", "content": meta_prompt}],
            temperature=0.1,
            response_format={"type": "json_object"}
        )

        return json.loads(response.choices[0].message.content)

    def extract_long_term_memories(
        self,
        summary_result: Dict,
        user_id: str
    ) -> List[Dict]:
        """
        Extract individual memory facts from a summary result.
        These get stored in the long-term vector database.

        WHY: The summary is good for LLM context injection.
        But individual facts are better for semantic search!

        "User is building Flask Healthcare API with JWT auth"
        → Searchable when user asks about "authentication"
        → Searchable when user asks about "my project"
        → Better than searching through summary paragraphs
        """
        memories_to_store = []

        # Store key facts as individual memories
        for fact in summary_result.get("key_facts", []):
            memories_to_store.append({
                "user_id": user_id,
                "text": fact,
                "category": "extracted_fact",
                "source": "summarization",
                "importance": 0.7,
                "created_at": datetime.now().isoformat()
            })

        # Store decisions as memories
        for decision in summary_result.get("decisions_made", []):
            memories_to_store.append({
                "user_id": user_id,
                "text": f"DECISION: {decision}",
                "category": "decision",
                "source": "summarization",
                "importance": 0.85,
                "created_at": datetime.now().isoformat()
            })

        # Store solved problems as memories
        for problem in summary_result.get("problems_solved", []):
            memories_to_store.append({
                "user_id": user_id,
                "text": f"SOLVED: {problem}",
                "category": "debugging",
                "source": "summarization",
                "importance": 0.80,
                "created_at": datetime.now().isoformat()
            })

        print(f"  📦 Extracted {len(memories_to_store)} "
              f"long-term memories from summary")
        return memories_to_store

    def format_summary_for_prompt(
        self,
        summary: str,
        key_facts: List[str] = None
    ) -> str:
        """
        Format a summary for injection into LLM system prompt.
        Placed BEFORE the live conversation messages.
        """
        if not summary:
            return ""

        lines = ["\n=== CONVERSATION HISTORY SUMMARY ==="]
        lines.append(summary)

        if key_facts:
            lines.append("\nKey Facts:")
            for fact in key_facts[:5]:  # Max 5 key facts
                lines.append(f"• {fact}")

        lines.append("=====================================\n")
        return "\n".join(lines)


class RollingConversationManager:
    """
    Manages a conversation with automatic rolling summarization.

    This is what you integrate into your chatbot loop!
    It automatically handles the summarize-when-needed logic.
    """

    def __init__(
        self,
        user_id: str,
        summarizer: ConversationSummarizer = None
    ):
        self.user_id = user_id
        self.summarizer = summarizer or ConversationSummarizer()

        self.all_messages: List[Dict] = []      # Full history
        self.live_messages: List[Dict] = []     # Recent messages
        self.current_summary: str = ""          # Running summary
        self.summary_key_facts: List[str] = []
        self.compression_count: int = 0

    def add_message(self, role: str, content: str):
        """Add a message to the conversation."""
        message = {
            "role": role,
            "content": content,
            "timestamp": datetime.now().isoformat()
        }
        self.all_messages.append(message)
        self.live_messages.append(message)

        # Check if we need to summarize
        if self.summarizer.should_summarize(self.live_messages):
            self._trigger_summarization()

    def _trigger_summarization(self):
        """
        Perform rolling summarization.
        Called automatically when token limit exceeded.
        """
        print(f"\n🗜️  Auto-summarization triggered (compression #{self.compression_count + 1})")

        # Get messages to summarize (all except recent)
        messages_to_compress = self.live_messages[
            :-self.summarizer.MESSAGES_TO_KEEP_LIVE
        ]
        self.live_messages = self.live_messages[
            -self.summarizer.MESSAGES_TO_KEEP_LIVE:
        ]

        # Generate new summary incorporating old summary
        summary_result = self.summarizer.summarize_messages(
            messages=messages_to_compress,
            existing_summary=self.current_summary
        )

        self.current_summary = summary_result["summary"]
        self.summary_key_facts = summary_result.get("key_facts", [])
        self.compression_count += 1

        print(f"  📊 Compression #{self.compression_count} complete")
        print(f"  📝 Summary length: {len(self.current_summary)} chars")
        print(f"  💡 Key facts: {len(self.summary_key_facts)}")

    def get_context_for_llm(self) -> List[Dict]:
        """
        Build the full context for an LLM call.

        Structure:
        [System: summary of past conversation]
        + [Last N live messages]

        This is what you pass to openai.chat.completions.create()!
        """
        context = []

        # Add summary as system context
        if self.current_summary:
            summary_text = self.summarizer.format_summary_for_prompt(
                self.current_summary,
                self.summary_key_facts
            )
            context.append({
                "role": "system",
                "content": f"You are a helpful assistant.\n{summary_text}"
            })

        # Add live messages
        context.extend(self.live_messages)
        return context

    def get_stats(self) -> Dict:
        """Show memory compression statistics."""
        live_tokens = self.summarizer.token_counter.count_messages_tokens(
            self.live_messages
        )
        summary_tokens = self.summarizer.token_counter.count_tokens(
            self.current_summary
        )

        total_tokens_if_uncompressed = (
            self.summarizer.token_counter.count_messages_tokens(
                self.all_messages
            )
        )
        current_tokens = live_tokens + summary_tokens

        savings_pct = (
            (1 - current_tokens / max(total_tokens_if_uncompressed, 1)) * 100
            if total_tokens_if_uncompressed > 0 else 0
        )

        return {
            "total_messages": len(self.all_messages),
            "live_messages": len(self.live_messages),
            "compressions_performed": self.compression_count,
            "tokens_if_uncompressed": total_tokens_if_uncompressed,
            "current_tokens_used": current_tokens,
            "token_savings_pct": round(savings_pct, 1)
        }

│  ✅ Enables near-infinite conversation length                   │
│  ❌ Loses nuance and exact wording                              │
│  ❌ LLM quality affects summary quality                         │
│  ❌ Adds latency when summarization triggers                    │
└─────────────────────────────────────────────────────────────────┘
```

# 🪟 TECHNIQUE 2: Sliding Window Truncation

## 1. What Is It?

> **Sliding Window Truncation = Maintain a fixed-size window over the conversation. As new messages arrive, old messages slide out automatically. The window slides FORWARD through time, keeping only the most recent N messages.**

We introduced this concept in Chapter 2. Now we go **deep** on implementation, tuning, and intelligent enhancement.

---

## 2. First-Principles: Why Sliding Window?

```
THE PURE SIMPLICITY ARGUMENT:

Summarization is powerful but:
→ Requires an LLM API call (costs money, adds latency)
→ Might introduce errors (LLM can misunderstand)
→ Complex to implement and debug

Sliding Window is:
→ Zero API calls (just a list slice!)
→ Zero errors (mathematical guarantee)
→ 10 lines of code to implement
→ Predictable token budget ALWAYS

TRADE-OFF:
  Sliding Window = FAST + CHEAP + SIMPLE but loses old info
  Summarization  = SLOW + COSTS + COMPLEX but preserves info

SOLUTION: Use BOTH!
  Sliding Window = Primary mechanism (always running)
  Summarization  = Triggered when window slides (save what's lost)
```

---

## 3. Analogy: The Airport Moving Walkway

```
🛄 Sliding Window = Airport Moving Walkway

The walkway moves at constant speed.
New arrivals step on at the back.
People at the front step off automatically.

The walkway always has the same number of people.
Nobody controls individual people — the system handles it.
People who step off are "forgotten" unless saved elsewhere.

SMART ENHANCEMENT:
  Before someone steps off the walkway:
  → Take a photo (summarize them!)
  → Archive their info in long-term storage
  → Now you have BOTH fresh window AND deep history

That's Sliding Window + Summarization combined!
```

---

## 4. Intelligent Sliding Window — The Smart Version

```
NAIVE SLIDING WINDOW:
  When message 21 comes in and window=20:
  → Message 1 slides out
  → GONE forever
  → "My name is Rahim" → LOST! 😱

INTELLIGENT SLIDING WINDOW:
  BEFORE message 1 slides out:
  1. Check: Is this message important?
   → "My name is Rahim" → YES, very important!
  2. Save important content to long-term memory FIRST
  3. THEN allow it to slide out

  RESULT:
  "My name is Rahim" slides out of window
  BUT was saved to long-term memory ✅
  Retrieval system finds it when needed ✅
  Zero information loss! ✅
```

# sliding_window_truncation.py
from collections import deque
from typing import List, Dict, Optional, Callable, Tuple
from datetime import datetime
from dataclasses import dataclass, field
import tiktoken


@dataclass
class WindowConfig:
    """
    Configuration for the sliding window.
    Tune these values based on your use case.
    """
    # Primary controls
    max_messages: int = 20          # Max messages in window
    max_tokens: int = 8000          # Max tokens in window

    # Importance-based protection
    min_importance_to_protect: float = 0.8  # Always keep if importance >= 0.8
    max_protected_messages: int = 3         # Max messages to protect

    # Saving strategy
    save_on_eviction: bool = True    # Save important msgs before eviction
    save_threshold: float = 0.5     # Save if importance >= this


class MessageImportanceDetector:
    """
    Quickly detect if a message is important enough to save
    before it slides out of the window.
    
    Uses heuristics (fast!) instead of LLM (slow/expensive!).
    """

    # High-importance patterns
    IMPORTANT_PATTERNS = [
        # Identity signals
        "my name is", "i am", "call me", "i work at",
        "my job is", "i'm a",
        # Project signals
        "my project", "i'm building", "my app", "my system",
        "my database", "my api", "my tech stack",
        # Decision signals
        "i decided", "we chose", "i prefer", "i want to use",
        "instead of", "rather than",
        # Key technical facts
        "the issue was", "the fix is", "the solution",
        "the error", "the bug", "it works when",
        # Learning moments
        "i learned", "i realized", "i understand now",
        "that's why", "so that's how",
        # Explicit requests
        "remember this", "don't forget", "important:",
        "note that", "keep in mind"
    ]

    # Low-importance patterns
    FILLER_PATTERNS = [
        "ok", "okay", "thanks", "thank you", "sure",
        "got it", "understood", "makes sense", "yes", "no",
        "alright", "sounds good", "perfect", "great",
        "i see", "interesting"
    ]

    def compute_importance(self, message: Dict) -> float:
        """
        Quickly estimate message importance using heuristics.
        
        Returns: 0.0 (unimportant) to 1.0 (very important)
        
        DESIGN CHOICE: Use heuristics, not LLM!
        Why: This runs on EVERY message — must be instant.
        LLM calls would add 1+ second latency per message.
        """
        content = message.get("content", "").lower()
        role = message.get("role", "user")

        # Base score
        score = 0.3

        # Length bonus (longer = more likely to have substance)
        word_count = len(content.split())
        if word_count > 50:   score += 0.2
        elif word_count > 20: score += 0.1
        elif word_count < 5:  score -= 0.2  # Very short = likely filler

        # Important pattern bonus
        for pattern in self.IMPORTANT_PATTERNS:
            if pattern in content:
                score += 0.25
                break  # One match is enough for bonus

        # Filler pattern penalty
        stripped = content.strip(".,!?")
        if stripped in self.FILLER_PATTERNS:
            score -= 0.3

        # Question bonus (questions often contain context)
        if "?" in content:
            score += 0.1

        # Code bonus (code blocks are usually important)
        if "```" in content or "def " in content or "class " in content:
            score += 0.3

        # User messages slightly more important (user reveals preferences)
        if role == "user":
            score += 0.05

        return max(0.0, min(1.0, score))

    def extract_key_content(self, message: Dict) -> Optional[str]:
        """
        Extract the most important part of a message for archiving.
        If message slides out, save just the key content, not full msg.
        """
        content = message.get("content", "")
        role = message.get("role", "user")

        # For short messages, keep entire content
        if len(content) < 200:
            return f"{role.upper()}: {content}"

        # For long messages, extract key sentences
        sentences = content.split(".")
        important_sentences = []

        for sentence in sentences:
            sentence = sentence.strip()
            if not sentence:
                continue

            # Keep sentences with important patterns
            for pattern in self.IMPORTANT_PATTERNS:
                if pattern in sentence.lower():
                    important_sentences.append(sentence)
                    break

        if important_sentences:
            return f"{role.upper()}: " + ". ".join(important_sentences[:3])

        # Fallback: first 200 chars
        return f"{role.upper()}: {content[:200]}..."


class SlidingWindowManager:
    """
    Complete sliding window implementation with:
    - Token-aware window sizing
    - Importance-based message protection
    - Save-on-eviction for important messages
    - Detailed statistics tracking
    """

    def __init__(
        self,
        config: WindowConfig = None,
        on_eviction_callback: Callable = None
    ):
        """
        on_eviction_callback: Called when a message is evicted.
        Use this to save important messages to long-term memory!
        
        Example:
        def save_to_ltm(message, importance, key_content):
            if importance >= 0.5:
                vector_store.add_memory(user_id, key_content)
        
        manager = SlidingWindowManager(
            on_eviction_callback=save_to_ltm
        )
        """
        self.config = config or WindowConfig()
        self.on_eviction = on_eviction_callback
        self.importance_detector = MessageImportanceDetector()

        try:
            self.encoder = tiktoken.get_encoding("cl100k_base")
        except Exception:
            self.encoder = None

        # The actual sliding window
        self.window: deque = deque()

        # Protected messages (always kept, not subject to sliding)
        self.protected: List[Dict] = []

        # Statistics
        self.stats = {
            "total_added": 0,
            "total_evicted": 0,
            "total_saved_on_eviction": 0,
            "total_protected": 0
        }

    def _count_tokens(self, text: str) -> int:
        """Count tokens in text."""
        if self.encoder:
            return len(self.encoder.encode(text))
        return len(text) // 4  # Rough fallback: 4 chars ≈ 1 token

    def _window_token_count(self) -> int:
        """Count total tokens currently in window."""
        return sum(
            self._count_tokens(msg.get("content", ""))
            for msg in self.window
        )

    def add_message(
        self,
        role: str,
        content: str,
        metadata: Dict = None
    ) -> Dict:
        """
        Add a message to the sliding window.
        
        Automatically handles:
        - Evicting old messages if window is full
        - Saving important messages before eviction
        - Protecting critical messages
        """
        message = {
            "role": role,
            "content": content,
            "timestamp": datetime.now().isoformat(),
            **(metadata or {})
        }

        # Compute importance before adding
        importance = self.importance_detector.compute_importance(message)
        message["_importance"] = importance

        # Check if this message should be protected
        if (importance >= self.config.min_importance_to_protect and
                len(self.protected) < self.config.max_protected_messages):
            self.protected.append(message)
            self.stats["total_protected"] += 1
            print(f"  🔒 Protected message (importance: {importance:.2f}): "
                  f"{content[:50]}...")

        # Add to window
        self.window.append(message)
        self.stats["total_added"] += 1

        # Evict if necessary
        self._enforce_limits()

        return message

    def _enforce_limits(self):
        """
        Enforce window size limits.
        Evicts oldest messages when limits are exceeded.
        """
        # Enforce message count limit
        while len(self.window) > self.config.max_messages:
            self._evict_oldest()

        # Enforce token limit
        while (self._window_token_count() > self.config.max_tokens and
               len(self.window) > 2):  # Never go below 2 messages
            self._evict_oldest()

    def _evict_oldest(self):
        """
        Evict the oldest message from the window.
        Optionally save it before eviction.
        """
        if not self.window:
            return

        evicted_message = self.window.popleft()  # Remove from LEFT (oldest)
        self.stats["total_evicted"] += 1

        importance = evicted_message.get("_importance", 0.0)

        # Save important messages before eviction
        if (self.config.save_on_eviction and
                importance >= self.config.save_threshold):

            key_content = self.importance_detector.extract_key_content(
                evicted_message
            )

            if key_content and self.on_eviction:
                self.on_eviction(evicted_message, importance, key_content)
                self.stats["total_saved_on_eviction"] += 1
                print(f"  💾 Saved before eviction (importance: "
                      f"{importance:.2f}): {key_content[:50]}...")

    def get_messages(
        self,
        include_protected: bool = True,
        exclude_metadata: bool = True
    ) -> List[Dict]:
        """
        Get current window messages for LLM context.

        include_protected: Add protected messages at start of context.
        exclude_metadata: Remove internal fields like _importance.
        """
        messages = []

        # Add protected messages first (core context)
        if include_protected and self.protected:
            for msg in self.protected:
                clean_msg = {
                    k: v for k, v in msg.items()
                    if not k.startswith("_")
                } if exclude_metadata else msg
                messages.append(clean_msg)

        # Add window messages
        for msg in self.window:
            clean_msg = {
                k: v for k, v in msg.items()
                if not k.startswith("_")
            } if exclude_metadata else msg
            messages.append(clean_msg)

        # Remove duplicates (protected messages might be in window too)
        seen_content = set()
        unique_messages = []
        for msg in messages:
            content_key = f"{msg['role']}:{msg['content']}"
            if content_key not in seen_content:
                seen_content.add(content_key)
                unique_messages.append(msg)

        return unique_messages

    def get_window_stats(self) -> Dict:
        """Comprehensive window statistics."""
        current_tokens = self._window_token_count()
        token_utilization = current_tokens / self.config.max_tokens * 100
        message_utilization = (
            len(self.window) / self.config.max_messages * 100
        )

        return {
            # Current state
            "window_messages": len(self.window),
            "window_tokens": current_tokens,
            "protected_messages": len(self.protected),

            # Limits
            "max_messages": self.config.max_messages,
            "max_tokens": self.config.max_tokens,

            # Utilization
            "message_utilization_pct": round(message_utilization, 1),
            "token_utilization_pct": round(token_utilization, 1),

            # Lifetime stats
            **self.stats
        }

    def visualize_window(self):
        """Visual representation of the current window state."""
        print(f"\n{'='*65}")
        print(f"SLIDING WINDOW STATE")
        print(f"{'='*65}")

        if self.protected:
            print(f"\n🔒 PROTECTED MESSAGES ({len(self.protected)}):")
            for i, msg in enumerate(self.protected):
                imp = msg.get('_importance', 0)
                content = msg['content'][:50] + "..."
                print(f"   [{i+1}] [{msg['role']}] "
                      f"(imp:{imp:.2f}) {content}")

        print(f"\n📬 ACTIVE WINDOW ({len(self.window)} messages):")
        for i, msg in enumerate(self.window):
            imp = msg.get('_importance', 0)
            bar = "█" * int(imp * 10)
            content = msg['content'][:45] + "..."
            print(f"   [{i+1}] [{msg['role']}] "
                  f"imp:{imp:.2f} {bar} {content}")

        stats = self.get_window_stats()
        print(f"\n📊 STATS:")
        print(f"   Tokens:   {stats['window_tokens']}/{stats['max_tokens']} "
              f"({stats['token_utilization_pct']}%)")
        print(f"   Messages: {stats['window_messages']}/{stats['max_messages']} "
              f"({stats['message_utilization_pct']}%)")
        print(f"   Evicted:  {stats['total_evicted']} total  "
              f"({stats['total_saved_on_eviction']} saved before eviction)")
        print(f"{'='*65}\n")

# ⭐ TECHNIQUE 3: Importance Scoring (for Pruning)

## 1. Importance Scoring as a PRUNING TOOL

> In Chapter 4, we learned Importance Scoring for **retrieval**. Now we use it for **pruning** — deciding which memories to delete, archive, or compress.

```
RETRIEVAL: "Which memories should I show the LLM right now?"
PRUNING:   "Which memories should I PERMANENTLY remove from the system?"

These are DIFFERENT questions with DIFFERENT scoring criteria!

RETRIEVAL importance = How relevant is this to the CURRENT query?
PRUNING importance   = How valuable is this LONG-TERM to the system?

Example:
  "User asked what's 2+2" 
  → Retrieval: Low (not relevant to most queries)
  → Pruning: VERY LOW (delete it, zero long-term value)
  
  "User's core project: Flask Healthcare API"
  → Retrieval: High (relevant to many queries)
  → Pruning: VERY HIGH (never delete this!)
```

---

## 2. The Pruning Decision Matrix

```
                    HIGH RETRIEVAL IMPORTANCE
                              ↑
                              │
     NEVER PRUNE              │         PROTECT ALWAYS
    (but compress if duped)   │         (highest tier)
                              │
LOW PRUNING ←─────────────────┼─────────────────────→ HIGH PRUNING
IMPORTANCE                    │                       IMPORTANCE
                              │
    CANDIDATE FOR ARCHIVING   │         PRUNE SOON
    (move to cold storage)    │         (safe to delete)
                              │
                              ↓
                    LOW RETRIEVAL IMPORTANCE
```

---

## 3. Complete Pruning-Focused Importance Scoring

```python
# pruning_importance.py
from datetime import datetime, timedelta
from typing import List, Dict, Tuple, Optional
from dataclasses import dataclass
from enum import Enum
import math


class PruningAction(Enum):
    """What to do with a memory based on its pruning score."""
    PROTECT    = "protect"    # Never delete, always keep
    KEEP       = "keep"       # Keep, low priority for pruning
    COMPRESS   = "compress"   # Keep but summarize with similar memories
    ARCHIVE    = "archive"    # Move to cold storage, don't delete yet
    PRUNE      = "prune"      # Safe to delete


@dataclass
class PruningDecision:
    """Result of the pruning analysis for a single memory."""
    memory_id: str
    memory_text: str
    action: PruningAction
    pruning_score: float         # 0 = never prune, 1 = prune immediately
    reasoning: List[str]         # Why this decision was made
    confidence: float            # How confident are we? (0-1)
    alternative_action: Optional[PruningAction] = None


class PruningScorer:
    """
    Computes pruning scores for memories.
    
    DIFFERENT from retrieval importance scoring!
    Pruning score focuses on LONG-TERM VALUE:
    
    → Has this fact been superseded?
    → Is this information still valid?
    → How unique is this fact (not duplicated elsewhere)?
    → What's the consequence of losing this?
    → Is this fact derivable from other memories?
    """

    # Base pruning scores by category
    # 0 = never prune, 1 = always prune
    CATEGORY_PRUNE_SCORES = {
        "core_identity":     0.00,  # NEVER prune identity
        "project_fact":      0.05,  # Almost never prune
        "technical":         0.10,  # Rarely prune
        "decision":          0.10,  # Rarely prune
        "debugging":         0.20,  # Occasionally prune old bugs
        "learning":          0.30,  # Can prune if superseded
        "preference":        0.25,  # Keep but review periodically
        "interaction":       0.50,  # Often safe to prune
        "personal":          0.40,  # Medium priority
        "casual":            0.80,  # Usually safe to prune
        "ephemeral":         0.95,  # Almost always prune
        "session_context":   0.70,  # Usually prune after session
    }

    def compute_pruning_score(
        self,
        memory: Dict,
        all_memories: List[Dict] = None
    ) -> Tuple[float, List[str]]:
        """
        Compute pruning score for a memory.
        
        Returns: (pruning_score, reasoning_list)
        
        Pruning score meaning:
        0.0 - 0.2: Protect (core knowledge, never delete)
        0.2 - 0.4: Keep (valuable, low deletion priority)
        0.4 - 0.6: Compress (reduce but don't fully delete)
        0.6 - 0.8: Archive (move to cold storage)
        0.8 - 1.0: Prune (safe to delete)
        """
        score = 0.0
        reasoning = []

        # ── Factor 1: Category Base Score ─────────────────────
        category = memory.get("category", "interaction")
        category_score = self.CATEGORY_PRUNE_SCORES.get(
            category, 0.50
        )
        score += category_score * 0.30
        reasoning.append(
            f"Category '{category}' base prune score: {category_score:.2f}"
        )

        # ── Factor 2: Age Score ───────────────────────────────
        created_str = memory.get("created_at", datetime.now().isoformat())
        if isinstance(created_str, str):
            created = datetime.fromisoformat(created_str)
        else:
            created = created_str

        age_days = (datetime.now() - created).days

        # Normalize age score (0 = just created, 1 = very old)
        # After 365 days → age_score = 0.8 (candidates for pruning)
        age_score = min(age_days / 365, 1.0) * 0.8
        score += age_score * 0.20
        reasoning.append(
            f"Age: {age_days} days old → age score: {age_score:.2f}"
        )

        # ── Factor 3: Access Frequency Score ──────────────────
        access_count = memory.get("access_count", 0)
        last_accessed_str = memory.get("last_accessed_at")

        if access_count == 0:
            access_score = 0.8  # Never accessed → candidate for pruning
            reasoning.append("Never accessed → high prune candidate")
        else:
            # More accesses = more valuable = lower prune score
            access_score = max(0.0, 0.8 - (access_count / 20))
            reasoning.append(
                f"Accessed {access_count} times → access score: {access_score:.2f}"
            )

        score += access_score * 0.25

        # ── Factor 4: Recency of Last Access ──────────────────
        if last_accessed_str:
            if isinstance(last_accessed_str, str):
                last_accessed = datetime.fromisoformat(last_accessed_str)
            else:
                last_accessed = last_accessed_str

            days_since_access = (datetime.now() - last_accessed).days

            # Not accessed in 90+ days → candidate for pruning
            if days_since_access > 180:
                access_recency_score = 0.8
                reasoning.append(
                    f"Not accessed in {days_since_access} days → prune candidate"
                )
            elif days_since_access > 90:
                access_recency_score = 0.5
                reasoning.append(
                    f"Not accessed in {days_since_access} days"
                )
            else:
                access_recency_score = 0.1
                reasoning.append(
                    f"Recently accessed ({days_since_access} days ago) → keep"
                )
        else:
            access_recency_score = 0.6  # No access record
            reasoning.append("No access record found")

        score += access_recency_score * 0.15

        # ── Factor 5: Is Superseded? ──────────────────────────
        is_superseded = memory.get("is_superseded", False)
        superseded_score = 0.9 if is_superseded else 0.0
        score += superseded_score * 0.10

        if is_superseded:
            reasoning.append("SUPERSEDED by newer memory → strong prune candidate")

        # ── Overall score ─────────────────────────────────────
        final_score = min(1.0, score)

        return round(final_score, 4), reasoning

    def decide_action(self, pruning_score: float) -> PruningAction:
        """Convert pruning score to concrete action."""
        if pruning_score <= 0.15:  return PruningAction.PROTECT
        elif pruning_score <= 0.35: return PruningAction.KEEP
        elif pruning_score <= 0.55: return PruningAction.COMPRESS
        elif pruning_score <= 0.75: return PruningAction.ARCHIVE
        else:                       return PruningAction.PRUNE

    def analyze_memories(
        self,
        memories: List[Dict],
        user_id: str
    ) -> List[PruningDecision]:
        """
        Analyze all memories and produce pruning decisions.
        This is what you run as a background maintenance job!
        """
        user_memories = [
            m for m in memories
            if m.get("user_id") == user_id
        ]

        decisions = []

        for memory in user_memories:
            pruning_score, reasoning = self.compute_pruning_score(
                memory, user_memories
            )
            action = self.decide_action(pruning_score)

            decisions.append(PruningDecision(
                memory_id=memory.get("id", ""),
                memory_text=memory.get("text", "")[:80],
                action=action,
                pruning_score=pruning_score,
                reasoning=reasoning,
                confidence=0.8
            ))

        # Sort by pruning score (highest first = prune these first)
        decisions.sort(key=lambda d: d.pruning_score, reverse=True)
        return decisions

    def generate_pruning_report(
        self,
        decisions: List[PruningDecision]
    ) -> str:
        """
        Generate a human-readable pruning report.
        Shows what WILL happen if pruning is executed.
        """
        action_counts = {}
        for decision in decisions:

# 🔁 TECHNIQUE 4: Deduplication

## 1. What Is It?

> **Deduplication = Detect and remove or merge DUPLICATE or near-duplicate memories that store the same information in different words.**

This is one of the most impactful optimizations you can make to a memory system.

---

## 2. Why Deduplication Is Critical

```
THE DUPLICATION PROBLEM:

Over 6 months, your system might store:
  m1: "User is building a Flask API"          (session 1)
  m47: "User works on Flask web API"           (session 8)
  m103: "User's project is a Flask backend"   (session 15)
  m251: "User develops Flask application"     (session 31)
  m389: "User is a Flask developer"           (session 45)

These are ALL saying the same thing!
Storage waste: 5x the necessary space
Retrieval confusion: AI gets same fact 5 times
Context pollution: 5 redundant facts take up space
LLM might even CONTRADICT itself using different phrasings

AFTER DEDUPLICATION:
  m1: "User is building a Flask API" (canonical, keep this one)
  ← All others deleted or merged into m1

Storage: 80% reduced
Retrieval: Clean, no redundancy
Context: Precise, no pollution ✅
```

---

## 3. Types of Duplicates

```
TYPE 1: EXACT DUPLICATES
  "User likes Python" == "User likes Python"
  Detection: Simple string equality
  Simple, rare in practice

TYPE 2: NEAR-DUPLICATES (Paraphrase)
  "User likes Python" ≈ "User enjoys Python programming"
  Detection: High cosine similarity (>0.92)
  Most common in practice!

TYPE 3: SEMANTIC DUPLICATES (Same fact, very different words)
  "User is a backend developer" ≈ "User builds server-side applications"
  Detection: Semantic similarity + LLM verification
  Harder to detect, but important to handle

TYPE 4: PARTIAL DUPLICATES (Subset information)
  Memory A: "User likes Python"
  Memory B: "User likes Python, especially for data science"
  → B contains A (A is a subset of B)
  Action: Keep B (more complete), delete A

TYPE 5: CONTRADICTING MEMORIES (Special case)
  Memory A: "User works at Google"
  Memory B: "User works at Meta"
  → NOT a duplicate, but a conflict!
  → Handle separately (see conflict detection)
```

```python
# deduplication.py
from typing import List, Dict, Tuple, Optional, Set
from datetime import datetime
import numpy as np
from dataclasses import dataclass, field
from openai import OpenAI
import json


@dataclass
class DuplicateGroup:
    """A group of memories that are duplicates of each other."""
    canonical_id: str              # Which one to KEEP
    canonical_text: str
    duplicate_ids: List[str]       # Which ones to DELETE
    duplicate_texts: List[str]
    similarity_scores: List[float]
    duplicate_type: str            # exact, near_duplicate, semantic
    merged_text: Optional[str] = None  # If we merge instead of delete


class DeduplicationEngine:
    """
    Complete deduplication system for AI memory.
    
    THREE-STAGE PIPELINE:
    Stage 1: Fast exact matching (O(n), hash-based)
    Stage 2: Near-duplicate detection (vector similarity)
    Stage 3: Semantic verification (LLM confirmation, if needed)
    """

    def __init__(
        self,
        embedding_fn=None,
        near_duplicate_threshold: float = 0.92,
        semantic_threshold: float = 0.80,
        use_llm_verification: bool = False
    ):
        """
        near_duplicate_threshold: Above this = near duplicate
        semantic_threshold: Below near_dup but above this = check semantically
        use_llm_verification: Use LLM to verify semantic duplicates (slower!)
        """
        self.embed = embedding_fn
        self.near_dup_threshold = near_duplicate_threshold
        self.semantic_threshold = semantic_threshold
        self.use_llm_verification = use_llm_verification
        self.openai = OpenAI() if use_llm_verification else None

    def _normalize_text(self, text: str) -> str:
        """Normalize text for comparison."""
        return " ".join(
            text.lower()
            .strip()
            .replace(".", " ")
            .replace(",", " ")
            .split()
        )

    def _cosine_similarity(
        self,
        vec_a: List[float],
        vec_b: List[float]
    ) -> float:
        """Compute cosine similarity between two vectors."""
        a, b = np.array(vec_a), np.array(vec_b)
        norm_a, norm_b = np.linalg.norm(a), np.linalg.norm(b)
        if norm_a == 0 or norm_b == 0:
            return 0.0
        return float(np.dot(a, b) / (norm_a * norm_b))

    # ── STAGE 1: EXACT DEDUPLICATION ──────────────────────────

    def find_exact_duplicates(
        self,
        memories: List[Dict]
    ) -> List[DuplicateGroup]:
        """
        Stage 1: Find exact duplicate memories.
        Uses hash comparison — O(n) time, very fast!
        """
        groups = []
        seen_hashes: Dict[str, Dict] = {}

        for memory in memories:
            normalized = self._normalize_text(
                memory.get("text", "")
            )

            if normalized in seen_hashes:
                # Exact duplicate found!
                canonical = seen_hashes[normalized]
                groups.append(DuplicateGroup(
                    canonical_id=canonical.get("id", ""),
                    canonical_text=canonical.get("text", ""),
                    duplicate_ids=[memory.get("id", "")],
                    duplicate_texts=[memory.get("text", "")],
                    similarity_scores=[1.0],
                    duplicate_type="exact"
                ))
            else:
                seen_hashes[normalized] = memory

        print(f"  Stage 1 (Exact): Found {len(groups)} exact duplicates")
        return groups

    # ── STAGE 2: NEAR-DUPLICATE DETECTION ─────────────────────

    def find_near_duplicates(
        self,
        memories: List[Dict],
        batch_size: int = 50
    ) -> List[DuplicateGroup]:
        """
        Stage 2: Find near-duplicate memories using embedding similarity.
        
        ALGORITHM:
        1. Compute embeddings for all memories (batch for efficiency)
        2. For each pair, compute cosine similarity
        3. Group memories with similarity > threshold
        
        EFFICIENCY NOTE:
        Naive: O(n²) comparisons for n memories
        Optimized: Use HNSW index for approximate search
        For small collections (<10k): O(n²) is fine
        For large collections: Use vector DB query approach
        """
        if not self.embed:
            print("⚠️ No embedding function provided, skipping near-dup detection")
            return []

        # Get all texts
        texts = [m.get("text", "") for m in memories]

        print(f"  Stage 2 (Near-Dup): Computing embeddings for "
              f"{len(texts)} memories...")

        # Batch embed (efficient!)
        embeddings = []
        for i in range(0, len(texts), batch_size):
            batch = texts[i:i + batch_size]
            batch_embeddings = [self.embed(t) for t in batch]
            embeddings.extend(batch_embeddings)

        # Build similarity matrix and find duplicates
        groups = []
        processed_ids: Set[str] = set()

        for i in range(len(memories)):
            mem_id_i = memories[i].get("id", f"mem_{i}")

            if mem_id_i in processed_ids:
                continue

            current_group_duplicates = []
            current_group_scores = []

            for j in range(i + 1, len(memories)):
                mem_id_j = memories[j].get("id", f"mem_{j}")

                if mem_id_j in processed_ids:
                    continue

                # Compute similarity
                sim = self._cosine_similarity(
                    embeddings[i],
                    embeddings[j]
                )

                if sim >= self.near_dup_threshold:
                    current_group_duplicates.append(memories[j])
                    current_group_scores.append(sim)
                    processed_ids.add(mem_id_j)

            if current_group_duplicates:
                # Determine canonical: keep the one with highest importance
                canonical = self._choose_canonical(
                    memories[i], current_group_duplicates
                )

                duplicates = [
                    m for m in [memories[i]] + current_group_duplicates
                    if m.get("id") != canonical.get("id")
                ]

                groups.append(DuplicateGroup(
                    canonical_id=canonical.get("id", ""),
                    canonical_text=canonical.get("text", ""),
                    duplicate_ids=[m.get("id", "") for m in duplicates],
                    duplicate_texts=[m.get("text", "") for m in duplicates],
                    similarity_scores=current_group_scores,
                    duplicate_type="near_duplicate"
                ))
                processed_ids.add(mem_id_i)

        print(f"  Stage 2 (Near-Dup): Found {len(groups)} duplicate groups")
        return groups

    def _choose_canonical(
        self,
        memory_a: Dict,
        memory_b_list: List[Dict]
    ) -> Dict:
        """
        When duplicates found, choose which one to KEEP.
        
        RULES (in order):
        1. Keep the one with higher importance score
        2. If equal: keep the one with more access counts
        3. If equal: keep the longer text (more informative)
        4. If equal: keep the most recently created
        """
        all_memories = [memory_a] + memory_b_list

        def canonical_score(m: Dict) -> Tuple:
            return (
                m.get("importance", 0.5),
                m.get("access_count", 0),
                len(m.get("text", "")),
                m.get("created_at", "")
            )

        return max(all_memories, key=canonical_score)

    # ── STAGE 3: LLM SEMANTIC VERIFICATION ────────────────────

    def llm_verify_duplicate(
        self,
        text_a: str,
        text_b: str
    ) -> Tuple[bool, str]:
        """
        Stage 3: Use LLM to verify if two memories are semantic duplicates.
        
        Only use for borderline cases (similarity 0.80-0.92).
        Slower and costs money, but very accurate.
        
        Returns: (is_duplicate: bool, reasoning: str)
        """
        if not self.openai:
            return False, "LLM verification disabled"

        prompt = f"""Are these two memory facts about the same information?

Memory A: "{text_a}"
Memory B: "{text_b}"

They are duplicates if they express the same core fact, even in different words.
They are NOT duplicates if they contain meaningfully different information.

Respond with JSON:
{{"is_duplicate": true/false, "reasoning": "brief explanation"}}"""

        response = self.openai.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            response_format={"type": "json_object"}
        )

        result = json.loads(response.choices[0].message.content)
        return (
            result.get("is_duplicate", False),
            result.get("reasoning", "")
        )

    # ── MERGE STRATEGY ─────────────────────────────────────────

    def merge_duplicates(
        self,
        memories: List[Dict],
        llm_merge: bool = True
    ) -> Optional[str]:
        """
        Instead of just keeping one and deleting others,
        MERGE duplicate memories into a single, richer memory.
        
        Example:
        Memory 1: "User builds Flask APIs"
        Memory 2: "User's Flask API uses JWT authentication"
        Memory 3: "User's Flask project is a healthcare application"
        
        MERGED:
        "User builds Flask healthcare APIs with JWT authentication"
        
        This is better than keeping just one!
        """
        if len(memories) < 2:
            return memories[0].get("text") if memories else None

        if not llm_merge or not self.openai:
            # Simple: return the longest (most informative) memory
            return max(memories, key=lambda m: len(m.get("text", ""))).get("text")

        # Use LLM to create a merged, comprehensive fact
        memory_texts = "\n".join([
            f"- {m.get('text', '')}" for m in memories
        ])

        prompt = f"""These memories all describe the same fact but with different details.
Merge them into ONE comprehensive, atomic fact that includes all unique information.

Memories to merge:
{memory_texts}

Rules:
- Keep it to ONE sentence
- Include all unique details from all memories
- Be specific and factual
- Don't add information not in the originals

Merged fact:"""

        response = self.openai.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
            temperature=0.1
        )

        return response.choices[0].message.content.strip()

    # ── COMPLETE DEDUPLICATION PIPELINE ───────────────────────

    def run_deduplication(
        self,
        memories: List[Dict],
        user_id: str,
        strategy: str = "delete_duplicates"
    ) -> Dict:
        """
        Run the complete deduplication pipeline.
        
        strategy options:
        "delete_duplicates" → Keep canonical, delete duplicates
        "merge_duplicates"  → Merge duplicates into one richer memory
        
        Returns: {
          "to_delete": [list of memory IDs to delete],
          "to_update": [list of {id, new_text} for merged memories],
          "groups_found": int,
          "memories_saved": int
        }
        """
        # Filter to user's memories
        user_memories = [
            m for m in memories
            if m.get("user_id") == user_id
        ]

        print(f"\n🔁 DEDUPLICATION PIPELINE")
        print(f"   Processing {len(user_memories)} memories for user: {user_id}")
        print(f"   Strategy: {strategy}")

        all_groups = []

        # Stage 1: Exact duplicates
        exact_groups = self.find_exact_duplicates(user_memories)
        all_groups.extend(exact_groups)

        # Stage 2: Near duplicates (if embedding function available)
        if self.embed:
            # Remove already-identified duplicates first
            already_dup_ids = {
                did
                for g in exact_groups
                for did in g.duplicate_ids
            }
            remaining = [
                m for m in user_memories
                if m.get("id") not in already_dup_ids
            ]
            near_dup_groups = self.find_near_duplicates(remaining)
            all_groups.extend(near_dup_groups)

        # Compile results
        to_delete = []
        to_update = []

        for group in all_groups:
            if strategy == "merge_duplicates" and group.canonical_id:
                # Get the actual memory objects for merging
                group_memories = [
                    m for m in user_memories
                    if m.get("id") == group.canonical_id
                    or m.get("id") in group.duplicate_ids
                ]
                merged_text = self.merge_duplicates(
                    group_memories,
                    llm_merge=False  # Use simple merge for speed
                )
                group.merged_text = merged_text

                # Update canonical, delete duplicates
                to_update.append({
                    "id": group.canonical_id,
                    "new_text": merged_text
                })
                to_delete.extend(group.duplicate_ids)
            else:
                # Just delete duplicates, keep canonical
                to_delete.extend(group.duplicate_ids)

        result = {
            "groups_found": len(all_groups),
            "total_duplicates_found": sum(
                len(g.duplicate_ids) for g in all_groups
            ),
            "to_delete": to_delete,
            "to_update": to_update,
            "memories_before": len(user_memories),
            "memories_after": len(user_memories) - len(to_delete),
            "space_saved_pct": round(
                len(to_delete) / max(len(user_memories), 1) * 100, 1
            )
        }

        print(f"\n📊 DEDUPLICATION RESULTS:")
        print(f"   Groups found: {result['groups_found']}")
        print(f"   Duplicates found: {result['total_duplicates_found']}")
        print(f"   Memories before: {result['memories_before']}")
        print(f"   Memories after: {result['memories_after']}")
        print(f"   Space saved: {result['space_saved_pct']}%")

        return result
```

# ⏰ TECHNIQUE 5: Aging & Expiry Policies

## 1. What Is It?

> **Aging & Expiry Policies = Rules that automatically reduce the importance of, archive, or delete memories based on TIME. Memories grow old and stale — expiry policies handle this systematically.**

---

## 2. First-Principles: Everything Has a Shelf Life

```
MILK IN A FRIDGE:
  Fresh milk: 7 days → drink it
  8-day-old milk: probably still ok → check it
  14-day-old milk: throw it away → don't even taste it
  
  Milk doesn't suddenly go bad at exactly day 7.
  It GRADUALLY degrades.
  Your fridge doesn't throw it away automatically.
  YOU check and decide.

AI MEMORIES WORK THE SAME WAY:

  "User's current task: fix login bug" (NOW)
  → Day 1: Highly relevant
  → Day 7: Probably still relevant (slow bug?)
  → Day 30: Almost certainly resolved → low importance
  → Day 90: Zero relevance → delete or archive

  "User's name is Rahim"
  → Day 1: Very relevant
  → Year 1: Still very relevant!  ← Different shelf life!
  → Year 5: Still relevant!       ← Names don't expire!

KEY INSIGHT: Different memory TYPES need different shelf lives.
```

---

## 3. The Memory Shelf Life Classification

```
┌─────────────────────────────────────────────────────────────────┐
│              MEMORY TYPE → SHELF LIFE TABLE                     │
├──────────────────────┬────────────────┬─────────────────────────┤
│  MEMORY TYPE         │  SHELF LIFE    │  EXPIRY ACTION          │
├──────────────────────┼────────────────┼─────────────────────────┤
│ Core Identity        │ FOREVER        │ Never expire            │
│  (name, job title)   │                │                         │
├──────────────────────┼────────────────┼─────────────────────────┤
│ Current Project      │ 2 years        │ Archive after 2 years   │
├──────────────────────┼────────────────┼─────────────────────────┤
│ Technical Facts      │ 6-12 months    │ Review after 6 months   │
│  (versions, tools)   │                │ (tech changes fast!)    │
├──────────────────────┼────────────────┼─────────────────────────┤
│ Bug/Fix History      │ 6 months       │ Archive → prune         │
├──────────────────────┼────────────────┼─────────────────────────┤
│ Session Context      │ 7 days         │ Delete after 7 days     │
├──────────────────────┼────────────────┼─────────────────────────┤
│ Current Task         │ 3 days         │ Delete after 3 days     │
├──────────────────────┼────────────────┼─────────────────────────┤
│ Casual Mentions      │ 30 days        │ Delete after 30 days    │
├──────────────────────┼────────────────┼─────────────────────────┤
│ Rate Limit Counters  │ 1 hour         │ Auto-expire (Redis TTL) │
├──────────────────────┼────────────────┼─────────────────────────┤
│ Session State        │ 30 minutes     │ Auto-expire (Redis TTL) │
└──────────────────────┴────────────────┴─────────────────────────┘
```

---

## 4. The Aging State Machine

```
Every memory moves through states over time:

ACTIVE ──→ AGING ──→ STALE ──→ ARCHIVED ──→ DELETED
  │
  │    (on access: reset to ACTIVE)
  └──→ ACTIVE ←────────────────────────────────────┘

STATE DEFINITIONS:
  ACTIVE:   Recently created or accessed, full importance weight
  AGING:    Not accessed recently, importance slowly decaying
  STALE:    Old and unaccessed, low importance, candidate for archive
  ARCHIVED: Moved to cold storage, retrievable but low priority
  DELETED:  Permanently removed, unrecoverable

TRANSITIONS:
  ACTIVE → AGING:   No access for [threshold] days
  AGING → STALE:    No access for [2×threshold] days  
  STALE → ARCHIVED: No access for [4×threshold] days
  ARCHIVED → DELETED: No access for [archive_retention] days
  ANY → ACTIVE:     Memory is accessed (resets the clock!)
```

## 5. Complete Aging & Expiry System

```python
# aging_expiry.py
from datetime import datetime, timedelta
from typing import List, Dict, Optional, Tuple
from dataclasses import dataclass
from enum import Enum
import json
import os


class MemoryState(Enum):
    """Lifecycle states of a memory."""
    ACTIVE   = "active"
    AGING    = "aging"
    STALE    = "stale"
    ARCHIVED = "archived"
    DELETED  = "deleted"


@dataclass
class ExpiryPolicy:
    """
    Expiry policy for a specific memory category.
    Defines the shelf life and aging thresholds.
    """
    category: str
    active_days: int           # Days before memory starts aging
    stale_days: int            # Days before memory becomes stale
    archive_days: int          # Days before memory is archived
    delete_days: Optional[int] # Days before deletion (None = never delete)
    decay_rate: float          # How fast importance decays (0 = no decay)

    def get_state(self, created_at: datetime,
                  last_accessed_at: Optional[datetime]) -> MemoryState:
        """Determine current state based on time elapsed."""
        reference = last_accessed_at or created_at
        days_idle = (datetime.now() - reference).days

        if self.delete_days and days_idle >= self.delete_days:
            return MemoryState.DELETED
        elif days_idle >= self.archive_days:
            return MemoryState.ARCHIVED
        elif days_idle >= self.stale_days:
            return MemoryState.STALE
        elif days_idle >= self.active_days:
            return MemoryState.AGING
        else:
            return MemoryState.ACTIVE


class ExpiryPolicyRegistry:
    """
    Registry of expiry policies for all memory categories.
    Define your policies here and apply them globally.
    """

    DEFAULT_POLICIES: Dict[str, ExpiryPolicy] = {
        "core_identity": ExpiryPolicy(
            category="core_identity",
            active_days=9999,    # Never ages
            stale_days=9999,
            archive_days=9999,
            delete_days=None,    # NEVER deleted!
            decay_rate=0.0
        ),
        "project_fact": ExpiryPolicy(
            category="project_fact",
            active_days=180,     # 6 months active
            stale_days=365,      # 1 year before stale
            archive_days=730,    # 2 years before archive
            delete_days=None,    # Archive but don't delete
            decay_rate=0.002
        ),
        "technical": ExpiryPolicy(
            category="technical",
            active_days=90,      # 3 months active
            stale_days=180,      # 6 months before stale
            archive_days=365,    # 1 year before archive
            delete_days=730,     # 2 years before deletion
            decay_rate=0.005     # Tech changes fast → faster decay
        ),
        "debugging": ExpiryPolicy(
            category="debugging",
            active_days=60,      # 2 months active
            stale_days=120,
            archive_days=180,
            delete_days=365,
            decay_rate=0.01
        ),
        "preference": ExpiryPolicy(
            category="preference",
            active_days=180,
            stale_days=365,
            archive_days=730,
            delete_days=None,    # Preferences don't expire
            decay_rate=0.001
        ),
        "session_context": ExpiryPolicy(
            category="session_context",
            active_days=1,       # 1 day
            stale_days=3,
            archive_days=7,
            delete_days=30,      # Deleted after 30 days
            decay_rate=0.1
        ),
        "casual": ExpiryPolicy(
            category="casual",
            active_days=7,       # 1 week
            stale_days=14,
            archive_days=21,
            delete_days=30,      # Fast deletion
            decay_rate=0.05
        ),
        "ephemeral": ExpiryPolicy(
            category="ephemeral",
            active_days=0,       # Active for 0 days (immediately aging)
            stale_days=1,
            archive_days=3,
            delete_days=7,       # Gone in a week
            decay_rate=0.2
        ),
    }

    def get_policy(self, category: str) -> ExpiryPolicy:
        """Get policy for a category, with fallback to default."""
        return self.DEFAULT_POLICIES.get(
            category,
            # Default fallback policy
            ExpiryPolicy(
                category=category,
                active_days=60,
                stale_days=120,
                archive_days=365,
                delete_days=730,
                decay_rate=0.01
            )
        )


class AgingEngine:
    """
    Complete aging and expiry management system.
    
    Run this as a BACKGROUND JOB (daily/weekly):
    → Evaluates all memories against expiry policies
    → Moves memories through lifecycle states
    → Deletes/archives as appropriate
    → Reports what changed
    """

    def __init__(
        self,
        policy_registry: ExpiryPolicyRegistry = None,
        archive_storage_path: str = "./memory_archive"
    ):
        self.registry = policy_registry or ExpiryPolicyRegistry()
        self.archive_path = archive_storage_path
        os.makedirs(archive_path, exist_ok=True)

    def evaluate_memory(self, memory: Dict) -> Dict:
        """
        Evaluate a single memory's aging state.
        Returns the memory with updated state information.
        """
        category = memory.get("category", "interaction")
        policy = self.registry.get_policy(category)

        # Parse timestamps
        created_str = memory.get("created_at", datetime.now().isoformat())
        last_acc_str = memory.get("last_accessed_at")

        created_at = (
            datetime.fromisoformat(created_str)
            if isinstance(created_str, str)
            else created_str
        )
        last_accessed = (
            datetime.fromisoformat(last_acc_str)
            if isinstance(last_acc_str, str) and last_acc_str
            else None
        )

        # Determine state
        current_state = policy.get_state(created_at, last_accessed)

        # Compute importance decay
        reference = last_accessed or created_at
        days_idle = (datetime.now() - reference).days
        import math
        decayed_importance = (
            memory.get("importance", 0.5) *
            math.exp(-policy.decay_rate * days_idle)
        )

        # Update memory with aging info
        memory["_aging_state"] = current_state.value
        memory["_decayed_importance"] = round(decayed_importance, 4)
        memory["_days_idle"] = days_idle
        memory["_policy_category"] = category

        return memory

    def run_aging_cycle(
        self,
        memories: List[Dict],
        user_id: str,
        dry_run: bool = True
    ) -> Dict:
        """
        Run a complete aging cycle on all memories for a user.
        
        dry_run=True: Show what WOULD happen without actually changing anything
        dry_run=False: Actually archive and delete memories
        
        ALWAYS run with dry_run=True first to review!
        """
        user_memories = [
            m for m in memories
            if m.get("user_id") == user_id
        ]

        print(f"\n{'='*65}")
        print(f"⏰ AGING CYCLE — User: {user_id}")
        print(f"   Mode: {'DRY RUN' if dry_run else '⚡ LIVE'}")
        print(f"   Memories to process: {len(user_memories)}")
        print(f"{'='*65}")

        results = {
            "total_processed": len(user_memories),
            "state_distribution": {},
            "to_archive": [],
            "to_delete": [],
            "importance_updates": [],
            "no_change": []
        }

        for memory in user_memories:
            evaluated = self.evaluate_memory(memory.copy())
            state = evaluated["_aging_state"]
            mem_id = memory.get("id", "")
            mem_text = memory.get("text", "")[:60]

            # Track state distribution
            results["state_distribution"][state] = (
                results["state_distribution"].get(state, 0) + 1
            )

            if state == MemoryState.DELETED.value:
                results["to_delete"].append({
                    "id": mem_id,
                    "text": mem_text,
                    "days_idle": evaluated["_days_idle"],
                    "category": memory.get("category")
                })

            elif state == MemoryState.ARCHIVED.value:
                results["to_archive"].append({
                    "id": mem_id,
                    "text": mem_text,
                    "days_idle": evaluated["_days_idle"],
                    "original_importance": memory.get("importance", 0.5),
                    "decayed_importance": evaluated["_decayed_importance"]
                })

            elif evaluated["_decayed_importance"] != memory.get("importance"):
                results["importance_updates"].append({
                    "id": mem_id,
                    "old_importance": memory.get("importance", 0.5),
                    "new_importance": evaluated["_decayed_importance"]
                })

            else:
                results["no_change"].append(mem_id)

            # Execute changes if not dry run
            if not dry_run:
                if state == MemoryState.ARCHIVED.value:
                    self._archive_memory(memory)
                # Note: actual deletion would call your DB delete method

        # Print report
        self._print_aging_report(results, dry_run)
        return results

    def _archive_memory(self, memory: Dict):
        """Move a memory to cold archive storage."""
        user_id = memory.get("user_id", "unknown")
        archive_file = os.path.join(
            self.archive_path,
            f"{user_id}_archive.jsonl"
        )

        memory["archived_at"] = datetime.now().isoformat()

        with open(archive_file, "a") as f:
            f.write(json.dumps(memory) + "\n")

    def _print_aging_report(
        self,
        results: Dict,
        dry_run: bool
    ):
        """Print a human-readable aging cycle report."""
        prefix = "[DRY RUN] " if dry_run else ""

        print(f"\n📊 AGING CYCLE RESULTS {prefix}")
        print(f"   Total processed: {results['total_processed']}")

        print(f"\n   State Distribution:")
        state_icons = {
            "active":   "🟢",
            "aging":    "🟡",
            "stale":    "🟠",
            "archived": "📦",
            "deleted":  "🗑️"
        }
        for state, count in sorted(results["state_distribution"].items()):
            icon = state_icons.get(state, "⚪")
            print(f"   {icon} {state.upper():<12}: {count}")

        if results["to_archive"]:
            print(f"\n   📦 TO ARCHIVE ({len(results['to_archive'])}):")
            for m in results["to_archive"][:3]:
                print(f"      [{m['days_idle']}d idle] {m['text']}")

        if results["to_delete"]:
            print(f"\n   🗑️ TO DELETE ({len(results['to_delete'])}):")
            for m in results["to_delete"][:3]:
                print(f"      [{m['days_idle']}d idle] {m['text']}")

        print(f"\n   ℹ️ Importance updates: {len(results['importance_updates'])}")
        print(f"   ✅ No change: {len(results['no_change'])}")

    def schedule_next_run(
        self,
        last_run: datetime,
        cycle_days: int = 7
    ) -> datetime:
        """
        Calculate when the next aging cycle should run.
        
        RECOMMENDED CYCLES:
        → Active apps (100+ daily users): Run daily
        → Medium apps: Run weekly
        → Small apps: Run monthly
        """
        return last_run + timedelta(days=cycle_days)

from datetime import datetime
from typing import List, Dict, Optional
import asyncio


class MemoryManagementOrchestrator:
    """
    Orchestrates all memory compression and pruning techniques.
    This is the TOP-LEVEL class you use in production.

    orchestrator = MemoryManagementOrchestrator(

    """

        self,
        user_id: str,
        vector_store=None,
        sql_db=None

        self.vector_store = vector_store
        self.sql_db = sql_db

        # Initialize all components
        self.window_manager = SlidingWindowManager(
            config=WindowConfig(
                max_messages=20,
                max_tokens=6000,
                min_importance_to_protect=0.85,
                save_on_eviction=True
            ),
            on_eviction_callback=self._on_message_evicted

        self.deduplicator = DeduplicationEngine()
        self.pruning_scorer = PruningScorer()
        self.aging_engine = AgingEngine()

    def handle_new_message(
        self,
        role: str,
        content: str
    ) -> List[Dict]:
        """
        Handle incoming message — runs on HOT PATH.
        Returns current context for LLM call.
        """
        # Add to sliding window
        self.window_manager.add_message(role, content)

        # Track full session
        self.session_messages.append({
            "role": role, "content": content,
            "timestamp": datetime.now().isoformat()
        })

        # Return context for LLM
        return self.window_manager.get_messages()

    def _on_message_evicted(
        self,
        message: Dict,
        importance: float,
        key_content: str
    ):
        """
        Callback: Save important messages to long-term memory
        BEFORE they slide out of the window.
        """
        if self.vector_store and importance >= 0.5:
            self.vector_store.add_memory(
                memory_id=f"evicted_{datetime.now().timestamp()}",
                user_id=self.user_id,
                text=key_content,
                metadata={
                    "source": "window_eviction",
                    "importance": importance,
                    "session_id": self.session_id
                }

    def end_session(self) -> Dict:
        """
        WARM PATH: Called when user session ends.
        Summarizes session and stores key facts.
        """
        print(f"\n🏁 Session ending: {self.session_id}")

        if len(self.session_messages) < 3:
            return {"status": "session_too_short", "memories_extracted": 0}

        # Generate comprehensive session summary
        summary_result = self.summarizer.summarize_messages(
            messages=self.session_messages

        memories_to_store = self.summarizer.extract_long_term_memories(
            summary_result, self.user_id
        )

        stored_count = 0
        if self.vector_store:
            for mem in memories_to_store:
                self.vector_store.add_memory(
                    memory_id=f"session_{self.session_id}_{stored_count}",
                    user_id=self.user_id,
                    text=mem["text"],
                    metadata=mem
                )

            "status": "completed",
            "memories_extracted": stored_count,
            "summary": summary_result.get("summary", ""),
            "compression_ratio": summary_result.get("compression_ratio", 1)
        }

        self,
        dry_run: bool = True

        COLD PATH: Run full maintenance cycle.

            user_id=self.user_id

            memories=all_memories,
            user_id=self.user_id
        )
        results["pruning_candidates"] = len([
            d for d in prune_decisions
            if d.action.value == "prune"

        aging_result = self.aging_engine.run_aging_cycle(
            memories=all_memories,
            user_id=self.user_id,
            dry_run=dry_run

        results["aging"] = aging_result

        # Apply changes if not dry run
        if not dry_run:

                for mem_id in dedup_result.get("to_delete", []):
                    self.sql_db.delete_memory(mem_id)

                # Archive old memories
                for mem in aging_result.get("to_archive", []):
                    self.sql_db.archive_memory(mem["id"])

                # Delete expired memories
                for mem in aging_result.get("to_delete", []):
                    self.sql_db.delete_memory(mem["id"])

        print(f"\n✅ Maintenance complete")
        return results

# 🎯 INTERVIEW QUESTIONS + STRONG ANSWERS

### ❓ Q1: "Why do AI memory systems need compression and pruning? Can't you just store everything?"

**💬 Strong Answer:**
> "You can store everything initially, but over time three problems emerge. First, storage cost scales linearly with data but usefulness doesn't — after 6 months, 90% of stored memories may be irrelevant, stale, or duplicated, yet you're paying to store and search all of them. Second, retrieval quality degrades — when the system searches through 50,000 memories including thousands of outdated facts, the relevant signal gets buried in noise, causing the LLM to receive poor context. Third, memory contradictions accumulate — without pruning, the system holds both 'User works at Google' and 'User now works at Meta,' confusing the AI. Compression and pruning keep the memory lean, accurate, and fast. The goal isn't to store everything — it's to store the RIGHT things."

---

### ❓ Q2: "Explain rolling summarization and how it differs from full summarization."

**💬 Strong Answer:**
> "Full summarization takes an entire conversation and produces one comprehensive summary — useful for archiving completed sessions. Rolling summarization is a continuous process: as the conversation grows beyond a token threshold, you summarize the oldest messages into a running summary while keeping the most recent messages in their original form. The context you pass to the LLM becomes 'running summary plus last N live messages.' As the conversation continues growing, you progressively incorporate more messages into the summary. This is superior for active conversations because it gives the LLM both compressed historical context and verbatim recent context, which is most important for maintaining conversational flow. The key engineering insight is that this converts an O(n) token cost per message to O(1) amortized cost."

---

### ❓ Q3: "How do you approach deduplication in a vector memory store?"

**💬 Strong Answer:**
> "I use a three-stage pipeline. Stage one is exact deduplication using hash comparison — normalize the text, compute an MD5 hash, and find identical hashes. This is O(n) time and handles obvious duplicates instantly. Stage two is near-duplicate detection using embedding similarity — compute cosine similarity between all memory pairs and group those above a threshold, typically 0.90 to 0.92. Memories in the same group say essentially the same thing in different words. Stage three is semantic verification using an LLM — for borderline cases between 0.80 and 0.90 similarity, ask the LLM whether two memories express the same core fact. When duplicates are found, I either delete all but the canonical memory — choosing the one with highest importance score — or merge duplicates into a single richer memory using an LLM to combine the unique details from each duplicate."

---

### ❓ Q4: "What is an aging and expiry policy? How would you design one for different memory types?"

**💬 Strong Answer:**
> "An aging policy defines the lifecycle of a memory — how long it stays active, when it becomes stale, when it gets archived, and when it gets permanently deleted. Different memory types have completely different shelf lives. Core identity memories like a user's name should never expire — they're as valid tomorrow as today. Technical facts like the Python version a user is using should expire after 6 to 12 months because technology evolves rapidly. Session context like 'user's current task today' should expire within 3 to 7 days. Casual mentions like 'user likes pizza' expire after 30 days. The key engineering principle is implementing this as a state machine — memories move through Active, Aging, Stale, Archived, and Deleted states, with transitions triggered by time elapsed since last access. Critically, access RESETS the clock — a memory used yesterday becomes Active again regardless of its age."

---

### ❓ Q5: "How does sliding window truncation differ from conversation summarization? When would you use each?"

**💬 Strong Answer:**
> "Sliding window truncation is a pure mechanical approach — it maintains a fixed-size queue of messages and discards oldest messages when the limit is reached. It requires zero LLM calls, has zero latency overhead, and has guaranteed token budget. Its weakness is potential information loss. Conversation summarization uses an LLM to compress old messages into a dense summary that preserves key facts even as verbatim messages are removed. It requires LLM API calls, adds latency, and can introduce rare summarization errors. In practice I use both together: sliding window runs on every message as the primary mechanism, and when messages are about to be evicted, an importance detector decides whether to save them. Then at session end, summarization runs as a batch process to compress the full session into extractable facts for long-term memory. The sliding window is the real-time safety valve; summarization is the high-quality archival mechanism."

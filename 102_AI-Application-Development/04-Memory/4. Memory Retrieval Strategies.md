## The Retrieval Quality Framework

Before any retrieval strategy, know what "good retrieval" means:

```
GOOD RETRIEVAL = R.A.F.T.

R = Relevant (semantically related to the current query)
A = Accurate (factually correct, not stale or wrong)
F = Fresh (recent enough to still be valid)
T = Targeted (specific to THIS user, not other users)

Every retrieval strategy we study tries to optimize R.A.F.T.
Each strategy excels at different letters.
That's why we need ALL FIVE strategies working together.
```

# 📅 STRATEGY 1: Recency-Based Retrieval

## 1. What Is It?

> **Recency-Based Retrieval = Find memories based on WHEN they were created or accessed. Most recent memories first.**

The idea is simple: **what happened recently is most likely relevant right now.**

---

## 2. First-Principles Breakdown

```
BASIC TRUTH:
  Most human conversations have temporal locality.
  "I just told you my name" → 30 seconds ago
  "We were discussing Flask" → 10 minutes ago
  "I set up this project" → 3 days ago
  
  Recent = More likely still relevant
  Old = May be outdated, no longer applies
  
  BUT: Recent ≠ Always Relevant
  "What's my name?" → needs memory from 3 months ago
  "What's my project stack?" → needs memory from yesterday
  
  Recency alone is NECESSARY but NOT SUFFICIENT.
```

---

## 3. Analogy: The Newspaper Stack

```
🗞️ Recency Retrieval = Reading the Newspaper Stack

You have a stack of newspapers:
  TODAY'S paper         ← top of stack (most recent)
  Yesterday's paper
  Last week's paper
  Last month's paper
  Last year's paper     ← bottom of stack (oldest)

For "What's in the news?" → TODAY'S paper is perfect ✅
For "What happened in elections last year?" → wrong strategy ❌

Recency works when the question is about recent events.
Fails when the answer lives in an old newspaper.
```

---

## 4. Types of Recency

```
THREE DIMENSIONS OF RECENCY:
─────────────────────────────────────────────────────────
1. CREATION TIME:
   When was this memory FIRST stored?
   "User joined project: Jan 2025" → created 6 months ago
   Sorted by: memory.created_at

2. ACCESS TIME:
   When was this memory LAST RETRIEVED?
   "User's name: Rahim" → retrieved 1 minute ago
   A memory accessed recently may be actively relevant!
   Sorted by: memory.last_accessed_at

3. SESSION RECENCY:
   From which session does this memory come?
   "Bug fix discussion" → from today's session
   vs "Same bug" → from session 3 months ago
   Sorted by: memory.session_id → session.started_at
```

---

## 5. The Time Decay Function

> **Key Insight:** Recency shouldn't be binary (recent/old). It should be a GRADIENT — memories become LESS relevant over time, but NEVER fully disappear.

```
HUMAN MEMORY TIME DECAY:
  10 minutes ago → 100% weight
  1 hour ago     → 95% weight
  1 day ago      → 70% weight
  1 week ago     → 40% weight
  1 month ago    → 20% weight
  1 year ago     → 5% weight  (still useful!)

MATHEMATICAL MODEL:
  recency_score = e^(-λ × time_elapsed)

  Where:
  e = Euler's number (2.718...)
  λ = decay rate (controls how fast relevance drops)
  time_elapsed = hours since memory was created

  λ = 0.01 → slow decay (memories stay relevant longer)
  λ = 0.1  → medium decay
  λ = 1.0  → fast decay (memories become irrelevant quickly)
```

```python
# recency_retrieval.py
import math
from datetime import datetime, timedelta
from typing import List, Dict, Optional, Tuple
from enum import Enum
from dataclasses import dataclass, field


class RecencyStrategy(Enum):
    """Different ways to define 'recent'."""
    CREATION_TIME = "creation_time"
    ACCESS_TIME   = "access_time"
    SESSION_ORDER = "session_order"
    DECAY_SCORED  = "decay_scored"  # Most sophisticated


@dataclass
class Memory:
    """A single memory entry with all temporal metadata."""
    id: str
    user_id: str
    text: str
    created_at: datetime
    last_accessed_at: Optional[datetime] = None
    session_id: str = ""
    session_order: int = 0       # Which session (1 = first, 100 = 100th)
    category: str = "general"
    importance_score: float = 0.5
    access_count: int = 0

    def time_since_creation(self) -> float:
        """Hours elapsed since this memory was created."""
        delta = datetime.now() - self.created_at
        return delta.total_seconds() / 3600  # Convert to hours

    def time_since_access(self) -> float:
        """Hours elapsed since this memory was last accessed."""
        if self.last_accessed_at is None:
            return self.time_since_creation()
        delta = datetime.now() - self.last_accessed_at
        return delta.total_seconds() / 3600


class RecencyRetrieval:
    """
    Complete recency-based memory retrieval system.
    
    Implements multiple recency strategies and time decay models.
    """

    def __init__(self, decay_rate: float = 0.05):
        """
        decay_rate (λ):
          0.01 = very slow decay (good for stable facts)
          0.05 = medium decay (good for most memories)
          0.20 = fast decay (good for volatile/session info)
        """
        self.decay_rate = decay_rate

    # ── CORE DECAY FUNCTION ───────────────────────────────────

    def exponential_decay(
        self,
        hours_elapsed: float,
        decay_rate: float = None
    ) -> float:
        """
        Calculate memory recency score using exponential decay.

        Formula: score = e^(-λ × t)

        INTUITION:
        - t = 0    → score = e^0 = 1.0  (just created, max score)
        - t = 10h  → score = e^(-0.05 × 10) ≈ 0.61 (still relevant)
        - t = 24h  → score = e^(-0.05 × 24) ≈ 0.30 (less relevant)
        - t = 100h → score = e^(-0.05 × 100) ≈ 0.01 (barely relevant)

        The score NEVER reaches 0 — old memories can still help!
        """
        λ = decay_rate or self.decay_rate
        score = math.exp(-λ * hours_elapsed)
        return round(score, 4)

    def stepped_decay(self, hours_elapsed: float) -> float:
        """
        Simpler stepped decay model.
        Assigns fixed weights based on time buckets.
        
        Less mathematically elegant but very intuitive.
        """
        if hours_elapsed < 1:          # Last hour
            return 1.00
        elif hours_elapsed < 6:        # Last 6 hours
            return 0.90
        elif hours_elapsed < 24:       # Today
            return 0.75
        elif hours_elapsed < 72:       # Last 3 days
            return 0.55
        elif hours_elapsed < 168:      # Last week
            return 0.35
        elif hours_elapsed < 720:      # Last month
            return 0.15
        else:                          # Older than a month
            return 0.05

    # ── RETRIEVAL METHODS ─────────────────────────────────────

    def get_by_creation_time(
        self,
        memories: List[Memory],
        n: int = 10,
        max_age_hours: float = None
    ) -> List[Memory]:
        """
        Get N most recently CREATED memories.
        Optional: filter out memories older than max_age_hours.

        WHEN TO USE:
        → User asks about recent events
        → Building short-term conversation context
        → Loading recent session history
        """
        # Optional age filter
        if max_age_hours:
            memories = [
                m for m in memories
                if m.time_since_creation() <= max_age_hours
            ]

        # Sort by creation time (newest first)
        sorted_memories = sorted(
            memories,
            key=lambda m: m.created_at,
            reverse=True
        )

        return sorted_memories[:n]

    def get_by_access_time(
        self,
        memories: List[Memory],
        n: int = 10
    ) -> List[Memory]:
        """
        Get memories that were most RECENTLY ACCESSED.

        WHY THIS MATTERS:
        A memory accessed 5 minutes ago for this conversation
        is highly likely to be relevant RIGHT NOW.

        This captures "working memory" — facts actively in use.
        """
        sorted_memories = sorted(
            memories,
            key=lambda m: m.last_accessed_at or m.created_at,
            reverse=True
        )
        return sorted_memories[:n]

    def get_with_decay_scores(
        self,
        memories: List[Memory],
        n: int = 10,
        use_access_time: bool = True,
        decay_type: str = "exponential"
    ) -> List[Tuple[Memory, float]]:
        """
        Retrieve memories ranked by TIME DECAY SCORE.

        Returns: List of (memory, recency_score) tuples

        This is the most sophisticated recency approach.
        Gives a CONTINUOUS score instead of binary fresh/stale.
        """
        scored_memories = []

        for memory in memories:
            # Choose which time to base decay on
            if use_access_time and memory.last_accessed_at:
                hours = memory.time_since_access()
            else:
                hours = memory.time_since_creation()

            # Calculate decay score
            if decay_type == "exponential":
                score = self.exponential_decay(hours)
            else:
                score = self.stepped_decay(hours)

            scored_memories.append((memory, score))

        # Sort by recency score (highest first)
        scored_memories.sort(key=lambda x: x[1], reverse=True)

        return scored_memories[:n]

    def get_session_window(
        self,
        memories: List[Memory],
        current_session_id: str,
        include_last_n_sessions: int = 3
    ) -> List[Memory]:
        """
        Get memories from the current session + last N sessions.

        STRATEGY:
        → Current session: Always included (most relevant!)
        → Last N sessions: Context about recent work
        → Older sessions: Excluded (too old for now)

        This is a session-aware sliding window.
        """
        # Get unique sessions ordered by recency
        sessions_seen = {}
        for m in memories:
            if m.session_id not in sessions_seen:
                sessions_seen[m.session_id] = m.created_at

        # Sort sessions by time (newest first)
        sorted_sessions = sorted(
            sessions_seen.items(),
            key=lambda x: x[1],
            reverse=True
        )

        # Include current session + last N
        relevant_session_ids = {current_session_id}
        session_counter = 0

        for session_id, _ in sorted_sessions:
            if session_id == current_session_id:
                continue
            if session_counter < include_last_n_sessions:
                relevant_session_ids.add(session_id)
                session_counter += 1

        # Filter memories to only included sessions
        filtered = [
            m for m in memories
            if m.session_id in relevant_session_ids
        ]

        # Sort by creation time within sessions
        return sorted(filtered, key=lambda m: m.created_at, reverse=True)

    # ── UTILITY: SCORE VISUALIZATION ──────────────────────────

    def visualize_decay_curve(
        self,
        max_hours: int = 168,   # 1 week
        decay_type: str = "exponential"
    ):
        """
        Show how scores change over time.
        Helps you choose the right decay_rate for your app.
        """
        print(f"\n{'='*50}")
        print(f"TIME DECAY CURVE ({decay_type})")
        print(f"{'='*50}")
        print(f"{'Time':<20} {'Score':<10} {'Bar'}")
        print("-" * 50)

        time_points = [0, 1, 6, 12, 24, 48, 72, 168]

        for hours in time_points:
            if decay_type == "exponential":
                score = self.exponential_decay(hours)
            else:
                score = self.stepped_decay(hours)

            bar_length = int(score * 30)
            bar = "█" * bar_length

            # Human readable time
            if hours == 0:
                label = "Now"
            elif hours < 24:
                label = f"{hours}h ago"
            else:
                label = f"{hours // 24}d ago"

            print(f"{label:<20} {score:<10.3f} {bar}")

        print("=" * 50)


# ── USAGE EXAMPLE ──────────────────────────────────────────────
def demo_recency_retrieval():
    """Show recency retrieval in action."""

    # Create sample memories at different times
    now = datetime.now()
    memories = [
        Memory("m1", "u1", "User's name is Rahim",
               now - timedelta(days=90)),
        Memory("m2", "u1", "User is building a Flask API",
               now - timedelta(days=7)),
        Memory("m3", "u1", "User had JWT authentication bug",
               now - timedelta(days=3)),
        Memory("m4", "u1", "User fixed the JWT issue with SECRET_KEY",
               now - timedelta(hours=5)),
        Memory("m5", "u1", "User is now working on user registration",
               now - timedelta(minutes=30)),
        Memory("m6", "u1", "Current bug: email validation not working",
               now - timedelta(minutes=5)),
    ]

    retriever = RecencyRetrieval(decay_rate=0.05)

    # Show decay curve
    retriever.visualize_decay_curve()

    # Get top 3 by creation time

    # Get with decay scores
    print("\n📊 ALL MEMORIES WITH DECAY SCORES:")
    scored = retriever.get_with_decay_scores(memories, n=6)
    for memory, score in scored:
        hours = memory.time_since_creation()
        bar = "█" * int(score * 20)
        print(f"  Score:{score:.3f} [{hours:.0f}h ago] {bar} {memory.text[:40]}")


if __name__ == "__main__":
    demo_recency_retrieval()
```

# 🔍 STRATEGY 2: Similarity-Based Retrieval

## 1. What Is It?

> **Similarity-Based Retrieval = Convert the user's query AND all memories into mathematical vectors, then find memories whose vectors are CLOSEST to the query vector. Closest = most similar in MEANING.**

This is the **most powerful** retrieval strategy for AI memory. It finds relevance based on **semantic meaning**, not just keywords or timestamps.

---

## 2. First-Principles: From Words to Numbers

```
THE FUNDAMENTAL QUESTION:
How do you measure how "related" two pieces of text are?

APPROACH 1: Count shared words (Jaccard Similarity)
  "Python debugging help" vs "Python coding assistance"
  Shared words: "Python"  → similarity = 1/5 = 0.20 (weak!)
  Misses: "debugging" ≈ "help" ≈ "coding" ≈ "assistance"

APPROACH 2: TF-IDF + Cosine (Classical NLP)
  Better! Weights rare words higher.
  Still doesn't understand MEANING.

APPROACH 3: Dense Embeddings (Modern AI)
  Converts TEXT → VECTOR of 1536 numbers
  Numbers ENCODE the meaning mathematically
  Similar meanings → similar numbers → high cosine similarity
  
  "Python debugging help" → [0.23, -0.45, 0.67, 0.12, ...]
  "coding error in Python" → [0.21, -0.43, 0.65, 0.14, ...]
  → Cosine similarity ≈ 0.97 (VERY similar!) ✅
  
  "chocolate cake recipe" → [-0.78, 0.92, -0.33, 0.67, ...]
  → Cosine similarity ≈ 0.05 (very different!) ✅
```

---

## 3. Analogy: The Constellation Map of Meaning

```
🌌 Imagine the entire universe of human language 
   as a 3D star map (actually 1536 dimensions, but imagine 3D):

   Cluster 1 (Tech):
     ●"Python"  ●"code" ●"debug" ●"programming"
   
   Cluster 2 (Food):
     ●"recipe" ●"cake" ●"baking" ●"cooking"
   
   Cluster 3 (Medical):
     ●"doctor" ●"diagnosis" ●"treatment" ●"patient"

   When you query "Fix my Python error":
   Your query lands near the Tech cluster.
   The retrieval system finds all memories NEAR that cluster.
   Memories about cooking? They're far away → not retrieved.

SIMILARITY SEARCH = "Show me the stars closest to this point."
```

---

## 4. Deep Dive: How Cosine Similarity Works

```
THE MATH (from zero, step by step):

STEP 1: You have two vectors
  Query Vector:  Q = [0.8, 0.2, 0.5]  ← represents "fix Python bug"
  Memory Vector: M = [0.7, 0.3, 0.6]  ← represents "debug Python code"

STEP 2: Calculate Dot Product (numerator)
  Q · M = (0.8 × 0.7) + (0.2 × 0.3) + (0.5 × 0.6)
        = 0.56 + 0.06 + 0.30
        = 0.92

STEP 3: Calculate Magnitudes (lengths of vectors)
  |Q| = √(0.8² + 0.2² + 0.5²) = √(0.64 + 0.04 + 0.25) = √0.93 = 0.964
  |M| = √(0.7² + 0.3² + 0.6²) = √(0.49 + 0.09 + 0.36) = √0.94 = 0.970

STEP 4: Divide
  cosine_similarity = Q · M / (|Q| × |M|)
                    = 0.92 / (0.964 × 0.970)
                    = 0.92 / 0.935
                    = 0.984 ← Very similar! (close to 1.0) ✅

INTERPRETATION:
  1.0  = Identical meaning
  0.9+ = Very similar meaning
  0.7+ = Related meaning
  0.5+ = Somewhat related
  0.3- = Unrelated
  0.0  = No relationship
  -1.0 = Opposite meaning
```

## 5. HNSW — How Vector DBs Search Fast

```
THE PROBLEM: You have 10 million memory vectors.
For each query, you'd need to compare against ALL 10 million.
That's 10 million cosine similarity calculations = SLOW!

THE SOLUTION: HNSW (Hierarchical Navigable Small World)

INTUITION — Think of it like a city navigation system:
  
  LAYER 3 (Highways): 
    Few nodes, long-range connections
    Start search here for rough direction
    ●─────────────────●─────────────────●
    
  LAYER 2 (Main Roads):
    More nodes, medium connections
    Narrow down the search
    ●───●─────●───●─────●───●
    
  LAYER 1 (Streets):
    All nodes, short connections
    Find exact nearest neighbor
    ●─●─●─●─●─●─●─●─●─●─●─●

SEARCH PROCESS:
  1. Enter at top layer (few nodes)
  2. Find nearest neighbor at this level
  3. Drop to next layer → search local neighborhood
  4. Repeat until bottom layer
  5. Return the exact nearest neighbors

RESULT:
  O(log n) search time instead of O(n)
  1 million vectors → 20 comparisons instead of 1,000,000!
  100,000x FASTER! 🚀
```

```python
# similarity_retrieval.py
import chromadb
from openai import OpenAI
from sentence_transformers import SentenceTransformer
from typing import List, Dict, Optional, Tuple
from datetime import datetime
import numpy as np
import hashlib
import json
import os


class EmbeddingEngine:
    """
    Handles text → vector conversion.
    Supports both OpenAI (paid) and local (free) models.
    """

    def __init__(
        self,
        use_openai: bool = True,
        openai_model: str = "text-embedding-3-small",
        local_model: str = "all-MiniLM-L6-v2",
        cache_path: str = "./embedding_cache.json"
    ):
        self.use_openai = use_openai
        self.openai_model = openai_model
        self.cache_path = cache_path

        if use_openai:
            self.client = OpenAI()
            # OpenAI small model = 1536 dimensions
            # OpenAI large model = 3072 dimensions
        else:
            # Free! Runs locally. 384 dimensions.
            print("Loading local embedding model...")
            self.local_model = SentenceTransformer(local_model)

        # Load embedding cache
        self.cache = self._load_cache()

    def _load_cache(self) -> dict:
        """Load cached embeddings from disk."""
        if os.path.exists(self.cache_path):
            with open(self.cache_path, 'r') as f:
                return json.load(f)
        return {}

    def _save_cache(self):
        """Save embedding cache to disk."""
        with open(self.cache_path, 'w') as f:
            json.dump(self.cache, f)

    def _cache_key(self, text: str) -> str:
        """Generate cache key from text + model."""
        model = self.openai_model if self.use_openai else "local"
        return hashlib.md5(f"{model}:{text}".encode()).hexdigest()

    def embed(self, text: str, use_cache: bool = True) -> List[float]:
        """
        Convert text to embedding vector.
        Uses cache to avoid redundant API calls.

        Cost example:
        OpenAI text-embedding-3-small = $0.02 per 1M tokens
        "Hello world" ≈ 2 tokens = $0.00000004 per call
        But with 1M calls → $40!
        Cache makes frequently-used texts FREE after first call.
        """
        if use_cache:
            key = self._cache_key(text)
            if key in self.cache:
                return self.cache[key]

        # Compute embedding
        if self.use_openai:
            response = self.client.embeddings.create(
                model=self.openai_model,
                input=text
            )
            embedding = response.data[0].embedding
        else:
            embedding = self.local_model.encode(text).tolist()

        # Cache the result
        if use_cache:
            key = self._cache_key(text)
            self.cache[key] = embedding
            self._save_cache()

        return embedding

    def embed_batch(self, texts: List[str]) -> List[List[float]]:
        """
        Embed multiple texts in ONE API call.
        100x cheaper than calling embed() in a loop!
        """
        if not texts:
            return []

        # Check cache for each text
        results = [None] * len(texts)
        uncached_indices = []
        uncached_texts = []

        for i, text in enumerate(texts):
            key = self._cache_key(text)
            if key in self.cache:
                results[i] = self.cache[key]
            else:
                uncached_indices.append(i)
                uncached_texts.append(text)

        # Compute only uncached embeddings
        if uncached_texts:
            if self.use_openai:
                response = self.client.embeddings.create(
                    model=self.openai_model,
                    input=uncached_texts  # ONE API call for ALL!
                )
                new_embeddings = [e.embedding for e in response.data]
            else:
                new_embeddings = self.local_model.encode(
                    uncached_texts
                ).tolist()

            # Fill in results and update cache
            for idx, (orig_i, emb) in enumerate(
                zip(uncached_indices, new_embeddings)
            ):
                results[orig_i] = emb
                key = self._cache_key(uncached_texts[idx])
                self.cache[key] = emb

            self._save_cache()

        return results

    def cosine_similarity(
        self,
        vec_a: List[float],
        vec_b: List[float]
    ) -> float:
        """
        Calculate cosine similarity between two vectors.
        Returns: -1.0 to 1.0 (higher = more similar)
        """
        a = np.array(vec_a)
        b = np.array(vec_b)

        dot = np.dot(a, b)
        norm_a = np.linalg.norm(a)
        norm_b = np.linalg.norm(b)

        if norm_a == 0 or norm_b == 0:
            return 0.0

        return float(dot / (norm_a * norm_b))

    def search(
        self,
        user_id: str,
        query: str,
        n_results: int = 5,
        min_similarity: float = 0.6,
        additional_filters: Dict = None
    ) -> List[Dict]:
        """
        THE CORE OPERATION: Semantic similarity search.

        Steps:
        1. Embed the query
        2. Find nearest neighbors in vector space
        3. Filter by user_id (privacy!)
        4. Filter by minimum similarity threshold
        5. Return ranked results with scores

        THRESHOLD GUIDE:
        0.90+ = Near-identical meaning
        0.80+ = Closely related
        0.70+ = Related (good default)
        0.60+ = Loosely related
        0.50+ = Possibly related
        < 0.50 = Probably irrelevant
        """
        # STEP 1: Embed query
        query_embedding = self.embedder.embed(query)

        # STEP 2: Build filter — ALWAYS filter by user_id!
        where_filter = {"user_id": user_id}
        if additional_filters:
            # Merge additional filters
            where_filter = {"$and": [
                {"user_id": user_id},
                *[{k: v} for k, v in additional_filters.items()]
            ]}

        # STEP 3: Query ChromaDB
        try:
            results = self.collection.query(
                query_embeddings=[query_embedding],
                n_results=min(
                    n_results + 5,  # Fetch extra, filter by threshold later
                    max(1, self.collection.count())
                ),
                where=where_filter,
                include=["documents", "metadatas", "distances"]
            )
        except Exception as e:
            print(f"⚠️ Search error: {e}")
            return []

        if not results["documents"][0]:
            return []

        # STEP 4: Process and filter results
        memories = []
        for doc, meta, distance in zip(
            results["documents"][0],
            results["metadatas"][0],
            results["distances"][0]
        ):
            # Convert distance to similarity
            # ChromaDB cosine distance: 0 = identical, 2 = opposite
            # similarity = 1 - (distance / 2)  OR  1 - distance
            # (depends on ChromaDB version and metric)
            similarity = 1 - distance

            if similarity >= min_similarity:
                memories.append({
                    "text": doc,
                    "similarity": round(similarity, 4),
                    "metadata": meta,
                    "created_at": meta.get("created_at", ""),
                    "category": meta.get("category", "general"),
                    "retrieval_method": "similarity"
                })

        # STEP 5: Sort by similarity (highest first)
        memories.sort(key=lambda x: x["similarity"], reverse=True)

        # STEP 6: Update access counts (background tracking)
        self._update_access_tracking(memories)

        return memories[:n_results]
```

# 🏷️ STRATEGY 3: Metadata Filtering

## 1. What Is It?

> **Metadata Filtering = Before or after semantic search, apply HARD FILTERS based on structured attributes (category, date range, user_id, importance score, etc.) to narrow down the candidate pool.**

Metadata filtering answers the question: *"I know WHAT I'm looking for — now let me look ONLY in the right place."*

---

## 2. First-Principles: Pre-filter vs Post-filter

```
TWO FILTERING APPROACHES:

PRE-FILTER (Filter → Then Search):
  → First: reduce candidate pool using metadata
  → Then: semantic search within that smaller pool
  
  Example:
  Total memories: 1,000,000
  After filter (user_id + category): 5,000
  Semantic search on 5,000: fast, precise ✅
  
  DOWNSIDE: If filter is too strict → might miss relevant memories

POST-FILTER (Search → Then Filter):
  → First: semantic search on ALL memories
  → Then: remove results that don't match metadata
  
  Example:
  Semantic search returns 100 candidates
  Filter by category="debugging" → 12 remain
  
  DOWNSIDE: Semantic search on all memories → expensive

BEST PRACTICE: Pre-filter on user_id ALWAYS
              Pre-filter on category/type when you're confident
              Post-filter for soft constraints (score thresholds)
```

---

## 3. Analogy: The Library with Call Numbers

```
📚 Library Analogy:

WITHOUT metadata filtering:
  "Find me books about authentication"
  → Search through ALL 500,000 books
  → Slow, finds irrelevant books

WITH metadata filtering:
  "Find books about authentication 
   in Section: Computer Science
   Published: after 2020
   Language: English"
  
  → Filter: Section=CS → 5,000 books
  → Filter: After 2020 → 1,200 books
  → Search within 1,200 for "authentication"
  → Find exactly what you need, fast! ✅

Metadata = The call number system that organizes the library.
Without it → chaos.
With it → instant navigation to the right section.
```

```python
# metadata_filtering.py
from datetime import datetime, timedelta
from typing import Any, Dict, List, Optional, Union
from dataclasses import dataclass, field
from enum import Enum


class FilterOperator(Enum):
    """Available filter operators."""
    EQUALS      = "eq"
    NOT_EQUALS  = "ne"
    GREATER     = "gt"
    LESS        = "lt"
    GTE         = "gte"   # Greater Than or Equal
    LTE         = "lte"   # Less Than or Equal
    IN          = "in"    # Value in list
    NOT_IN      = "nin"   # Value not in list
    CONTAINS    = "contains"
    STARTS_WITH = "starts_with"


@dataclass
class FilterCondition:
    """
    A single filter condition.

    Examples:
    FilterCondition("category", FilterOperator.EQUALS, "debugging")
    FilterCondition("importance", FilterOperator.GTE, 0.7)
    FilterCondition("created_at", FilterOperator.GT, "2025-01-01")
    FilterCondition("tags", FilterOperator.IN, ["python", "flask"])
    """
    field: str
    operator: FilterOperator
    value: Any

    def matches(self, memory_metadata: Dict) -> bool:
        """
        Check if a memory's metadata satisfies this condition.
        """
        memory_value = memory_metadata.get(self.field)

        if memory_value is None:
            return False

        op = self.operator

        if op == FilterOperator.EQUALS:
            return memory_value == self.value

        elif op == FilterOperator.NOT_EQUALS:
            return memory_value != self.value

        elif op == FilterOperator.GREATER:
            return float(memory_value) > float(self.value)

        elif op == FilterOperator.LESS:
            return float(memory_value) < float(self.value)

        elif op == FilterOperator.GTE:
            return float(memory_value) >= float(self.value)

        elif op == FilterOperator.LTE:
            return float(memory_value) <= float(self.value)

        elif op == FilterOperator.IN:
            return memory_value in self.value

        elif op == FilterOperator.NOT_IN:
            return memory_value not in self.value

        elif op == FilterOperator.CONTAINS:
            return self.value.lower() in str(memory_value).lower()

        elif op == FilterOperator.STARTS_WITH:
            return str(memory_value).startswith(self.value)

        return False


@dataclass
class MetadataFilter:
    """
    A composable filter that combines multiple conditions.

    Usage:
    f = MetadataFilter()
    f.add_condition("user_id", FilterOperator.EQUALS, "rahim_123")
    f.add_condition("importance", FilterOperator.GTE, 0.7)
    f.add_condition("category", FilterOperator.IN, ["project", "debugging"])
    
    filtered = f.apply(memories)
    """
    conditions: List[FilterCondition] = field(default_factory=list)
    logic: str = "AND"   # "AND" = all must match, "OR" = any must match

    def add_condition(
        self,
        field: str,
        operator: FilterOperator,
        value: Any
    ) -> "MetadataFilter":
        """
        Add a filter condition.
        Returns self for method chaining!
        """
        self.conditions.append(
            FilterCondition(field, operator, value)
        )
        return self  # ← enables chaining: f.add(...).add(...).add(...)

    def apply(self, memories: List[Dict]) -> List[Dict]:
        """
        Apply all conditions to a list of memories.
        Returns only memories that satisfy the filter.
        """
        if not self.conditions:
            return memories  # No filter = return all

        filtered = []
        for memory in memories:
            meta = memory.get("metadata", memory)  # Support both formats

            if self.logic == "AND":
                # ALL conditions must match
                passes = all(c.matches(meta) for c in self.conditions)
            else:
                # ANY condition must match
                passes = any(c.matches(meta) for c in self.conditions)

            if passes:
                filtered.append(memory)

        return filtered

    def to_chromadb_where(self) -> Dict:
        """
        Convert filter to ChromaDB 'where' clause.

        ChromaDB filter syntax:
        {"field": {"$eq": "value"}}
        {"field": {"$gte": 0.7}}
        {"$and": [{"field1": {...}}, {"field2": {...}}]}
        """
        OPERATOR_MAP = {
            FilterOperator.EQUALS:      "$eq",
            FilterOperator.NOT_EQUALS:  "$ne",
            FilterOperator.GREATER:     "$gt",
            FilterOperator.LESS:        "$lt",
            FilterOperator.GTE:         "$gte",
            FilterOperator.LTE:         "$lte",
            FilterOperator.IN:          "$in",
            FilterOperator.NOT_IN:      "$nin",
        }

        if not self.conditions:
            return {}

        if len(self.conditions) == 1:
            c = self.conditions[0]
            op = OPERATOR_MAP.get(c.operator, "$eq")
            return {c.field: {op: c.value}}

        # Multiple conditions
        logic_op = "$and" if self.logic == "AND" else "$or"
        parts = []
        for c in self.conditions:
            op = OPERATOR_MAP.get(c.operator, "$eq")
            parts.append({c.field: {op: c.value}})

        return {logic_op: parts}


class MemoryFilterBuilder:
    """
    Fluent API for building memory filters.
    Makes complex filtering readable and easy.

    Usage:
    filter = (
        MemoryFilterBuilder()
        .for_user("rahim_123")
        .in_category("debugging")
        .min_importance(0.7)
        .from_last_days(30)
        .build()
    )
    """

    def __init__(self):
        self._filter = MetadataFilter()

    def for_user(self, user_id: str) -> "MemoryFilterBuilder":
        """ALWAYS use this — scopes to specific user (privacy!)."""
        self._filter.add_condition(
            "user_id", FilterOperator.EQUALS, user_id
        )
        return self

    def in_category(
        self,
        *categories: str
    ) -> "MemoryFilterBuilder":
        """Filter by one or more categories."""
        if len(categories) == 1:
            self._filter.add_condition(
                "category", FilterOperator.EQUALS, categories[0]
            )
        else:
            self._filter.add_condition(
                "category", FilterOperator.IN, list(categories)
            )
        return self

    def min_importance(
        self,
        score: float
    ) -> "MemoryFilterBuilder":
        """Only retrieve memories with importance >= score."""
        self._filter.add_condition(
            "importance", FilterOperator.GTE, score
        )
        return self

    def from_last_days(self, days: int) -> "MemoryFilterBuilder":
        """Only retrieve memories from the last N days."""
        cutoff = (
            datetime.now() - timedelta(days=days)
        ).isoformat()
        self._filter.add_condition(
            "created_at", FilterOperator.GTE, cutoff
        )
        return self

    def from_session(
        self,
        session_id: str
    ) -> "MemoryFilterBuilder":
        """Only from a specific session."""
        self._filter.add_condition(
            "session_id", FilterOperator.EQUALS, session_id
        )
        return self

    def with_tag(self, tag: str) -> "MemoryFilterBuilder":

        self._filter.add_condition(

    def exclude_category(

        self._filter.add_condition(
            "confidence", FilterOperator.GTE, threshold
        )
        return self

    def build(self) -> MetadataFilter:
        """Build and return the filter."""
        return self._filter

    def to_chromadb_where(self) -> Dict:
        """Directly get ChromaDB-compatible where clause."""
        return self._filter.to_chromadb_where()

            )
        except Exception as e:
            print(f"Filter error: {e}. Falling back to no filter.")
            results = self.vector_store.collection.query(
                query_embeddings=[query_embedding],
                n_results=n_results + 5,
                include=["documents", "metadatas", "distances"]
            )

        if not results["documents"][0]:
            return []

        memories = []
        for doc, meta, dist in zip(
            results["documents"][0],
            results["metadatas"][0],
            results["distances"][0]
        ):
            similarity = 1 - dist
            if similarity >= min_similarity:
                memories.append({
                    "text": doc,
                    "similarity": round(similarity, 4),
                    "metadata": meta
                })

        memories.sort(key=lambda x: x["similarity"], reverse=True)
        return memories[:n_results]
```

# ⭐ STRATEGY 4: Importance-Based Recall

## 1. What Is It?

> **Importance-Based Recall = Assign each memory an IMPORTANCE SCORE and prioritize high-importance memories during retrieval, regardless of recency or similarity.**

Not all memories are equal. Some facts are **critical** (user's core project stack). Others are **trivial** (user mentioned liking coffee once). Importance-based recall ensures the critical facts are ALWAYS remembered.

---

## 2. First-Principles: What Makes a Memory Important?

```
SIGNALS THAT INCREASE IMPORTANCE:
──────────────────────────────────────────────────────────
📌 Explicitly stated facts
   "My name is Rahim" → HIGH importance
   User explicitly told us → We MUST remember this

🔄 Frequently referenced
   "Python" mentioned in 50 sessions → HIGH importance
   Accessed 200 times → clearly important

🏗️ Core project/identity facts
   "My project is a healthcare AI app" → HIGH importance
   Core identity → shapes ALL responses

⚠️ Error/failure moments
   "The authentication bug that took 3 days" → HIGH
   Painful memories = important lessons

🎯 Explicitly bookmarked by user
   User says "Remember this!" → HIGHEST importance

SIGNALS THAT DECREASE IMPORTANCE:
──────────────────────────────────────────────────────────
⌛ Contradicted by newer information
   "Works at Google" → superseded by "Works at Meta"
   Old fact → LOW importance now

📅 Temporal facts that are now stale
   "My todo today: fix login bug" → was important THEN
   Completed/past tasks → LOW importance now

🎲 Random mentions
   "I had pizza last night" → LOW importance
   Not core to what AI needs to help with
```

---

## 3. Analogy: The Sticky Note vs. the Bulletin Board

```
🗒️ Importance = How prominent is the note displayed?

A good assistant has three types of notes:

TIER 1 (Sticky Note on Monitor — Always Visible):
  "User's name: Rahim"
  "User's main project: Flask Healthcare API"
  "User's tech stack: Python, PostgreSQL, React"
  → ALWAYS retrieved, no matter what question is asked

TIER 2 (Bulletin Board — Frequently Referenced):
  "User struggled with JWT auth last month"
  "User's coding style: functional, PEP8"
  "User prefers short explanations with code"
  → Retrieved when remotely relevant

TIER 3 (Filing Cabinet — Low Priority):
  "User mentioned liking dark mode once"
  "User's timezone: UTC+6"
  "User tried VSCode before switching to Cursor"
  → Only retrieved when specifically relevant

IMPORTANCE SCORE = How high on the wall is the note posted?
```

---

## 4. The Importance Scoring System

```
IMPORTANCE SCORE FORMULA:

final_score = (
    explicit_weight     × 0.35  +  # Was explicitly stated?
    frequency_weight    × 0.25  +  # How often accessed?
    recency_weight      × 0.20  +  # How recently accessed?
    category_weight     × 0.15  +  # What type of memory?
    user_marked_weight  × 0.05     # Did user flag as important?
)

WHERE:
  explicit_weight = 1.0 if explicitly stated, 0.5 if inferred
  frequency_weight = min(access_count / 10, 1.0)
  recency_weight = exponential_decay(hours_since_access, λ=0.02)
  category_weight = {
    "core_identity": 1.0,
    "project_fact": 0.9,
    "debugging": 0.8,
    "learning": 0.6,
    "preference": 0.5,
    "personal": 0.3,
    "casual": 0.1
  }
  user_marked_weight = 1.0 if user marked important, 0.0 otherwise
```

```python
from datetime import datetime, timedelta
from typing import List, Dict, Optional, Tuple
from dataclasses import dataclass, field
from enum import Enum


class MemoryCategory(Enum):
    """
    Categories with built-in importance weights.
    Higher weight = more likely to be retrieved.
    """
    CORE_IDENTITY   = ("core_identity",   1.00)  # Name, job, etc.
    PROJECT_FACT    = ("project_fact",    0.90)  # Project details
    TECHNICAL       = ("technical",       0.85)  # Tech stack, skills
    DEBUGGING       = ("debugging",       0.80)  # Bugs and fixes
    DECISION        = ("decision",        0.75)  # Past decisions
    LEARNING        = ("learning",        0.65)  # Lessons learned
    PREFERENCE      = ("preference",      0.55)  # User preferences
    INTERACTION     = ("interaction",     0.45)  # General interactions
    PERSONAL        = ("personal",        0.30)  # Personal info
    CASUAL          = ("casual",          0.10)  # Casual mentions
    EPHEMERAL       = ("ephemeral",       0.05)  # Temporary/expiring

    def __init__(self, category_name: str, base_weight: float):
        self.category_name = category_name
        self.base_weight = base_weight

    @classmethod
    def from_string(cls, name: str) -> "MemoryCategory":
        for member in cls:
            if member.category_name == name:
                return member
        return cls.INTERACTION  # default


@dataclass
class ScoredMemory:
    """A memory with its computed importance score."""
    id: str
    text: str
    user_id: str
    importance_score: float
    category: str
    created_at: datetime
    last_accessed_at: Optional[datetime]
    access_count: int
    is_user_marked: bool = False
    is_explicitly_stated: bool = True
    recency_score: float = 0.0
    frequency_score: float = 0.0
    category_weight: float = 0.5
    final_score: float = 0.0


class ImportanceScorer:
    """
    Computes importance scores for memories.
    Combines multiple signals into a single score.
    """

    # Weights for each scoring component
    WEIGHTS = {
        "explicit":   0.35,  # Explicitly stated by user
        "frequency":  0.25,  # Access frequency
        "recency":    0.20,  # How recently accessed
        "category":   0.15,  # Memory category
        "user_marked": 0.05  # User explicitly marked important
    }

    def __init__(self, recency_decay: float = 0.02):
        """
        recency_decay: How fast recency score drops over time
        Lower value = slower decay = older memories stay relevant longer
        """
        self.recency_decay = recency_decay

    def compute_score(
        self,
        memory: Dict,
        max_access_count: int = 100
    ) -> Tuple[float, Dict]:
        """
        Compute importance score for a single memory.

        Returns: (final_score, component_scores)
        component_scores helps you DEBUG why a memory got its score!
        """
        # ── Component 1: Explicit Score ──────────────────────
        is_explicit = memory.get("is_explicitly_stated", True)
        explicit_score = 1.0 if is_explicit else 0.5
        # Explicitly stated = "My name is Rahim" (high)
        # Inferred = "User probably prefers dark mode" (lower)

        # ── Component 2: Frequency Score ─────────────────────
        access_count = memory.get("access_count", 0)
        frequency_score = min(access_count / max_access_count, 1.0)
        # Accessed 100 times → score = 1.0 (max importance)
        # Accessed 0 times → score = 0.0
        # Accessed 50 times → score = 0.5

        # ── Component 3: Recency Score ────────────────────────
        last_access = memory.get("last_accessed_at")
        created = memory.get("created_at", datetime.now())

        if last_access:
            reference_time = last_access
        else:
            reference_time = created

        if isinstance(reference_time, str):
            reference_time = datetime.fromisoformat(reference_time)

        hours_elapsed = (
            datetime.now() - reference_time
        ).total_seconds() / 3600

        recency_score = math.exp(-self.recency_decay * hours_elapsed)

        # ── Component 4: Category Weight ──────────────────────
        category_name = memory.get("category", "interaction")
        try:
            cat = MemoryCategory.from_string(category_name)
            category_weight = cat.base_weight
        except Exception:
            category_weight = 0.5

        # ── Component 5: User-Marked ──────────────────────────
        user_marked = float(memory.get("is_user_marked", False))
        # 1.0 if user explicitly said "remember this!"
        # 0.0 otherwise

        # ── Final Weighted Combination ────────────────────────
        w = self.WEIGHTS
        final_score = (
            explicit_score   * w["explicit"]   +
            frequency_score  * w["frequency"]  +
            recency_score    * w["recency"]     +
            category_weight  * w["category"]   +
            user_marked      * w["user_marked"]
        )

        component_scores = {
            "explicit":     round(explicit_score * w["explicit"], 4),
            "frequency":    round(frequency_score * w["frequency"], 4),
            "recency":      round(recency_score * w["recency"], 4),
            "category":     round(category_weight * w["category"], 4),
            "user_marked":  round(user_marked * w["user_marked"], 4),
            "final":        round(final_score, 4)
        }

        return round(final_score, 4), component_scores

    def explain_score(self, memory: Dict) -> str:
        """
        Human-readable explanation of why a memory got its score.
        Crucial for DEBUGGING importance calculations!
        """
        score, components = self.compute_score(memory)

        lines = [
            f"\n📊 IMPORTANCE SCORE BREAKDOWN",
            f"   Memory: '{memory.get('text', '')[:50]}...'",
            f"   {'─'*40}"
        ]

        component_names = {
            "explicit":    "Explicitly stated",
            "frequency":   "Access frequency",
            "recency":     "Recent access",
            "category":    "Category weight",
            "user_marked": "User-marked"
        }

        for key, label in component_names.items():
            val = components[key]
            bar = "█" * int(val * 50)
            lines.append(f"   {label:<22} {val:.4f} {bar}")

        lines.append(f"   {'─'*40}")
        lines.append(f"   FINAL SCORE:           {score:.4f}")

        return "\n".join(lines)


class ImportanceRetrieval:
    """
    Retrieves memories prioritized by importance score.
    Ensures critical memories are ALWAYS available.
    """

    def __init__(self):
        self.scorer = ImportanceScorer()

    def get_top_memories(
        self,
        memories: List[Dict],
        user_id: str,
        n: int = 10,
        min_score: float = 0.3,
        always_include_core: bool = True
    ) -> List[Dict]:
        """
        Retrieve top N most important memories for a user.

        always_include_core = True means:
        Core identity memories (name, job, project) are ALWAYS included
        even if their score falls below min_score.
        This prevents the AI from ever "forgetting" who the user is!
        """
        # Filter to this user only
        user_memories = [
            m for m in memories
            if m.get("user_id") == user_id
        ]

        # Score all memories
        scored = []
        for mem in user_memories:
            score, _ = self.scorer.compute_score(mem)
            scored.append((mem, score))

        # Sort by importance (highest first)
        scored.sort(key=lambda x: x[1], reverse=True)

        # Filter by minimum score
        filtered = [
            (mem, score) for mem, score in scored
            if score >= min_score
        ]

        # ALWAYS include core identity memories
        if always_include_core:
            core_cats = {"core_identity", "project_fact"}
            core_memories = [
                (mem, score) for mem, score in scored
                if mem.get("category") in core_cats
                and (mem, score) not in filtered
            ]
            filtered = core_memories + filtered

        # Deduplicate and take top N
        seen_ids = set()
        results = []
        for mem, score in filtered:
            mem_id = mem.get("id", mem.get("text", ""))
            if mem_id not in seen_ids:
                seen_ids.add(mem_id)
                results.append({
                    **mem,
                    "importance_score": score
                })

        return results[:n]

    def get_importance_tier(
        self,
        memories: List[Dict],
        user_id: str
    ) -> Dict[str, List[Dict]]:
        """
        Categorize memories into importance tiers.

        Tier 1 (ALWAYS LOAD): Score >= 0.8
        Tier 2 (LOAD IF RELEVANT): Score 0.5 - 0.8
        Tier 3 (LOAD IF SPECIFICALLY NEEDED): Score < 0.5
        """
        user_memories = [
            m for m in memories
            if m.get("user_id") == user_id
        ]

        tiers = {"tier_1": [], "tier_2": [], "tier_3": []}

        for mem in user_memories:
            score, _ = self.scorer.compute_score(mem)

            if score >= 0.8:
                tiers["tier_1"].append({**mem, "score": score})
            elif score >= 0.5:
                tiers["tier_2"].append({**mem, "score": score})
            else:
                tiers["tier_3"].append({**mem, "score": score})

        # Sort each tier
        for tier in tiers.values():
            tier.sort(key=lambda x: x["score"], reverse=True)

        return tiers

    def update_importance_on_access(
        self,
        memory: Dict,
        accessed_from_query: str = None
    ) -> Dict:
        """
        When a memory is retrieved, update its importance signals.
        Accessed memories become MORE important over time!
        (Frequency effect)
        """
        memory["access_count"] = memory.get("access_count", 0) + 1
        memory["last_accessed_at"] = datetime.now().isoformat()

        # If accessed many times → might be worth promoting to higher tier
        if memory["access_count"] >= 10:
            if memory.get("category") not in (
                "core_identity", "project_fact"
            ):
                print(
                    f"  📈 Memory accessed {memory['access_count']}x — "
                    f"consider promoting to higher importance tier"
                )

        return memory

    def mark_as_important(
        self,
        memory: Dict,
        reason: str = "user_requested"
    ) -> Dict:
        """
        User explicitly marks a memory as important.
        "Remember this!" → boosts importance score significantly.
        """
        memory["is_user_marked"] = True
        memory["user_mark_reason"] = reason
        memory["user_marked_at"] = datetime.now().isoformat()

        print(f"⭐ Memory marked as important: {memory.get('text', '')[:50]}")
        return memory

    def decay_importance(
        self,
        memories: List[Dict],
        aggressive: bool = False
    ) -> List[Dict]:
        """
        Periodically reduce importance of old, unaccessed memories.
        Prevents important tier from overflowing over time.

        Run this as a background job (e.g., daily).
        """
        cutoff_days = 7 if aggressive else 30
        cutoff = datetime.now() - timedelta(days=cutoff_days)

        updated = []
        for mem in memories:
            last_access = mem.get("last_accessed_at")

            if last_access:
                if isinstance(last_access, str):
                    last_access = datetime.fromisoformat(last_access)
                
                # Never decay core identity memories
                if (last_access < cutoff and
                    mem.get("category") not in
                    ("core_identity", "project_fact")):
                    old_score = mem.get("importance_score", 0.5)
                    mem["importance_score"] = max(0.1, old_score * 0.7)

            updated.append(mem)

        return updated
```

# 🔀 STRATEGY 5: Hybrid Retrieval

## 1. What Is It?

> **Hybrid Retrieval = Combine MULTIPLE retrieval strategies, fuse their results, re-rank them, and return the best combined set of memories.**

This is the **production-grade** strategy. No single strategy is perfect:
- Recency alone → misses important old memories
- Similarity alone → misses recent context
- Metadata alone → too rigid
- Importance alone → ignores what's actually relevant right now

**Hybrid = Take the best of ALL worlds.**

---

## 2. First-Principles: Why Hybrid?

```
REAL-WORLD SCENARIO:
User asks: "Help me fix the same authentication bug again"

RECENCY says:
  → Last 5 messages from current session ✅
  (but misses the bug fix from 2 months ago!)

SIMILARITY says:
  → "JWT authentication debugging session"
  → "Flask auth middleware issue"
  (semantic match — from 2 months ago!) ✅

IMPORTANCE says:
  → User's core project: Flask Healthcare API
  → User's tech stack: Python, PostgreSQL
  (always-relevant context) ✅

METADATA says:
  → category=debugging, importance>=0.8
  (narrows to debugging memories only) ✅

HYBRID says:
  → Recent session context (recency)
  → Past auth bug details (similarity)
  → Always-on project context (importance)
  → Only debugging memories (metadata filter)
  
  PERFECT ANSWER: "2 months ago you had the same JWT issue.
  Here's what fixed it: SECRET_KEY was different in prod.
  You also just mentioned the same symptom — check config!" ✅
```

---

## 3. The Reciprocal Rank Fusion Algorithm

```
HOW TO COMBINE RESULTS FROM MULTIPLE STRATEGIES?

NAIVE APPROACH: Just concatenate all results
  → Duplicates!
  → No principled ranking
  → Some strategies get more weight just by returning more results

BETTER APPROACH: Reciprocal Rank Fusion (RRF)
  
  RRF IDEA:
  Each strategy returns ranked results.
  For each memory in each list:
    contribution = 1 / (rank_position + k)   where k=60 (constant)
  
  Final score = sum of contributions across all strategies
  
  EXAMPLE:
  Memory A:
    Recency rank: #1   → score = 1/(1+60)  = 0.0164
    Similarity rank: #2 → score = 1/(2+60)  = 0.0161
    Importance rank: #1  → score = 1/(1+60)  = 0.0164
    TOTAL = 0.0164 + 0.0161 + 0.0164 = 0.0489 ← HIGH ✅
  
  Memory B:
    Recency rank: #15  → score = 1/(15+60) = 0.0133
    Similarity rank: #8  → score = 1/(8+60)  = 0.0147
    Importance rank: #20 → score = 1/(20+60) = 0.0125
    TOTAL = 0.0133 + 0.0147 + 0.0125 = 0.0405 ← LOWER
  
  Memory A ranked above Memory B! Makes sense.
  Memory A appeared at top of MULTIPLE strategy lists.
```

## 4. Complete Hybrid Retrieval Implementation

```python
# hybrid_retrieval.py
import math
from datetime import datetime, timedelta
from typing import List, Dict, Optional, Tuple, Any
from collections import defaultdict
from dataclasses import dataclass, field


@dataclass
class RetrievalResult:
    """
    A single memory retrieved by one or more strategies.
    Tracks which strategies found it and at what rank.
    """
    memory_id: str
    text: str
    metadata: Dict = field(default_factory=dict)

    # Scores from individual strategies
    recency_score: float = 0.0
    similarity_score: float = 0.0
    importance_score: float = 0.0
    metadata_score: float = 0.0

    # Rank positions in each strategy's results (-1 = not found)
    recency_rank: int = -1
    similarity_rank: int = -1
    importance_rank: int = -1

    # Final combined score
    rrf_score: float = 0.0
    final_score: float = 0.0

    # Which strategies found this memory
    found_by: List[str] = field(default_factory=list)

    @property
    def found_by_multiple(self) -> bool:
        """True if multiple strategies agree this is relevant."""
        return len(self.found_by) >= 2

    @property
    def consensus_strength(self) -> str:
        """How strongly do strategies agree?"""
        count = len(self.found_by)
        if count >= 4:   return "very_strong"
        elif count >= 3: return "strong"
        elif count >= 2: return "moderate"
        else:            return "weak"


class ReciprocalRankFusion:
    """
    Implements Reciprocal Rank Fusion for combining ranked lists.

    RRF is a robust, parameter-light rank aggregation method.
    Originally from information retrieval research.
    Works better than simple score averaging because:
    → Handles different score scales from different strategies
    → Rewards consistent top-ranking across multiple strategies
    → Robust to outliers
    """

    def __init__(self, k: int = 60):
        """
        k = constant that controls sensitivity to top rankings.
        k=60 is the standard value from the original RRF paper.
        Larger k = smaller difference between top and bottom ranks.
        """
        self.k = k

    def rrf_score(self, rank: int) -> float:
        """
        Compute RRF score for a given rank position.
        rank 1 (best) → score = 1/(1+60) = 0.0164
        rank 10       → score = 1/(10+60) = 0.0143
        rank 100      → score = 1/(100+60) = 0.0063
        """
        return 1.0 / (rank + self.k)

    def fuse(
        self,
        ranked_lists: Dict[str, List[Dict]],
        weights: Dict[str, float] = None
    ) -> List[Dict]:
        """
        Fuse multiple ranked lists into one using RRF.

        ranked_lists: {strategy_name: [memories_in_rank_order]}
        weights: {strategy_name: weight} (optional — usually equal)

        Returns: Unified ranked list with RRF scores
        """
        if weights is None:
            # Equal weight to all strategies by default
            weights = {name: 1.0 for name in ranked_lists.keys()}

        # Accumulate RRF scores per memory
        # Key = memory text (use text as universal ID)
        memory_scores = defaultdict(float)
        memory_data = {}
        memory_found_by = defaultdict(list)

        for strategy_name, memories in ranked_lists.items():
            strategy_weight = weights.get(strategy_name, 1.0)

            for rank, memory in enumerate(memories, start=1):
                # Memory identifier
                mem_key = memory.get("id", memory.get("text", ""))

                # Compute weighted RRF score
                rrf = self.rrf_score(rank) * strategy_weight
                memory_scores[mem_key] += rrf

                # Store memory data
                memory_data[mem_key] = memory

                # Track which strategies found this memory
                memory_found_by[mem_key].append(strategy_name)

        # Build final results
        final_results = []
        for mem_key, rrf_total in memory_scores.items():
            memory = memory_data[mem_key].copy()
            memory["rrf_score"] = round(rrf_total, 6)
            memory["found_by"] = memory_found_by[mem_key]
            memory["found_by_count"] = len(memory_found_by[mem_key])
            memory["consensus"] = (
                "strong" if len(memory_found_by[mem_key]) >= 2
                else "weak"
            )
            final_results.append(memory)

        # Sort by RRF score
        final_results.sort(key=lambda x: x["rrf_score"], reverse=True)
        return final_results


class HybridRetrievalEngine:
    """
    Production-grade hybrid memory retrieval.

    Combines all retrieval strategies:
    1. Recency-based
    2. Similarity-based (semantic)
    3. Importance-based
    4. Metadata-filtered

    Uses RRF to fuse results into a single ranked list.
    Applies diversity to avoid redundant results.
    """

    def __init__(
        self,
        recency_retriever,
        similarity_retriever,
        importance_retriever,
        strategy_weights: Dict[str, float] = None
    ):
        """
        Pass in your initialized retriever objects.
        strategy_weights: customize how much each strategy contributes.
        """
        self.recency = recency_retriever
        self.similarity = similarity_retriever
        self.importance = importance_retriever
        self.rrf = ReciprocalRankFusion(k=60)

        # Default weights — tune based on your use case!
        self.strategy_weights = strategy_weights or {
            "similarity": 1.0,   # Most important for memory retrieval
            "importance": 0.8,   # Critical facts always included
            "recency":    0.6,   # Recent context is helpful
            "metadata":   0.4    # Structural filtering
        }

    def retrieve(
        self,
        user_id: str,
        query: str,
        all_memories: List[Dict],
        n_results: int = 5,
        metadata_filters: Dict = None,
        strategy_override: List[str] = None,
        debug: bool = False
    ) -> List[Dict]:
        """
        Main hybrid retrieval method.

        FLOW:
        1. Run all strategies in PARALLEL (conceptually)
        2. Collect ranked results from each
        3. Fuse using Reciprocal Rank Fusion
        4. Apply diversity filter
        5. Return top N results

        strategy_override: If provided, use ONLY these strategies.
        e.g., ["similarity", "recency"] skips importance + metadata
        """
        active_strategies = strategy_override or list(
            self.strategy_weights.keys()
        )

        ranked_lists = {}
        strategy_details = {}

        # ── Strategy 1: Similarity-Based ─────────────────────
        if "similarity" in active_strategies:
            sim_results = self.similarity.search(
                user_id=user_id,
                query=query,
                n_results=n_results * 2,  # Fetch more, RRF will rank
                min_similarity=0.55
            )
            ranked_lists["similarity"] = sim_results
            strategy_details["similarity"] = len(sim_results)

        # ── Strategy 2: Importance-Based ─────────────────────
        if "importance" in active_strategies:
            imp_results = self.importance.get_top_memories(
                memories=all_memories,
                user_id=user_id,
                n=n_results * 2,
                min_score=0.4,
                always_include_core=True
            )
            ranked_lists["importance"] = imp_results
            strategy_details["importance"] = len(imp_results)

        # ── Strategy 3: Recency-Based ─────────────────────────
        if "recency" in active_strategies:
            rec_results = self.recency.get_with_decay_scores(
                memories=all_memories,
                n=n_results * 2
            )
            # Convert (memory, score) tuples to dicts
            rec_as_dicts = [
                {**mem, "recency_score": score}
                for mem, score in rec_results
                if mem.get("user_id") == user_id
            ]
            ranked_lists["recency"] = rec_as_dicts
            strategy_details["recency"] = len(rec_as_dicts)

        # ── Strategy 4: Metadata-Filtered ────────────────────
        if "metadata" in active_strategies and metadata_filters:
            from metadata_filtering import MetadataFilter, FilterCondition, FilterOperator
            meta_filter = MetadataFilter()
            for field_name, value in (metadata_filters or {}).items():
                meta_filter.add_condition(
                    field_name, FilterOperator.EQUALS, value
                )
            meta_results = meta_filter.apply(all_memories)
            # Sort by importance_score within metadata results
            meta_results.sort(
                key=lambda m: m.get("importance_score", 0),
                reverse=True
            )
            ranked_lists["metadata"] = meta_results[:n_results * 2]
            strategy_details["metadata"] = len(ranked_lists["metadata"])

        if not ranked_lists:
            print("⚠️ No retrieval strategies produced results!")
            return []

        # ── FUSION: Combine all strategy results ─────────────
        fused_results = self.rrf.fuse(
            ranked_lists=ranked_lists,
            weights=self.strategy_weights
        )

        # ── DIVERSITY: Remove near-duplicate memories ─────────
        diverse_results = self._apply_diversity_filter(
            fused_results,
            similarity_threshold=0.92   # Remove if >92% similar text
        )

        # ── DEBUG MODE: Show detailed retrieval info ──────────
        if debug:
            self._print_debug_info(
                query=query,
                strategy_details=strategy_details,
                fused_results=fused_results,
                final_results=diverse_results[:n_results]
            )

        return diverse_results[:n_results]

    def _apply_diversity_filter(
        self,
        memories: List[Dict],
        similarity_threshold: float = 0.92
    ) -> List[Dict]:
        """
        Remove near-duplicate memories from results.

        PROBLEM WITHOUT THIS:
        Vector search might return:
        1. "User debugged Flask JWT authentication"
        2. "User fixed Flask JWT authentication bug"
        These are essentially the same fact → REDUNDANT!

        SOLUTION: Compute pairwise similarity.
        If two results are too similar → keep only the higher-ranked one.

        This is called MAXIMAL MARGINAL RELEVANCE (MMR) concept.
        """
        if not memories:
            return []

        kept = [memories[0]]  # Always keep the top result

        for candidate in memories[1:]:
            # Check if this candidate is too similar to any kept result
            is_redundant = False

            for kept_mem in kept:
                # Simple word overlap similarity
                # In production: use embedding similarity
                cand_words = set(
                    candidate.get("text", "").lower().split()
                )
                kept_words = set(
                    kept_mem.get("text", "").lower().split()
                )

                if cand_words and kept_words:
                    overlap = len(cand_words & kept_words)
                    union = len(cand_words | kept_words)
                    jaccard = overlap / union if union > 0 else 0

                    if jaccard >= similarity_threshold:
                        is_redundant = True
                        break

            if not is_redundant:
                kept.append(candidate)

        return kept

    def _print_debug_info(
        self,
        query: str,
        strategy_details: Dict,
        fused_results: List[Dict],
        final_results: List[Dict]
    ):
        """Print detailed retrieval debug information."""
        print(f"\n{'='*65}")
        print(f"🔍 HYBRID RETRIEVAL DEBUG")
        print(f"   Query: '{query}'")
        print(f"{'='*65}")

        print("\n📊 STRATEGY RESULTS:")
        for strategy, count in strategy_details.items():
            weight = self.strategy_weights.get(strategy, 1.0)
            print(f"   {strategy:<15} {count:>3} results  "
                  f"(weight: {weight:.1f})")

        print(f"\n🔀 AFTER RRF FUSION: {len(fused_results)} unique memories")
        print(f"✅ AFTER DIVERSITY:  {len(final_results)} final results")

        print(f"\n🏆 FINAL RANKED RESULTS:")
        print(f"   {'#':<4} {'RRF Score':<12} {'Strategies':<20} {'Memory'}")
        print(f"   {'-'*65}")

        for i, mem in enumerate(final_results, 1):
            strategies = ", ".join(mem.get("found_by", []))
            text = mem.get("text", "")[:35] + "..."
            rrf = mem.get("rrf_score", 0)
            print(f"   {i:<4} {rrf:<12.6f} {strategies:<20} {text}")

        print(f"{'='*65}\n")

    def format_for_prompt(
        self,
        memories: List[Dict],
        include_metadata: bool = True
    ) -> str:
        """
        Format retrieved memories for LLM prompt injection.
        Returns clean, structured text the LLM can use.
        """
        if not memories:
            return ""

        lines = ["\n=== RETRIEVED MEMORIES (Ranked by Relevance) ==="]

        for i, mem in enumerate(memories, 1):
            text = mem.get("text", "")
            rrf_score = mem.get("rrf_score", 0)
            found_by = mem.get("found_by", [])
            timestamp = (
                mem.get("created_at", "")
                or mem.get("metadata", {}).get("created_at", "")
            )

            if isinstance(timestamp, str):
                date_str = timestamp[:10] if timestamp else "unknown"
            else:
                date_str = "unknown"

            if include_metadata:
                lines.append(
                    f"\n{i}. [{date_str}] "
                    f"(relevance: {int(rrf_score * 6000):d}/100) "
                    f"{text}"
                )
            else:
                lines.append(f"\n{i}. {text}")

        lines.append("\n=================================================\n")
        return "\n".join(lines)
```

```python
class CompleteMemoryRetrieval:

    Production-ready memory retrieval pipeline.
    Orchestrates all 5 strategies intelligently.

    1. Query Understanding (what does the user actually need?)
    2. Strategy Selection (which strategies apply here?)

        → Identity requests ("what's my name", "who am I")
        → Project requests ("my project", "my stack")
        → Debug requests ("fix", "bug", "error")
        → Learning requests ("how", "explain", "understand")
        """

        signals = {
            "needs_recency": any(w in query_lower for w in [
                "recent", "last", "yesterday", "today", "just",
                "lately", "this week", "earlier"
            ]),
            "needs_identity": any(w in query_lower for w in [
                "my name", "who am i", "my email", "remember me",
                "what do you know about me"
            ]),
            "needs_project": any(w in query_lower for w in [
                "my project", "my app", "my stack", "my database",

            ]),

                "debug", "fix", "bug", "error", "issue", "problem",

            ]),
            "needs_history": any(w in query_lower for w in [

                "we discussed", "you told me", "earlier you"
            ]),
            "is_general": True  # Always include as fallback
        }

        # Determine which strategies to activate
        active_strategies = ["similarity"]  # Always use similarity

        if signals["needs_recency"]:
            active_strategies.append("recency")

        if signals["needs_identity"] or signals["needs_project"]:
            active_strategies.append("importance")

        if signals["needs_debugging"]:
            active_strategies.extend(["metadata", "similarity"])

        if signals["needs_history"]:
            active_strategies.extend(["recency", "similarity"])

        # Always include importance for core context
        if "importance" not in active_strategies:
            active_strategies.append("importance")

        # Determine metadata filters based on signals
        metadata_filters = None
        if signals["needs_debugging"]:
            metadata_filters = {"category": "debugging"}

        return {
            "signals": signals,
            "active_strategies": list(set(active_strategies)),
            "metadata_filters": metadata_filters,
            "query_type": self._classify_query_type(signals)
        }

    def _classify_query_type(self, signals: Dict) -> str:
        """Classify the query into a retrieval type."""
        if signals["needs_identity"]:     return "identity"
        if signals["needs_project"]:      return "project_context"
        if signals["needs_debugging"]:    return "debugging"
        if signals["needs_history"]:      return "historical"
        if signals["needs_recency"]:      return "recent_context"
        return "general"

        self,
        user_id: str,
        query: str,
        all_memories: List[Dict],

        Complete retrieval pipeline.

        Returns:

          "memories": [...],
          "prompt_context": "=== MEMORIES ===...",
          "query_analysis": {...},
          "retrieval_stats": {...}
        }

        query_analysis = self.understand_query(query)

        }

        }

            {"role": "system", "content": full_system},
```

# 🎯 INTERVIEW QUESTIONS + STRONG ANSWERS

### ❓ Q1: "What are the different memory retrieval strategies and when would you use each?"

**💬 Strong Answer:**
> "There are five main strategies. Recency-based retrieval returns the most recently created or accessed memories — useful for conversation continuity but fails when important memories are old. Similarity-based retrieval uses embedding vectors and cosine similarity to find semantically related memories — the most powerful strategy for finding relevant context regardless of when it was stored. Metadata filtering applies hard constraints on attributes like category, user_id, or importance score to narrow the search space — essential for privacy and precision. Importance-based recall prioritizes memories with high importance scores computed from signals like access frequency, explicit statements, and category — ensures critical facts are always available. In production, you use hybrid retrieval that combines all four using Reciprocal Rank Fusion to produce a single, well-ranked result set."

---

### ❓ Q2: "Explain Reciprocal Rank Fusion and why it's better than score averaging."

**💬 Strong Answer:**
> "Reciprocal Rank Fusion is a rank aggregation algorithm that combines ranked lists from multiple sources. For each memory in each list, it computes a score of 1 divided by the rank position plus a constant k — typically 60. Final scores are the sum of these contributions across all lists. RRF is superior to simple score averaging for three reasons: first, it's invariant to the absolute scale of scores — similarity scores range 0 to 1 while importance scores might range 0 to 10, but RRF only cares about rank position. Second, it naturally rewards memories that appear at the top of MULTIPLE strategies, which is a strong signal of relevance. Third, it's robust to outliers — one strategy returning a spurious high-similarity result doesn't dominate the final ranking since RRF heavily discounts lower-ranked results."

---

### ❓ Q3: "What is a time decay function in memory retrieval and why do we need it?"

**💬 Strong Answer:**
> "A time decay function assigns a recency score to memories based on how long ago they were created or accessed. The most common implementation is exponential decay — score equals e to the power of negative lambda times time elapsed, where lambda is the decay rate. This gives a continuous gradient rather than a binary fresh-or-stale classification. We need it because memories don't suddenly become irrelevant at a specific age — they gradually become less relevant over time. A memory from one hour ago is extremely relevant, one from yesterday is quite relevant, one from a month ago is somewhat relevant, and one from a year ago is still slightly relevant. Flat recency sorting misses this nuance. In hybrid retrieval, the decay score is one component of the final ranking, allowing recently accessed memories to rank higher without completely ignoring older but potentially critical information."

---

### ❓ Q4: "How do you handle the threshold problem in similarity-based retrieval?"

**💬 Strong Answer:**
> "The threshold problem is that min_similarity controls the quality versus quantity trade-off. Too high and you return nothing or miss relevant memories. Too low and you return noise that pollutes the LLM context. My approach is three-pronged. First, empirically tune the threshold on your actual data — I'd run threshold analysis on a sample of real queries and plot how many results return at each threshold. For most use cases, 0.65 to 0.75 is the sweet spot. Second, implement progressive relaxation — if a query returns zero results at 0.70, automatically retry at 0.60, then 0.50, logging each fallback. Third, apply a diversity filter after retrieval to remove near-duplicate results regardless of threshold — this prevents the context from being dominated by slightly different phrasings of the same memory. Different memory categories may also need different thresholds — factual project memories might need 0.75 while conversational memories work fine at 0.60."

---

### ❓ Q5: "Explain the importance scoring system and what signals you use to compute it."

**💬 Strong Answer:**
> "Importance scoring combines multiple signals into a single number between zero and one. The five key signals are: explicit weight — whether the user directly stated the fact versus whether we inferred it; frequency weight — how many times this memory has been retrieved, normalized to a 0-1 range; recency weight — how recently the memory was last accessed, computed with exponential decay; category weight — a predefined weight based on memory type, with core identity and project facts having weights near 1.0 and casual mentions near 0.1; and user-marked weight — whether the user explicitly said 'remember this,' which gets a large boost. These are combined as a weighted sum. The key insight is that importance is dynamic — a memory that was unimportant when stored can become highly important after being retrieved 50 times. Running importance decay as a background job prevents the important tier from overflowing with stale memories that were once accessed frequently but haven't been needed for months."

# 📌 PART 1 — The Anatomy of Retrieval Approaches

```
+-----------------------------------------------------------------------------------+
|                           RETRIEVAL PARADIGMS COMPARED                            |
|                                                                                   |
|  DENSE RETRIEVAL (Semantic / Vector)          SPARSE RETRIEVAL (Lexical / BM25)   |
|  • Understands synonyms and concepts          • Matches exact keywords & terms    |
|  • "automobile" matches "car"                 • "RX4092-B" matches "RX4092-B"     |
|  • Fails on rare terms, IDs, jargon           • Fails on paraphrasing & synonyms  |
|                                       \    /                                      |
|                                        \  /                                       |
|                                         ▼                                         |
|                             HYBRID RETRIEVAL (RRF)                                |
|                             Best of both worlds                                   |
|                             Combines ranks via RRF                                |
+-----------------------------------------------------------------------------------+
```

### 1. Dense Retrieval (Bi-Encoder Embeddings)
- Pass document chunk through a neural encoder to produce a dense floating-point vector (e.g., 768 to 3072 dimensions).
- Compute vector similarity (Cosine, Dot Product, Euclidean L2).
- **Strengths:** Handles concept drift, typos, cross-lingual retrieval, semantic abstraction.
- **Weaknesses:** Keyword blindness; fails on part numbers, IDs, specialized legal/medical acronyms.

### 2. Sparse Retrieval (BM25 & Inverted Indexes)
- Scores documents based on Term Frequency (TF) and Inverse Document Frequency (IDF):
$$\text{BM25}(D, Q) = \sum_{i=1}^N \text{IDF}(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot \left(1 - b + b \cdot \frac{|D|}{\text{avgdl}}\right)}$$
- **Strengths:** Blazing fast, zero GPU requirement, pinpoint precision on unique strings, exact matches.
- **Weaknesses:** Zero semantic comprehension; searching for "canine care" will fail to find documents titled "dog health".

### 3. Learned Sparse Retrieval (SPLADE)
- Neural models that output sparse token vectors over the entire vocabulary.
- Generates *query and document expansions* while preserving sparse index efficiency.
- Bridges the gap by learning which words to inject into an inverted index.

# 📌 PART 2 — Vector Indexing Algorithms: Inside the Vector Database

When storing millions of vectors, brute-force exact search ($\mathcal{O}(N \cdot d)$) is too slow for real-time SLAs (< 50ms). Modern vector databases use **Approximate Nearest Neighbor (ANN)** algorithms:

| Algorithm | How It Works | Query Latency | Memory Footprint | Recall Quality |
|---|---|---|---|---|
| **Flat Index (Exact)** | Brute force scan across every vector | Very Slow ($\mathcal{O}(N)$) | Baseline (100%) | 100% (Ground truth) |
| **HNSW (Hierarchical Navigable Small World)** | Multi-layer graph where top layers take huge leaps and lower layers refine local neighbors | Ultra Fast (< 10ms) | High (Stores graph edges) | 95%–99% |
| **IVF (Inverted File Index)** | Clusters vector space into Voronoi cells using k-means; searches only vectors in nearest centroids | Fast | Low | 85%–95% |
| **Product Quantization (PQ)** | Compresses high-dimensional vectors into compact byte codes | Ultra Fast | 75%–90% reduction | 80%–90% |

> **Production Standard:** **HNSW + PQ** (used by Qdrant, Pinecone, Weaviate, Milvus) delivers sub-15ms search latency across 100M+ vectors with >95% recall.

# 📌 PART 3 — Reciprocal Rank Fusion (RRF) Implementation

Instead of trying to normalize and sum incompatible raw scores (BM25 scores range from 0 to $\infty$, whereas Cosine scores range from -1 to 1), **Reciprocal Rank Fusion (RRF)** combines items strictly by their positional ranks.

from collections import defaultdict

def reciprocal_rank_fusion(
    dense_results: List[Dict[str, Any]],
    sparse_results: List[Dict[str, Any]],
    k: int = 60,
    top_n: int = 5
) -> List[Dict[str, Any]]:
    """
    Fuses dense and sparse rankings using Reciprocal Rank Fusion.
    
    Formula: RRF_Score(d) = sum(1 / (k + rank_i))
    k: Smoothing parameter (standard default is 60).
    """
    rrf_scores = defaultdict(float)
    doc_lookup = {}
    
    # Process dense ranks
    for rank, doc in enumerate(dense_results, start=1):
        doc_id = doc["id"]
        rrf_scores[doc_id] += 1.0 / (k + rank)
        doc_lookup[doc_id] = doc

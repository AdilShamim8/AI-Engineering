## 🤔 STEP 1 — Prediction Before Explanation

> **Let me ask you first:**
> *"Consider two user queries in a corporate enterprise system:*
> *Query A: 'What were the major operational risks identified across all 500 audit reports filed in 2025?'*
> *Query B: 'Compare our European data privacy policy with the one we adopted in California.'*
> *Why will standard vector-similarity RAG fail miserably on both?"*

A beginner usually thinks:
> *"The vector database will just return the most similar chunks and the LLM will summarize them."*

An experienced AI engineer knows:
> **Standard vector RAG is fundamentally local, not global or relational.**
> - For **Query A**: The answer isn't located in any single chunk. It requires holistic entity aggregation across all 500 documents. Vector search will just pull 5 random paragraphs that mention the words "operational risks", completely missing the systemic pattern.
> - For **Query B**: This is a multi-hop comparative query. Standard search collapses both concepts into a single vector midpoint that retrieves muddled chunks from neither policy clearly.
>
> **Advanced RAG introduces Query Transformations, Autonomous Self-Reflective Loops, and Knowledge Graphs (GraphRAG).**

### 1. Multi-Query Retrieval
Users often phrase queries poorly or use uncommon terminology. An LLM generates 3–5 synonymous query formulations. Each is retrieved independently, and results are merged using Reciprocal Rank Fusion (RRF).

### 2. Sub-Question Decomposition
When a user asks: *"Did Apple's revenue grow faster than Microsoft's in 2025?"*
The system decomposes this into two discrete parallel queries:
- Query 1: *"Apple total revenue growth rate fiscal year 2025"*
- Query 2: *"Microsoft total revenue growth rate fiscal year 2025"*
The results are retrieved independently and combined into a final comparative prompt.

### 3. Step-Back Prompting
For hyper-specific or confusing questions, an LLM generates a higher-level "step-back" question about underlying principles. Both the specific and step-back contexts are retrieved, providing the LLM with foundational context to reason through edge cases.

### 4. HyDE (Hypothetical Document Embeddings)
- Query vectors often live in a different semantic space than document vectors (questions don't look like answers).
- **HyDE Solution:** Ask the LLM to write a hypothetical ideal answer to the question (even if it contains factual hallucinations).
- Embed this *hypothetical answer* and use its vector to search the database. Since answer vectors match answer vectors closely, retrieval precision improves dramatically!

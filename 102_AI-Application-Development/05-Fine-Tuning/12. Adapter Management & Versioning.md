## 1. What Is Actually Stored In An Adapter File?

### Starting From The Most Basic Truth

```
RECALL FROM SESSION 6 (LoRA Deep Dive):

A LoRA adapter consists of:
→ Matrix A: shape [r × d_model] for each targeted weight
→ Matrix B: shape [d_model × r] for each targeted weight
→ Scaling factor: α/r (a constant, not a trained weight)
→ Configuration: which matrices were targeted, rank r, alpha

NOTHING ELSE. That's it.

FOR LLAMA 3 8B WITH r=16, targeting q,k,v,o:
──────────────────────────────────────────────────────────────
Per attention layer (32 layers total):
  q_proj: A [16 × 4096] + B [4096 × 16]
  k_proj: A [16 × 4096] + B [4096 × 16]
  v_proj: A [16 × 4096] + B [4096 × 16]
  o_proj: A [16 × 4096] + B [4096 × 16]
  
Per layer parameter count:
  Each A: 16 × 4096 = 65,536 parameters
  Each B: 4096 × 16 = 65,536 parameters
  4 matrices × 2 (A+B) × 65,536 = 524,288 params per layer

Total across 32 layers:
  32 × 524,288 = 16,777,216 trainable parameters
  ≈ 16.8 million parameters

STORAGE SIZE:
  16.8M params × 2 bytes (bf16) = 33.6 MB
  16.8M params × 4 bytes (fp32) = 67.2 MB

ACTUAL FILE SIZE IN PRACTICE:
  ~16-50 MB depending on rank, targets, and precision
  Compare: Base model (LLaMA 3 8B) = 16 GB (bf16)
  Adapter = 0.1% - 0.3% of base model size.

THIS IS THE POWER OF ADAPTERS:
One 16 GB base model.
50 adapters = 50 × 32 MB = 1.6 GB additional.
vs 50 full models = 50 × 16 GB = 800 GB.
Adapters are 500× more storage-efficient.
```

## 2. The Complete Adapter File Anatomy

```
WHEN YOU CALL model.save_pretrained("./my_adapter"):

TWO FILES ARE CREATED:

FILE 1: adapter_config.json (~1-2 KB)
──────────────────────────────────────────────────────────────
{
    "alpha_pattern": {},
    "auto_mapping": null,
    "base_model_name_or_path": "meta-llama/Meta-Llama-3-8B",
    "bias": "none",
    "fan_in_fan_out": false,
    "inference_mode": true,
    "init_lora_weights": true,
    "lora_alpha": 32,
    "lora_dropout": 0.05,
    "modules_to_save": null,
    "peft_type": "LORA",
    "r": 16,
    "rank_pattern": {},
    "revision": null,
    "target_modules": [
        "q_proj",
        "k_proj", 
        "v_proj",
        "o_proj"
    ],
    "task_type": "CAUSAL_LM"
}

THIS FILE TELLS YOU:
→ peft_type: What kind of adapter (LoRA, prefix, prompt)
→ base_model_name_or_path: Which base model this was trained on
→ r: The rank used
→ lora_alpha: The scaling factor
→ target_modules: Which weight matrices have adapters
→ bias: Whether biases were trained
→ task_type: What the model is designed for
→ lora_dropout: Regularization setting during training

FILE 2: adapter_model.safetensors (~16-50 MB)
──────────────────────────────────────────────────────────────
The actual tensor weights.
Binary format. Not human-readable.
Contains ALL the A and B matrices for all targeted layers.

Key naming convention inside the file:
"base_model.model.model.layers.0.self_attn.q_proj.lora_A.weight"
"base_model.model.model.layers.0.self_attn.q_proj.lora_B.weight"
"base_model.model.model.layers.0.self_attn.k_proj.lora_A.weight"
"base_model.model.model.layers.0.self_attn.k_proj.lora_B.weight"
...
(Continues for all layers and all targeted matrices)

OPTIONALLY: tokenizer_config.json and special_tokens_map.json
If tokenizer was saved with the adapter.
Usually not needed (tokenizer comes with base model).
Only needed if you added special tokens during fine-tuning.
```

## 3. Storage Formats — SafeTensors vs Bin vs GGUF

```
THREE STORAGE FORMATS FOR ADAPTER WEIGHTS:

FORMAT 1: SafeTensors (.safetensors) ← RECOMMENDED
──────────────────────────────────────────────────────────────
What: A safe, efficient binary format designed by HuggingFace.
Created: 2022. Now the industry standard.

ADVANTAGES:
✅ Safe: Cannot execute arbitrary code when loaded.
          (PyTorch .bin files CAN execute code via pickle)
✅ Fast: Memory-mapped loading, zero-copy access.
          Load a 16 GB model in seconds, not minutes.
✅ Cross-platform: Works in Python, Rust, JavaScript.
✅ Atomic: File is valid or invalid, never partially corrupt.
✅ Streaming: Can stream tensors without loading entire file.

STRUCTURE:
[8 bytes: metadata length] [metadata JSON] [tensor data]

HOW TO SAVE:
model.save_pretrained("./my_adapter")
# Automatically uses safetensors as of PEFT >= 0.5.0

# Force safetensors:
model.save_pretrained("./my_adapter", safe_serialization=True)

──────────────────────────────────────────────────────────────

FORMAT 2: PyTorch Bin (.bin) ← Legacy, Avoid
──────────────────────────────────────────────────────────────
What: PyTorch's native pickle-based serialization.
Used: Before safetensors became standard.

DISADVANTAGES:
❌ SECURITY RISK: Pickle can execute arbitrary Python code.
                   Loading a malicious .bin file = remote code execution.
❌ Slow: Requires full deserialization (not memory-mapped).
❌ Python-only: Cannot be loaded in other languages.
❌ Can be partially corrupted: Harder to detect corruption.

WHEN YOU MIGHT STILL SEE IT:
→ Old adapters on HuggingFace Hub (pre-2023).
→ Some legacy training pipelines.
→ If loading: Verify source. Convert to safetensors:

import torch
from safetensors.torch import save_file

# Load old .bin adapter
weights = torch.load("adapter_model.bin", map_location="cpu")
# Save as safetensors
save_file(weights, "adapter_model.safetensors")

──────────────────────────────────────────────────────────────

FORMAT 3: GGUF (.gguf) ← For CPU/Edge Inference
──────────────────────────────────────────────────────────────
What: A format used by llama.cpp for quantized inference.
Primary use: Running models on CPU, edge devices, consumer hardware.

For adapters specifically:
→ LoRA adapters can be exported to GGUF format.
→ Used with llama.cpp which supports --lora flag.
→ Allows running quantized base model + LoRA on CPU.

WHEN TO USE GGUF ADAPTERS:
→ Edge deployment (laptop, embedded system).
→ CPU-only inference environment.
→ When using llama.cpp as the inference engine.

CONVERSION:
# Using llama.cpp tools
python convert-lora-to-ggml.py my_adapter/
# Creates: ggml-adapter-model.bin

──────────────────────────────────────────────────────────────

FORMAT SELECTION GUIDE:
Training and most production: safetensors ✅
Edge/CPU deployment: GGUF
Legacy systems: bin (with security caution)
```

```
PYTHON INTERFACE:
import boto3

class S3AdapterStore:
    def __init__(self, bucket, prefix="adapters"):
        self.s3 = boto3.client('s3')
        self.bucket = bucket
        self.prefix = prefix
    
    def save_adapter(self, model, adapter_id, version, metadata):
        """Save adapter to S3"""
        local_tmp = f"/tmp/{adapter_id}/{version}"
        model.save_pretrained(local_tmp, safe_serialization=True)
        
        s3_path = f"{self.prefix}/{adapter_id}/{version}"
        
        for filename in ['adapter_model.safetensors', 
                         'adapter_config.json']:
            self.s3.upload_file(
                f"{local_tmp}/{filename}",
                self.bucket,
                f"{s3_path}/{filename}"
            )
        
        # Save metadata
        self.s3.put_object(
            Bucket=self.bucket,
            Key=f"{s3_path}/adapter_metadata.json",
            Body=json.dumps(metadata, indent=2)
        )
        
        print(f"✅ Saved to s3://{self.bucket}/{s3_path}/")
        return f"s3://{self.bucket}/{s3_path}/"
    
    def load_adapter(self, adapter_id, version="latest"):
        """Download adapter from S3 to local cache"""
        if version == "latest":
            version = self._get_latest_version(adapter_id)
        
        s3_path = f"{self.prefix}/{adapter_id}/{version}"
        local_cache = f"~/.adapter_cache/{adapter_id}/{version}"
        
        if not os.path.exists(local_cache):
            os.makedirs(local_cache, exist_ok=True)
            for filename in ['adapter_model.safetensors',
                             'adapter_config.json']:
                self.s3.download_file(
                    self.bucket,
                    f"{s3_path}/{filename}",
                    f"{local_cache}/{filename}"
                )
        
        return local_cache
    
    def _get_latest_version(self, adapter_id):
        """Find latest version by metadata status"""
        response = self.s3.list_objects_v2(
            Bucket=self.bucket,
            Prefix=f"{self.prefix}/{adapter_id}/"
        )
        versions = sorted([
            obj['Key'].split('/')[2] 
            for obj in response.get('Contents', [])
            if obj['Key'].endswith('adapter_metadata.json')
        ])
        return versions[-1] if versions else None

PROS: Scalable. Redundant. Shared across team. Audit trail via S3 logs.
CONS: Network latency for download. Cost.
```

## 6. Storage Optimization at Scale

```
PROBLEM: 50 adapters × 50 MB = 2.5 GB. Not bad.
PROBLEM: 500 adapters × 50 MB = 25 GB. Getting significant.
PROBLEM: 5,000 adapters × 50 MB = 250 GB. Expensive.
PROBLEM: 50,000 adapters = 2.5 TB. Need real optimization.

STRATEGY 1: QUANTIZE THE ADAPTERS
────────────────────────────────────
LoRA adapters can be stored in lower precision.

Training: bf16 (2 bytes per parameter)
Storage: int8 or fp16 (1-2 bytes per parameter)
At runtime: Dequantize when loading.

# Quantize adapters to int8 for storage
from safetensors.torch import load_file, save_file
import torch

adapter_weights = load_file("adapter_model.safetensors")

# Quantize to int8
quantized = {}
scales = {}
for key, tensor in adapter_weights.items():
    scale = tensor.abs().max() / 127
    quantized[key] = (tensor / scale).to(torch.int8)
    scales[key + "_scale"] = scale

# Save quantized
save_file({**quantized, **scales}, "adapter_model_int8.safetensors")

# Size comparison:
# bf16 adapter: 33 MB
# int8 adapter: 16.5 MB (50% smaller)
# Quality impact: Minimal for LoRA adapters

STRATEGY 2: DELTA STORAGE (Store Only Changes)
────────────────────────────────────────────────
When you have v1.0.0 and v1.1.0 of an adapter:
They share most weights.

Instead of storing both fully:
Store v1.0.0 fully.
Store only the DIFF from v1.0.0 → v1.1.0.

import torch
from safetensors.torch import load_file, save_file

def compute_adapter_diff(old_weights, new_weights):
    """Compute delta between two adapter versions"""
    delta = {}
    for key in new_weights:
        if key in old_weights:
            diff = new_weights[key] - old_weights[key]
            # Only store if the diff is non-trivial
            if diff.abs().max() > 1e-7:
                delta[key] = diff
        else:
            delta[key] = new_weights[key]  # New key
    return delta

old_v1 = load_file("v1.0.0/adapter_model.safetensors")
new_v2 = load_file("v1.1.0/adapter_model.safetensors")
delta = compute_adapter_diff(old_v1, new_v2)

save_file(delta, "v1.1.0_delta.safetensors")
# Delta size: Often 10-30% of full adapter size

STRATEGY 3: SHARED BASE ADAPTER
──────────────────────────────────
If multiple adapters are fine-tuned from the same base adapter:
Store the base adapter once.
Store incremental adapters relative to the base.

adapter_hierarchy/
├── base_instruction_following/  # Shared base adapter (SFT)
│   └── adapter_model.safetensors
├── medical/ (fine-tuned from base)
│   └── delta.safetensors
├── legal/ (fine-tuned from base)
│   └── delta.safetensors
└── financial/ (fine-tuned from base)
    └── delta.safetensors
```

## 1. Why Adapter Version Control Is Different From Code

```
THE FUNDAMENTAL DIFFERENCE:

CODE VERSION CONTROL (Git):
→ Text files. Human-readable. Diff is meaningful.
→ git diff shows exactly what changed.
→ Every commit is a few KB.
→ Branching is instant (just moves a pointer).

ADAPTER VERSION CONTROL:
→ Binary files. Not human-readable.
→ git diff shows: "Binary files differ." (Useless.)
→ Every "commit" is 16-50 MB.
→ Branching creates full copies of large files.

YOU CANNOT SIMPLY USE GIT FOR ADAPTERS.
You need tools designed for binary ML artifacts.

BUT YOU STILL NEED THE SAME PROPERTIES AS GIT:
→ Every version is uniquely identifiable.
→ You can reproduce any previous version.
→ You know what changed between versions.
→ You can roll back to any previous version.
→ You know who made each version and why.

THE THREE TOOLS THAT PROVIDE THIS:
1. Git-LFS (Git Large File Storage) — Basic binary tracking.
2. DVC (Data Version Control) — ML-specific versioning.
3. MLflow Model Registry — Enterprise model management.
```

## 3. The Adapter Registry — Design and Implementation

```python
# THE COMPLETE ADAPTER REGISTRY IMPLEMENTATION

import json
import os
import hashlib
import shutil
from datetime import datetime
from pathlib import Path
from dataclasses import dataclass, field, asdict
from typing import List, Optional, Dict

# ──────────────────────────────────────────────────────────────────────
# DATA MODELS
# ──────────────────────────────────────────────────────────────────────

@dataclass
class AdapterVersion:
    """Represents one version of one adapter"""
    
    # Identity
    adapter_name: str
    version: str
    description: str
    created_at: str = field(default_factory=lambda: datetime.utcnow().isoformat())
    created_by: str = ""
    
    # Model provenance
    base_model_id: str = ""
    base_model_revision: str = ""
    peft_version: str = ""
    
    # Training config
    lora_rank: int = 16
    lora_alpha: int = 32
    target_modules: List[str] = field(default_factory=list)
    learning_rate: float = 2e-4
    num_epochs: int = 3
    training_examples: int = 0
    
    # Evaluation results
    evaluation_results: Dict = field(default_factory=dict)
    evaluation_status: str = "pending"  # pending/approved/rejected
    
    # Deployment state
    tags: List[str] = field(default_factory=list)
    deployment_status: str = "staging"  # staging/production/deprecated
    
    # File tracking
    weights_hash: str = ""  # SHA-256 of adapter_model.safetensors
    weights_size_bytes: int = 0


# ──────────────────────────────────────────────────────────────────────
# REGISTRY IMPLEMENTATION
# ──────────────────────────────────────────────────────────────────────

class AdapterRegistry:
    """
    A local file-based adapter registry.
    Can be extended to use S3, MLflow, etc. as backend.
    """
    
    def __init__(self, registry_path: str):
        self.registry_path = Path(registry_path)
        self.registry_path.mkdir(parents=True, exist_ok=True)
        self.index_file = self.registry_path / "registry_index.json"
        self._load_index()
    
    def _load_index(self):
        """Load the registry index from disk"""
        if self.index_file.exists():
            with open(self.index_file) as f:
                self.index = json.load(f)
        else:
            self.index = {}
    
    def _save_index(self):
        """Persist the registry index to disk"""
        with open(self.index_file, 'w') as f:
            json.dump(self.index, f, indent=2)
    
    def _compute_hash(self, filepath: str) -> str:
        """Compute SHA-256 hash of a file"""
        sha256 = hashlib.sha256()
        with open(filepath, 'rb') as f:
            for chunk in iter(lambda: f.read(8192), b''):
                sha256.update(chunk)
        return sha256.hexdigest()
    
    def register(
        self,
        adapter_path: str,
        adapter_name: str,
        version: str,
        description: str,
        metadata: dict,
        tags: List[str] = None
    ) -> AdapterVersion:
        """
        Register a new adapter version in the registry.
        
        Args:
            adapter_path: Path to directory containing adapter files
            adapter_name: Logical name (e.g., "medical-assistant")
            version: Semantic version string (e.g., "1.2.0")
            description: Human-readable description of this version
            metadata: Training metadata dictionary
            tags: Optional list of tags (e.g., ["staging", "rollback-safe"])
        
        Returns:
            AdapterVersion object for this registration
        """
        adapter_path = Path(adapter_path)
        weights_file = adapter_path / "adapter_model.safetensors"
        config_file = adapter_path / "adapter_config.json"
        
        # Validate files exist
        assert weights_file.exists(), f"Weights file not found: {weights_file}"
        assert config_file.exists(), f"Config file not found: {config_file}"
        
        # Load config
        with open(config_file) as f:
            adapter_config = json.load(f)
        
        # Create version record
        version_record = AdapterVersion(
            adapter_name=adapter_name,
            version=version,
            description=description,
            base_model_id=adapter_config.get('base_model_name_or_path', ''),
            lora_rank=adapter_config.get('r', 0),
            lora_alpha=adapter_config.get('lora_alpha', 0),
            target_modules=adapter_config.get('target_modules', []),
            weights_hash=self._compute_hash(str(weights_file)),
            weights_size_bytes=weights_file.stat().st_size,
            tags=tags or [],
            **{k: v for k, v in metadata.items() 
               if k in AdapterVersion.__dataclass_fields__}
        )
        
        # Store adapter files in registry
        store_path = self.registry_path / adapter_name / version
        store_path.mkdir(parents=True, exist_ok=True)
        
        shutil.copy2(weights_file, store_path / "adapter_model.safetensors")
        shutil.copy2(config_file, store_path / "adapter_config.json")
        
        # Save metadata
        metadata_path = store_path / "adapter_metadata.json"
        with open(metadata_path, 'w') as f:
            json.dump(asdict(version_record), f, indent=2)
        
        # Update index
        if adapter_name not in self.index:
            self.index[adapter_name] = {}
        
        self.index[adapter_name][version] = {
            'store_path': str(store_path),
            'created_at': version_record.created_at,
            'tags': version_record.tags,
            'deployment_status': version_record.deployment_status,
            'weights_hash': version_record.weights_hash
        }
        self._save_index()
        
        print(f"✅ Registered {adapter_name} v{version}")
        print(f"   Path: {store_path}")
        print(f"   Hash: {version_record.weights_hash[:16]}...")
        print(f"   Size: {version_record.weights_size_bytes / 1e6:.1f} MB")
        
        return version_record
    
    def get_adapter_path(
        self, 
        adapter_name: str, 
        version: str = "latest",
        tag: str = None
    ) -> str:
        """
        Get the filesystem path to an adapter.
        
        Args:
            adapter_name: Logical adapter name
            version: Specific version, or "latest" for newest
            tag: Get version with this tag (e.g., "production")
        
        Returns:
            Path to directory containing adapter files
        """
        if adapter_name not in self.index:
            raise KeyError(f"Adapter '{adapter_name}' not found in registry")
        
        versions = self.index[adapter_name]
        
        if tag:
            # Find version with the specified tag
            matching = [v for v, info in versions.items() 
                       if tag in info.get('tags', [])]
            if not matching:
                raise KeyError(f"No version of '{adapter_name}' with tag '{tag}'")
            version = sorted(matching)[-1]  # Latest with this tag
        
        elif version == "latest":
            version = sorted(versions.keys())[-1]
        
        if version not in versions:
            raise KeyError(f"Version '{version}' not found for '{adapter_name}'")
        
        return versions[version]['store_path']
    
    def promote(
        self, 
        adapter_name: str, 
        version: str,
        from_status: str,
        to_status: str,
        approved_by: str = None
    ):
        """
        Promote an adapter through deployment stages.
        staging → production, or production → deprecated
        """
        if adapter_name not in self.index:
            raise KeyError(f"Adapter '{adapter_name}' not found")
        
        if version not in self.index[adapter_name]:
            raise KeyError(f"Version '{version}' not found")
        
        # Validate transition
        valid_transitions = {
            'staging': ['production'],
            'production': ['deprecated'],
            'deprecated': []  # Cannot be re-promoted
        }
        
        current = self.index[adapter_name][version]['deployment_status']
        
        if to_status not in valid_transitions.get(current, []):
            raise ValueError(
                f"Invalid transition: {current} → {to_status}. "
                f"Valid: {valid_transitions.get(current, [])}"
            )
        
        # Update tags and status
        self.index[adapter_name][version]['deployment_status'] = to_status
        
        if 'tags' not in self.index[adapter_name][version]:
            self.index[adapter_name][version]['tags'] = []
        
        if to_status == 'production':
            # Remove production tag from all other versions
            for v in self.index[adapter_name]:
                if 'production' in self.index[adapter_name][v].get('tags', []):
                    self.index[adapter_name][v]['tags'].remove('production')
            
            self.index[adapter_name][version]['tags'].append('production')
            print(f"✅ {adapter_name} v{version} → PRODUCTION")
        
        elif to_status == 'deprecated':
            tags = self.index[adapter_name][version]['tags']
            if 'production' in tags:
                tags.remove('production')
            tags.append('deprecated')
            print(f"🗑️  {adapter_name} v{version} → DEPRECATED")
        
        # Record promotion event
        if 'promotion_history' not in self.index[adapter_name][version]:
            self.index[adapter_name][version]['promotion_history'] = []
        
        self.index[adapter_name][version]['promotion_history'].append({
            'from': from_status,
            'to': to_status,
            'timestamp': datetime.utcnow().isoformat(),
            'approved_by': approved_by
        })
        
        self._save_index()
    
    def list_versions(self, adapter_name: str) -> None:
        """Print formatted version table for an adapter"""
        if adapter_name not in self.index:
            print(f"Adapter '{adapter_name}' not found.")
            return
        
        print(f"\n{'='*70}")
        print(f"ADAPTER: {adapter_name}")
        print(f"{'='*70}")
        print(f"{'VERSION':10} {'STATUS':12} {'TAGS':30} {'CREATED':20}")
        print(f"{'-'*70}")
        
        for version in sorted(self.index[adapter_name].keys()):
            info = self.index[adapter_name][version]
            tags = ', '.join(info.get('tags', []))
            created = info.get('created_at', '')[:10]
            status = info.get('deployment_status', 'unknown')
            
            # Highlight production
            marker = "🟢" if 'production' in info.get('tags', []) else "  "
            print(f"{marker} {version:8} {status:12} {tags:30} {created:20}")
        
        print(f"{'='*70}\n")
    
    def get_production_path(self, adapter_name: str) -> str:
        """Shortcut: Get path to current production adapter"""
        return self.get_adapter_path(adapter_name, tag="production")
    
    def rollback(
        self, 
        adapter_name: str, 
        reason: str,
        performed_by: str
    ) -> str:
        """
        Roll back to the previous production version.
        Returns the version that was rolled back to.
        """
        versions = self.index.get(adapter_name, {})
        
        # Find current production
        current_prod = None
        for v, info in versions.items():
            if 'production' in info.get('tags', []):
                current_prod = v
                break
        
        if not current_prod:
            raise ValueError(f"No production version found for {adapter_name}")
        
        # Find rollback-safe versions (not current, not deprecated)
        rollback_candidates = [
            v for v, info in versions.items()
            if (v != current_prod and 
                'rollback-safe' in info.get('tags', []) and
                info.get('deployment_status') != 'deprecated')
        ]
        
        if not rollback_candidates:
            raise ValueError(f"No rollback-safe version available for {adapter_name}")
        
        # Roll back to the most recent safe version
        rollback_to = sorted(rollback_candidates)[-1]
        
        # Execute rollback
        print(f"⏪ ROLLING BACK {adapter_name}")
        print(f"   From: v{current_prod}")
        print(f"   To:   v{rollback_to}")
        print(f"   Reason: {reason}")
        
        # Deprecate current
        self.promote(adapter_name, current_prod, 'production', 'deprecated')
        
        # Promote rollback candidate to production
        old_status = versions[rollback_to]['deployment_status']
        self.promote(
            adapter_name, rollback_to, 
            old_status, 'production',
            approved_by=performed_by
        )
        
        # Log rollback event
        if 'rollback_history' not in self.index[adapter_name]:
            self.index[adapter_name]['rollback_history'] = []
        
        self.index[adapter_name]['rollback_history'].append({
            'from_version': current_prod,
            'to_version': rollback_to,
            'reason': reason,
            'performed_by': performed_by,
            'timestamp': datetime.utcnow().isoformat()
        })
        self._save_index()
        
        print(f"✅ Rollback complete. Now serving v{rollback_to}")
        return rollback_to
```

## 1. What Adapter Swapping Means Technically

```
THE CORE CONCEPT:

One base model loaded in GPU memory.
Multiple adapters stored as small files.
At serving time: Apply different adapter per request.
Switch between adapters without reloading the base model.

WHY THIS IS POWERFUL:
──────────────────────────────────────────────────────────────

Without swapping:
  Medical assistant = base model + medical adapter → 16 GB
  Legal assistant = base model + legal adapter → 16 GB
  Finance assistant = base model + finance adapter → 16 GB
  Total GPU memory needed: 3 × 16 GB = 48 GB (3 separate models)

With swapping:
  Base model: 16 GB (loaded once)
  Medical adapter: 32 MB (load when needed)
  Legal adapter: 32 MB (load when needed)
  Finance adapter: 32 MB (load when needed)
  Total GPU memory: 16 GB + 96 MB ≈ 16.1 GB

MEMORY SAVINGS: 66% reduction for 3 adapters.
With 50 adapters: 97% memory savings.

WHAT SWAPPING ACTUALLY DOES MECHANICALLY:
──────────────────────────────────────────────────────────────

The base model layers look like this (conceptually):

ATTENTION LAYER k (without adapter):
  h = W_Q @ x + W_K @ x + W_V @ x → attention → W_O @ attn_out

ATTENTION LAYER k (with adapter "medical"):
  h = (W_Q + B_Q_med @ A_Q_med × α/r) @ x + ...

ATTENTION LAYER k (with adapter "legal"):
  h = (W_Q + B_Q_leg @ A_Q_leg × α/r) @ x + ...

To swap:
1. Remove medical adapter matrices (B_Q_med, A_Q_med, etc.)
2. Load legal adapter matrices (B_Q_leg, A_Q_leg, etc.)
3. Next forward pass uses legal adapter.

The base matrices (W_Q, W_K, W_V, W_O) NEVER CHANGE.
Only the tiny adapter matrices change.
That is why swapping is so fast.
```

---

## 2. Hot-Swapping vs Cold-Swapping

```
TWO APPROACHES TO ADAPTER SWITCHING:

COLD-SWAPPING:
──────────────────────────────────────────────────────────────
Definition: Fully unload current adapter. Load new adapter from disk.

PROCESS:
1. Current request finishes.
2. Unload adapter A: Remove A_matrices from GPU memory.
3. Load adapter B: Read from disk → GPU memory.
4. Process new request with adapter B.

LATENCY:
Load from local SSD: 50-200ms for 32MB adapter.
Load from S3/network: 500ms - 5 seconds.
Acceptable if requests are infrequent (batch scenarios).
NOT acceptable for real-time serving (< 100ms SLA).

WHEN TO USE COLD-SWAPPING:
→ Batch inference (process all medical requests, then all legal)
→ Low-traffic systems (one swap per minute is fine)
→ When you cannot keep all adapters in GPU memory simultaneously

HOT-SWAPPING:
──────────────────────────────────────────────────────────────
Definition: All adapters pre-loaded into GPU memory.
            Switch between them by changing which is "active."
            No disk access at switch time.

PROCESS:
1. At startup: Load ALL adapters into GPU memory.
2. Request arrives with adapter_id="medical".
3. Set active adapter to "medical" (pointer change, nanoseconds).
4. Forward pass uses medical adapter.
5. Next request with adapter_id="legal".
6. Set active adapter to "legal" (pointer change).
7. Forward pass uses legal adapter.

LATENCY OVERHEAD: < 1ms (just changing a pointer)
MEMORY COST: base_model + ALL adapters in GPU memory

FOR 10 ADAPTERS × 32MB:
  Extra memory: 320 MB → Negligible on 40-80GB GPU

FOR 100 ADAPTERS × 32MB:
  Extra memory: 3.2 GB → Acceptable on 40GB+ GPU

FOR 1000 ADAPTERS × 32MB:
  Extra memory: 32 GB → Need memory management (LRU cache)

WHEN TO USE HOT-SWAPPING:
→ Real-time serving (strict latency SLA)
→ Moderate number of adapters (< 100)
→ High-throughput systems (many rapid switches)
```

## 3. The Complete Hot-Swap Implementation

```python
# PRODUCTION HOT-SWAP SYSTEM

import torch
from typing import Dict, Optional, OrderedDict
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer
from collections import OrderedDict as OrderedDictType
import threading
import time

class AdapterSwapManager:
    """
    Production-grade adapter hot-swap system.
    
    Features:
    - Multi-adapter loading into GPU memory
    - Zero-latency switching between loaded adapters
    - LRU cache for memory management
    - Thread-safe for concurrent requests
    - Metrics tracking
    """
    
    def __init__(
        self,
        base_model_path: str,
        max_cached_adapters: int = 10,
        device: str = "cuda",
        dtype: torch.dtype = torch.bfloat16
    ):
        self.device = device
        self.dtype = dtype
        self.max_cached_adapters = max_cached_adapters
        self._lock = threading.Lock()
        
        # Performance metrics
        self.metrics = {
            'cache_hits': 0,
            'cache_misses': 0,
            'total_requests': 0,
            'swap_times': []
        }
        
        # Load base model ONCE
        print(f"Loading base model from {base_model_path}...")
        self.base_model = AutoModelForCausalLM.from_pretrained(
            base_model_path,
            torch_dtype=dtype,
            device_map=device,
            trust_remote_code=True
        )
        self.tokenizer = AutoTokenizer.from_pretrained(base_model_path)
        print(f"✅ Base model loaded: "
              f"{sum(p.numel() for p in self.base_model.parameters()):,} params")
        
        # PEFT model wrapping (enables multi-adapter)
        self.peft_model = None  # Will be initialized with first adapter
        
        # LRU Cache: adapter_id → loaded state
        # OrderedDict preserves insertion order for LRU
        self._cache: OrderedDictType[str, dict] = OrderedDict()
        self._adapter_paths: Dict[str, str] = {}
        self._current_adapter: Optional[str] = None
    
    def register_adapter(self, adapter_id: str, adapter_path: str):
        """Register an adapter path (doesn't load it yet)"""
        self._adapter_paths[adapter_id] = adapter_path
        print(f"Registered adapter: {adapter_id} → {adapter_path}")
    
    def _load_adapter_to_cache(self, adapter_id: str):
        """Load an adapter from disk into GPU memory cache"""
        if adapter_id not in self._adapter_paths:
            raise ValueError(f"Adapter '{adapter_id}' not registered. "
                           f"Available: {list(self._adapter_paths.keys())}")
        
        load_start = time.perf_counter()
        adapter_path = self._adapter_paths[adapter_id]
        
        if self.peft_model is None:
            # First adapter: Initialize PEFT model
            self.peft_model = PeftModel.from_pretrained(
                self.base_model,
                adapter_path,
                adapter_name=adapter_id
            )
            print(f"✅ Initialized PEFT model with first adapter: {adapter_id}")
        else:
            # Subsequent adapters: Load alongside existing ones
            self.peft_model.load_adapter(
                adapter_path,
                adapter_name=adapter_id
            )
            print(f"✅ Loaded additional adapter: {adapter_id}")
        
        load_time = time.perf_counter() - load_start
        
        # Add to LRU cache (most recently used = end of OrderedDict)
        self._cache[adapter_id] = {
            'loaded_at': time.time(),
            'last_used': time.time(),
            'load_time_ms': load_time * 1000,
            'request_count': 0
        }
        
        # If cache is full: evict least recently used
        if len(self._cache) > self.max_cached_adapters:
            self._evict_lru()
        
        print(f"   Load time: {load_time*1000:.1f}ms | "
              f"Cache size: {len(self._cache)}/{self.max_cached_adapters}")
        self.metrics['cache_misses'] += 1
    
    def _evict_lru(self):
        """Remove least recently used adapter from GPU memory"""
        # First item in OrderedDict = least recently used
        lru_id = next(iter(self._cache))
        
        # Remove from PEFT model
        if hasattr(self.peft_model, 'delete_adapter'):
            self.peft_model.delete_adapter(lru_id)
        
        # Remove from cache
        del self._cache[lru_id]
        
        print(f"⚡ Evicted LRU adapter: {lru_id} "
              f"(cache at max: {self.max_cached_adapters})")
    
    def _switch_adapter(self, adapter_id: str):
        """Switch the active adapter (zero-latency if cached)"""
        if self.peft_model is None:
            raise RuntimeError("No adapters loaded yet")
        
        self.peft_model.set_adapter(adapter_id)
        self._current_adapter = adapter_id
        
        # Update LRU order: Move to end (most recently used)
        self._cache.move_to_end(adapter_id)
        self._cache[adapter_id]['last_used'] = time.time()
        self._cache[adapter_id]['request_count'] += 1
    
    @torch.inference_mode()
    def generate(
        self,
        prompt: str,
        adapter_id: str,
        max_new_tokens: int = 256,
        temperature: float = 0.7,
        **generation_kwargs
    ) -> str:
        """
        Generate text using the specified adapter.
        Thread-safe, auto-manages adapter cache.
        """
        self.metrics['total_requests'] += 1
        swap_start = time.perf_counter()
        
        with self._lock:
            # Check if adapter is in cache
            if adapter_id not in self._cache:
                # Cache miss: Load from disk
                self._load_adapter_to_cache(adapter_id)
            else:
                self.metrics['cache_hits'] += 1
            
            # Switch to requested adapter (zero-latency)
            self._switch_adapter(adapter_id)
        
        swap_time = time.perf_counter() - swap_start
        self.metrics['swap_times'].append(swap_time * 1000)
        
        # Generate
        inputs = self.tokenizer(
            prompt, 
            return_tensors="pt",
            truncation=True,
            max_length=2048
        ).to(self.device)
        
        model_to_use = self.peft_model if self.peft_model else self.base_model
        
        outputs = model_to_use.generate(
            **inputs,
            max_new_tokens=max_new_tokens,
            temperature=temperature,
            do_sample=temperature > 0,
            pad_token_id=self.tokenizer.eos_token_id,
            **generation_kwargs
        )
        
        # Decode only the new tokens
        new_tokens = outputs[0][inputs['input_ids'].shape[1]:]
        return self.tokenizer.decode(new_tokens, skip_special_tokens=True)
    
    def preload_adapters(self, adapter_ids: list):
        """Warm up cache by preloading specified adapters"""
        print(f"Preloading {len(adapter_ids)} adapters...")
        for adapter_id in adapter_ids:
            if adapter_id not in self._cache:
                self._load_adapter_to_cache(adapter_id)
        print(f"✅ Preloaded. Cache: {list(self._cache.keys())}")
    
    def get_stats(self) -> dict:
        """Return current performance statistics"""
        swap_times = self.metrics['swap_times']
        return {
            'total_requests': self.metrics['total_requests'],
            'cache_hit_rate': (self.metrics['cache_hits'] / 
                             max(self.metrics['total_requests'], 1)),
            'cache_miss_rate': (self.metrics['cache_misses'] / 
                              max(self.metrics['total_requests'], 1)),
            'cached_adapters': list(self._cache.keys()),
            'current_adapter': self._current_adapter,
            'avg_swap_time_ms': sum(swap_times) / len(swap_times) if swap_times else 0,
            'p95_swap_time_ms': sorted(swap_times)[int(len(swap_times)*0.95)] if swap_times else 0,
        }
    
    def print_stats(self):
        """Pretty-print performance statistics"""
        stats = self.get_stats()
        print("\n" + "="*50)
        print("ADAPTER SWAP MANAGER STATISTICS")
        print("="*50)
        print(f"Total requests:    {stats['total_requests']}")
        print(f"Cache hit rate:    {stats['cache_hit_rate']:.1%}")
        print(f"Cached adapters:   {stats['cached_adapters']}")
        print(f"Current adapter:   {stats['current_adapter']}")
        print(f"Avg swap time:     {stats['avg_swap_time_ms']:.2f}ms")
        print(f"P95 swap time:     {stats['p95_swap_time_ms']:.2f}ms")
        print("="*50 + "\n")
```

```python
# INTELLIGENT REQUEST ROUTING SYSTEM

from enum import Enum
import re
from typing import Tuple, Optional

class RoutingStrategy(Enum):
    EXPLICIT = "explicit"           # User specifies adapter in request
    KEYWORD = "keyword"             # Route based on keyword matching
    CLASSIFIER = "classifier"       # Use ML classifier for routing
    EMBEDDING = "embedding"         # Use semantic similarity for routing

class AdapterRouter:
    """
    Routes incoming requests to the correct adapter.
    Supports multiple routing strategies.
    """
    
    def __init__(self, swap_manager: AdapterSwapManager):
        self.manager = swap_manager
        self.routing_rules = {}
        self.fallback_adapter = "general"
        self.routing_metrics = {}
    
    # ──────────────────────────────────────────────────────────────────
    # STRATEGY 1: EXPLICIT ROUTING (Simplest)
    # User or calling system specifies adapter_id directly
    # ──────────────────────────────────────────────────────────────────
    
    def route_explicit(self, request: dict) -> str:
        """Route based on explicit adapter_id field in request"""
        adapter_id = request.get('adapter_id')
        if not adapter_id:
            return self.fallback_adapter
        return adapter_id
    
    # ──────────────────────────────────────────────────────────────────
    # STRATEGY 2: KEYWORD ROUTING
    # Route based on keywords in the user's message
    # ──────────────────────────────────────────────────────────────────
    
    def register_keyword_rule(
        self, 
        adapter_id: str, 
        keywords: list, 
        priority: int = 0
    ):
        """Register keyword routing rules"""
        self.routing_rules[adapter_id] = {
            'keywords': [kw.lower() for kw in keywords],
            'priority': priority,
            'patterns': [re.compile(kw, re.IGNORECASE) for kw in keywords]
        }
    
    def route_keyword(self, message: str) -> Tuple[str, float]:
        """
        Route based on keyword matching.
        Returns: (adapter_id, confidence)
        """
        message_lower = message.lower()
        scores = {}
        
        for adapter_id, rules in self.routing_rules.items():
            matches = sum(
                1 for kw in rules['keywords'] 
                if kw in message_lower
            )
            if matches > 0:
                confidence = min(matches / 3, 1.0)
                scores[adapter_id] = (confidence, rules['priority'])
        
        if not scores:
            return self.fallback_adapter, 0.3
        
        # Sort by priority first, then confidence
        best = max(scores.items(), 
                   key=lambda x: (x[1][1], x[1][0]))
        return best[0], best[1][0]
    
    # ──────────────────────────────────────────────────────────────────
    # STRATEGY 3: EMBEDDING-BASED ROUTING (Most Accurate)
    # Use semantic similarity to find best matching adapter
    # ──────────────────────────────────────────────────────────────────
    
    def setup_embedding_router(
        self, 
        adapter_descriptions: dict,
        embedding_model: str = "all-MiniLM-L6-v2"
    ):
        """
        Setup semantic routing using adapter descriptions.
        
        Args:
            adapter_descriptions: {adapter_id: "natural language description of what this adapter does"}
        """
        from sentence_transformers import SentenceTransformer
        import numpy as np
        
        self.embedding_model = SentenceTransformer(embedding_model)
        self.adapter_desc_embeddings = {}
        
        for adapter_id, description in adapter_descriptions.items():
            self.adapter_desc_embeddings[adapter_id] = \
                self.embedding_model.encode(description)
        
        print(f"✅ Embedding router initialized with "
              f"{len(adapter_descriptions)} adapters")
    
    def route_embedding(self, message: str) -> Tuple[str, float]:
        """
        Route using cosine similarity between message and adapter descriptions.
        Returns: (adapter_id, confidence)
        """
        import numpy as np
        from sklearn.metrics.pairwise import cosine_similarity
        
        message_embedding = self.embedding_model.encode([message])
        
        best_adapter = self.fallback_adapter
        best_similarity = -1
        
        for adapter_id, desc_embedding in self.adapter_desc_embeddings.items():
            similarity = cosine_similarity(
                message_embedding, 
                [desc_embedding]
            )[0][0]
            
            if similarity > best_similarity:
                best_similarity = similarity
                best_adapter = adapter_id
        
        # If best similarity is low, use fallback
        if best_similarity < 0.4:
            return self.fallback_adapter, best_similarity
        
        return best_adapter, float(best_similarity)
    
    def route(self, request: dict) -> Tuple[str, float]:
        """
        Main routing method. Combines strategies.
        Returns: (adapter_id, confidence)
        """
        message = request.get('message', '')
        
        # Priority 1: Explicit routing (user knows what they want)
        if 'adapter_id' in request:
            return request['adapter_id'], 1.0
        
        # Priority 2: Embedding routing (if configured)
        if hasattr(self, 'embedding_model'):
            adapter_id, conf = self.route_embedding(message)
            if conf > 0.6:
                return adapter_id, conf
        
        # Priority 3: Keyword routing
        adapter_id, conf = self.route_keyword(message)
        if conf > 0.5:
            return adapter_id, conf
        
        # Fallback
        return self.fallback_adapter, 0.3
```

## 1. What Makes an Adapter Compatible With a Base Model?

```
THE COMPATIBILITY QUESTION:

You have an adapter trained on LLaMA 3 8B.
Can you load it on LLaMA 3 70B?
Can you load it on LLaMA 3.1 8B?
Can you load it on Mistral 7B?

ANSWER: It depends on WHAT is compatible.
There are FIVE layers of compatibility.
ALL must match. One mismatch = failure.

THE FIVE COMPATIBILITY LAYERS:
──────────────────────────────────────────────────────────────

LAYER 1: ARCHITECTURE COMPATIBILITY
─────────────────────────────────────
The base model must have the SAME architecture as the model
the adapter was trained on.

WHAT MUST MATCH:
→ Number of transformer layers
→ Hidden dimension (d_model)
→ Number of attention heads
→ Number of key-value heads (GQA vs MHA)
→ Intermediate dimension (FFN size)
→ Attention type (causal, bidirectional)
→ Positional encoding type (RoPE, ALiBi, etc.)

COMPATIBLE:
LLaMA 3 8B (trained on) → LLaMA 3 8B (load on): ✅
  Same architecture, same dimensions.

INCOMPATIBLE:
LLaMA 3 8B (trained on) → LLaMA 3 70B (load on): ❌
  Different number of layers, different hidden dimensions.
  The A and B matrices have wrong shape.

INCOMPATIBLE:
LLaMA 3 8B (trained on) → Mistral 7B (load on): ❌
  Different architecture family.
  Matrix shapes don't match.

──────────────────────────────────────────────────────────────

LAYER 2: WEIGHT NAMING COMPATIBILITY
──────────────────────────────────────
The adapter was trained using specific weight names.
The names must match in the target model.

ADAPTER KEY EXAMPLE:
"model.layers.0.self_attn.q_proj.lora_A.weight"

TARGET MODEL MUST HAVE A LAYER NAMED:
"model.layers.0.self_attn.q_proj"

If the target model names its layers differently:
"transformer.blocks.0.attention.query_proj"
→ INCOMPATIBLE. Name mismatch.

BETWEEN VERSIONS (usually compatible):
LLaMA 3 8B (v1 revision) → LLaMA 3 8B (v2 revision)
→ If same architecture, weight names usually match. ✅

──────────────────────────────────────────────────────────────

LAYER 3: TARGET MODULE COMPATIBILITY
──────────────────────────────────────
If adapter targeted q_proj and v_proj:
The target model must also have modules named q_proj and v_proj.

Adapter config says: target_modules = ["q_proj", "v_proj"]
Target model must have: self_attn.q_proj, self_attn.v_proj

──────────────────────────────────────────────────────────────

LAYER 4: QUANTIZATION COMPATIBILITY
─────────────────────────────────────
If adapter was trained with QLoRA on NF4 base:
→ Can load on bf16 base: ✅ (adapters are bf16, base just provides forward pass)
→ Can load on INT8 base: ✅ (same reason)
→ Can load on fp32 base: ✅

If adapter was trained on bf16 base:
→ Can load on NF4 base: ✅ (weights are compatible, precision different)

Generally: Quantization of base model is INDEPENDENT of adapter compatibility.
The adapter's OWN weights are always stored in bf16 or fp32.
The base model quantization only affects compute efficiency.

──────────────────────────────────────────────────────────────

LAYER 5: VOCABULARY COMPATIBILITY
───────────────────────────────────
This matters if the adapter added special tokens.

Base model vocabulary: 128,000 tokens (LLaMA 3 standard)
If adapter added tokens: "Medical_Start", "Medical_End"
→ New vocabulary size: 128,002

Loading this adapter on a base model with 128,000 vocab:
→ Embedding layer has wrong size. ❌ INCOMPATIBLE.

Unless the adapter's tokenizer is also loaded alongside.
```

## 2. How Base Model Upgrades Break Adapters

```
THE MOST COMMON PRODUCTION SURPRISE:

"LLaMA 3 is great. We have 20 adapters trained on it."
"LLaMA 3.1 just released. It's much better. Let's upgrade."
"Wait — do our adapters still work?"

SCENARIO 1: SAME ARCHITECTURE, MINOR WEIGHT UPDATE
──────────────────────────────────────────────────────────────
LLaMA 3 8B → LLaMA 3.1 8B (minor revision)

What changed in the base model:
→ Same architecture (same number of layers, same dimensions)
→ Different weight VALUES (better pretraining, more data)
→ Same weight NAMES

Adapter compatibility: ✅ LOADS SUCCESSFULLY
Performance impact: ⚠️ DEPENDS

The adapter was trained to MODIFY the LLaMA 3 weights.
LLaMA 3.1 has different weights.
The adapter's B×A correction was learned relative to LLaMA 3's weights.
On LLaMA 3.1's different weights: The correction may be misaligned.

HOW MISALIGNED?
→ Minor revision: Usually small impact. Adapter works ~90% as well.
→ Major revision: Potentially large impact. Adapter may need retraining.

TESTING REQUIRED after any base model upgrade.

──────────────────────────────────────────────────────────────

SCENARIO 2: SAME FAMILY, DIFFERENT SIZE
──────────────────────────────────────────────────────────────
LLaMA 3 8B → LLaMA 3 70B

What changed:
→ Different architecture (different number of layers, different d_model)
→ Different weight shapes completely

Adapter compatibility: ❌ COMPLETELY INCOMPATIBLE
The A and B matrices have wrong shapes.
Will fail to load with a shape mismatch error.

Must retrain adapter from scratch on the new model size.

──────────────────────────────────────────────────────────────

SCENARIO 3: DIFFERENT ARCHITECTURE FAMILY
──────────────────────────────────────────────────────────────
LLaMA 3 8B → Mistral 7B v0.3

What changed:
→ Different architecture (Mistral uses sliding window attention)
→ Different layer organization
→ Different dimension names

Adapter compatibility: ❌ INCOMPATIBLE
Cannot load at all.

──────────────────────────────────────────────────────────────

SCENARIO 4: BASE MODEL WITH VOCABULARY CHANGE
──────────────────────────────────────────────────────────────
LLaMA 3 (128K vocab) → Hypothetical LLaMA 4 (256K vocab)

What changed:
→ Vocabulary size doubled
→ Embedding matrix shapes changed

If adapter targeted embedding layers:
→ ❌ INCOMPATIBLE (embedding matrix shapes mismatch)

If adapter only targeted attention layers:
→ Might still work if attention architecture is preserved.
→ But embedding mismatch causes issues at generation time.
→ Needs testing and likely retraining.
```

```python
# COMPLETE ADAPTER COMPATIBILITY CHECKER

import json
import torch
from pathlib import Path
from typing import Dict, Tuple, List
from dataclasses import dataclass

@dataclass
class CompatibilityReport:
    """Result of compatibility check"""
    is_compatible: bool
    issues: List[str]
    warnings: List[str]
    recommendations: List[str]
    compatibility_score: float  # 0.0 = incompatible, 1.0 = fully compatible

class AdapterCompatibilityChecker:
    """
    Checks if a LoRA adapter is compatible with a given base model.
    Runs before attempting to load (prevents runtime crashes).
    """
    
    def check_compatibility(
        self,
        adapter_path: str,
        target_model_config: dict,
        target_model_tokenizer_config: dict = None
    ) -> CompatibilityReport:
        """
        Comprehensive compatibility check.
        
        Args:
            adapter_path: Path to adapter directory
            target_model_config: model_config from AutoConfig
            target_model_tokenizer_config: Optional tokenizer config
        
        Returns:
            CompatibilityReport with detailed findings
        """
        issues = []
        warnings = []
        recommendations = []
        
        # Load adapter config
        adapter_config_path = Path(adapter_path) / "adapter_config.json"
        if not adapter_config_path.exists():
            return CompatibilityReport(
                is_compatible=False,
                issues=["adapter_config.json not found"],
                warnings=[], recommendations=[],
                compatibility_score=0.0
            )
        
        with open(adapter_config_path) as f:
            adapter_config = json.load(f)
        
        # ──────────────────────────────────────────────────────────────
        # CHECK 1: Architecture Compatibility
        # ──────────────────────────────────────────────────────────────
        
        trained_on = adapter_config.get('base_model_name_or_path', 'unknown')
        target_arch = target_model_config.get('architectures', ['unknown'])[0]
        
        # Check key architectural dimensions
        arch_checks = {
            'hidden_size': ('hidden_size', 'd_model', 'n_embd'),
            'num_layers': ('num_hidden_layers', 'n_layer', 'num_layers'),
            'num_heads': ('num_attention_heads', 'n_head'),
            'vocab_size': ('vocab_size',),
        }
        
        target_dims = {}
        for key, possible_names in arch_checks.items():
            for name in possible_names:
                if name in target_model_config:
                    target_dims[key] = target_model_config[name]
                    break
        
        # Load adapter metadata if available
        metadata_path = Path(adapter_path) / "adapter_metadata.json"
        adapter_metadata = {}
        if metadata_path.exists():
            with open(metadata_path) as f:
                adapter_metadata = json.load(f)
        
        # Check hidden size (d_model)
        adapter_hidden = self._infer_hidden_size_from_weights(adapter_path)
        target_hidden = target_dims.get('hidden_size')
        
        if adapter_hidden and target_hidden:
            if adapter_hidden != target_hidden:
                issues.append(
                    f"CRITICAL: Hidden size mismatch. "
                    f"Adapter: {adapter_hidden}, Target: {target_hidden}. "
                    f"Cannot load."
                )
            else:
                recommendations.append(
                    f"✅ Hidden size matches: {adapter_hidden}"
                )
        
        # ──────────────────────────────────────────────────────────────
        # CHECK 2: Target Module Compatibility
        # ──────────────────────────────────────────────────────────────
        
        adapter_target_modules = adapter_config.get('target_modules', [])
        
        for module_name in adapter_target_modules:
            # Check if this module exists in target model
            # (We check by name pattern, not by loading the model)
            common_names = {
                'q_proj': ['q_proj', 'query', 'query_proj', 'wq'],
                'k_proj': ['k_proj', 'key', 'key_proj', 'wk'],
                'v_proj': ['v_proj', 'value', 'value_proj', 'wv'],
                'o_proj': ['o_proj', 'out_proj', 'output_proj', 'wo'],
                'gate_proj': ['gate_proj', 'w1'],
                'up_proj': ['up_proj', 'w3'],
                'down_proj': ['down_proj', 'w2'],
            }
            
            if module_name not in common_names:
                warnings.append(
                    f"⚠️ Unknown target module '{module_name}' — "
                    f"Verify this exists in target model architecture"
                )
        
        recommendations.append(
            f"✅ Target modules: {adapter_target_modules}"
        )
        
        # ──────────────────────────────────────────────────────────────
        # CHECK 3: Base Model Version Compatibility
        # ──────────────────────────────────────────────────────────────
        
        # Extract family from trained_on
        adapter_family = self._extract_model_family(trained_on)
        target_family = self._extract_model_family(
            target_model_config.get('model_type', '')
        )
        
        if adapter_family != target_family:
            issues.append(
                f"CRITICAL: Model family mismatch. "
                f"Adapter trained on '{adapter_family}', "
                f"target is '{target_family}'. "
                f"Adapters are not cross-family compatible."
            )
        else:
            # Same family — check for minor version differences
            if trained_on != target_model_config.get('_name_or_path', ''):
                warnings.append(
                    f"⚠️ Different model version. "
                    f"Adapter: '{trained_on}', "
                    f"Target: '{target_model_config.get('_name_or_path', 'unknown')}'. "
                    f"Performance may differ. Testing recommended."
                )
                recommendations.append(
                    "ACTION: Run full evaluation suite after loading "
                    "to verify performance is maintained."
                )
        
        # ──────────────────────────────────────────────────────────────
        # CHECK 4: Vocabulary Compatibility
        # ──────────────────────────────────────────────────────────────
        
        if target_model_tokenizer_config:
            target_vocab_size = target_model_tokenizer_config.get('vocab_size')
            adapter_vocab_size = adapter_metadata.get('vocab_size')
            
            if target_vocab_size and adapter_vocab_size:
                if target_vocab_size != adapter_vocab_size:
                    if 'embed_tokens' in str(adapter_target_modules) or \
                       'lm_head' in str(adapter_target_modules):
                        issues.append(
                            f"CRITICAL: Vocabulary size mismatch. "
                            f"Adapter vocab: {adapter_vocab_size}, "
                            f"Target vocab: {target_vocab_size}. "
                            f"Adapter targets embedding layers."
                        )
                    else:
                        warnings.append(
                            f"⚠️ Vocabulary size difference "
                            f"({adapter_vocab_size} vs {target_vocab_size}). "
                            f"Not an issue if adapter doesn't target embeddings."
                        )
        
        # ──────────────────────────────────────────────────────────────
        # CHECK 5: Rank and Config Sanity
        # ──────────────────────────────────────────────────────────────
        
        rank = adapter_config.get('r', 0)
        alpha = adapter_config.get('lora_alpha', 0)
        
        if rank <= 0:
            issues.append(f"Invalid rank r={rank}")
        if alpha <= 0:
            warnings.append(f"Invalid alpha={alpha}")
        
        recommendations.append(f"✅ LoRA config: r={rank}, alpha={alpha}")
        
        # ──────────────────────────────────────────────────────────────
        # FINAL SCORE AND REPORT
        # ──────────────────────────────────────────────────────────────
        
        is_compatible = len(issues) == 0
        score = 1.0 - (len(issues) * 0.5) - (len(warnings) * 0.1)
        score = max(0.0, min(1.0, score))
        
        return CompatibilityReport(
            is_compatible=is_compatible,
            issues=issues,
            warnings=warnings,
            recommendations=recommendations,
            compatibility_score=score
        )
    
    def _infer_hidden_size_from_weights(self, adapter_path: str) -> int:
        """Infer hidden size from adapter weight shapes"""
        try:
            from safetensors.torch import load_file
            weights = load_file(
                str(Path(adapter_path) / "adapter_model.safetensors"),
                device="cpu"
            )
            for key, tensor in weights.items():
                if 'lora_B' in key:
                    # lora_B shape is [d_model × r]
                    return tensor.shape[0]
            return None
        except Exception:
            return None
    
    def _extract_model_family(self, model_id: str) -> str:
        """Extract model family from model ID"""
        model_id_lower = model_id.lower()
        families = {
            'llama': 'llama',
            'mistral': 'mistral',
            'mixtral': 'mistral',
            'falcon': 'falcon',
            'mpt': 'mpt',
            'gpt2': 'gpt2',
            'gptj': 'gptj',
            'bloom': 'bloom',
            'opt': 'opt',
        }
        for key, family in families.items():
            if key in model_id_lower:
                return family
        return 'unknown'
    
    def print_report(self, report: CompatibilityReport):
        """Pretty-print the compatibility report"""
        print("\n" + "="*60)
        print("ADAPTER COMPATIBILITY REPORT")
        print("="*60)
        
        status = "✅ COMPATIBLE" if report.is_compatible else "❌ INCOMPATIBLE"
        print(f"Status: {status}")
        print(f"Score:  {report.compatibility_score:.2f}/1.00")
        
        if report.issues:
            print(f"\n❌ CRITICAL ISSUES ({len(report.issues)}):")
            for issue in report.issues:
                print(f"  • {issue}")
        
        if report.warnings:
            print(f"\n⚠️  WARNINGS ({len(report.warnings)}):")
            for warning in report.warnings:
                print(f"  • {warning}")
        
        if report.recommendations:
            print(f"\n📋 INFORMATION:")
            for rec in report.recommendations:

        print("="*60 + "\n")
```

## 4. Migration Strategies for Base Model Upgrades

```
THE MIGRATION PROBLEM:
You have adapters trained on LLaMA 3 8B.
You want to upgrade to LLaMA 3.1 8B.
Your adapters cannot be directly transferred.

STRATEGY 1: FULL RETRAINING (Brute Force)
──────────────────────────────────────────────────────────────
Retrain every adapter from scratch on the new base model.
Using the same training data and configuration.

WHEN TO USE:
→ Major version upgrade (different architecture)
→ When you have the training data available
→ When performance is critical

COST:
→ Full training cost per adapter, multiplied by number of adapters
→ For 20 adapters × $300 each = $6,000
→ 2-4 weeks of engineering time

──────────────────────────────────────────────────────────────

STRATEGY 2: DELTA FINE-TUNING (If minor version change)
──────────────────────────────────────────────────────────────
Load the OLD adapter on the NEW base model.
Fine-tune with a very small learning rate to "re-align."

RATIONALE:
The adapter was trained to modify LLaMA 3 weights.
LLaMA 3.1 weights are slightly different.
A brief fine-tuning "corrects" the adapter for the new base.

PROCESS:
1. Load new base model (LLaMA 3.1).
2. Load old adapter (trained on LLaMA 3).
3. Fine-tune for 1 epoch with LR = 1/10th of original.
4. Evaluate: Is performance restored?
5. If yes: Save as new adapter version.

ADVANTAGE: 10x cheaper than full retraining.
RISK: May not fully restore performance for large base model changes.
WHEN TO USE: Minor version upgrades (3.0 → 3.1).

──────────────────────────────────────────────────────────────

STRATEGY 3: KNOWLEDGE DISTILLATION APPROACH
──────────────────────────────────────────────────────────────
Use the OLD adapter model as a TEACHER.
Train a NEW adapter on the new base model with teacher guidance.

PROCESS:
1. Old model (LLaMA 3 + old adapter) → TEACHER
2. New base model (LLaMA 3.1) → STUDENT
3. Generate training data from TEACHER (rejection sampling)
4. Fine-tune NEW adapter on STUDENT using teacher-generated data

ADVANTAGE: Teacher's knowledge is preserved in generated data.
           Student learns on new base model natively.
COST: Extra generation step, but training is cheaper than full FT.
WHEN TO USE: When teacher quality is high, base model changes significantly.

──────────────────────────────────────────────────────────────

STRATEGY 4: COMPATIBILITY SHIM (Quick Workaround)
──────────────────────────────────────────────────────────────
For architecturally compatible but slightly different base models:
Add a small "shim" layer that translates between weight spaces.

CONCEPT:
Old adapter was trained for: W_Q_old + B_Q × A_Q
New base model has:          W_Q_new (different values)

Shim: Learn a small correction matrix C such that:
(W_Q_new + C) ≈ W_Q_old in effect on fine-tuning task

This is complex to implement but reuses most of the original adapter.
Experimental in production. Used in research settings.

──────────────────────────────────────────────────────────────

MIGRATION DECISION FRAMEWORK:
──────────────────────────────────────────────────────────────

           ┌─────────────────────────────────────┐
           │ Does the new base model have the    │
           │ SAME architecture as the old?       │
           └─────────────────────────────────────┘
                     ↙             ↘
                   NO             YES
                    ↓              ↓
            Full Retraining   Minor version change?
            Required ❌           ↙          ↘
            (No shortcut)       YES           NO (major change)
                                 ↓              ↓
                          Delta FT         Full Retraining
                          (1 epoch,        or Knowledge
                          10% LR)          Distillation
```

## 2. Canary Deployments for Adapters

```python
# CANARY DEPLOYMENT SYSTEM FOR ADAPTERS

class CanaryDeployment:
    """
    Gradually shifts traffic from old adapter to new adapter.
    Monitors metrics during the rollout.
    Auto-rolls back if quality degrades.
    """
    
    def __init__(
        self,
        swap_manager: AdapterSwapManager,
        registry: AdapterRegistry,
        metric_tracker: dict
    ):
        self.manager = swap_manager
        self.registry = registry
        self.metric_tracker = metric_tracker
        
        self.canary_adapter = None
        self.baseline_adapter = None
        self.canary_percentage = 0
        self.auto_rollback_threshold = 0.05  # 5% quality drop triggers rollback
    
    def start_canary(
        self,
        adapter_name: str,
        new_version: str,
        initial_percentage: float = 0.05
    ):
        """Start a canary deployment"""
        # Get current production
        self.baseline_adapter = f"{adapter_name}-production"
        self.canary_adapter = f"{adapter_name}-canary"
        
        # Load new version as canary
        canary_path = self.registry.get_adapter_path(adapter_name, new_version)
        self.manager.register_adapter(self.canary_adapter, canary_path)
        
        # Get current production version
        prod_path = self.registry.get_production_path(adapter_name)
        self.manager.register_adapter(self.baseline_adapter, prod_path)
        
        self.canary_percentage = initial_percentage
        
        print(f"🐤 Canary deployment started:")
        print(f"   Baseline: {self.baseline_adapter}")
        print(f"   Canary:   {self.canary_adapter}")
        print(f"   Initial traffic: {initial_percentage:.1%}")
    
    def route_canary(self) -> str:
        """Decide which adapter to use for this request"""
        import random
        
        if random.random() < self.canary_percentage:
            return self.canary_adapter
        return self.baseline_adapter
    
    def increase_canary(self, new_percentage: float):
        """Increase canary traffic percentage"""
        old = self.canary_percentage
        self.canary_percentage = new_percentage
        print(f"📈 Canary traffic: {old:.1%} → {new_percentage:.1%}")
    
    def check_and_auto_rollback(self):
        """Check metrics and auto-rollback if quality drops"""
        baseline_metrics = self.metric_tracker.get(self.baseline_adapter, {})
        canary_metrics = self.metric_tracker.get(self.canary_adapter, {})
        
        if not baseline_metrics or not canary_metrics:
            return False
        
        baseline_quality = baseline_metrics.get('quality_score', 1.0)
        canary_quality = canary_metrics.get('quality_score', 1.0)
        
        quality_drop = baseline_quality - canary_quality
        
        if quality_drop > self.auto_rollback_threshold:
            print(f"🚨 AUTO-ROLLBACK TRIGGERED")
            print(f"   Canary quality: {canary_quality:.3f}")
            print(f"   Baseline quality: {baseline_quality:.3f}")
            print(f"   Drop: {quality_drop:.3f} > threshold {self.auto_rollback_threshold:.3f}")
            
            # Set canary to 0% traffic
            self.canary_percentage = 0
            return True  # Rollback triggered
        
        return False  # No rollback needed
    
    def finalize_canary(self, adapter_name: str, version: str):
        """Complete the canary — promote to full production"""
        print(f"✅ Finalizing canary → promoting to production")
        self.canary_percentage = 1.0
        
        # Official promotion in registry
        self.registry.promote(
            adapter_name, version,
            'staging', 'production'
        )
        
        print(f"✅ {adapter_name} v{version} now at 100% production traffic")

"""
Day 1:  1% canary  → Monitor for 24h
Day 2:  5% canary  → Monitor for 24h
Day 3: 10% canary  → Monitor for 24h
Day 4: 25% canary  → Monitor for 24h
Day 5: 50% canary  → Monitor for 24h
Day 6: 100% (full promotion)

At any point: If quality drops > 5% → Auto-rollback to 0%
```

## 3. Failure Modes ⚠️

```
STORAGE FAILURES:
──────────────────────────────────────────────────────────────

❌ FAILURE 1: SAVING .BIN INSTEAD OF SAFETENSORS
What:  Old code uses torch.save(model.state_dict(), "adapter.bin")
       Security risk (pickle). Slower loading. Python-only.
Fix:   Always use model.save_pretrained(path, safe_serialization=True)
       Audit all training scripts for torch.save usage.

❌ FAILURE 2: NO METADATA SAVED WITH WEIGHTS
What:  Only adapter_model.safetensors saved. No metadata.
       Cannot answer: What was this trained on? When? With what data?
Fix:   Build metadata saving into training script. Not optional.
       Always save adapter_metadata.json alongside weights.

❌ FAILURE 3: OVERWRITING VERSIONS
What:  New version saved to same path as old version.
       Old version is destroyed. Cannot roll back.
Fix:   NEVER overwrite existing adapter versions.
       Always use versioned paths (v1.0.0/, v1.1.0/).
       Add validation: If path exists and has weights → error out.

VERSION CONTROL FAILURES:
──────────────────────────────────────────────────────────────

❌ FAILURE 4: USING "LATEST" IN PRODUCTION CODE
What:  Production serving code: 
       model.load_adapter("registry/medical/latest/")
       "latest" changes when new version is registered.
       Monday: latest = v1.2.0 (good). 
       Tuesday: latest = v2.0.0 (untested!) 
       Production silently changes without deployment process.
Fix:   Production code MUST use explicit versions.
       Only version promoter script should update "production" tag.
       Never hardcode "latest" in serving code.

❌ FAILURE 5: NO LINEAGE TRACKING
What:  Cannot answer "what training data produced this adapter?"
       Regulatory audit requires this. Cannot comply.
Fix:   Always record: dataset names, hashes, source URLs, dates.
       Store in adapter_metadata.json. Store in registry.

SWAPPING FAILURES:
──────────────────────────────────────────────────────────────

❌ FAILURE 6: THREAD SAFETY VIOLATION
What:  Two requests simultaneously try to switch adapters.
       Request A: set_adapter("medical")
       Request B: set_adapter("legal") — halfway through A's process
       Result: Undefined behavior. Wrong adapter serves both.
Fix:   Use threading.Lock() around all adapter switching code.
       Or: Use separate model instances per adapter (more memory).

❌ FAILURE 7: ADAPTER CACHE MEMORY LEAK
What:  Adapters loaded but never evicted.
       GPU memory grows until OOM crash.
       Happens when LRU eviction is not implemented.
Fix:   Implement LRU cache with strict max_size limit.
       Test: Load 100 adapters with max_cache=10. Verify memory stable.

❌ FAILURE 8: COLD START LATENCY SURPRISE
What:  Testing showed swap latency = 1ms.
       Production shows swap latency = 2 seconds.
       Why? Testing: adapter was cached. Production: first request cold.
Fix:   Preload adapters at server startup (warm up cache).
       Measure cold start separately from warm swap latency.
       Design SLA around cold start (first request) and warm (subsequent).

COMPATIBILITY FAILURES:
──────────────────────────────────────────────────────────────

❌ FAILURE 9: LOADING WRONG ARCHITECTURE
What:  Load adapter trained on LLaMA 3 8B onto LLaMA 3 70B.
       Error: "size mismatch for ... expected [4096, 16] got [8192, 16]"
       Runtime crash. Service down.
Fix:   Run compatibility checker BEFORE attempting to load.
       Store base_model_revision in adapter_metadata.
       Add architecture check in deployment pipeline.

❌ FAILURE 10: SILENT PERFORMANCE DEGRADATION AFTER BASE MODEL UPGRADE
What:  Upgraded base model. Adapter loads fine (same architecture).
       No errors. But quality metrics drop 15%.
       Nobody noticed for 2 weeks.
Fix:   Run FULL evaluation suite after any base model upgrade.
       Even if the adapter "loads" — test it!
       "It loaded" ≠ "it performs well."
```

## 5. Interview Answers 💬

---

**Answer to Q5 (Five Compatibility Layers):**

> *"Adapter-model compatibility requires matching across five layers. First, architecture compatibility — the base model must have identical transformer dimensions (hidden size, number of layers, attention heads). An 8B model adapter cannot load on a 70B model because the matrix shapes differ. Second, weight naming compatibility — adapter matrices are stored with specific parameter names that must match the target model's layer names. Different frameworks or model variants can use different naming conventions. Third, target module compatibility — if the adapter targeted q_proj and v_proj, those exact module names must exist in the target model. Fourth, quantization compatibility — this is largely independent; a bf16-trained adapter can load on a 4-bit quantized model because the adapter stores its own weights independently. Fifth, vocabulary compatibility — if the adapter added special tokens during training, the target model's tokenizer must have a matching vocabulary size, particularly if embedding layers were targeted. The key trap is that an adapter can load without errors (passing basic shape checks) while still having significant performance degradation due to weight value differences between a minor revision upgrade."*

---

**Answer to Q15 (Trap — No errors = compatible):**

> *"False, and this is one of the most dangerous misconceptions in production adapter management. Loading without errors only verifies one thing: the matrix shapes are compatible — meaning the architectural dimensions match. It says nothing about performance. The most common failure is upgrading a base model within the same family (e.g., LLaMA 3 to LLaMA 3.1), where the architecture is identical but the weight VALUES have changed from more training data or improved optimization. The adapter's learned corrections in B×A were calibrated against the original weight values. When those base weights change, the adapter's corrections become misaligned. The model still loads, runs inference, and produces text — but accuracy can drop 10-20% silently. The correct practice is: load the adapter, then run your complete evaluation suite comparing against the pre-upgrade baseline. Only if evaluation metrics are maintained should you consider the upgrade successful."*

---

**Answer to Q16 (Trap — Always merge for performance):**

> *"Disagree — merging is optimal for single-adapter single-task deployments but actively harmful for multi-adapter serving systems. Merging eliminates the latency overhead of the LoRA branches at inference time, which is a real benefit when you have one adapter and need maximum throughput. However, once merged, the adapter becomes permanently baked into the weights — you cannot hot-swap to a different adapter without maintaining separate merged copies of the entire base model. For a system serving 50 clients with 50 different adapters, merging would require 50 × 16 GB = 800 GB of storage and 50 separate serving deployments, versus one 16 GB base model plus 50 × 32 MB = 1.6 GB of adapters with hot-swapping. The correct decision depends on the use case: single adapter at high throughput → merge. Multiple adapters at moderate throughput → keep separate with hot-swap. Additionally, the latency overhead of non-merged LoRA adapters is typically only 5-15%, which is acceptable for most production SLAs."*

## 6. Common Beginner Mistakes ❌

```
MISTAKE 1: Saving adapters without metadata
──────────────────────────────────────────────
FIX: Every adapter save must include adapter_metadata.json.
     Training pipeline → save metadata → non-negotiable.
     Without metadata: adapter is an opaque binary blob.
     You WILL need to know what it was trained on in 6 months.

MISTAKE 2: Using "latest" or mutable pointers in production
──────────────────────────────────────────────────────────────
FIX: Production serving code MUST reference EXACT versions.
     "latest" changes silently. Bugs introduced silently.
     Only exception: An explicit "production" tag managed by
     a controlled promotion process (not auto-updated).

MISTAKE 3: Not testing after base model upgrade
────────────────────────────────────────────────
FIX: "It loaded without errors" ≠ "It works correctly."
     ALWAYS run full evaluation suite after base model change.
     Even minor revision bumps can degrade performance 10-20%.

MISTAKE 4: No rollback plan
─────────────────────────────
FIX: Before promoting ANY version to production:
     Identify the version you would roll back to.
     Tag it as "rollback-safe."
     Document and test the rollback procedure.
     Rollbacks under pressure with no plan = disasters.

MISTAKE 5: Not implementing thread safety in swap manager
──────────────────────────────────────────────────────────
FIX: Adapter swapping is NOT thread-safe by default.
     Two concurrent requests switching adapters = race condition.
     Use threading.Lock() around all set_adapter() calls.
     Or use adapter-per-request model if concurrency is high.

MISTAKE 6: Hardcoding adapter paths in application code
─────────────────────────────────────────────────────────
FIX: Application code should query registry for paths.
     WRONG: adapter_path = "/adapters/medical/v2.1.0/"
     RIGHT: adapter_path = registry.get_production_path("medical")
     Hardcoded paths → cannot update without code changes.

MISTAKE 7: Not measuring cold-start latency separately
────────────────────────────────────────────────────────
FIX: First request after server startup hits cold cache.
     Subsequent requests hit warm cache.
     Both must be measured and included in SLA planning.
     Preload most-used adapters at startup to eliminate cold start.

MISTAKE 8: Deleting deprecated adapters immediately
──────────────────────────────────────────────────────
FIX: Keep deprecated adapters for retention period.
     For regulated industries: 7+ years.
     For standard applications: 12 months minimum.
     Every inference in production must be auditable
     to the exact adapter that produced it.
     Deleted adapters = failed audits.

MISTAKE 9: Storing adapter weights in Git
──────────────────────────────────────────
FIX: Binary weights in Git = bloated repository.
     50 MB per version × 100 versions = 5 GB in Git history.
     Use Git-LFS or DVC to store actual weights externally.
     Git tracks POINTERS to weights, not weights themselves.

MISTAKE 10: Not implementing compatibility checker
────────────────────────────────────────────────────
FIX: Always run compatibility check before loading an adapter.
     Especially before: Base model upgrades, new environment deploys.
     Runtime shape mismatch errors are confusing and slow to debug.
     Compatibility check catches these instantly before loading.
```
